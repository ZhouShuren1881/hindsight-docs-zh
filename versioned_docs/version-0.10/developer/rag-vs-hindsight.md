# RAG 与记忆 {#rag-vs-memory}

传统 RAG（检索增强生成）检索与查询相似的文档。Hindsight 提供具备时间推理、实体理解和信念形成能力的结构化记忆。

## 能力对比 {#capability-comparison}

| 能力 | RAG | Hindsight |
|------------|-----|-----------|
| **搜索策略** | 仅语义相似度 | 语义 + 关键词 + 图 + 时间 |
| **多跳推理** | 局限于检索到的文本块 | 沿实体关系遍历图 |
| **时间查询** | 关键词匹配（“春天”） | 日期解析和范围过滤 |
| **实体理解** | 无 | 实体消歧、共现跟踪 |
| **知识整合** | 无状态 | 综合信息并持续演进的心智模型 |
| **性格倾向** | 无 | 3 种特质（怀疑倾向、字面理解倾向、共情）影响解读 |

## 架构对比 {#architecture-comparison}

### RAG

| 步骤 | 操作 |
|------|-----------|
| 1 | 为查询生成嵌入向量 |
| 2 | 向量相似度搜索 |
| 3 | 返回前 k 个文本块 |
| 4 | 生成回答 |

单一检索策略，查询之间不保留状态。

### Hindsight

| 步骤 | 操作 |
|------|-----------|
| 1 | 解析查询（提取时间表达式和实体） |
| 2 | 并行执行 4 种检索：语义、BM25、图、时间 |
| 3 | 使用 RRF 融合结果 |
| 4 | 使用交叉编码器重排序 |
| 5 | 应用性格倾向特质 |
| 6 | 生成回答 |

多种检索策略，在会话之间保留持久状态。

## 示例场景 {#example-scenarios}

### 多跳推理 {#multi-hop-reasoning}

**已存储的事实：**
- “Alice 是 Project Atlas 的技术负责人”
- “Project Atlas 使用 Kubernetes”
- “Kubernetes 集群周二发生故障”

**查询：**“Alice 是否受到近期问题的影响？”

| 系统 | 结果 |
|--------|--------|
| RAG | 只检索有关 Alice 的事实（与“问题”没有语义相似度） |
| Hindsight | 通过实体链接遍历 Alice → Project Atlas → Kubernetes → 故障 |

### 时间查询 {#temporal-queries}

**带时间戳的已存储事实：**
- 3 月：“Alice 开始进行微服务迁移”
- 4 月：“Alice 完成了身份验证服务”
- 10 月：“Alice 正在关注性能问题”

**查询：**“Alice 去年春天做了什么？”

| 系统 | 结果 |
|--------|--------|
| RAG | 返回有关 Alice 的全部事实，不考虑日期 |
| Hindsight | 将“去年春天”解析为 3 至 5 月，过滤到该范围 |

### 实体理解 {#entity-understanding}

**跨会话存储的用户事实：**
- “Pro 订阅”
- “移动应用在设置页面崩溃”
- “改为按年计费”
- “桌面应用运行正常”

**查询：**“你对我的账户了解多少？”

| 系统 | 结果 |
|--------|--------|
| RAG | 列出彼此独立的事实 |
| Hindsight | 通过实体图返回相关联的事实：订阅状态、计费方式、已知问题 |

### 知识演进 {#knowledge-evolution}

**第 1 周：**用户难以使用异步 Python，但能成功使用线程。
**第 3 周：**用户询问 asyncio，并实现异步数据库调用。

| 系统 | 行为 |
|--------|----------|
| RAG | 不记得用户的进步过程 |
| Hindsight | 将心智模型从“用户偏好同步方式”细化为“用户逐渐熟悉异步方式” |

## 各自适用的场景 {#when-to-use-each}

| 使用场景 | 推荐方案 |
|----------|-------------|
| 对静态语料进行文档问答 | RAG |
| 没有时间要求的搜索 | RAG |
| 具有持久记忆的 AI 助手 | Hindsight |
| 需要跟踪实体的应用 | Hindsight |
| 需要一致性格倾向的系统 | Hindsight |
| 时间查询（“上个月”“2023 年”） | Hindsight |
