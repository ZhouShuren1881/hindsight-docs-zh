# 模型 {#models}

Hindsight 使用多种机器学习模型完成不同任务。

## 概述 {#overview}

- **LLM**：事实提取、推理和生成。按提供方配置，完全可定制。
- **嵌入模型**：为语义搜索生成向量表示。默认 `BAAI/bge-small-en-v1.5`。
- **交叉编码器**：对搜索结果重排序。默认 `cross-encoder/ms-marco-MiniLM-L-6-v2`。

首次运行时，嵌入和交叉编码器模型会自动从 HuggingFace 下载。

## LLM

用于事实提取、实体消歧、心智模型整合和回答综合。

**支持的提供方：**

<LLMProvidersGrid />

还支持**任何兼容 OpenAI 的 API**（例如 Azure OpenAI、Together AI、Fireworks），以及**通过 LiteLLM 使用 100+ 提供方**（例如 AWS Bedrock、Azure OpenAI、Together AI）。

:::tip 兼容 OpenAI 的提供方
Hindsight 适用于任何提供兼容 OpenAI API 的服务。设置 `HINDSIGHT_API_LLM_PROVIDER=openai`，并将 `HINDSIGHT_API_LLM_BASE_URL` 指向提供 `/chat/completions` 的端点；多数提供方是以 `/v1` 结尾的 URL，**而非**账户或资源根路径。

**Azure OpenAI 不在资源根路径提供 API**，因此单独使用 `https://<resource>.openai.azure.com` 会返回 `404 Resource not found`。两种可用 URL 格式见 [Azure OpenAI 设置](#azure-openai-setup)。

`openai` 提供方调用 **Chat Completions API**（`/v1/chat/completions`）。新版 **Responses API**（`/v1/responses`）请使用 `HINDSIGHT_API_LLM_PROVIDER=openai-responses`，见下方提示。两者都接受自定义 `HINDSIGHT_API_LLM_BASE_URL`，因此提供 `/v1/responses` 的兼容 OpenAI 端点使用方式与 Chat Completions 相同。

设置示例见[配置](./configuration#llm-provider)。
:::

:::tip OpenAI Responses API（推理与工具同时使用）
设置 `HINDSIGHT_API_LLM_PROVIDER=openai-responses`，调用 OpenAI **Responses API**（`/v1/responses`），而非 Chat Completions。

提供此选项的原因是：部分推理模型（例如 `gpt-5.6-terra`）在 Chat Completions 中**有函数工具时拒绝 `reasoning_effort`**（除非 `reasoning_effort="none"`，否则 HTTP 400）。反思是工具调用循环，因此 `openai`（Completions）提供方会被迫在整个操作（包括最终综合）中禁用推理。（Hindsight 收到该 400 后，会以 `reasoning_effort="none"` 重试一次，调用仍成功，但没有推理。）Responses API 将模型思维链作为独立推理条目，因此**推理与工具可并存**：反思搜索循环使用实际的 `HINDSIGHT_API_LLM_REASONING_EFFORT`（例如 `high`）。

推荐用于使用工具的推理模型（gpt-5.x、o 系列）。也支持自定义 `HINDSIGHT_API_LLM_BASE_URL`，因此任何提供 `/v1/responses` 的兼容 OpenAI 端点（网关、Azure 风格部署）都可像 Chat Completions 路径一样使用。

设置示例见[配置](./configuration#llm-provider)。
:::

:::info 推理/思考模型与 `max_tokens`
思考模型（Gemini 2.5+/3.x、GPT-5/o 系列、Grok 推理、Claude 扩展思考）的提供方输出预算涵盖**推理 token 与可见输出**，推理计入相同的 `max_output_tokens`/`max_completion_tokens` 上限。因此小上限可能完全被推理消耗，导致可见回答在词语中途被截断。

Hindsight 保持反思/心智模型 `max_tokens` 表示**可见页面长度**：通过提示词目标和事后重写实现，**不作为**提供方调用的硬上限。反思综合调用默认不设上限，防止推理挤占回答。需要调用的硬性成本上限时，设置 `HINDSIGHT_API_REFLECT_MAX_COMPLETION_TOKENS`，但要在页面长度之外为推理预留足够余量，否则思考模型仍会截断。

Gemini 调用达到上限时，Hindsight 记录 `truncated at max_output_tokens` 警告，不会将未完成文本静默当作成功返回。
:::

:::tip AWS Bedrock
设置 `HINDSIGHT_API_LLM_PROVIDER=bedrock` 可直接使用 AWS Bedrock 模型。模型名称采用 Bedrock 模型 ID（例如 `us.amazon.nova-2-lite-v1:0`）。无需 API 密钥，身份验证使用 AWS 凭据（`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、`AWS_REGION_NAME`）或 IAM 角色。设置 `HINDSIGHT_API_LLM_BEDROCK_SERVICE_TIER=flex` 可节省 50% 吞吐量成本（见[配置](./configuration#llm-provider)）。

设置示例见[配置](./configuration#llm-provider)。
:::

:::tip 内置 llama.cpp（完全本地，无需 API 密钥）
设置 `HINDSIGHT_API_LLM_PROVIDER=llamacpp` 可运行无外部依赖的内置 llama.cpp 服务器。首次运行自动下载 Gemma 4 E2B GGUF 模型（约 3.5 GB）。需要 `local-llm` 可选依赖：`pip install 'hindsight-api-slim[local-llm]'`。

已发布 Docker 镜像不包含 `llama-cpp-python`（为缩小镜像）。可运行且额外安装该依赖的 Docker 设置见 [`docker/docker-compose/local-llm/`](https://github.com/vectorize-io/hindsight/tree/v0.10.3/docker/docker-compose/local-llm)。

全部选项见[配置](./configuration#built-in-llamacpp)。
:::

:::tip LiteLLM 提供方（Azure、Together AI 等）
设置 `HINDSIGHT_API_LLM_PROVIDER=litellm` 可使用 [LiteLLM](https://docs.litellm.ai/docs/providers) 支持的任意模型，包括 **Azure OpenAI**、**Together AI**、**Fireworks AI** 等。模型名称采用 LiteLLM 提供方前缀格式（例如 `azure/gpt-4o`）。

设置示例见[配置](./configuration#llm-provider)。
:::

:::tip LiteLLM Router（回退链、负载均衡、逐部署限制）
设置 `HINDSIGHT_API_LLM_PROVIDER=litellmrouter`，通过 [LiteLLM Router](https://docs.litellm.ai/docs/routing) 运行默认 LLM。[`Router` 配置](https://docs.litellm.ai/docs/routing#fallbacks)支持跨部署顺序回退、同级负载均衡路由、加权选择、逐部署 `rpm`/`tpm` 限制和冷却时间。Hindsight 原样传入 JSON 配置。

设置见[配置](./configuration#llm-router-litellm-router)。
:::

### 提供方能力 {#provider-capabilities}

除基础生成外，部分提供方支持降低成本或延迟的可选功能。配置的提供方支持时，Hindsight 自动使用各功能。

<LLMProviderCapabilities />

- **Batch API**：通过提供方异步批量端点提交批量记忆提取，成本通常降低约 50%。可用时自动使用，否则同步调用。
- **显式提示词缓存**：复用记忆存储（事实提取）、整合和反思工具循环每次发送的大型固定系统前缀，按提供方缓存输入价格计费。Gemini/Vertex 使用 `CachedContent` API。**默认开启**，用 `HINDSIGHT_API_LLM_PROMPT_CACHE_ENABLED=false` 禁用。提示词结构使缓存前缀**不依赖记忆库**：所有库共享一个缓存，而非每个库/任务目标一个；创建失败时回退到无缓存调用，绝不中断请求。

:::note
“显式提示词缓存”单元格为空，不意味着提供方没有缓存。例如 OpenAI 在服务器端**自动**缓存稳定的提示词开头，无需配置即可获益；Anthropic 通过 `cache_control` 断点支持缓存，也可通过同一提供方钩子接入。本列仅跟踪 Hindsight 的显式 `get_or_create_cached_prefix` 钩子，目前由 Gemini/Vertex 实现。
:::

### 提供方默认模型 {#provider-default-models}

每个提供方都有推荐默认模型，未显式设置 `HINDSIGHT_API_LLM_MODEL` 时使用。这让配置更简单：只需指定提供方，即可采用合理默认值。

<LLMProvidersTable />

**示例：**只设置提供方，使用其默认模型：
```bash
# 自动使用 claude-haiku-4-5
export HINDSIGHT_API_LLM_PROVIDER=anthropic
export HINDSIGHT_API_LLM_API_KEY=sk-ant-xxxxxxxxxxxx
```

显式设置 `HINDSIGHT_API_LLM_MODEL` 可覆盖默认值：
```bash
# 覆盖为使用 Sonnet
export HINDSIGHT_API_LLM_PROVIDER=anthropic
export HINDSIGHT_API_LLM_API_KEY=sk-ant-xxxxxxxxxxxx
export HINDSIGHT_API_LLM_MODEL=claude-sonnet-4-5-20250929
```

也适用于逐操作覆盖：
```bash
# 全局：OpenAI gpt-4o-mini（默认）
export HINDSIGHT_API_LLM_PROVIDER=openai

# 记忆存储：Anthropic claude-haiku-4-5（默认）
export HINDSIGHT_API_RETAIN_LLM_PROVIDER=anthropic
```

### 使用其他模型 {#using-other-models}

未列出的其他 LLM 模型也可能适用于 Hindsight，但必须支持**至少 65,000 个输出 token**，以确保事实提取可靠。如果需要支持不满足此要求的特定模型，请[提交 issue](https://github.com/hindsight-ai/hindsight/issues)申请例外。

:::tip 输出 token 受限的模型
如果模型只支持 32k 或更少输出 token（例如某些旧模型），可以降低记忆存储完成 token 上限：

```bash
# 适用于支持 32k 输出 token 的模型
export HINDSIGHT_API_RETAIN_MAX_COMPLETION_TOKENS=32000

# 适用于支持 16k 输出 token 的模型
export HINDSIGHT_API_RETAIN_MAX_COMPLETION_TOKENS=16000
```

**注意：**`HINDSIGHT_API_RETAIN_MAX_COMPLETION_TOKENS` 必须大于 `HINDSIGHT_API_RETAIN_CHUNK_SIZE`（默认 3000）。系统启动时验证，配置无效时提供错误消息。
:::

:::warning Groq 免费套餐不适用于 Hindsight
Groq 免费套餐每分钟仅允许 8,000 tokens，远低于 Hindsight 单次记忆存储调用所需量（约 64k）。因此不能使用 Groq 免费套餐模型；请使用付费套餐或其他提供方。
:::

### GitHub Copilot 设置 {#github-copilot-setup}

通过官方 GitHub Copilot SDK 使用 GitHub Copilot 订阅，执行 Hindsight 的提取、整合和反思调用。

**前提条件：**
- 有效的 GitHub Copilot 使用资格
- Copilot CLI 已使用运行 Hindsight 的同一操作系统用户登录

**配置 Hindsight：**

```bash
export HINDSIGHT_API_LLM_PROVIDER=github-copilot
export HINDSIGHT_API_LLM_MODEL=gpt-5.6-terra
# 无需 HINDSIGHT_API_LLM_API_KEY。
```

提供方为所有 Hindsight LLM 通道启动一个共享 Copilot 运行时。它使用不含钩子的临时 `COPILOT_HOME`，仅包含已登录账户选择；凭据本身由运行时从系统钥匙串或已有 `gh` CLI 登录中解析。每次调用使用独立临时会话，禁用仓库指令、技能、Copilot 记忆、内置工具和跨会话存储，避免记忆集成递归存储自己的提取调用。

自动化场景中，Copilot SDK 也接受 `COPILOT_GITHUB_TOKEN`、`GH_TOKEN` 或 `GITHUB_TOKEN`。设置其中之一后，主机无需运行过 Copilot CLI，容器和 CI 镜像即使完全没有 `~/.copilot` 也可使用。GitHub Actions 和服务器间部署必须具有适当的 Copilot 组织策略和令牌权限。

**注意事项：**
- 用量计入已认证账户或组织的 Copilot 额度和 AI Credits。
- `HINDSIGHT_API_LLM_BASE_URL` 可指向已有无界面 Copilot 运行时，例如 `http://127.0.0.1:4321`；对此提供方，它不是 LLM 提供方端点。
- GitHub 托管的 Copilot 会话未通过 SDK 提供温度或最大输出 token 控制，因此不应用这些 Hindsight 设置。
- 嵌入和重排序继续使用 Hindsight 单独配置的提供方，本地默认值无需 API 密钥。

### OpenAI Codex 设置（ChatGPT Plus/Pro） {#openai-codex-setup-chatgpt-pluspro}

使用 ChatGPT Plus 或 Pro 订阅运行 Hindsight，无需另付 OpenAI Platform API 费用。

**前提条件：**
- 有效的 ChatGPT Plus 或 Pro 订阅
- 已安装 Node.js/npm（用于 Codex CLI）

**设置步骤：**

1. **安装 Codex CLI：**
   ```bash
   npm install -g @openai/codex
   ```

2. **使用 ChatGPT 凭据登录：**
   ```bash
   codex auth login
   ```
   这会打开浏览器，用 ChatGPT 账户完成身份验证，并将 OAuth 令牌保存到 `~/.codex/auth.json`。

3. **确认身份验证：**
   ```bash
   ls ~/.codex/auth.json  # 应显示身份验证文件已存在
   ```

4. **配置 Hindsight：**
   ```bash
   export HINDSIGHT_API_LLM_PROVIDER=openai-codex
   # export HINDSIGHT_API_LLM_MODEL=gpt-5.6-luna  # 默认 gpt-5.4-mini
   # 无需 API 密钥，自动读取 ~/.codex/auth.json
   ```

5. **启动 Hindsight：**
   ```bash
   hindsight-api
   ```

可以使用 OpenAI Codex CLI 支持的任意模型。

**注意事项：**
- OAuth 令牌存储在 `~/.codex/auth.json`
- 需要时自动刷新令牌
- 用量计入 ChatGPT 订阅，不单独收取 API 费用
- 仅供个人开发使用（见 ChatGPT 服务条款）

#### 为长期运行服务隔离 Codex 身份验证 {#isolating-codex-auth-for-long-running-services}

默认 Hindsight 从 `~/.codex/auth.json` 读取 Codex 凭据，与 `@openai/codex` CLI、编辑器插件和其他智能体运行时共享文件。本地开发很方便，但 Hindsight 作为**长期运行服务**（systemd 单元、容器、后台守护进程）与其他 Codex 进程并行时，可能出现隐蔽故障：

- Codex 刷新令牌仅可使用一次，刷新时轮换。
- 另一个进程刷新共享令牌后，Hindsight 长期进程仍持有过期刷新令牌。
- 记忆召回和 `/health` 继续工作（数据库和 API 正常），但 `/reflect` 失败，例如报错：
  ```text
  Codex refresh_token is permanently invalid (error.code=refresh_token_reused).
  Run 'codex auth login' to re-authenticate.
  ```

为避免此问题，通过 `CODEX_HOME` 环境变量给 Hindsight 服务提供**独立专用 Codex 身份验证目录**。Hindsight 与 `@openai/codex` CLI 一样遵循 `CODEX_HOME`：设置后读取 `$CODEX_HOME/auth.json`，而非 `~/.codex/auth.json`。

```bash
# Hindsight 服务专用凭据目录
export CODEX_HOME=/var/lib/hindsight/codex

# 在隔离目录中执行一次登录（打开浏览器 / 设备代码流程）
codex auth login   # 写入 $CODEX_HOME/auth.json

export HINDSIGHT_API_LLM_PROVIDER=openai-codex
hindsight-api
```

systemd 单元中，将其设在服务定义里，确保不与交互式 Codex 会话共享身份验证：

```ini
[Service]
Environment=CODEX_HOME=/var/lib/hindsight/codex
```

在专用目录重新登录并仅重启 Hindsight 服务后，`/reflect` 使用自己的令牌，不会被其他 Codex 进程轮换而失效。

`openai-codex` 嵌入提供方也遵循 `CODEX_HOME`。

#### 一个进程中使用两个 Codex 配置档 {#two-codex-profiles-in-one-process}

`CODEX_HOME` 是进程级变量，因此同一个 Hindsight 进程创建的所有 Codex 提供方都会解析同一 `auth.json`。要运行多个独立授权的 ChatGPT 账户，例如首选账户达到用量限制时进行故障转移，请通过 `HINDSIGHT_API_LLM_CODEX_HOME`（主提供方）和 `HINDSIGHT_API_LLM_<n>_CODEX_HOME`（带索引的[多 LLM 链](./configuration#multi-llm-strategies-failover--round-robin)成员）为每个账户提供独立凭据目录。各项未设置时先回退到 `CODEX_HOME`，再回退到 `~/.codex`。

```bash
# 两个配置档，分别登录
CODEX_HOME=/var/lib/hindsight/codex-a codex auth login
CODEX_HOME=/var/lib/hindsight/codex-b codex auth login

export HINDSIGHT_API_LLM_PROVIDER=openai-codex
export HINDSIGHT_API_LLM_CODEX_HOME=/var/lib/hindsight/codex-a
export HINDSIGHT_API_LLM_1_PROVIDER=openai-codex
export HINDSIGHT_API_LLM_1_CODEX_HOME=/var/lib/hindsight/codex-b
export HINDSIGHT_API_LLM_STRATEGY='{"mode": "failover"}'
```

令牌刷新按身份验证文件路径协调，因此两个配置档独立刷新，不覆盖对方令牌。故障转移采用通用多 LLM 行为：前一个成员耗尽自身重试并抛错后才尝试下一个成员。没有独立配额分类器或冷却，因此被限流的主提供方仍会在每次请求开始时重试并失败，之后才由后备提供方服务。

### Meta Model API 设置 {#meta-model-api-setup}

[Meta Model API](https://ai.developer.meta.com) 通过兼容 OpenAI 的端点提供 Muse Spark 模型。从 Model API 仪表盘获取密钥，然后：

```bash
export HINDSIGHT_API_LLM_PROVIDER=meta
export HINDSIGHT_API_LLM_API_KEY=your-meta-model-api-key
export HINDSIGHT_API_LLM_MODEL=muse-spark-1.3
```

基础 URL 默认为 `https://api.meta.ai/v1`。可用模型包括 `muse-spark-1.3`（推荐）、`muse-spark-1.2`、`muse-spark-1.1`，以及 1.3 和 1.2 的折扣 `-contributor` 变体，后者允许使用你的提示词和生成内容训练。全部共享 1,048,576-token 上下文窗口。

#### 必需设置 {#required-knobs}

Muse Spark 回答前**始终推理**。这一特性决定了下列设置，因此应视为必需，而非可选调优：

| 变量 | 设置为 | 原因 |
|----------|-----------|-----|
| `HINDSIGHT_API_REFLECT_LLM_TIMEOUT` | `300` | 反思默认 30 秒。Muse Spark 最终综合超过该时间，重试后调用失败而非降级，反思不返回内容。 |
| `HINDSIGHT_API_LLM_TIMEOUT` | `300` | 全局超时（默认 120 秒）涵盖记忆存储和整合，这些操作比非推理模型更慢。 |
| `HINDSIGHT_API_LLM_REASONING_EFFORT` | 不设置，或 `minimal`/`low`/`medium`/`high`/`xhigh` | `none` 会被拒绝并返回 `HTTP 400`。不设置可让模型自行选择深度。 |
| `HINDSIGHT_API_RETAIN_MAX_COMPLETION_TOKENS` | 保留默认 `64000` | 推理 token 计入**输出**预算。降得太低会收到完全没有内容的回答。 |

#### 需要了解 {#good-to-know}

- **提示词缓存自动启用。** 无需设置密钥、标志或断点，Meta 自行复用匹配前缀，因此下方能力表虽不列出显式缓存支持，仍可获得收益。
- **没有批量 API 或嵌入端点。** 嵌入仍由 `HINDSIGHT_API_EMBEDDINGS_PROVIDER` 指定的提供方生成。
- **递归 JSON schema 会被拒绝**，返回 `HTTP 400`。Hindsight 的所有代码路径都不发送递归 schema，因此仅添加自引用响应模型时才需考虑。
- **调用速度较慢。** 一个简单提示词用于推理的 token 可能超过返回输出的 token。

### Cursor 设置（Cursor 订阅） {#cursor-setup-cursor-subscription}

通过无界面输出模式调用 `cursor-agent` CLI，使用 **Cursor 订阅**执行 Hindsight 的提取、整合和反思调用。无需 API 密钥，也没有第二套按 token 计费关系。

这与 [Cursor 集成](/sdks/integrations/cursor)方向相反：后者让 Cursor 成为 Hindsight 的*客户端*，此处 Cursor 是 Hindsight 调用的模型后端。

**前提条件：**
- 有效 Cursor 订阅（免费套餐可用，但仅能使用 `auto`，见下文）
- `cursor-agent` 已安装，并使用运行 Hindsight 的同一操作系统用户登录

**设置步骤：**

1. **安装 CLI：**
   ```bash
   curl https://cursor.com/install -fsS | bash
   ```

2. **登录：**
   ```bash
   cursor-agent login
   ```

3. **确认：**
   ```bash
   cursor-agent --version
   cursor-agent --list-models
   ```

4. **配置 Hindsight：**
   ```bash
   export HINDSIGHT_API_LLM_PROVIDER=cursor
   export HINDSIGHT_API_LLM_MODEL=auto
   # 智能体 CLI 一轮耗时 15-30 秒，明显超过反思默认 30 秒。
   export HINDSIGHT_API_LLM_TIMEOUT=300
   export HINDSIGHT_API_REFLECT_LLM_TIMEOUT=180
   # 无需 API 密钥。要改用密钥认证：
   # export HINDSIGHT_API_LLM_API_KEY=...   # 或 CURSOR_API_KEY
   ```

**注意事项：**

- **提高超时。** 每次调用启动一个 `cursor-agent` 轮次，使用 `auto` 时耗时 15-30 秒，比 chat-completions 请求慢，并超过 `HINDSIGHT_API_REFLECT_LLM_TIMEOUT` 默认 30 秒。保留默认值时，反思首轮会在恢复前不断因超时重试。
- **结构化输出和工具调用在提示词层模拟。** CLI 没有 `response_format`、JSON schema、温度或工具定义标志，只有描述响应封装的 `--output-format text|json|stream-json`。Hindsight 将 schema 或工具列表放入提示词，解析模型返回的 JSON，解析失败时重试。可靠性低于原生 schema，因此最依赖工具的反思操作推荐使用能力强的明确模型，而非 `auto`。
- **免费套餐仅限 `auto`。** 指定 `--model` 会返回 `Named models unavailable Free plans can only use Auto`。付费套餐可使用 `cursor-agent --list-models` 中任意 ID。
- **关闭智能体自身工具。** `cursor-agent` 是智能体，而非补全端点，内置 Shell、Read、Write、Delete、网页获取等工具；`--mode ask` *不是*工具开关，无界面 ask 模式仍会读取工作目录文件。因此 Hindsight 在空白临时工作区运行 CLI，并使用独立 `CURSOR_CONFIG_DIR`（不会读取你的 `~/.cursor` 配置、钩子或会话历史），在其中写入按名称拒绝所有工具的 `cli-config.json`。这等同于 `claude-code` 提供方传给 SDK 的 `tools=[]`，非常关键，因为记忆存储提示词由你存储在 Hindsight 中的任意文本构成。
- 用量计入 Cursor 订阅。
- 不支持推理强度，CLI 没有该标志；设置 `HINDSIGHT_API_LLM_REASONING_EFFORT` 时，Hindsight 在启动时警告一次。
- 嵌入和重排序继续使用 Hindsight 单独配置的提供方。

### SuperGrok 订阅设置（设备代码 OAuth） {#supergrok-subscription-setup-device-code-oauth}

使用 **SuperGrok 订阅**（设备代码 OAuth）执行 LLM 调用，无需 API 密钥。若通过 API 密钥访问 `api.x.ai`，请使用 `provider: openai` 并设置 `HINDSIGHT_API_LLM_BASE_URL=https://api.x.ai/v1`。**此提供方属于订阅通道**，与 `openai-codex`（ChatGPT 订阅）和 `claude-code`（Claude 订阅）同类。两条路径访问相同公开端点，唯一差别在凭据：在浏览器中授权一次的固定费用消费者订阅，或按 token 计费的密钥。

身份验证使用 xAI 自身位于 `https://auth.x.ai` 的 OIDC 颁发者，采用 RFC 8628 设备代码流程，OAuth 公共客户端 ID 来自 xAI 以 Apache-2.0 发布的 Grok CLI 源码。Hindsight 保存自己的凭据文件，绝不读写 Grok CLI 的 `~/.grok/auth.json`。

:::note 订阅使用资格

xAI 可能按 SuperGrok 订阅等级限制 `api.x.ai` 访问：OAuth 授权有效，也可能被 HTTP 403 拒绝。Hindsight 将其报告为独立使用资格错误并说明原因，而非凭据失败；不会重试，也不丢弃令牌。遇到此情况请确认账户等级，或改用 API 密钥提供方。

用量计入 SuperGrok 订阅限制。账户消费上限阻止调用时，Hindsight 抛出独立配额错误，不更改凭据。

:::

**前提条件：**
- 有效的 SuperGrok 订阅
- 执行登录的机器上有浏览器（设备代码流程需要交互批准，运行中的服务绝不执行该流程）

**设置步骤：**

1. **在将保存凭据的主机上登录一次：**
   ```bash
   python -m hindsight_api.engine.providers.xai_oauth_auth login
   ```
   命令输出验证 URL 和用户代码，等待批准，然后以仅所有者可访问的权限写入 `~/.hindsight/xai_oauth.json`。

2. **配置 Hindsight：**
   ```bash
   export HINDSIGHT_API_LLM_PROVIDER=xai-oauth
   # export HINDSIGHT_API_LLM_MODEL=grok-4.5   # 默认 grok-4.5
   # 无需 API 密钥
   ```

3. **启动 Hindsight：**
   ```bash
   hindsight-api
   ```

**注意事项：**
- 自动刷新访问令牌：在过期前 60 秒主动刷新（或配置的请求超时时间，取较长者），并在 HTTP 401 后响应式刷新一次。多个已配置通道可以安全共享凭据文件，刷新会取得咨询锁并在锁内重新读取文件，其他通道不会各自刷新。
- 运行中的服务**绝不**启动设备代码流程。只有重新登录才能恢复时，调用失败并提供要执行的准确命令。
- 与通过 `provider: openai` 访问 `api.x.ai` 不同，此提供方发送成员配置的 `reasoning_effort`，因此该设置会生效。唯一不转发的值是 `none`，xAI 会直接拒绝它（HTTP 400），因此此通道按 API 预期通过省略字段表达。
- 仅实现非流式调用。流式响应不含 `prompt_tokens_details`，会导致缓存 token 计量偏低。

**可选环境变量覆盖：**

| 变量 | 用途 | 默认值 |
|---|---|---|
| `HINDSIGHT_API_XAI_OAUTH_BASE_URL` | 指向其他上游，优先于 `HINDSIGHT_API_LLM_BASE_URL`。 | `https://api.x.ai/v1` |
| `HINDSIGHT_API_XAI_OAUTH_TOKEN_PATH` | 更改凭据存储位置，读写均遵循此路径。 | `~/.hindsight/xai_oauth.json` |
| `HINDSIGHT_API_XAI_OAUTH_CLIENT_ID` | 覆盖登录和刷新所用 OAuth 客户端 ID。 | xAI 发布的公共客户端 ID |
| `HINDSIGHT_API_XAI_OAUTH_SCOPE` | 覆盖登录请求的范围字符串。 | `openid profile email offline_access grok-cli:access api:access` |
| `HINDSIGHT_API_XAI_OAUTH_REFRESH_SKEW_SECONDS` | 在过期前多少秒刷新。较少调用此提供方的部署可增加。 | `60` |
| `HINDSIGHT_API_XAI_OAUTH_REFRESH_TIMEOUT_SECONDS` | 发现、登录和刷新调用的逐请求超时。 | `20` |

#### 部署说明 {#deployment-note}

凭据是主机本地文件，只有交互登录可以创建。因此容器化引擎需要从已登录主机挂载该存储（或在容器内部交互登录一次），并设置 `HINDSIGHT_API_XAI_OAUTH_TOKEN_PATH` 指向它。挂载必须**可写**：与 Grok CLI 自身文件不同，此存储由 Hindsight 持久化每次轮换令牌，只读挂载会在当前令牌过期后导致失败。

xAI **每次刷新都颁发新刷新令牌**，并使旧令牌失效。因此副本必须共享同一个凭据文件，不能各自使用同一次登录输出的副本：另一个副本刷新后，独立副本立即失效，必须重新登录。受支持方式是单一共享可写卷；无法提供时，仅让一个副本使用此提供方，其他副本使用 API 密钥通道。

### Azure OpenAI 设置 {#azure-openai-setup}

Azure OpenAI 通过 **`openai`** 提供方访问，没有 `azure` 提供方；设置为后者会在启动时失败：`Invalid LLM provider: azure`。

容易出错的是基础 URL。Azure 不在资源根路径提供 OpenAI API，因此 Azure 门户显示的端点不能单独使用：

| `HINDSIGHT_API_LLM_BASE_URL` | 结果 |
|---|---|
| `https://<resource>.openai.azure.com` | `404 Resource not found` |
| `https://<resource>.openai.azure.com/openai/deployments/<deployment>` | `404 Resource not found`（没有 `api-version`） |
| `https://<resource>.openai.azure.com/openai/v1` | 可用 |
| `https://<resource>.openai.azure.com/openai/deployments/<deployment>?api-version=<version>` | 可用 |

**推荐使用 v1 接口：**

```bash
export HINDSIGHT_API_LLM_PROVIDER=openai
export HINDSIGHT_API_LLM_API_KEY=<azure-openai-resource-key>
export HINDSIGHT_API_LLM_MODEL=<deployment-name>
export HINDSIGHT_API_LLM_BASE_URL=https://<resource>.openai.azure.com/openai/v1
```

**也可以使用部署范围格式。** 保留 `api-version` 查询字符串，Hindsight 会从基础 URL 解析并传给 SDK：

```bash
export HINDSIGHT_API_LLM_BASE_URL=https://<resource>.openai.azure.com/openai/deployments/<deployment>?api-version=2025-01-01-preview
```

**注意事项：**
- `HINDSIGHT_API_LLM_MODEL` 是**部署名称**，而非模型名称。`gpt-4o` 部署为 `my-gpt4o` 时，配置应填 `my-gpt4o`。
- 密钥是 Azure OpenAI **资源**密钥（`az cognitiveservices account keys list -n <resource> -g <group>`）。API Management 订阅密钥是另一种凭据；前置 APIM 时，基础 URL 必须为 APIM 路由，APIM 必须转发 `api-key` 头。先直接测试 Azure 端点，确定哪个层级失败。
- 网关和代理必须保留相同路径格式（`/openai/v1` 或 `/openai/deployments/...?api-version=`）。
- Azure OpenAI 的 GPT 部署接受 `prompt_cache_key`（改善 GPT-5.6 及更新版本的缓存路由），但相同 `*.openai.azure.com` 端点也提供非 OpenAI Foundry 模型（DeepSeek、Llama、Mistral），这些模型会以 `unrecognized_request_argument` 拒绝该参数。仅主机名无法区分，因此 [`HINDSIGHT_API_LLM_CACHE_AFFINITY`](./configuration#llm-provider) 在 Azure 主机将 `auto` 解析为 `none`。部署提供 OpenAI 模型时，请显式设为 `openai_prompt_cache_key`。

### Vertex AI 设置（Google Cloud） {#vertex-ai-setup-google-cloud}

Google Cloud Vertex AI 通过原生 Google GenAI SDK 提供 Gemini 模型访问。

**前提条件：**
- GCP 项目已启用 Vertex AI API
- 凭据拥有 IAM 角色 `roles/aiplatform.user`

**环境变量：**

|----------|-------------|----------|

**身份验证方式：**

1. **应用默认凭据（ADC）**：开发环境推荐
   ```bash
   # 设置 ADC

   ```

2. **服务账户密钥**：生产环境推荐


**说明：**
- 模型名称可选包含 `google/` 前缀（例如 `google/gemini-3.1-flash-lite`），会自动移除
- 原生 SDK 自动处理令牌刷新
- 提供服务账户凭据时使用它，否则回退到 ADC

## 嵌入模型 {#embedding-model}

将文本转换为用于语义相似度搜索的稠密向量表示。

**默认：** `BAAI/bge-small-en-v1.5` （384 维，约 130MB）

### 支持的提供方 {#supported-providers}

| 提供方 | 说明 | 适用场景 |
|----------|-------------|----------|
| `local` | SentenceTransformers（默认） | 开发、低延迟 |
| `onnx` | 进程内 ONNX Runtime 嵌入器（无需 Ollama/TEI/API 边车） | 轻量本地 CPU、多语言 |
| `openai` | OpenAI 嵌入 API | 生产、高质量 |
| `openai-codex` | 通过 Codex OAuth 使用 OpenAI 嵌入（ChatGPT Plus/Pro，无需 API 密钥） | 现有 ChatGPT/Codex 订阅用户 |
| `openrouter` | OpenRouter 嵌入（兼容 OpenAI 的网关） | 多提供方配置 |
| `cohere` | Cohere 嵌入 API | 生产、多语言 |
| `google` | Google 嵌入（Gemini API 或 Vertex AI） | 生产、多语言、高质量 |
| `tei` | HuggingFace Text Embeddings Inference | 生产、自托管 |
| `zeroentropy` | ZeroEntropy zembed-1 | 生产、高质量 retrieval |
| `litellm` | LiteLLM 代理（统一网关） | 多提供方配置 |
| `litellm-sdk` | LiteLLM SDK（直接 API，无需代理） | 多提供方、更简单的配置 |

### 本地模型 {#local-models}

| 模型 | 维度 | 使用场景 |
|-------|------------|----------|
| `BAAI/bge-small-en-v1.5` | 384 | 默认、快速、质量良好 |
| `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | 384 | 多语言（50+ 种语言） |

### OpenAI 模型 {#openai-models}

| 模型 | 维度 | 使用场景 |
|-------|------------|----------|
| `text-embedding-3-small` | 1536 | OpenAI 默认、高性价比 |
| `text-embedding-3-large` | 3072 | 质量更高、费用更高 |
| `text-embedding-ada-002` | 1536 | 旧版模型 |

### Google 模型 {#google-models}

| 模型 | 维度 | 使用场景 |
|-------|------------|----------|
| `gemini-embedding-001` | 768（可配置） | Google 默认、通用 |
| `gemini-embedding-2-preview` | 768（可配置） | Gemini Embedding 2 系列，多模态，每个输入一个向量 |

Google `gemini-embedding-001` 支持通过截断配置输出维度，Google 推荐 768、1536、3072，可通过 `HINDSIGHT_API_EMBEDDINGS_GEMINI_OUTPUT_DIMENSIONALITY` 设置。默认 768。

Gemini API 和 Vertex AI 均支持 `gemini-embedding-2` 系列，包括 `gemini-embedding-2-preview`。这些模型聚合多输入请求，因此 Hindsight 自动每次调用只嵌入一个输入，确保逐事实向量对齐。

### Cohere 模型 {#cohere-models}

| 模型 | 维度 | 使用场景 |
|-------|------------|----------|
| `embed-english-v3.0` | 1024 | 英文文本 |
| `embed-multilingual-v3.0` | 1024 | 100+ 种语言 |

### ZeroEntropy 模型 {#zeroentropy-models}

| 模型 | 维度 | 使用场景 |
|-------|------------|----------|
| `zembed-1` | 默认 1280（2560/1280/640/320/160/80/40 可配置） | 高质量非对称检索 |

Hindsight 将已存储记忆文本作为 `document` 输入发送给 ZeroEntropy，将召回/搜索文本作为 `query` 输入。ZeroEntropy API 默认 2560 维；Hindsight 默认 1280，以便不更换向量扩展即可使用 pgvector HNSW。

:::warning 嵌入维度
Hindsight 在启动时自动检测嵌入维度并调整数据库 schema。存储记忆后，更改维度会造成数据丢失。
:::

**配置示例：**

```bash
# 本地提供方（默认）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=local
export HINDSIGHT_API_EMBEDDINGS_LOCAL_MODEL=BAAI/bge-small-en-v1.5

# ONNX 提供方（进程内本地 CPU，无需 Ollama/TEI/API 边车；pip install hindsight-api-slim[local-onnx]）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=onnx
export HINDSIGHT_API_EMBEDDINGS_ONNX_MODEL_ID=intfloat/multilingual-e5-small
export HINDSIGHT_API_EMBEDDINGS_ONNX_DIMENSIONS=384

# OpenAI
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=openai
export HINDSIGHT_API_EMBEDDINGS_OPENAI_API_KEY=sk-xxxxxxxxxxxx
export HINDSIGHT_API_EMBEDDINGS_OPENAI_MODEL=text-embedding-3-small

# Cohere
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=cohere
export HINDSIGHT_API_COHERE_API_KEY=your-api-key
export HINDSIGHT_API_EMBEDDINGS_COHERE_MODEL=embed-english-v3.0

# Google（API 密钥认证）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=google
export HINDSIGHT_API_EMBEDDINGS_GEMINI_API_KEY=xxxxxxxxxxxx
export HINDSIGHT_API_EMBEDDINGS_GEMINI_MODEL=gemini-embedding-001

# Google（Vertex AI 认证，设置项目 ID 时自动检测）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=google
export HINDSIGHT_API_EMBEDDINGS_GEMINI_MODEL=gemini-embedding-001
export HINDSIGHT_API_EMBEDDINGS_VERTEXAI_PROJECT_ID=your-gcp-project-id

# TEI（自托管）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=tei
export HINDSIGHT_API_EMBEDDINGS_TEI_URL=http://localhost:8080

# ZeroEntropy
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=zeroentropy
export HINDSIGHT_API_EMBEDDINGS_ZEROENTROPY_API_KEY=your-api-key
export HINDSIGHT_API_EMBEDDINGS_ZEROENTROPY_MODEL=zembed-1
export HINDSIGHT_API_EMBEDDINGS_ZEROENTROPY_DIMENSIONS=1280

# LiteLLM 代理
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm
export HINDSIGHT_API_LITELLM_API_BASE=http://localhost:4000
export HINDSIGHT_API_EMBEDDINGS_LITELLM_MODEL=text-embedding-3-small

# LiteLLM SDK（直接调用，无需代理）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm-sdk
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_API_KEY=sk-xxxxxxxxxxxx
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=openai/text-embedding-3-small

# AWS Bedrock（通过 LiteLLM SDK，凭据来自环境变量或 IAM 角色）
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm-sdk
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=bedrock/amazon.titan-embed-text-v2:0
```

:::tip AWS Bedrock 应用推理配置档

如果组织的服务控制策略在存在[应用推理配置档](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)时拒绝对原始模型 ID 执行 `bedrock:InvokeModel`，请保持 `..._MODEL` 不变，单独添加配置档 ARN：

```bash
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm-sdk
# 保持为可识别模型 ID，用于选择请求格式
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=bedrock/amazon.titan-embed-text-v2:0
# 实际调用的配置档
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL_ID=arn:aws:bedrock:eu-west-1:123456789012:application-inference-profile/abc123
```

两者分开，因为 Bedrock 各模型系列（Titan、Cohere、TwelveLabs、Nova）的嵌入请求和响应格式不同，系列从模型 ID 识别。配置档 ARN 不透明且限定到账户，无法用于识别，因此放在 `..._MODEL_ID` 中，`..._MODEL` 保持真实模型名称。

聊天模型不需要这样处理：设置 `HINDSIGHT_API_LLM_MODEL=bedrock/converse/<arn>` 即可，因为 Converse API 对所有模型使用统一格式。

:::

所有选项（包括 Azure OpenAI 和自定义端点）见[配置](./configuration#embeddings)。

通过自托管 TEI 边车同时提供嵌入与重排序的可运行 Docker Compose 设置，见 [`docker/docker-compose/tei/`](https://github.com/vectorize-io/hindsight/tree/v0.10.3/docker/docker-compose/tei)。

## 交叉编码器（重排序器） {#cross-encoder-reranker}

对初始搜索结果重排序，提高准确度。

**默认：** `cross-encoder/ms-marco-MiniLM-L-6-v2` （约 85MB）

### 支持的提供方 {#supported-providers-1}

| 提供方 | 说明 | 适用场景 |
|----------|-------------|----------|
| `local` | SentenceTransformers CrossEncoder（默认） | 开发、低延迟 |
| `cohere` | Cohere 重排序 API | 生产、高质量 |
| `openrouter` | OpenRouter 重排序 API（兼容 Cohere 的网关） | 多提供方配置 |
| `zeroentropy` | ZeroEntropy 重排序 API（zerank-2） | 生产、领先准确率 |
| `siliconflow` | SiliconFlow 重排序 API（兼容 Cohere 的 `/rerank` 端点） | 中国用户或 SiliconFlow 平台用户 |
| `typesafe` | TypeSafe 类型化决策 API（Jev），通过一个问题对整个候选池排序 | 生产、最高排序质量，也可只返回相关候选 |
| `alibaba` | 阿里云 DashScope 重排序 API（qwen3-rerank） | 阿里云 / DashScope 用户 |
| `google` | Google Discovery Engine 排序 API（REST + Google 认证） | 生产、GCP 集成 |
| `tei` | HuggingFace Text Embeddings Inference | 生产、自托管 |
| `flashrank` | FlashRank（轻量、快速） | 资源受限环境 |
| `litellm` | LiteLLM 代理（统一网关） | 多提供方配置 |
| `litellm-sdk` | LiteLLM SDK（直接 API，无需代理） | 多提供方、更简单的配置 |
| `jina-mlx` | 通过 Apple Silicon MLX 使用 Jina rerank v3（本地，无需 API 密钥） | Apple Silicon（M1+）本地推理 |
| `rrf` | 仅 RRF（无神经网络重排序） | 测试、最少资源 |

### 本地模型 {#local-models-1}

| 模型 | 使用场景 |
|-------|----------|
| `cross-encoder/ms-marco-MiniLM-L-6-v2` | 默认、快速 |
| `cross-encoder/ms-marco-MiniLM-L-12-v2` | 更高准确率 |
| `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` | 多语言 |

### Cohere 模型 {#cohere-models-1}

| 模型 | 使用场景 |
|-------|----------|
| `rerank-english-v3.0` | 英文文本 |
| `rerank-multilingual-v3.0` | 100+ 种语言 |

### ZeroEntropy 模型 {#zeroentropy-models-1}

| 模型 | 使用场景 |
|-------|----------|
| `zerank-2` | 旗舰多语言重排序器（默认） |
| `zerank-2-small` | 更快、更轻量的变体 |

### SiliconFlow 模型 {#siliconflow-models}

SiliconFlow 通过兼容 Cohere 的 `/rerank` 端点托管多种开放权重重排序器：

| 模型 | 使用场景 |
|-------|----------|
| `BAAI/bge-reranker-v2-m3` | 多语言、优秀默认选择 |
| `Qwen/Qwen3-Reranker-8B` | 更大、更高准确率 |

### TypeSafe 模型 {#typesafe-models}

TypeSafe 并非 `/rerank` 端点，而是针对*状态*回答类型化*问题*。Hindsight 将候选作为 Choice 问题选项，因此返回的概率分布就是排序。候选池在 250 选项上限和上下文 token 预算内时，单次调用排序整个池。更大的池或含长文档的池分组处理，各组最佳候选进入最终排序轮，并通过 token 截断适应上下文窗口。

| 模型 | 使用场景 |
|-------|----------|
| `jev-latest` | 默认，跟随当前 Jev 发布版本 |

设置 `HINDSIGHT_API_RERANKER_TYPESAFE_PRUNE_CANDIDATES=true` 增加第二个问题，在相关性结束处截断排序列表，让召回仅返回相关候选。默认关闭，因为会显著缩减召回结果。完整行为和取舍见[配置](/developer/configuration#typesafe)。

TypeSafe 分数是单次召回中的排名位置，而非相关性分数，因此召回不提供 `scores.reranker`，并以 HTTP 400 拒绝 `min_scores.reranker`。

### 阿里云模型 {#alibaba-cloud-models}

阿里云 DashScope 通过兼容 Cohere 的 `/reranks` 端点提供 `qwen3-rerank`：

| 模型 | 使用场景 |
|-------|----------|
| `qwen3-rerank` | 100+ 种语言、默认 |

### LiteLLM 支持的提供方 {#litellm-supported-providers}
