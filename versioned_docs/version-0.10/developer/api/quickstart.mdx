## 启动 API 服务器 {#start-the-api-server}

<Tabs>
<TabItem value="pip" label="pip（仅 API）">

```bash
pip install hindsight-api
export OPENAI_API_KEY=sk-xxx
export HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY

hindsight-api
```

API 地址：[http://localhost:8888](http://localhost:8888/docs)

</TabItem>
<TabItem value="docker" label="Docker（完整体验）">

```bash

export OPENAI_API_KEY=sk-xxx

docker run -it --pull always --name hindsight --restart unless-stopped --shm-size=1g -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v $HOME/.hindsight-docker:/home/hindsight/.pg0 \
  ghcr.io/vectorize-io/hindsight:latest
```

- **API**：http://localhost:8888
- **控制平面**（Web 界面）：http://localhost:9999

:::tip 在生产环境中设置稳定的 `HINDSIGHT_API_WORKER_ID`
工作进程使用容器主机名作为身份，Docker 默认将其设为容器 ID。该值每次重启都会变化，因此容器停止时正在处理的任务会留在旧 ID 下，新容器无法识别这些任务属于自己。

将 `HINDSIGHT_API_WORKER_ID` 设为稳定值，例如 `-e HINDSIGHT_API_WORKER_ID=hindsight-prod`，使工作进程在重启后保持同一身份。即使只有一个容器，也建议这样设置。诊断和恢复命令见[管理 CLI：恢复卡住的操作](/developer/admin-cli#recovering-stuck-or-zombie-operations)。
:::

</TabItem>
</Tabs>

:::tip LLM 提供程序
Hindsight 需要支持结构化输出的 LLM。推荐 **Groq** 搭配 `gpt-oss-20b`，实现快速且经济的推理。
详情见 [LLM 提供程序](/developer/models#llm)。
:::

## 执行过程 {#whats-happening}

| 操作 | 作用 |
|-----------|--------------|
| **记忆存储（Retain）** | 处理内容、提取事实、识别实体，并在知识图谱中建立关联 |
| **记忆召回（Recall）** | 并行运行语义、关键词、图和时间四种搜索策略，找到相关记忆 |
| **反思（Reflect）** | 利用检索到的记忆，生成考虑性格倾向的回答 |
