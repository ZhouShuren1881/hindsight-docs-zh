## 概述 {#overview}

记忆库模板是一份 JSON 清单，用于描述记忆库的完整设置：配置覆盖项、心智模型、强制指令等。无需多次调用 API 来配置记忆库，只需提交一份清单，API 就会完成所有配置。

模板适用于以下场景：
- **复制部署** — 为多个用户或智能体快速创建配置完全相同的记忆库
- **引导入门** — 新用户可以从经过验证的配置开始，而不必从头配置
- **共享** — 将推荐配置作为可移植的 JSON 文件分发
- **框架集成** — 随集成一并提供推荐模板

浏览 [记忆库模板中心](/templates)，查找可直接使用的模板。

## 清单模式 {#manifest-schema}

```json
{
  "version": "1",
  "bank": {
    "reflect_mission": "...",
    "retain_mission": "...",
    "retain_extraction_mode": "concise | verbose | custom | verbatim | chunks",
    "retain_custom_instructions": "...",
    "retain_chunk_size": 2048,
    "retain_structured_chunk_size": 8192,
    "disposition_skepticism": 3,
    "disposition_literalism": 3,
    "disposition_empathy": 3,
    "enable_observations": true,
    "observations_mission": "...",
    "entity_labels": [{ "key": "sentiment", "type": "value", "values": [{ "value": "positive" }, { "value": "negative" }] }],
    "entities_allow_free_form": true
  },
  "mental_models": [
    {
      "id": "unique-lowercase-id",
      "name": "Human-Readable Name",
      "source_query": "The query that generates this mental model's content",
      "tags": ["optional", "tags"],
      "max_tokens": 2048,
      "trigger": {
        "refresh_after_consolidation": false,
        "fact_types": ["world", "experience", "observation"],
        "exclude_mental_models": false,
        "exclude_mental_model_ids": []
      }
    }
  ],
  "directives": [
    {
      "name": "directive-name",
      "content": "The directive instruction text",
      "priority": 0,
      "is_active": true,
      "tags": ["optional", "tags"]
    }
  ]
}
```

### 字段 {#fields}

| 字段 | 必填 | 说明 |
|-------|----------|-------------|
| `version` | 是 | 模式版本。目前为 `"1"`。 |
| `bank` | 否 | 记忆库配置覆盖项。省略时，配置保持不变。 |
| `mental_models` | 否 | 要创建或更新的心智模型。省略时，保持不变。 |
| `directives` | 否 | 要创建或更新的强制指令。省略时，保持不变。 |

`bank`、`mental_models` 和 `directives` 都是可选项。省略任一部分，该部分对应的记忆库设置就会保持不变。

### 记忆库配置字段 {#bank-config-fields}

模板可以包含每项记忆库级配置，因此在其他位置导入导出的记忆库时，也能还原其完整配置。`bank` 中的所有字段均为可选项：只有你填写的字段才会作为记忆库级覆盖项设置，其余字段都从服务器/租户默认值继承。

完整且始终保持最新的字段列表见 [模板 JSON 模式](/bank-template-schema.json)；每个字段的含义与[配置](../configuration.mdx)中的定义相同。最常用的字段包括：

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `reflect_mission` | string | 反思操作的任务说明/上下文 |
| `retain_mission` | string | 指定存入时提取哪些内容 |
| `retain_extraction_mode` | string | `concise`、`verbose`、`custom`、`verbatim` 或 `chunks` |
| `retain_custom_instructions` | string | 自定义提取提示词（要求 `mode=custom`） |
| `retain_chunk_size` | integer | 每个内容分块的目标最大字符数 |
| `retain_structured_chunk_size` | integer | 保持完整的一行 JSONL 或一轮对话的最大字符数；未设置时默认为 `retain_chunk_size` |
| `disposition_skepticism` | integer (1-5) | 性格倾向的怀疑程度 |
| `disposition_literalism` | integer (1-5) | 性格倾向按字面解读的程度 |
| `disposition_empathy` | integer (1-5) | 性格倾向的共情程度 |
| `enable_observations` | boolean | 开启或关闭观测整合 |
| `observations_mission` | string | 控制哪些内容会被综合生成为观测 |
| `entity_labels` | object[] | 按标签组定义的受控词表；参见[记忆库 → entity_labels](./memory-banks#entity-labels) |
| `entities_allow_free_form` | boolean | 是否允许使用受控词表之外的实体 |

### 心智模型字段 {#mental-model-fields}

| 字段 | 必填 | 说明 |
|-------|----------|-------------|
| `id` | 是 | 唯一 ID（小写字母数字字符，可带连字符）。重新导入时用于匹配。 |
| `name` | 是 | 便于阅读的名称 |
| `source_query` | 是 | 通过反思生成此模型内容所用的查询 |
| `tags` | 否 | 用于限定可见范围的标签。默认值：`[]` |
| `max_tokens` | 否 | 生成内容的最大 token 数（256-8192）。默认值：`2048` |
| `trigger` | 否 | 自动刷新的触发器设置 |

### 强制指令字段 {#directive-fields}

| 字段 | 必填 | 说明 |
|-------|----------|-------------|
| `name` | 是 | 强制指令名称。重新导入时作为匹配键。 |
| `content` | 是 | 强制指令的具体文本。 |
| `priority` | 否 | 优先级数值（数值越大越重要）。默认值：`0` |
| `is_active` | 否 | 强制指令是否启用。默认值：`true` |
| `tags` | 否 | 用于分类的标签。默认值：`[]` |

### 行为 {#behavior}

- **配置**：`bank` 中的所有字段都会作为记忆库级配置覆盖项应用
- **心智模型**：按 `id` 匹配——创建新模型；仅当现有模型的定义与清单不同时才更新
- **强制指令**：按 `name` 匹配——创建新指令；仅当现有指令与清单不同时才更新
- **异步处理**：心智模型内容会异步生成。响应包含用于跟踪进度的 `operation_ids`。
- **幂等**：重新导入未变化的清单不会更新任何内容，也不会排入刷新任务，因此每次同步都应用同一模板不会产生 LLM 调用。系统只会重新生成新建或已变更的心智模型。

## 控制平面 {#control-plane}

控制平面的记忆库创建对话框中包含一个可选的“从模板导入”开关。启用后，可以粘贴清单 JSON，在创建记忆库时预先完成配置。

你也可以在记忆库的“设置”页面中选择 **操作 → 导出模板**，将任意记忆库的模板导出并复制到剪贴板。

## 版本管理 {#versioning}

`version` 字段用于支持向前兼容的模式演进。当前版本为 `"1"`。

未来版本发布后：
- 导入时会自动将旧版清单升级到当前模式
- 导出始终生成最新版本
- 如果清单版本高于服务器支持的版本，API 会拒绝该清单，并清楚说明错误及建议升级

因此，旧模板可以一直使用，无需手动更新。
