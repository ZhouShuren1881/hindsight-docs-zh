# 知识页面 {#knowledge-pages}

动态 Markdown 文档，按文件夹树组织，并随着记忆库学习新知识而自行更新。

页面由[心智模型](./mental-models)支撑，但采用面向文档的配置：仅根据记忆库的[观察](../observations)构建，绝不读取其他页面，并在每次整合后增量刷新。有关此 API 背后的概念，请参见[知识页面](../knowledge-pages)。

```json
        }
      ]
    }

```

|字段|说明|
|---|---|
|`kind`|`folder`或`page`|
|`mental_model_id`|支撑页面的心智模型（仅页面具有）|
|`description`|页面的源查询，即用于重建页面的问题|
|`timestamp`|页面的上次刷新、文件夹的上次更新|
|`is_stale`|仅页面具有：自页面上次读取记忆以来，若有记忆写入*该页面自身*的范围，则为 `true`（见下文）|
|`last_refresh_failed_at`|仅页面具有：上次刷新失败的时间；成功时为 `null`。该值存在时，页面不会通过触发器自行重建，但仍可显式刷新；刷新成功后会清除此值|
|`managed`|`true` 当节点被标记为系统拥有而不是手工创作时|

### is_stale 的判定方式 {#how-isstale-is-decided}

每个页面均针对自身范围（标签和 `fact_types`）使用相同的[过时检查](./mental-models#staleness-gating)，以决定计划刷新是否需要执行。被标记的页面会在刷新时重写；未标记的页面保持不变。记忆库其他范围的活动不会标记自身范围内没有变化的页面。

整棵树通过一次查询完成检查，因此无论记忆库有三页还是三百页，标志的计算成本都相同。[`GET /mental-models/{id}`](./mental-models) 对页面背后的心智模型返回相同的值。

该检查无法感知**删除操作**。它只检查自页面上次读取记忆以来发生的*写入*；删除范围内的记忆不会留下写入记录。因此，即使页面引用了已删除的事实，仍会报告自己是最新的。

### 参数 {#parameters}

|参数|类型|必填|说明|
|---|---|---|---|
|`name`|string|是|页面名称。在所属文件夹内必须唯一，比较时不区分大小写；重复名称返回 `409`。（仅在 PostgreSQL 上强制执行。）|
|`source_query`|string|是|页面回答的问题，每次刷新时都会重新询问。|
|`parent_id`|string|否|用于在其中创建页面的文件夹。 `null`（或省略）在根创建它。|
|`tags`|list|否|限定页面构建所用记忆范围的标签，参见[标签是过滤条件](#tags-are-a-filter)。`type:<x>` 标签还设置页面的呈现类型，同时仍参与过滤。|
|`max_tokens`|int|否|内容的 Token 预算，默认为 `4096`（普通心智模型默认为 `2048`）。|
|`trigger`|object|否|刷新配置 - 见下文。|

### 标签是一个过滤器 {#tags-are-a-filter}

`tags` 并非仅用于标注页面，而是限定页面构建所用的记忆范围。有标签的页面默认按 **`all_strict`** 匹配：记忆必须包含页面的**每一个**标签，未标记的记忆则被**完全排除**。

因此创建的页面如下：

```json
{
  "name": "家庭实验室基础设施",
  "source_query": "NAS、ThinkPad、docker 容器、jellyfin",
  "tags": ["type:runbook", "homelab", "infrastructure"]
}
```

该页面仅根据同时带有 `type:runbook`、`homelab` **和** `infrastructure` 标签的记忆构建。如果存储记忆时没有附上这些确切的标签（在创建页面时临时编造主题标签通常会出现这种情况），页面将匹配不到任何记忆，并生成*“我没有这方面的信息。”*。对同一查询直接进行[记忆召回](./recall)仍可返回全部结果，因为召回并未使用同样的过滤条件。

`type:<x>` 标签尤其容易引发此问题：虽然文档说明它用于设置页面呈现类型，但它也会像其他标签一样缩小检索范围。

解决此问题的三种方法：

|你想要|这样做|
|---|---|
|根据整个记忆库构建页面|省略 `tags`（或传入 `[]`）|
|用于限制页面范围的标签，但仍包含未标记的记忆|保留`tags`，添加`"trigger": {"tags_match": "all"}`|
|仅带有每个标签的记忆（严格隔离，例如每个用户页面）|保留`tags` 和 `all_strict`默认|

要修复已生成空内容的页面，请用 `PATCH` 传入 `{"tags": []}` 或扩大 `tags_match` 的匹配范围，再刷新页面。标签存储在支撑页面的心智模型上，并非写死在正文中。

参见[标签匹配模式](./recall#tags) 的完整语义 `any`，`all`，`any_strict`，`all_strict`，和`exact`。

### 默认触发器 {#default-trigger}

省略 `trigger` 时，页面采用面向文档的默认配置：

```json
{
  "mode": "delta",
  "fact_types": ["observation"],
  "exclude_mental_models": true,
  "refresh_after_consolidation": true
}
```

这使页面成为仅根据整合后的观察构建的动态文档：当整合在其范围内产生新知识时增量刷新，且绝不受其他页面影响。

|设置|为什么|
|---|---|
|`fact_types: ["observation"]`|页面读取整合后的认知，而非底层原始对话噪声。观察已经去重且有证据支持，因此页面读起来像整理好的文档而非对话记录。此限制由工具结构强制执行：范围仅包含 `observation` 时，刷新智能体根本不会获得原始记忆的召回工具。|
|`exclude_mental_models: true`|页面绝不基于其他同级页面进行反思。否则页面可能相互引用，形成反馈循环，使一条错误陈述扩散到整个知识库。|
|`mode: "delta"`|每次刷新都会使用自上次刷新以来的新内容编辑现有文档，而不是重新生成它，因此手动调整的结构和措辞得以保留。参见[刷新模式](./mental-models#refresh-mode)。|
|`refresh_after_consolidation: true`|当整合在页面范围内产生新知识时重写页面。与其他心智模型一样，该过程受[过时检查](./mental-models#staleness-gating)控制；无关的记忆库活动不会触发重建。|

### 页面生命周期 {#page-lifecycle}

1. **创建** — 页面存储占位符内容并提交后台刷新；调用立即返回并带有 `operation_id`。
2. **首次构建** — 由于尚无可编辑的文档，执行完整生成。
3. **整合** — 存储新记忆，并将其整合为观察。
4. **过时检查** — 对触发器要求检查的页面，按各自范围进行检查（标签和 `fact_types` 均适用）。
5. **增量刷新** — 通过仅使用新观察编辑现有文档来重写过时页面。

页面*基于观察构建*，但仍可检查观察的底层证据：刷新智能体可将记忆展开为原始文本块或文档（除非记忆库禁用了 `store_document_text`）。启用默认关闭的 `HINDSIGHT_API_REFLECT_SOURCE_FACTS_MAX_TOKENS` 后，观察搜索还会返回每条观察所依据的事实。

:::info
传入的 `trigger` 是**部分更新**：仅应用实际发送的字段，其余字段保留上述默认值。发送 `{"trigger": {"tags_match": "all"}}` 会扩大标签过滤范围，并保留 `mode`、`fact_types`、`exclude_mental_models` 和 `refresh_after_consolidation`。唯一例外是两个刷新触发器保持互斥：设置 `refresh_cron` 会清除 `refresh_after_consolidation`，反之亦然。
:::

这里支持全部[心智模型触发设置](./mental-models#trigger-settings)，包括用 `refresh_cron` 执行计划重建以替代整合驱动的重建，以及用 `tag_groups` 定义复合标签范围。

```json

    {
      "id": "kp-2e85...",
      "name": "部署API",
      "mental_model_id": "mm-77ab...",
      "snippet": "API 通过...部署",
```

|参数|类型|默认|说明|
|---|---|---|---|
|`q`|string|—|必填。搜索查询（最小长度 1）。|
|`limit`|int|`10`|最大结果，1–50。|
|`tags`|string[]|—|仅返回带有这些标签的页面，按 `tags_match` 匹配。参见[按标签过滤](#filter-by-tags)。|
|`tags_match`|string|`any`|`any`，`all`，`any_strict`，`all_strict`，或`exact`。|
|`tag_groups`|string|—|JSON 编码的复合过滤条件，结构与记忆召回的 `tag_groups` 相同。|

这里搜索的是整个页面。要搜索单条记忆，请使用[记忆召回](./recall)。

### 按标签过滤 {#filter-by-tags}

树查询和搜索使用与[记忆召回](./recall)相同的标签过滤条件：`tags` 配合 `tags_match`，或复合 `tag_groups` 表达式（两者都是 `GET` 请求，因此在查询字符串中进行 JSON 编码）。过滤条件匹配各页面自身的标签。搜索仅对匹配页面排序；树仅保留匹配页面及其祖先文件夹。没有匹配页面的文件夹会被排除，因为其名称也可能泄露与页面一样多的信息。

与记忆召回一样，`any` 和 `all` 也返回**未标记**的页面。若仅应返回带标签的页面（例如只向用户展示自己的页面），请使用 `any_strict`、`all_strict` 或 `exact`。

## 存储 {#storage}

|表|存储内容|
|---|---|
|`knowledge_pages`|树结构：文件夹和页面及其名称、父级和顺序。页面行引用其背后的心智模型；文件夹行没有此引用。|
|`mental_models`|内容：文档正文、源查询、标签、Token 预算、触发器和刷新历史。|

页面层仅负责树结构；所有内容相关信息均存储在背后的心智模型中，因此每项[心智模型](./mental-models)功能均可原样用于页面。

## 端点摘要 {#endpoint-summary}

|方法|路径|说明|
|---|---|---|
|`GET`|`/knowledge-base/tree`|带有过时状态的嵌套文件夹/页面树|
|`POST`|`/knowledge-base/folders`|创建文件夹|
|`POST`|`/knowledge-base/pages`|创建页面（异步首次构建）|
|`GET`|`/knowledge-base/pages/{page_id}`|阅读页面为 markdown|
|`GET`|`/knowledge-base/search`|页面混合搜索|
|`PATCH`|`/knowledge-base/nodes/{node_id}`|重命名、移动或重新配置节点|
|`DELETE`|`/knowledge-base/nodes/{node_id}`|删除节点及其子树|
|`GET`|`/knowledge-base/export`|将整个库导出为markdown 文件|
