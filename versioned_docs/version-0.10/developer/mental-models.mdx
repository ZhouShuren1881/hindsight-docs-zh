# 心智模型 {#mental-models}

**心智模型**是针对记忆库某个问题长期维护的答案。你只需定义一次问题，Hindsight 就会编写并保存答案，在记忆库学到更多知识时于后台改写它。

[观察](./observations)自动生成，且是原子化的，一次表达一个认知；心智模型则由你主动规划：由你决定哪些问题值得拥有一个长期存在、始终保持最新的答案。

## 答案已经写好 {#the-answer-is-already-written}

使用心智模型的原因是速度。基于记忆库中的记忆进行推理，涉及检索、综合以及由 LLM 编写答案，成本很高。心智模型将这些工作移出请求路径：提前在后台完成，你的应用只需**读取当前版本**。

获取心智模型只需读取数据库，无需检索、综合、调用 LLM 或等待。启动时加载心智模型的智能体，可以直接获得一页已经整理好的知识，无需在最初几秒重新探索这些内容。

这也让答案保持**一致**。两个用户提出同一问题，会得到同一份文档，因为这里仅有一份文档，而不是两个独立生成、细节可能相互矛盾的答案。

心智模型也是[反思](./reflect)首先查找的内容。其检索层次如下：

| 层次 | 生成方式 | 粒度 |
|---|---|---|
| **心智模型** | 由你明确指定 | 每个问题对应一份完整文档 |
| **观察** | 自动整合 | 每组事实对应一个认知 |
| **原始事实** | 自动记忆存储 | 每条陈述对应一条事实 |

每一层都是下层知识成本更低、更确定的版本。如果第一步找到最新且覆盖问题的心智模型，反思就可以直接据此回答，无需继续深入观察和原始事实。这将同样的节省效果应用到了智能体循环内部。

## 无需请求，始终保持最新 {#always-current-without-asking}

心智模型不会像缓存答案那样悄然过时。Hindsight 会跟踪是否出现了模型应当覆盖的新记忆，并在有新记忆时重建模型：可以在新知识整合完成后立即重建，也可以按照你设置的计划重建。

检查会先进行，而且限定在模型自身的范围内：只有*该模型范围内*确有变化，才会触发重建。繁忙的记忆库不会让不相关的模型不断改写，对没有变化的记忆库执行计划重建也不会产生开销。

模型提供给反思智能体时，会携带新鲜度信号，说明其范围内是否有在上次编写之后进入记忆库的记忆。落后的模型仍会显示，但不再使检索提前结束；智能体应通过下层知识验证它，而不是盲目信任。

---

## 多次改写仍保持稳定 {#stable-across-rewrites}

一份被改写数百次的文档会遇到一个问题，仅靠礼貌地要求 LLM 无法解决：即使告诉它「保留未变化的部分」，它仍会逐渐偏移。项目符号变成编号，大小写发生变化，句子被悄然换一种说法。模型擅长的是生成文本，而不是逐字复制。

Hindsight 可以改为**增量**刷新模型，只应用新知识所要求的修改，其余内容保持原样，无需重新生成并寄希望于结果不变。一份长期使用的操作手册仍会保持为你原先写下的文档，并加入新内容，而不会慢慢变成另一份大致表达同样意思的文档。

---

## 范围与隔离 {#scope-and-isolation}

心智模型的标签决定两件事：它允许读取哪些记忆，以及哪些调用者可以看到它。限定为某个客户、团队或用户的模型，只会基于该范围内的记忆构建，也只会出现在该范围的请求中。这将记忆库其他部分使用的相同隔离规则应用到了综合后的知识。

---

## 溯源 {#provenance}

心智模型不是没有来源的文字。它会记录构建时使用的事实和观察，每次内容变化也会保留上一版本。你可以看到模型上个月说了什么，以及依据哪些证据。当模型给出令人意外的结论，需要有人追问其来源时，这一点很重要。
