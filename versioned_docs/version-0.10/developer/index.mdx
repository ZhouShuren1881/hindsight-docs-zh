## 为什么选择 Hindsight？ {#why-hindsight}

AI 智能体在不同会话之间会忘记所有内容。每次对话都从零开始，不知道你是谁、你们讨论过什么，也不记得助手已经学到了什么。这不仅是实现细节，还从根本上限制了 AI 智能体的能力。

**问题比看起来更难：**

- **简单的向量检索不够**——“Alice 去年春天做了什么？”需要时间推理，单靠语义相似度无法解决。
- **事实彼此脱节**——知道“Alice 在 Google 工作”和“Google 位于 Mountain View”，就应该能回答“Alice 在哪里工作？”，即使从未直接存储过这个答案。
- **AI 智能体需要整合知识**——编程助手如果记得“用户偏好函数式编程”，就应该将其整合为观测，并在提出建议时加以考虑。
- **上下文很重要**——性格倾向不同的记忆库，对同一信息可能有不同的理解。

Hindsight 通过专为 AI 智能体设计的记忆系统解决这些问题。

### 记忆类型 {#memory-types}

Hindsight 不存储对话本身。它将对话中的内容提取为带类型的事实，再以这些事实为基础构建知识：

- **世界事实**——系统获知的一项客观陈述。*“Alice 在 Google 工作。”*
- **经历事实**——记忆库自身做过的事。*“我向 Bob 推荐了 Python。”*
- **观测**——从多条事实整合得到的认知判断，带有证据和历史记录。*“用户曾热衷 React，现在转向了 Vue。”*
- **心智模型**——针对经常询问的问题，由你编写并维护的摘要。
- **知识页**——记忆库围绕自身内容编写、持续更新的文档。

事实并非只是一个列表。每条事实都与它提及的实体，以及共享这些实体的其他事实相连。正因如此，系统才能根据两条从未一起存储的事实回答“Alice 在哪里工作？”。本页顶部的图来自一个示例记忆库；将鼠标悬停在某条记忆上，就能看到它与哪些内容相连。

### 多策略检索 {#multi-strategy-retrieval}

`recall()` 会**并行**执行四路搜索，因为没有任何单一策略能够处理所有问题：

- **语义**——按含义而非措辞匹配，因此“Alice 的工作”可以找到“Alice 是一名软件工程师”。
- **关键词（BM25）**——查找嵌入向量容易混淆的名称和技术术语；支持五种可插拔的 Postgres 后端，其中一种可用于 Citus 集群。
- **图**——沿实体连接检索，即便某条事实与查询没有相同词语，只要它可通过两跳到达，也能被返回。
- **时间**——将时间表达式解析为窗口，按相关性填充结果，同时使结果*分布在整个时间范围内*，因此“2023 年发生了什么？”不会只返回 12 月的内容。

随后进行比任何单一路径都更关键的处理：

- **按排名融合，而非按分数融合**——多个策略共同认可的记忆会胜出，任何一路的评分尺度都无法压过其他策略。
- **由交叉编码器重排序**——同时读取查询和记忆，重新判断相关性。
- **按 token 预算截取，而非取前 k 项**——你指定可承担的上下文大小，Hindsight 据此填充内容，因为智能体按 token 而非结果数量分配预算。

完整策略说明请参阅 [Recall](/developer/retrieval)。

### 观测整合 {#observation-consolidation}

后台工作进程持续将原始事实转化为持久的认知判断：

- **去重**——重叠的事实会合并为一条观测，而不会作为重复项不断堆积。
- **有证据依据**——每条观测都指向支持它的记忆，并保留准确引文和支持事实数。
- **逐步完善并保留历史**——新证据会更新观测，同时保留历史记录，让你看到认知判断如何变化。
- **感知更新状态**——新记忆已写入但尚未完成整合时，`reflect` 会将受影响的观测视为待更新，并在采信前用原始事实核验。

### 知识页 {#knowledge-pages}

观测一次回答一个问题。**知识页**是记忆库围绕自身内容编写、持续更新的文档，例如“这里有哪些组件？”或“我们的错误处理约定是什么？”。当整合在其范围内产生新知识时，页面会以增量方式改写：

- **具有 Wiki 结构**——页面位于目录树中，可浏览、可搜索，每页回答一个问题。
- **以观测为基础**——内容从整合后的认知判断综合生成，而非直接来自原始对话，因此页面不是对话转录的摘要。
- **绝不自我引用**——页面绝不读取其他页面，因此不会相互引用而形成反馈循环。
- **按需映射为真实文件**——`hindsight fs mount` 将目录树映射到磁盘，呈现为普通 Markdown 文件，无需 SDK 即可使用 `grep`、编辑器或智能体文件工具。

完整模型说明请参阅[知识页](/developer/knowledge-pages)。

### Reflect {#reflect}

`recall()` 返回记忆，`reflect()` 返回**答案**。它围绕记忆库运行智能体循环，而非只执行一次查询：

- **自行收集证据**——智能体决定需要哪些信息，并调用自身工具，最多进行十轮；在检索到内容之前不能作答。
- **按优先级检查来源**——先查心智模型和知识页，再查观测，最后才查原始事实，因此会先读取提炼后的答案，再读取原始记录。
- **引用实际使用的来源**——只有实际检索到的 ID 才能被引用。

两个记忆库对相同问题给出不同答案，取决于它们的配置：

- **任务说明**——用自然语言描述记忆库的身份，告诉它优先考虑什么。*“我是专注于 ML 的研究助手。我更看重简单实用，而非追求最前沿。”*
- **强制指令**——绝不能违反的硬性规则。*“绝不推荐具体股票。”*
- **性格倾向**——怀疑倾向、字面解读倾向和共情倾向，均采用 1–5 的量表，影响它如何解读检索到的内容。

这些配置只影响 `reflect`。无论谁发起查询，`recall` 都返回相同的记忆。

循环的详细说明请参阅 [Reflect](/developer/reflect)。

## 集成 {#integrations}

**编程智能体**——[一次安装](/sdks/integrations/coding-agents)即可将 20 多种智能体运行框架，包括 Claude Code、Codex CLI、Cursor CLI、opencode、Copilot CLI 等，连接到按仓库划分的记忆库。

**个人智能体**——[Hermes](/sdks/integrations/hermes) 和 [OpenClaw](/sdks/integrations/openclaw) 将 Hindsight 安装为其记忆服务提供方：每轮回答前召回相关内容，回答后存入本轮对话。Hermes 桌面应用可[在设置中配置](/sdks/integrations/hermes-desktop)，无需终端。

其他框架、MCP 服务器和工具均可在[集成中心](/integrations)找到。
