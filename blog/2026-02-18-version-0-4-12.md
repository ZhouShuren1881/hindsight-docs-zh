Hindsight 0.4.12 扩展了可摄取的内容类型，降低了摄取成本，也拓宽了可运行它的环境。

<!-- truncate -->

- [**文件摄取**](#file-ingestion)：直接摄取 PDF、图像和 Office 文档。
- [**异步 Retain 的 Batch API**](#batch-api-for-async-retain)：使用 OpenAI 和 Groq 的 Batch API，将 LLM 摄取成本降低 50%。
- [**Go 客户端 SDK**](#go-client-sdk)：符合 Go 惯用模式的客户端，支持函数式选项并覆盖完整 API。
- [**DiskANN 向量索引**](#diskann-vector-indexing)：支持 pgvectorscale 和 Azure pg_diskann，满足大规模部署需求。

## 文件摄取 {#file-ingestion}

Hindsight 现在可以直接摄取 PDF、图像和常见的 Office 文档（DOCX、PPTX、XLSX），无需先由你提取文本。

```python
from hindsight_sdk import HindsightClient

client = HindsightClient()

# 存入 PDF
with open("report.pdf", "rb") as f:
    client.retain_files("my-bank", files=[("file", ("report.pdf", f, "application/pdf"))])

# 存入图像
with open("screenshot.png", "rb") as f:
    client.retain_files("my-bank", files=[("file", ("screenshot.png", f, "image/png"))])
```

也可以直接使用 REST 端点：

```bash
curl -X POST http://localhost:8888/v1/default/banks/my-bank/files/retain \
  -F "file=@report.pdf;type=application/pdf"
```

目前有两种文件解析器：**Markitdown**（默认）和新推出的 **Iris**。后者能提升复杂文档的提取质量。切换解析器的命令如下：

```bash
export HINDSIGHT_API_FILE_PARSER=iris  # 或 markitdown（默认）
```

## 异步 Retain 的 Batch API {#batch-api-for-async-retain}

使用异步存入时，启用模型供应商的 Batch API 即可将 LLM 成本降低 50%。OpenAI 和 Groq 都为批量工作负载提供 50% 的 token 定价折扣，条件是处理窗口最长可达 24 小时。

```bash
export HINDSIGHT_API_RETAIN_BATCH_ENABLED=true
```

此功能要求使用异步存入（在请求中设置 `async=true`）。Hindsight 会将事实提取调用作为批处理作业提交给模型供应商，轮询作业是否完成，并自动处理结果。由于存入流程本来就在后台运行，延迟的处理窗口通常不会被最终用户察觉。

对于需要摄取大量内容的工作负载（例如回填、文档库和对话存档），这是影响最大的成本优化措施。

此版本还改进了可靠性，确保大型载荷在整个批处理生命周期中都能得到正确处理，并确保通过异步存入流程处理时保留文档标签。

## Go 客户端 SDK {#go-client-sdk}

Hindsight 现在提供 Go 客户端。该客户端使用 [OpenAPI Generator](https://github.com/OpenAPITools/openapi-generator)，根据 OpenAPI 3.1 规范生成。

```go
import hindsight "github.com/vectorize-io/hindsight/hindsight-clients/go"

cfg := hindsight.NewConfiguration()
cfg.Servers = hindsight.ServerConfigurations{
    {URL: "http://localhost:8888"},
}
client := hindsight.NewAPIClient(cfg)
ctx := context.Background()

// 存入一条记忆
retainReq := hindsight.RetainRequest{
    Items: []hindsight.MemoryItem{
        {Content: "The deployment succeeded at 14:32 UTC.", Tags: []string{"ops"}},
    },
}
client.MemoryAPI.RetainMemories(ctx, "my-bank").RetainRequest(retainReq).Execute()

// 召回记忆
recallReq := hindsight.RecallRequest{Query: "recent deployments"}
resp, _, _ := client.MemoryAPI.RecallMemories(ctx, "my-bank").RecallRequest(recallReq).Execute()
for _, r := range resp.Results {
    fmt.Println(r.Text)
}
```

完整参考请参阅 [Go SDK 文档](/sdks/go)。

## DiskANN 向量索引 {#diskann-vector-indexing}

现在提供两种新的向量索引后端，适用于大规模部署：

**pgvectorscale (DiskANN)** — 面向自托管部署的高性能近似最近邻搜索：

```bash
# 使用 TimescaleDB + DiskANN 的 docker-compose 示例
docker compose -f docker/docker-compose/timescale/docker-compose.yml up
```

**Azure pg_diskann** — 为 Azure Database for PostgreSQL – Flexible Server 提供原生 DiskANN 索引，无需额外基础设施。

通过环境变量配置索引后端：

```bash
export HINDSIGHT_API_VECTOR_INDEX_BACKEND=diskann        # pgvectorscale
export HINDSIGHT_API_VECTOR_INDEX_BACKEND=azure_diskann  # Azure pg_diskann
```

这两种后端都可以直接替代默认的 pgvector 索引，在不更改 API 的情况下提升大规模场景中的召回性能。

## 其他更新 {#other-updates}

- **AI SDK 工具链**：Vercel AI SDK 集成经过简化和改进，TypeScript 类型更完善，工具定义也更清晰。
- **Python 客户端**：异步 API 一致性改进和 keepalive 超时修复，减少了高负载下的连接中断问题。
- **OpenClaw 加固**：采用更安全的 shell 处理方式（使用 `execFile` 而不是 `exec`）、HTTP 双模式通信、按用户隔离记忆库，并通过冷却逻辑提升重新初始化的可靠性。
