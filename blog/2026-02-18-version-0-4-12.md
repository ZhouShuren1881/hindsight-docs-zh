## 文件摄取 {#file-ingestion}

Hindsight 现在可以直接记忆存储 PDF、图像和常见 Office 文档（DOCX、PPTX、XLSX），而无需先提取文本。

```python
from hindsight_sdk import HindsightClient

client = HindsightClient()

#记忆存储 PDF
with open("report.pdf", "rb") as f:
    client.retain_files("my-bank", files=[("file", ("report.pdf", f, "application/pdf"))])

#记忆存储图像
with open("screenshot.png", "rb") as f:
    client.retain_files("my-bank", files=[("file", ("screenshot.png", f, "image/png"))])
```

或者直接使用REST端点：

```bash
curl -X POST http://localhost:8888/v1/default/banks/my-bank/files/retain \
  -F "file=@report.pdf;type=application/pdf"
```

有两个文件解析器可用：**降价**（默认）和新的**鸢尾花**解析器，它可以提高复杂文档的提取质量。切换解析器：

```bash
export HINDSIGHT_API_FILE_PARSER=iris  #或降价（默认）
```

## Batch API 用于异步记忆存储 {#batch-api-for-async-retain}

使用异步记忆存储时，您现在可以通过启用提供者 Batch API 将 LLM 成本降低 50%。 OpenAI 和 Groq 都为批量工作负载提供 50% 的token定价折扣，以换取长达 24 小时的处理窗口。

```bash
export HINDSIGHT_API_RETAIN_BATCH_ENABLED=true
```

这需要异步记忆存储（您请求中的`async=true`）。 Hindsight 将事实提取调用作为批处理作业提交给提供者，轮询是否完成，并自动处理结果。因为记忆存储无论如何都在后台运行，所以延迟的处理窗口通常对最终用户来说是不可见的。

对于摄取大量内容（回填、文档库、对话存档）的工作负载来说，这是最有影响力的成本优化。

此版本中的可靠性改进还确保在整个批处理生命周期中正确处理大型有效负载，并且在使用异步记忆存储流时保留文档标签。

## Go 客户端SDK {#go-client-sdk}

Hindsight 现在有一个 Go 客户端，它是使用 [OpenAPI 生成器](https://github.com/OpenAPITools/openapi-generator) 根据 OpenAPI 3.1 规范生成的。

```go
import hindsight "github.com/vectorize-io/hindsight/hindsight-clients/go"

cfg := hindsight.NewConfiguration()
cfg.Servers = hindsight.ServerConfigurations{
    {URL: "http://localhost:8888"},
}
client := hindsight.NewAPIClient(cfg)
ctx := context.Background()

//记忆存储 a 记忆
retainReq := hindsight.RetainRequest{
    Items: []hindsight.MemoryItem{
        {Content: "部署于 UTC 时间 14:32 成功。", Tags: []string{"ops"}},
    },
}
client.MemoryAPI.RetainMemories(ctx, "my-bank").RetainRequest(retainReq).Execute()

//记忆召回记忆
recallReq := hindsight.RecallRequest{Query: "最近部署"}
resp, _, _ := client.MemoryAPI.RecallMemories(ctx, "my-bank").RecallRequest(recallReq).Execute()
for _, r := range resp.Results {
    fmt.Println(r.Text)
}
```

请参阅 [转到SDK文档](/sdks/go) 以获得完整参考。

## DiskANN 向量索引 {#diskann-vector-indexing}

两个新的向量索引后端可用于大规模部署：

**pgvectorscale (DiskANN)** — 自托管部署的高性能近似最近邻搜索：

```bash
#使用 TimescaleDB + DiskANN docker-compose 示例
docker compose -f docker/docker-compose/timescale/docker-compose.yml up
```

**Azure pg_diskann** — 适用于 PostgreSQL 的 Azure 数据库本机 DiskANN 索引 – 灵活的服务器，无需额外的基础设施。

通过环境变量配置索引后端：

```bash
export HINDSIGHT_API_VECTOR_INDEX_BACKEND=diskann        # pgvectorscale
export HINDSIGHT_API_VECTOR_INDEX_BACKEND=azure_diskann  #Azure pg_diskann
```

两个后端都是默认pgvector索引的直接替代品，在不改变API的情况下提供更好的大规模记忆召回性能。

## 其他更新 {#other-updates}

- **AI SDK 工装**：VercelAISDK集成已得到简化和改进，具有更好的TypeScript类型和更清晰的工具定义。
- **Python客户端**：异步API一致性改进和保持活动超时修复减少了负载下的连接丢失问题。
- **OpenClaw硬化**：更安全的 shell 处理（`execFile` 而不是 `exec`）、HTTP 双模式通信、每用户记忆库隔离以及更可靠的冷却逻辑重新初始化。
