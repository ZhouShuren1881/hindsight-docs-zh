Hindsight 0.9.0 提供了我们几个月来并行构建的两件事：**知识页面** — 您的记忆库编写和维护的有关其自身的动态文档 — 以及 **统一编码-智能体插件**，它将长期项目记忆带入十个编码智能体 — Claude Code、Codex CLI、 Cursor CLI、opencode、GitHub Copilot CLI、Cline、Kilo、Grok Build、Antigravity 和 Devin — 只需一条命令，零配置。

两者看起来都不像我们想要构建的。这篇文章讲述的是我们如何走到这一步的故事，因为弯路就是产品：我们必须发明一个基准，它杀死了我们的架构，以及一个学会自我修复的维基。

## 1。 “这真的有帮助吗？” {#1-is-this-actually-helping}

它以一个令人不舒服的问题开始。我们有用于编码智能体的记忆集成，用户喜欢它们，演示进展顺利 - 你会向智能体询问错误，记忆会浮出解释它的旧决策，房间会点头。然后客户会问_这实际上有多大帮助？_我们会寻找轶事，因为我们没有数字。

所以我们去买一个，显而易见的方法：SWE-长凳。真实的存储库、真实的问题、领域的标准。花了几天时间才意识到它无法回答我们的问题——不是因为它是一个糟糕的基准，而是因为它衡量的是一个不同的世界。

SWE-bench 是**单发**：智能体读取问题，发出补丁，补丁被评分，完成。没有人以这种方式使用编码智能体。真正的工作是“行走”：你提出要求，智能体尝试，测试推回，它修改，你推动。弱智能体的代价并不是最终失败的补丁，而是人类必须停止自己的工作并纠正路线的中间每一步。一次性基准测试在结构上对这个循环是盲目的。

还有更深层次的不匹配：SWE 基准任务可以从存储库中解决。问题加上代码就包含了答案。 记忆只能在决定性上下文**不在仓库中**的任务上持续发挥作用——在SWE-bench上，完美的记忆和无记忆应该融合。记忆不重要的基准无法告诉您记忆是否重要。

## 2。类似于真实作品的数据集 {#2-a-dataset-shaped-like-real-work}

所以我们建立了自己的。 **六十一个错误修复任务**，托管在一个真正的开源代码库 (`boltons`) 中，其中约 1,600 个真实提交被留在原处，成为噪音，还有 140 个诱饵对话——冗长、可信、技术性、什么决定都没有——混入了历史。检索必须_排名_，而不仅仅是获取。

每项任务都取决于**不可猜测的、针对具体项目的决策**。可见的错误报告重现了真正的故障，并且明显的修复通过了该重现。然后，**隐藏测试**——从未向智能体展示过——检查团队实际决定的内容。我们最喜欢的例子：一个导出错误，其中教科书修复（标准 CSV 引用）_记录为已尝试并拒绝_，因为接收 ERP 甚至会强制引用数字字符串并删除前导零；它逐字节导入的唯一格式是 Excel 文本公式形式 `="00042"` — 并且仅适用于前导零数字字符串，在其他地方使用最少的引用和 CRLF 结尾，这三个相互作用的约束是任何模型都无法从代码中派生出来的。决定性的基本原理存在于团队真正保留的地方：过去的开发人员对话（27 个任务）、提交消息（28），或者最糟糕的对话**由后来的修改**（6），以惩罚任何无法区分被取代的决定和最终决定的记忆。

评分反映了步行情况。尝试 → 运行完整的测试套件，包括隐藏测试 → 失败逐字返回，没有提示 → 智能体重试，上限为五轮。指标是**修正**：修复错误的次数。每一个都是人类可能会被打断的时刻。确定性pytest端到端；没有LLM判断。

还有一条规则，是通过惨痛的教训才学到的：早期，“记忆”运行的得分可疑地接近普通，当我们深入研究时，检索一直在默默地失败——我们对安慰剂进行了基准测试。从那时起，每次记忆运行都携带每个任务、机器可检查的证据，证明检索实际上已达到智能体，否则就会被视为无数据而被丢弃。

是的，答案被故意植入记忆库中，因为这是现实的前提。在每个真正的团队中，决定性的上下文已经存在，在 git、线程和票据中。测试是系统是否能够找到它：跨越词汇间隙、在噪音下、不提供被取代的版本。

设计数据集在运行单个任务之前教会了我们一些东西。为了现实地制定决策，我们必须询问他们在真正的团队中实际上生活在哪里——而诚实的答案不断出现**git**。我们一半的任务最终在提交消息中得到了它们的基本原理，因为那是真正要保存工程决策的地方。然后我们查看了自己的插件并皱起了眉头：**他们根本没有摄入 git。** 他们记住了对话和会话，却对每个存储库免费提供的最丰富的决策记录视而不见。基准测试尚未产生数字，但它已经发现了架构中的第一个漏洞。

## 3。运行我们自己的插件——并且一无所有 {#3-running-our-own-plugin--and-losing-to-nothing}

然后我们将基准指向我们已经发货的产品，并得到了今年最有用的坏消息。

我们的集成做了大多数生态系统所做的事情：**每次提示时自动记忆** - 嵌入消息，检索相似的记忆，注入它们。在当时的套件中，得分为**每项任务需要 1.06 次修正，而完全没有记忆则为 0.97 次**。我们的记忆使智能体变得_更糟_。

尸检告诉我们两件事，我们现在认为是原则。

**分散的记忆分散了注意力。** 记忆召回返回片段——一些松散相似的片段，每个片段都是合理的，没有合成的。对于症状相距较远的错误（导出错误表示“损坏行”；决定性对话表示“前导零”——零共享词汇），相似性搜索会返回仅听起来相似的内容。一个编码智能体有自己的使命和计划；向它喂食分散的、自信地注入的碎片并不能告知任务，反而会使其脱轨。智能体开始追逐记忆的词汇而不是错误的词汇。

**切勿将工作添加到热路径中。** 每个提示的记忆召回在_每条消息_之前放置了一个检索往返行程——延迟和噪音，每一次都付出代价，对于几乎没有任何帮助的上下文。编码会话的热路径是神圣的：智能体应该读取代码并运行测试，而不是等待即将分散它注意力的记忆服务器。

​​我们已经发布了这种模式的变体。基准测试在一个下午就杀死了它。

## 4。 总结：把智慧放在目标所在的地方 {#4-reflect-put-the-intelligence-where-the-goal-is}

Hindsight 有第二种检索模式 - **反思** - 而且它是智能模式：对整个记忆库进行代理推理，跟踪从症状到决策的线索，检查后来的对话是否修改了它，并返回一个综合答案，其中包含逐字引用的确切规则和文字值。它不像记忆那么快——真正的推理需要几秒钟，而不是几毫秒——这正是它不属于每个提示的原因。

但是看看它_确实_属于哪里。会议的第一条消息很特别：这是您将智能体交给其**目标**的地方 - 整个会议将围绕的错误、功能和问题。在这一时刻，对项目过去的深入了解将为接下来的整个会议带来回报。因此，该插件反映了**一次，在第一个提示时**，缓存了合成，并在每个回合中重新注入它——深度恰好位于任务所规定的位置，之后在热路径上的零添加工作。而且智能体并没有锁定在那个镜头上：预计保持可用**作为工具**，因此，如果会话中途转向新问题，智能体可以根据自己的判断进行另一次深度传递——就像任何其他工具调用一样，在记录中可见。会议以记忆召回永远无法产生的一件事开始——_结论_：

> 🧠 来自 Hindsight 记忆：带有前导零的数字字符串被写为 `="00042"` — ERP 强制甚至引用数字；去年尝试过普通报价，但后来又被取消。所有其他字段：最小引用、双倍嵌入引号、`\r\n` 行结尾。

数字立即发生变化，并且自此之后的每一次重新架构都保持不变。最终的活动——完整的 61 项任务套件，三个智能体，双臂，每个运行 3 次——是我们命名的数字：

|智能体（61 个任务，每个任务运行 3 次的平均值）|修正/任务，原版|与 Hindsight|更正|成本|墙上时间/任务|
| ------------------------------------- | --------------------------- | -------------- | ----------- | ---- | ----------------------------- |
|**Claude Code**·Claude十四行诗 5|0.85|**0.36**|**−57%**|-24%|84.7s → **75.1秒** (**−11%**)|
|**开放代码** · Gemini 3.5 闪光灯|1.20|**0.80**|**−33%**|-13%|174.2s → **163.3s** (**−6%**)|
|**Codex CLI** · GPT-5.4 迷你|1.34|**0.47**|**−65%**|-52%|53.6s → **48.6s** (**−9%**)|

双臂的解决率保持在 99-100%，并且每个智能体的每项任务的墙时间都下降了——九次记忆运行中的每一次都低于其智能体的普通平均值——所以记忆并不是用正确性或速度来换取准确性；它取消了人类用于反馈测试失败的审查轮次。每个任务都会验证注入（如果没有证明记忆达到智能体的运行会因为没有数据而被丢弃），并且每种配置的成本都会下降，因为一个有针对性的综合取代了许多探索性阅读。每个源的拆分讲述了架构故事：对于那些决策仅存在于过去对话中的任务（如果没有记忆就无法实现），更正率下降了 28-71%；在基于 git 的决策中，最强的智能体几乎不需要帮助（Claude 自己挖掘历史），而较弱的智能体则有效地获得了该技能。我们早期十四行诗活动中首次出现的模式一直持续到最后：智能体越好，其剩余的失败就越多，而这些正是记忆所带来的不可猜测的决定。

## 5。知识页面：自我修复的维基 {#5-knowledge-pages-the-wiki-that-heals-itself}

当基准测试工作正在艰难进行时，第二个线程正在运行 - 一个完全从不同的挫败感开始的线程。

我们一直在尝试 _llm-wiki_ 想法：让智能体维护一个关于代码库的 wiki — 架构注释、约定、决策 — 并在未来的会议中重新阅读它。我们用自己的智能体、Hermes和Claude Code进行了尝试，并遇到了每个人都会遇到的失败：**智能体不会保持维基更新。**它在第一天热情地编写页面，第二天不情愿地进行编辑，到了第二周，维基就变成了一个格式精美的谎言。出于同样的原因，要求执行工作的智能体也管理工作文档正是人类失败的苦差事。

然后显而易见的事情让我们震惊：**Hindsight 已经坐在数据上了。** 每一次提交、每一次会话、每一个决定都作为提取的事实流入记忆库，而我们的_心智模型_（保存的综合视图，随着新事实的整合而重新生成）在架构上是完美契合的：当现实发生变化时，页面会重写自身。自我修复，因为修复不是智能体忘记的苦差事；这就是记忆引擎已经做的事情。

但是原始心智模型暴露了太多的机制——综合查询、触发器、整合设置。没有人应该考虑建立一个维基。因此，我们在顶部构建了一个层：**知识页面**——分层，用文件夹组织在树中，并以智能体已经知道如何思考的方式呈现给智能体：**像文件系统**。列出页面、阅读页面、搜索页面。记忆形状的引擎上的维基形状的界面。

值得暂停一下，因为其中隐藏着一个公平的反对意见：_如果答案是树中的文档，那么你不是刚刚重新发明了文件 - 记忆系统的存在是为了取代它吗？_区别在于下面的内容。文件是原始信息老化的地方：最后写下它的人获胜，矛盾悄然累积，一切都无法调和。知识页面是 **投影视图** 过度处理的记忆 - 就像数据库视图不是表一样。在底层，Hindsight 已经完成了文件本身无法完成的工作：从原始提交、会话和文档中提取事实；对它们进行重复数据删除和清理；并且 - 最重要的部分 - **通过整合解决了他们的矛盾**，因此当团队决定 X 并随后将其修改为 Y 时，页面会说 Y 并且可以说_为什么_，而不是像 wiki 那样将两个陈述保留一个段落。您的原始文件仍然是所说内容的真相来源；这些页面是关于所持有的内容的调和真相。删除一页并不会丢失任何内容——它会从记忆中重新投影。尝试删除 wiki 并将其恢复。

这就是为什么自我修复不是一个噱头：页面修复是因为它们不是存储——它们是_渲染_，并且只要集成改变了底层的真实情况，引擎就会重新渲染。

我们在页面上提供了智能体**混合搜索**的编码（全文+语义，融合服务器端，在数十毫秒内对片段进行排名）——它_选择_调用的工具，在记录中可见，而不是将内容推送到其上下文中。这尊重了第三课中的焦点原则：检索所需的智能体为任务提供信息；检索它并没有要求使它脱轨。

仍然存在一个差距：从历史合成的页面仅与摄取的页面一样好，而新的存储库在记忆库中还没有历史。因此，在第一次打开时，**探索智能体**——在您自己的智能体的 CLI 下运行的简短、只读、预算上限的调查——映射代码库结构并为初始页面提供种子：组件图、核心概念、约定和模式、关键决策和基本原理、积极举措。从那一刻起，_Hindsight_维护它们_ — 每个会话和每次提交都会自动流入，集成重新综合，页面保持真实。未能维护维基的智能体永远不必这样做；无法忘记的引擎会代替它。

通过循环中的页面，会话变得更快_并且_更准确 - 过去需要触发几分钟的代码探索的问题（“这里的组件是什么？”，“我们的错误处理约定是什么？”）在一个可见的工具调用中得到解决，答案记为：`🧠 From Hindsight memory (Conventions and patterns): …`。

## 今天：0.9.0 {#today-090}

以上所有内容现已发货。

**一个插件，每个智能体，一个命令：**

```bash
npx @vectorize-io/hindsight-coding-agents install all
```

它会检测您已安装的编码智能体，并在本地连接每个智能体 - 钩子或本机插件，在主机需要的地方使用 MCP。 （`install`采用明确的目标 - `all`，或像`claude-code`这样的线束名称 - 因此连接机器上的每个智能体绝不会发生意外。）在终端上，它还会询问**记忆应该存在的地方** - Hindsight Cloud，您运行的服务器或该机器上的本地守护程序。没有摄取 CLI，也没有同步按钮 — 记忆在后台自行构建（首先是最近的历史记录，逐步加深），会话会自行写回，横幅会告诉您您所处的位置：

```
Hindsight is tracking the decisions, conventions and history of this repo
  ↳ memory bank “coding-agent::your-repo” · git in sync
```

您的数据将通过您的密钥发送到_您的_ Hindsight 服务器（自托管或云）。完整的设置——每个智能体接线、配置以及迁移旧的每个智能体插件——都在[编码智能体文档](/sdks/integrations/coding-agents)中。

**知识页面，适合每个记忆库**——不仅仅是编码。在仪表板的新知识视图中浏览和编辑它们，将它们组织在树中，在混合API上搜索它们，使用记忆库模板一次性播种整个分类法。如果你的记忆库一直在积累事实，那么这些页面正等待着被写入。

该数据集今天已公开 - [github.com/vectorize-io/sde-bench](https://github.com/vectorize-io/sde-bench)，[抱脸](https://huggingface.co/datasets/vectorize-io/sde-bench) 上有一个 `load_dataset()` 就绪镜像 - 以及工具、每个任务的结果和完整的强化日志（包括我们自己的架构完全没有记忆的运行）于 2026 年 8 月登陆[agentmemorybenchmark.ai](https://agentmemorybenchmark.ai)。文档：[编码智能体集成](/sdks/integrations/coding-agents)。

我们问“这真的有帮助吗？”期待营销号。我们得到了不同的产品。值得。
