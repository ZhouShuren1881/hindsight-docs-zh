Hindsight 0.4.21 新增了三个框架集成（LlamaIndex、AG2、Strands）、Codex CLI 集成、可跳过未变内容的增量存入、支持 100 多种 LLM 后端的 LiteLLM 提供方、原生 Windows 支持、审计日志，以及一系列可靠性修复。

<!-- truncate -->

- [**LlamaIndex 集成**](#llamaindex-integration)：通过 BaseToolSpec 和 BaseMemory 提供持久记忆。
- [**AG2 集成**](#ag2-integration)：为 AG2 多智能体工作流提供长期记忆。
- [**Strands 集成**](#strands-integration)：为 Strands 智能体提供存入、召回和反思工具。
- [**Codex CLI 集成**](#codex-cli-integration)：为 OpenAI 的 Codex CLI 自动提供记忆。
- [**增量存入**](#delta-retain)：更新插入时跳过对未变文本分块的 LLM 处理。
- [**LiteLLM 提供方**](#litellm-provider)：通过 LiteLLM 使用 Bedrock、Azure 和 100 多种提供方。
- [**原生 Windows 支持**](#native-windows-support)：无需 Docker 即可在 Windows 上运行 Hindsight。
- [**审计日志**](#audit-logging)：通过内置审计日志跟踪功能使用情况。
- [**MCP 改进**](#mcp-improvements)：按用户筛选工具、选择存入策略。

## LlamaIndex 集成 {#llamaindex-integration}

`hindsight-llamaindex` 通过两种互补模式，将持久记忆集成到 [LlamaIndex](https://docs.llamaindex.ai/) 智能体中；两种模式包含在同一个包里。

```bash
pip install hindsight-llamaindex
```

**由智能体驱动的工具** — 将存入、召回和反思作为工具提供，由智能体决定何时调用：

```python
from hindsight_client import Hindsight
from hindsight_llamaindex import HindsightToolSpec

client = Hindsight(base_url="http://localhost:8888")
spec = HindsightToolSpec(
    client=client,
    bank_id="user-123",
    mission="Track user preferences",
)
tools = spec.to_tool_list()

agent = ReActAgent(tools=tools, llm=OpenAI(model="gpt-4o"))
```

**自动记忆** — 每轮都会存储消息，并自动将召回的内容作为上下文提供：

```python
from hindsight_llamaindex import HindsightMemory

memory = HindsightMemory.from_client(
    client=client,
    bank_id="user-123",
    mission="Track user preferences and project context",
)

agent = ReActAgent(tools=tools, llm=llm, memory=memory)
```

两种模式都支持通过 `mission=` 自动创建记忆库、按标签限定记忆范围，以及同步和异步智能体。完整 API 参考请见 [LlamaIndex 集成文档](/sdks/integrations/llamaindex)。

## AG2 集成 {#ag2-integration}

`hindsight-ag2` 为 [AG2](https://ag2.ai/) 多智能体工作流加入持久记忆。

```bash
pip install hindsight-ag2
```

```python
from autogen import AssistantAgent, UserProxyAgent, LLMConfig
from hindsight_ag2 import register_hindsight_tools

llm_config = LLMConfig(api_type="openai", model="gpt-4o-mini")

with llm_config:
    assistant = AssistantAgent(
        name="assistant",
        system_message="You are a helpful assistant with long-term memory.",
    )
    user_proxy = UserProxyAgent(
        name="user",
        human_input_mode="NEVER",
    )

# 在两个智能体上注册 Hindsight 记忆工具
register_hindsight_tools(
    assistant, user_proxy,
    bank_id="my-bank",
    hindsight_api_url="http://localhost:8888",
)

result = user_proxy.initiate_chat(
    assistant,
    message="Remember that I prefer Python over JavaScript.",
)
```

详情请见 [AG2 集成文档](/sdks/integrations/ag2)。

## Strands 集成 {#strands-integration}

`hindsight-strands` 为 [Strands Agents SDK](https://github.com/strands-agents/sdk-python) 智能体添加存入、召回和反思工具。

```bash
pip install hindsight-strands
```

```python
from strands import Agent
from hindsight_strands import create_hindsight_tools

tools = create_hindsight_tools(
    bank_id="user-123",
    hindsight_api_url="http://localhost:8888",
)

agent = Agent(tools=tools)
agent("Remember that I prefer dark mode")
agent("What are my preferences?")
```

完整设置指南请见 [Strands 集成文档](/sdks/integrations/strands)。

## Codex CLI 集成 {#codex-cli-integration}

Hindsight 现已集成 [OpenAI 的 Codex CLI](https://github.com/openai/codex)。三个 Python 挂钩脚本会在每次提示前自动召回相关上下文，并在每轮结束后存入对话，无需更改 Codex 的工作流程。

```bash
curl -fsSL https://hindsight.vectorize.io/get-codex | bash
```

安装程序会引导你选择本地或云端模式。安装完成后，启动新的 Codex 会话即可使用记忆。配置详情请见 [Codex 集成文档](/sdks/integrations/codex)。

## 增量存入 {#delta-retain}

存入操作现已支持**增量模式**：更新插入文档时，Hindsight 会为每个文本分块计算内容哈希，并跳过对未变分块执行 LLM 事实提取。只有新增或修改过的分块会进入提取流程，从而显著降低 LLM 成本和处理时间。

这对最常见的使用场景尤其有帮助：**实时更新的对话**。当某个集成在每轮都存入完整对话记录时（例如 Claude Code、Codex 和大多数聊天集成），增量存入只会对新消息触发事实提取，之前的轮次则会全部跳过。对于逐步变化的文档（例如代码库文件或持续更新的笔记），同样适用。

如果存入时提供的 `document_id` 已存在，增量模式就会自动启用。若要强制完整地重新摄取文档，请先删除该文档，再次存入。

## LiteLLM 提供方 {#litellm-provider}

新增的 `litellm` LLM 提供方让 Hindsight 可以通过 [LiteLLM](https://github.com/BerriAI/litellm) 使用 **100 多种 LLM 后端**，包括 AWS Bedrock、Azure OpenAI、Cohere、Together AI 等。

```bash
# Azure OpenAI via LiteLLM
export HINDSIGHT_API_LLM_PROVIDER=litellm
export HINDSIGHT_API_LLM_API_KEY=your-azure-api-key
export HINDSIGHT_API_LLM_MODEL=azure/gpt-4o

# Together AI via LiteLLM
export HINDSIGHT_API_LLM_PROVIDER=litellm
export HINDSIGHT_API_LLM_API_KEY=your-together-api-key
export HINDSIGHT_API_LLM_MODEL=together_ai/meta-llama/Llama-3-70b-chat-hf
```

对于需要使用尚无原生支持的后端的情况，LiteLLM 可补充现有原生提供方（OpenAI、Anthropic、Gemini、Groq 等）。LiteLLM 也可用于[嵌入和重排序](/developer/configuration#embeddings)。此版本还新增了支持字节跳动 Doubao 模型的 **Ark 和火山引擎（Volcano Engine）** 提供方。

## 原生 Windows 支持 {#native-windows-support}

现在无需 Docker 即可在 Windows 上原生运行 Hindsight。通过 pip 安装后直接启动服务器：

```bash
pip install hindsight-all
hindsight-api
```

这与 macOS 和 Linux 一样，使用嵌入式 PostgreSQL（`pg0`）和本地模型。详情请见 [Windows 安装指南](/developer/installation#windows)。

## 审计日志 {#audit-logging}

新增的审计日志可跟踪 Hindsight 部署中的功能使用情况。每次存入、召回和反思操作都会记录请求耗时、记忆库 ID 和操作元数据。你可以通过 API 查询审计日志，了解使用模式、找出耗时较长的操作，并跟踪各团队的采用情况。

## MCP 改进 {#mcp-improvements}

MCP 服务器新增了以下功能：

- **按用户筛选工具** — 新增的 `filter_mcp_tools` 挂钩允许扩展控制每位用户可以看到哪些 MCP 工具。对于多租户部署很有用，因为不同用户可能需要看到不同的功能。
- **选择存入策略** — MCP 存入工具现在接受 `strategy` 参数，客户端可以在每次调用时选择存入策略（例如 `verbose`、`fast`）。
- **无状态 HTTP 模式** — MCP 服务器现在可以配置为以无状态 HTTP 模式运行，从而提高与 Claude Code 及其他会通过 GET 请求探测服务器的客户端的兼容性。

## 其他更新 {#other-updates}

**改进**
- OpenClaw 日志记录现在可以配置，并支持结构化输出。
- 观测搜索结果是否包含来源事实，现在可以配置。
- 集成不再使用硬编码的默认模型，而是依赖已配置的默认值。
- Claude Code 集成现在会通过文档更新插入来存入完整会话，支持配置标签，并将工具调用记录为结构化 JSON。
- 现在可以通过 `max_observations_per_scope` 配置每个记忆库的观测数量上限。

**错误修复**
- 每个记忆库的向量索引创建现在会遵循已配置的向量扩展设置。
- 详细模式的存入提取现在会正确包含存入任务说明上下文。
- API 配额耗尽（HTTP 429）时，Codex 集成现在不会在启动时崩溃。
- OpenAI 嵌入客户端现在可以正确解析 `base_url` 中包含的查询参数。
- 修复了 Codex 和 Claude Code 在强制指定工具调用时对 `tool_choice` 的处理。
- 修复了控制台 UI 中的召回和数据查看问题。
- 召回响应现在包含相关元数据。
- Python 客户端的 `update_bank_config()` 现在会公开所有可配置字段。
- 现在会将 JSON 字符串形式的标签转换为 MemoryItem 和 MCP 工具所需的列表。
- Docker 容器现在可以正常处理优雅关闭，避免重启时丢失 pg0 数据。
- 迁移运行器现在可以通过 `MIGRATION_DATABASE_URL` 绕过 PgBouncer，以获取 advisory lock。
