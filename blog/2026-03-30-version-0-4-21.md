Hindsight 0.4.21 添加了三个新的框架集成（LlamaIndex、AG2、Strands）、一个Codex CLI 集成、用于跳过未更改内容的 delta 记忆存储、一个用于 100 多个LLM 后端的LiteLLM 提供程序、原生Windows支持、审计日志记录以及一系列全面的可靠性修复。

<!-- truncate -->

- [**LlamaIndex 积分**](#llamaindex-integration)：通过 BaseToolSpec 和 BaseMemory 实现持久记忆。
- [**AG2 集成**](#ag2-integration)：AG2 多智能体工作流程的长期记忆。
- [**Strands 积分**](#strands-integration)：用于Strands智能体的记忆存储、记忆召回和反思工具。
- [**Codex CLI 集成**](#codex-cli-integration)：OpenAI的Codex CLI的自动记忆。
- [**Delta 记忆存储**](#delta-retain)：在更新插入时跳过LLM处理未更改的块。
- [**LiteLLM 提供商**](#litellm-provider)：通过 LiteLLM 访问 Bedrock、Azure 和 100 多个提供商。
- [**原生Windows 支持**](#native-windows-support)：在 Windows 上运行 Hindsight，无需 Docker。
- [**审计日志记录**](#audit-logging)：使用内置审核日志跟踪功能使用情况。
- [**MCP 改进**](#mcp-improvements)：每用户工具过滤和记忆存储策略选择。

## LlamaIndex 积分 {#llamaindex-integration}

​​`hindsight-llamaindex` 将持久记忆添加到 [LlamaIndex](https://docs.llamaindex.ai/) 智能体中，在单个包中具有两种互补模式。

```bash
pip install hindsight-llamaindex
```

**智能体驱动工具** — 将记忆存储/记忆召回/反思作为智能体决定何时调用的工具：

```python
from hindsight_client import Hindsight
from hindsight_llamaindex import HindsightToolSpec

client = Hindsight(base_url="http://localhost:8888")
spec = HindsightToolSpec(
    client=client,
    bank_id="user-123",
    mission="追踪用户偏好",
)
tools = spec.to_tool_list()

agent = ReActAgent(tools=tools, llm=OpenAI(model="gpt-4o"))
```

**自动记忆** — 每轮都会存储消息并自动作为上下文调用：

```python
from hindsight_llamaindex import HindsightMemory

memory = HindsightMemory.from_client(
    client=client,
    bank_id="user-123",
    mission="跟踪用户偏好和项目背景",
)

agent = ReActAgent(tools=tools, llm=llm, memory=memory)
```

两种模式都支持通过`mission=`、基于标签的记忆范围以及同步和异步智能体自动创建记忆库。有关完整的 API 参考，请参阅 [LlamaIndex集成文档](/sdks/integrations/llamaindex)。

## AG2 集成 {#ag2-integration}

`hindsight-ag2`为[AG2](https://ag2.ai/)多智能体工作流程带来持久记忆。

```bash
pip install hindsight-ag2
```

```python
from autogen import AssistantAgent, UserProxyAgent, LLMConfig
from hindsight_ag2 import register_hindsight_tools

llm_config = LLMConfig(api_type="openai", model="gpt-4o-mini")

with llm_config:
    assistant = AssistantAgent(
        name="assistant",
        system_message="你是一个有长期记忆力的得力助手。",
    )
    user_proxy = UserProxyAgent(
        name="user",
        human_input_mode="NEVER",
    )

#在智能体上注册 Hindsight 记忆工具
register_hindsight_tools(
    assistant, user_proxy,
    bank_id="my-bank",
    hindsight_api_url="http://localhost:8888",
)

result = user_proxy.initiate_chat(
    assistant,
    message="请记住，我更喜欢Python而不是JavaScript。",
)
```

详情请参阅[AG2 集成文档](/sdks/integrations/ag2)。

## Strands 积分 {#strands-integration}

`hindsight-strands`在[Strands智能体SDK](https://github.com/strands-agents/sdk-python)智能体上添加了记忆存储、记忆召回和反思工具。

```bash
pip install hindsight-strands
```

```python
from strands import Agent
from hindsight_strands import create_hindsight_tools

tools = create_hindsight_tools(
    bank_id="user-123",
    hindsight_api_url="http://localhost:8888",
)

agent = Agent(tools=tools)
agent("记住我更喜欢深色模式")
agent("我的偏好是什么？")
```

请参阅[Strands集成文档](/sdks/integrations/strands) 获取完整的设置指南。

## Codex CLI 集成 {#codex-cli-integration}

Hindsight 现在与 [OpenAI 的 Codex CLI](https://github.com/openai/codex) 集成。三个 Python 挂钩脚本会在每次提示之前自动记忆召回相关上下文，并在每次转动之后自动记忆存储对话 — 无需更改您的 Codex 工作流程。

```bash
curl -fsSL https://hindsight.vectorize.io/get-codex | bash
```

安装程序将引导您完成本地或云模式。安装后，启动新的Codex会话，记忆就会生效。配置详情请参见[Codex集成文档](/sdks/integrations/codex)。

## Delta 记忆存储 {#delta-retain}

记忆存储现在支持**增量模式**——更新插入文档时，Hindsight计算每个块的内容哈希值并跳过LLM未更改的块的事实提取。只有新的或修改的块才会通过提取管道，从而显著减少 LLM 成本和处理时间。

这对于最常见的用例特别有影响：**实时更新的对话**。当集成在每个回合都保留完整的对话记录时（如Claude Code、Codex和大多数聊天集成所做的那样），增量记忆存储意味着只有新消息才会触发事实提取——之前的回合将被完全跳过。这同样适用于增量更改的文档，例如代码库文件或不断演变的注释。

当您使用记忆存储时，Delta 模式会自动激活`document_id`已经存在。要强制完全重新摄取文档，请先删除它，然后再次删除记忆存储。

## LiteLLM 提供商 {#litellm-provider}

新的 `litellm` LLM 提供商可让 Hindsight 通过 [LiteLLM](https://github.com/BerriAI/litellm) 访问 **100+ LLM 后端**，包括 AWS Bedrock、Azure OpenAI、Cohere、Together AI 等等。

```bash
#天蓝色 OpenAI 通过 LiteLLM
export HINDSIGHT_API_LLM_PROVIDER=litellm
export HINDSIGHT_API_LLM_API_KEY=your-azure-api-key
export HINDSIGHT_API_LLM_MODEL=azure/gpt-4o

#一起AI通过LiteLLM
export HINDSIGHT_API_LLM_PROVIDER=litellm
export HINDSIGHT_API_LLM_API_KEY=your-together-api-key
export HINDSIGHT_API_LLM_MODEL=together_ai/meta-llama/Llama-3-70b-chat-hf
```

这补充了现有的本机提供程序（OpenAI、Anthropic、Gemini、Groq 等），适合您需要不直接支持的后端的情况。 LiteLLM 也适用于 [嵌入和重排序](/developer/configuration#embeddings)。此版本中还新增了：字节跳动豆宝模型的**方舟与火山引擎**提供商。

## 原生Windows 支持 {#native-windows-support}

Hindsight 现在可以在 Windows 上本机运行，无需 Docker。通过pip安装并直接启动服务器：

```bash
pip install hindsight-all
hindsight-api
```

这使用嵌入式PostgreSQL（`pg0`）和本地模型，与macOS和Linux相同。详情请参阅[Windows安装指南](/developer/installation#windows)。

## 审计日志记录 {#audit-logging}

新的审核日志可跟踪整个Hindsight部署中的功能使用情况。每个记忆存储、记忆召回和反思操作都记录有请求持续时间、记忆库 ID 和操作元数据。通过API查询审核日志，以了解使用模式、识别缓慢的操作并跟踪跨团队的采用情况。

## MCP 改进 {#mcp-improvements}

MCP 服务器添加了两个内容：

- **每用户工具过滤** — 新的 `filter_mcp_tools` 挂钩可让扩展控制哪些 MCP 工具对每个用户可见。对于多租户部署很有用，其中不同的用户应该看到不同的功能。
- **记忆存储策略选择** — MCP 记忆存储工具现在接受 `strategy` 参数，因此客户可以在每次调用时选择记忆存储策略（例如，`verbose`、`fast`）。
- **无状态HTTP模式** — MCP 服务器现在可以配置为无状态 HTTP 操作，从而提高与 Claude Code和其他使用 GET 请求探测服务器的客户端的兼容性。

## 其他更新 {#other-updates}

**改进**
- OpenClaw 日志记录现在可配置并支持结构化输出。
- 观察搜索结果中包含的源事实现在可以配置。
- 集成不再使用硬编码的默认模型，而是依赖于配置的默认值。
- Claude Code集成现在保留带有文档更新插入和可配置标签的完整会话，并将工具调用记录为结构化JSON。
- 每个记忆库观察限制现在可以通过`max_observations_per_scope`进行配置。

**错误修复**
- 每记忆库向量索引创建现在遵循配置的向量扩展设置。
- 详细记忆存储提取现在会正确包含记忆存储使命上下文。
- Codex集成不再在启动时崩溃API配额已用完 (HTTP 429)。
- OpenAI 嵌入客户端现在可以正确解析`base_url`中包含的查询参数。
- 修复了强制特定工具调用时Codex和Claude Code的`tool_choice`处理。
- 用于记忆召回和数据查看的控制平面 UI 修复。
- 记忆召回响应现在包括相关的元数据。
- Python客户端`update_bank_config()`现在公开所有可配置字段。
- JSON 字符串标签现在被强制转换为 MemoryItem 和 MCP 工具的列表。
- Docker 容器现在可以正确处理正常关闭，以防止重启时 pg0 数据丢失。
- 迁移运行程序现在可以通过 `MIGRATION_DATABASE_URL` 绕过 PgBouncer 进行咨询锁定。
