Hindsight 0.5.0 引入了用于便携式配置的记忆库模板中心、控制平面中的星座图视图、主要记忆存储和记忆召回性能改进、新的 LLM 提供程序（llama.cpp、OpenRouter、Google）、记忆存储附加模式、新框架集成（AutoGen、 OpenCode），以及对遗留图检索策略和Hermes集成的突破性删除。

<!-- truncate -->

- [**记忆库模板中心**](#bank-template-hub)：将完整记忆库配置导出和导入为可重用清单。
- [**星座视图**](#constellation-view)：控制平面中的交互式实体图可视化。
- [**性能：记忆存储和记忆再现**](#performance-retain-and-recall)：3 阶段记忆存储管道和上限实体图扩展，以实现更快的查询。
- [**新LLM提供商**](#new-llm-providers)：内置 llama.cpp，用于本地推理、OpenRouter 和 Google 嵌入/重排序器。

- [**重大变更**](#breaking-changes)：删除了 BFS/MPFP 策略； Hermes 集成度下降。

## 记忆库模板中心 {#bank-template-hub}

记忆库现在可以导出为便携式模板清单，在单个JSON文档中捕获完整配置 - 设置、心智模型和指令。将清单导入任何记忆库以立即复制设置。

清单格式捕获了重现记忆库行为所需的一切：

```json
{
  "version": "1",
  "bank": {
    "retain_mission": "提取客户问题、解决方案和情绪。",
    "enable_observations": true,
    "observations_mission": "跟踪反复出现的客户痛点。"
  },
  "mental_models": [
    {
      "id": "sentiment-overview",
      "name": "客户情绪概述",
      "source_query": "整体情绪趋势如何？",
      "trigger": { "refresh_after_consolidation": true }
    }
  ],
  "directives": [
    {
      "name": "承认挫折",
      "content": "在提供解决方案之前始终承认挫败感。",
      "priority": 10
    }
  ]
}
```

空运行模式 (`dry_run=True`) 在不应用更改的情况下验证清单，并且架构端点返回完整的 JSON 架构以进行工具集成。 心智模型由`id`匹配，指令由`name`匹配——现有条目被更新，新条目被创建。

这对于标准化智能体配置或跨项目共享经过验证的记忆库设置的团队特别有用。

请参阅[记忆库模板中心文档](/developer/api/bank-templates)以获取完整的清单架构和API参考。

## 星座视图 {#constellation-view}

控制平面现在包括一个交互式星座视图，它将记忆实体图呈现为可缩放、可平移的画布。节点代表实体，它们的位置是确定性计算的，因此布局在每次访问时都是稳定的。

链接按类型进行颜色编码 - 语义（蓝色）、时间（青色）、实体（琥珀色）、因果（紫色） - 节点颜色强度映射到连接：更亮的节点有更多连接。该视图自动支持深色模式，并基于 `@chenglou/pretext` 布局引擎构建，可在任何缩放级别实现流畅的文本渲染。

单击任何节点可导航到其实体详细信息页面，或缩小以鸟瞰记忆如何在记忆库中连接。

## 性能：记忆存储和记忆再现 {#performance-retain-and-recall}

### 3阶段记忆存储管道 {#3-phase-retain-pipeline}

记忆存储管道已重组为三个不同的阶段，以消除并发负载下的数据库锁争用：

1. **预解决** — 实体解析和语义 ANN 搜索在只读连接的事务外部运行，防止缓慢读取阻塞写入。
2. **插入** — 事实、时间链接、语义链接和因果链接以原子方式写入单个事务中，确保检索一致性。
3. **帖子链接** — 实体共现链接（仅用于 UI 可视化）在事务提交后构建，作为尽力而为的后台步骤。

以前，整个管道在一个长事务中运行，这意味着并发智能体在 O(bank_size) ANN 查找期间将在彼此后面排队。新结构将所有读取密集型工作移出关键写入路径，从而在许多智能体同时写入时显著降低延迟。

### 上限实体图扩展 {#capped-entity-graph-expansion}

在大型记忆库上，当种子结果引用高扇出实体（例如，提及 25K+ 次的实体）时，图扩展中的实体共现自连接可能会产生大量中间行计数。这导致记忆召回延迟不可预测地激增。

图扩展查询现在使用 LATERAL 每个实体上限（`graph_per_entity_limit`，默认 200），将中间行从可能数百万减少到最多 `num_entities × 200`。结果通过 `ORDER BY unit_id DESC` 进行新近度偏差，它利用主键索引，无需额外的排序成本。如果查询仍然花费太长时间，超时回退（`graph_expansion_timeout`，默认 10 秒）会完全放弃实体扩展，并回退到语义 + 因果信号。

`unit_entities`中`(entity_id, unit_id)`上的新复合索引支持对上限子查询进行仅索引扫描，即使在非常大的记忆库上也能保持快速扩展。

## 新LLM提供商 {#new-llm-providers}

### 内置llama.cpp {#built-in-llamacpp}

Hindsight 现在附带内置的 llama.cpp LLM 提供程序，无需任何外部 API 调用即可实现完全本地推理。将提供程序设置为 `llama-cpp` 并将其指向 GGUF 模型文件：

```bash
HINDSIGHT_API_LLM_PROVIDER=llama-cpp
HINDSIGHT_API_LLM_MODEL=/path/to/model.gguf
```

这是气隙环境、开发设置或任何您想要避免外部 API 成本的理想选择。提供程序使用 `llama-cpp-python` 绑定并支持所有标准 Hindsight LLM 操作（事实提取、整合、映射）。

### 开放路由器 {#openrouter}

Hindsight 现在支持 [开放路由器](https://openrouter.ai/) 作为 LLM、嵌入和重排序的提供者。这使您可以通过单个 API 键访问数百个模型：

```bash
HINDSIGHT_API_LLM_PROVIDER=openrouter
HINDSIGHT_API_LLM_API_KEY=sk-or-...
HINDSIGHT_API_LLM_MODEL=anthropic/claude-sonnet-4-20250514
```

OpenRouter 对于比较模型或访问尚未直接集成 Hindsight 的提供商特别有用。

### Google 嵌入和重排序器 {#google-embeddings-and-reranker}

Google 作为嵌入和重排序的提供程序，补充了现有的 Gemini LLM 提供程序支持。

## 记忆存储追加模式 {#retain-append-mode}

记忆存储的新`update_mode='append'`选项可让您将新内容连接到现有文档上，而不是替换它。这对于流式传输或增量摄取场景非常有用 - 例如，将新的日志条目或对话轮附加到现有文档：

```python
from hindsight_client import Hindsight

client = Hindsight(base_url="http://localhost:8888")

#首先记忆存储创建文档
client.retain(bank_id="my-bank", content="Day 1 notes...", document_id="journal")

#后续保留追加而不是替换
client.retain(bank_id="my-bank", content="Day 2 notes...", document_id="journal", update_mode="append")
```

默认的`update_mode`保留`replace`以实现向后兼容性。

## AutoGen 整合 {#autogen-integration}

`hindsight-autogen`通过三个`FunctionTool`包装器为[AutoGen](https://github.com/microsoft/autogen)智能体提供持久的长期记忆：`hindsight_retain`、`hindsight_recall`和`hindsight_reflect`。

```bash
pip install hindsight-autogen
```

```python
from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient
from hindsight_client import Hindsight
from hindsight_autogen import create_hindsight_tools

client = Hindsight(base_url="http://localhost:8888")
await client.acreate_bank(bank_id="user-123")

model_client = OpenAIChatCompletionClient(model="gpt-4o")
tools = create_hindsight_tools(client=client, bank_id="user-123")

agent = AssistantAgent(
    name="assistant",
    model_client=model_client,
    tools=tools,
)

await agent.run(task="记住我更喜欢深色模式")
await agent.run(task="我的 UI 偏好是什么？")
```

集成支持通过标签、事实类型过滤、自定义元数据和选择性工具包含来确定记忆范围。使用 `configure()` 设置全局默认值，例如预算、最大令牌和标签过滤器。

请参阅 [AutoGen集成文档](/sdks/integrations/autogen) 以获取完整的 API 参考。

## 重大变更 {#breaking-changes}

### 图检索简化 {#graph-retrieval-simplification}

BFS（广度优先传播激活）和 MPFP（多路径事实传播）图检索策略已被删除。 `LinkExpansionRetriever` 现在是唯一的图检索算法。

LinkExpansionRetriever 在三个预先计算的一流信号上运行 - 实体链接、语义 kNN 链接和因果链接 - 没有迭代图行走或扇出上限。它更易于维护，查询速度更快，并且在我们的基准测试中根据经验更准确。

**迁移：** 如果您通过配置明确选择 BFS 或 MPFP，请删除该设置。自 0.4.x 起，默认值为 LinkExpansionRetriever，因此大多数部署不需要更改。

### Hermes 积分下降 {#hermes-integration-dropped}

`hindsight-hermes`集成包已被删除。 Hermes智能体现在附带内置于框架本身的本机Hindsight记忆提供程序，从而无需外部集成包。请参阅 [Hermes集成文档](/sdks/integrations/hermes) 了解本机提供商的设置说明。

## 其他更新 {#other-updates}

**特点**
- 为OpenCode编辑器添加了OpenCode持久记忆插件。
- Helm Chart 现在支持本地模型缓存的持久卷。
- MCP 服务器添加了 `sync_retain` 工具并验证 UUID 输入。
- OpenClaw 现在支持 `bankId` 静态记忆库配置。
- 记忆召回综合评分包括`proof_count`提升以获得更好的排名。
- 事实序列化现在包括`occurred_end`和`mentioned_at`，以获得更丰富的时间上下文。

**改进**
- 整合 通过结构化处理规则提高观察质量，以实现更好的综合。
- OpenClaw 获得一个 JSONL 支持的记忆存储队列，当外部 API 无法访问时，该队列可以在本地缓冲记忆存储调用，从而防止在中断期间丢失数据。
- LiteLLM SDK 嵌入 `encoding_format` 现在是可配置的，而不是硬编码的。

**错误修复**
- 修复了记忆召回结果映射中超出范围的`content_index`崩溃问题。
- 经验事实类型现在可以在规范化过程中正确保留，而不是默默地重新分类。
- `clear memories`端点不再删除记忆库配置文件和记忆。
- 嵌入守护进程在启动前清除端口上的陈旧进程，防止启动失败。
- 每记忆库向量索引迁移现在遵循配置的向量扩展。
- 时间轴组排序使用数字日期比较而不是区域设置字符串比较。
- MCP 服务器自动强制工具参数中的字符串编码JSON。
- 在 PATCH 上验证实体标签结构以防止无效配置。
- 修复了`bank_id`公制标签可供选择，防止 OTel 记忆泄漏。
- 修复了具有自定义基本 URL 的 OpenAI 兼容端点的 `max_tokens` 处理。
- 查询分析器可以优雅地处理日期解析器内部崩溃。
- Windows 上的 hindsight-embed的兼容性修复。
- 解决了依赖项中的关键和高严重性安全漏洞。
