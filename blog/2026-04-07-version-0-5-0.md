Hindsight 0.5.0 带来了记忆库模板中心，便于迁移配置；控制台中的星座图视图；Retain（存入）和 Recall（召回）性能的大幅提升；新的 LLM 服务提供方（llama.cpp、OpenRouter、Google）；Retain 追加模式；新的框架集成（AutoGen、OpenCode）；以及一项重大变更：移除旧版图检索策略和 Hermes 集成。

<!-- truncate -->

- [**记忆库模板中心**](#bank-template-hub)：将完整的记忆库配置导出并导入为可复用的清单。
- [**星座图视图**](#constellation-view)：在控制台中交互式查看实体图。
- [**性能：Retain 和 Recall**](#performance-retain-and-recall)：采用三阶段 Retain 管道，并限制实体图扩展规模，以加快查询速度。
- [**新的 LLM 服务提供方**](#new-llm-providers)：内置 llama.cpp，用于本地推理；支持 OpenRouter；并支持 Google 嵌入和重排序。
- [**Retain 追加模式**](#retain-append-mode)：使用 `update_mode='append'` 将新内容追加到现有文档。
- [**AutoGen 集成**](#autogen-integration)：为 AutoGen 智能体提供持久记忆。
- [**重大变更**](#breaking-changes)：移除 BFS/MPFP 策略和 Hermes 集成。

## 记忆库模板中心 {#bank-template-hub}

现在可以将记忆库导出为便携式模板清单，在单个 JSON 文档中完整记录其配置，包括设置、心智模型和强制指令。将清单导入任意记忆库，即可立即复现这套配置。

清单格式包含复现记忆库行为所需的全部内容：

```json
{
  "version": "1",
  "bank": {
    "retain_mission": "Extract customer issues, resolutions, and sentiment.",
    "enable_observations": true,
    "observations_mission": "Track recurring customer pain points."
  },
  "mental_models": [
    {
      "id": "sentiment-overview",
      "name": "Customer Sentiment Overview",
      "source_query": "What is the overall sentiment trend?",
      "trigger": { "refresh_after_consolidation": true }
    }
  ],
  "directives": [
    {
      "name": "Acknowledge frustration",
      "content": "Always acknowledge frustration before offering solutions.",
      "priority": 10
    }
  ]
}
```

试运行模式（`dry_run=True`）可以在不应用变更的情况下验证清单；Schema 端点会返回完整的 JSON Schema，供工具集成使用。心智模型按 `id` 匹配，强制指令按 `name` 匹配：已有条目会更新，新条目会创建。

这对希望统一智能体配置，或在不同项目间共享经过验证的记忆库配置的团队尤其有用。

完整的清单模式和 API 参考请参阅[记忆库模板中心文档](/developer/api/bank-templates)。

## 星座图视图 {#constellation-view}

控制台现在提供交互式星座图视图，将记忆实体图呈现在可缩放、可平移的画布上。节点代表实体，其位置通过确定性计算得出，因此每次访问时布局都保持稳定。

连线按类型着色：语义（蓝色）、时间（青绿色）、实体（琥珀色）和因果（紫色）。节点颜色的亮度表示连接数量：颜色越亮，连接越多。该视图会自动支持深色模式，并采用 `@chenglou/pretext` 布局引擎，确保在任意缩放级别都能流畅渲染文本。

单击任意节点即可前往对应的实体详情页；也可以缩小视图，鸟瞰记忆库中的记忆如何彼此关联。

## 性能：Retain 和 Recall {#performance-retain-and-recall}

### 三阶段 Retain 管道 {#3-phase-retain-pipeline}

Retain 管道现已重构为三个独立阶段，以消除并发负载下的数据库锁竞争：

1. **预解析** — 实体解析和语义 ANN 搜索在事务之外、通过只读连接执行，避免缓慢的读取操作阻塞写入。
2. **写入** — 事实、时间链接、语义链接和因果链接在单个事务中原子写入，确保检索结果的一致性。
3. **后置关联** — 实体共现链接（仅用于 UI 可视化）会在事务提交后构建，作为尽力而为的后台步骤执行。

此前，整个管道都在一个长事务中运行。因此，并发智能体会在 O(bank_size) 的 ANN 查找期间相互排队。新结构将所有读取密集型工作移出关键写入路径，在多个智能体同时写入时显著降低延迟。

### 限制实体图扩展规模 {#capped-entity-graph-expansion}

在大型记忆库中，如果种子结果引用了高扇出的实体（例如某实体被提及 25K 次以上），图扩展中的实体共现自连接可能会生成大量中间行。这会导致 Recall 延迟不可预测地升高。

现在，图扩展查询会对每个实体应用 LATERAL 上限（`graph_per_entity_limit`，默认值为 200），将中间行数从可能达到数百万压到最多 `num_entities × 200`。结果按 `ORDER BY unit_id DESC` 排序，使较新的结果优先；该操作利用主键索引，无需额外排序。如果查询仍然耗时过长，超时回退（`graph_expansion_timeout`，默认值为 10s）会完全跳过实体扩展，仅使用语义和因果信号。

`unit_entities` 上新增的 `(entity_id, unit_id)` 复合索引可让上限子查询执行仅索引扫描，即使在非常大的记忆库中也能保持扩展查询的速度。

## 新的 LLM 服务提供方 {#new-llm-providers}

### 内置 llama.cpp {#built-in-llamacpp}

Hindsight 现在内置 llama.cpp LLM 服务提供方，无需调用任何外部 API 即可完全在本地进行推理。将服务提供方设为 `llama-cpp`，并指定 GGUF 模型文件：

```bash
HINDSIGHT_API_LLM_PROVIDER=llama-cpp
HINDSIGHT_API_LLM_MODEL=/path/to/model.gguf
```

这适用于隔离网络环境、开发环境，以及任何希望避免外部 API 费用的场景。该服务提供方使用 `llama-cpp-python` 绑定，并支持 Hindsight 的所有标准 LLM 操作（事实提取、整合和 Reflect）。

### OpenRouter

Hindsight 现在支持将 [OpenRouter](https://openrouter.ai/) 用作 LLM、嵌入和重排序的服务提供方。只需一个 API 密钥，即可通过它访问数百种模型：

```bash
HINDSIGHT_API_LLM_PROVIDER=openrouter
HINDSIGHT_API_LLM_API_KEY=sk-or-...
HINDSIGHT_API_LLM_MODEL=anthropic/claude-sonnet-4-20250514
```

如果要比较不同模型，或使用尚未直接集成到 Hindsight 的服务提供方，OpenRouter 尤其有用。

### Google 嵌入和重排序 {#google-embeddings-and-reranker}

现在也支持将 Google 用作嵌入和重排序的服务提供方，补充了原有的 Gemini LLM 服务提供方支持。

## Retain 追加模式 {#retain-append-mode}

Retain 新增 `update_mode='append'` 选项，可将新内容追加到现有文档，而不是替换原有内容。这适用于流式或增量摄取场景，例如，向现有文档追加日志条目或新的对话轮次：

```python
from hindsight_client import Hindsight

client = Hindsight(base_url="http://localhost:8888")

# 首次 Retain 会创建文档
client.retain(bank_id="my-bank", content="Day 1 notes...", document_id="journal")

# 后续 Retain 会追加内容，而不是替换文档
client.retain(bank_id="my-bank", content="Day 2 notes...", document_id="journal", update_mode="append")
```

为保持向后兼容，`update_mode` 的默认值仍为 `replace`。

## AutoGen 集成 {#autogen-integration}

`hindsight-autogen` 通过三个 `FunctionTool` 封装工具，为 [AutoGen](https://github.com/microsoft/autogen) 智能体提供持久的长期记忆：`hindsight_retain`、`hindsight_recall` 和 `hindsight_reflect`。

```bash
pip install hindsight-autogen
```

```python
from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient
from hindsight_client import Hindsight
from hindsight_autogen import create_hindsight_tools

client = Hindsight(base_url="http://localhost:8888")
await client.acreate_bank(bank_id="user-123")

model_client = OpenAIChatCompletionClient(model="gpt-4o")
tools = create_hindsight_tools(client=client, bank_id="user-123")

agent = AssistantAgent(
    name="assistant",
    model_client=model_client,
    tools=tools,
)

await agent.run(task="Remember that I prefer dark mode")
await agent.run(task="What are my UI preferences?")
```

该集成支持通过标签限定记忆范围、按事实类型筛选、设置自定义元数据，以及选择要包含的工具。使用 `configure()` 可设置预算、最大令牌数和标签过滤器等全局默认值。

完整 API 参考请参阅 [AutoGen 集成文档](/sdks/integrations/autogen)。

## 重大变更 {#breaking-changes}

### 简化图检索 {#graph-retrieval-simplification}

BFS（广度优先扩散激活）和 MPFP（多路径事实传播）这两种图检索策略已被移除。`LinkExpansionRetriever` 现在是唯一的图检索算法。

`LinkExpansionRetriever` 基于三个预先计算的一等信号运行：实体链接、语义 kNN 链接和因果链接。它不进行迭代式图遍历，也不限制扇出规模。该算法更易于维护，查询时速度更快，并且在我们的基准测试中准确度更高。

**迁移：** 如果你曾通过配置显式选择 BFS 或 MPFP，请移除相应设置。自 0.4.x 起，默认算法一直是 `LinkExpansionRetriever`，因此大多数部署无需更改。

### 移除 Hermes 集成 {#hermes-integration-dropped}

`hindsight-hermes` 集成包已被移除。Hermes Agent 现在在框架本身内置了原生 Hindsight 记忆提供方，因此不再需要外部集成包。有关原生提供方的设置说明，请参阅 [Hermes 集成文档](/sdks/integrations/hermes)。

## 其他更新 {#other-updates}

**功能**
- 为 OpenCode 编辑器新增 OpenCode 持久记忆插件。
- Helm Chart 现在支持为本地模型缓存使用持久卷。
- MCP 服务器新增 `sync_retain` 工具，并会验证 UUID 输入。
- OpenClaw 现在支持在静态记忆库配置中使用 `bankId`。
- Recall 综合评分新增 `proof_count` 加权项，以改善排序。
- think-prompt 中的事实序列化现在包含 `occurred_end` 和 `mentioned_at`，提供更丰富的时间上下文。

**改进**
- 通过结构化处理规则改进整合时的观测质量，提升综合效果。
- OpenClaw 新增由 JSONL 支持的 Retain 队列：外部 API 无法访问时，该队列会在本地缓冲 Retain 调用，避免服务中断期间丢失数据。
- LiteLLM SDK 的嵌入 `encoding_format` 现在可以配置，不再是硬编码值。

**错误修复**
- 修复 Recall 结果映射中 `content_index` 越界导致的崩溃。
- 现在会在规范化过程中正确保留经历事实类型，不再将其静默地重新分类。
- `clear memories` 端点现在只清除记忆，不再连同记忆一起删除记忆库配置文件。
- 嵌入守护进程启动前会清除该端口上的过期进程，避免启动失败。
- 每个记忆库的向量索引迁移现在会遵循已配置的向量扩展。
- 时间线分组现在按日期数值排序，不再按区域设置格式的字符串排序。
- MCP 服务器现在会自动将工具参数中以字符串编码的 JSON 转换为 JSON。
- PATCH 请求现在会验证实体标签结构，避免无效配置。
- 修复了 `bank_id` 指标标签始终启用的问题。现在可选择启用该标签，避免 OTel 内存泄漏。
- 修复了使用自定义基础 URL 的 OpenAI 兼容端点对 `max_tokens` 的处理。
- 查询分析器现在可以妥善处理 dateparser 内部崩溃。
- 修复 hindsight-embed 在 Windows 上的兼容性问题。
- 修复依赖项中严重和高危安全漏洞。
