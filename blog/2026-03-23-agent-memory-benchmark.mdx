我们正在努力让 Hindsight 成为全球最好的 AI 记忆系统。“最好”并不意味着赢得每一项基准测试，而是要打造真正有效的系统，并如实说明它在哪些方面有效、哪些方面还不够。

这就是我们构建智能体记忆基准（Agent Memory Benchmark，AMB）的原因，也是我们选择将它完全开源的原因。

<!-- truncate -->

## “最好”不只看准确率 {#best-is-more-than-accuracy}

我们说希望 Hindsight 成为最好的 AI 记忆系统时，指的不是排行榜上的名次，而是一个能在生产环境中真正重要的多个维度上表现出色的完整系统：

- **准确率** — 智能体能否使用自己的记忆正确回答问题？
- **速度** — Retain（存入）和 Recall（召回）实际需要多长时间？
- **成本** — 系统每次操作会消耗多少 token？
- **易用性** — 系统要正常运行，需要多少配置、调优和基础设施？

准确率达到 90%，但每天每位用户要花费 10 美元的系统，不如准确率为 82%、成本为 0.10 美元的系统。一个需要配置三个推理服务提供方和一个图数据库的系统，也不如开箱即用的系统。

基准测试往往会把这些差异压平：它们只衡量一个维度——通常是在固定数据集上的准确率——然后宣布胜者。我们认为这会造成误导。AMB 从准确率开始，因为它最难造假；但长远目标是让上述四个维度都能衡量和比较。

## 现有基准测试的问题 {#the-problem-with-existing-benchmarks}

LoComo 和 LongMemEval 是扎实的数据集。它们经过了精心设计，也确实能测试记忆系统，因此才成为了标准。

问题在于它们诞生的时代。这两个数据集都来自上下文窗口为 32k 的时期，当时无法在一次模型调用中放入一段很长的对话。这些基准测试的核心前提是，你*不能*把所有内容都塞进上下文，而必须依靠记忆系统有选择地检索正确的事实。

那个时代已经过去。当前最先进的模型现在拥有百万 token 级别的上下文窗口。在 LoComo 和 LongMemEval 的大多数样例上，简单粗暴地“把所有内容都倒进上下文”也能取得有竞争力的分数。这不是因为这种架构有利于记忆，而是因为检索已经成了容易解决的部分。原本用于考验检索能力的基准测试，如今主要衡量的是你的 LLM 能不能读懂内容。

这会造成一种失真的图景：在这些数据集上，一个廉价、快速、架构合理且能规模化的系统，得分可能和蛮力填满上下文的系统相近。基准测试已经无法区分两者。

还有第二个问题：这两个数据集都是围绕聊天机器人用例构建的——两个人之间的对话历史，以及针对过往会话的问答。这是它们设计时占主导地位的范式，但现在已经不是了。如今的智能体不只是回答有关对话历史的问题；它们还会研究、规划、执行多步骤任务，并从许多不同的交互和来源中积累知识。智能体工作流中的记忆问题，与聊天机器人的记忆召回有着根本区别。

LoComo 和 LongMemEval 仍然是有效的基础：问题格式不错，评估方法也合理，而且仍有助于发现回归问题。但它们只覆盖了整个问题的一部分。AMB 正在加入专注于智能体任务的数据集，测试工具调用之间的记忆、文档研究形成的知识，以及应用于多步骤决策的偏好。这才是评估应该发展的方向。

## 开放且可复现的结果 {#open-results-reproducibly}

我们认为，只有能够由你亲自复现的基准测试结果才可信。

AMB 会公开所有内容：

- 评估工具（[github.com/vectorize-io/agent-memory-benchmark](https://github.com/vectorize-io/agent-memory-benchmark)）
- 完整的方法论——如何进行摄取、如何评估召回、如何编写 LLM 评审模型的提示词

那些看似只是实现细节的评估选择，实际上可能决定结果成败：评审提示词、答案生成提示词，以及各环节使用的模型。对其中任何一项做微小改动，都可能让准确率分数上下波动十几个百分点。我们会把这些全部公开。你可以不同意我们的选择、分叉项目并采用不同的运行方式；只要说明改了什么，这同样是合理的结果。

评估工具不依赖 Hindsight 的内部实现。方法论也不假定任何特定的检索策略。任何人都可以接入不同的记忆后端，运行同一套工具，并得到可比较的结果。

## AMB v1 中的数据集 {#datasets-in-amb-v1}

| 数据集 | 压力测试内容 |
| --- | --- |
| **[LoComo](https://arxiv.org/abs/2402.17753)** | 跨越长期、多场次对话的多跳推理和时间推理 |
| **[LongMemEval](https://arxiv.org/abs/2410.10813)** | 知识更新和认知判断修正——系统能否处理随时间变化的事实？ |
| **[LifeBench](https://arxiv.org/abs/2504.20945)** | 基于贴近现实的长期用户历史进行多来源个性化 |
| **[MemBench](https://arxiv.org/abs/2505.13590)** | 不同抽象层级的记忆——低级事实与高级推断 |
| **[MemSim](https://arxiv.org/abs/2409.17037)** | 需要综合多条记忆的条件题、比较题和聚合题 |
| **[PersonaMem](https://arxiv.org/abs/2504.05187)** | 偏好跟踪——系统是否记得用户真正关心的事情？ |

这些是基础，不是上限。

## 运行前先探索 {#explore-before-you-run}

脱离上下文的基准测试分数只是一个数字。在判断某个数据集的结果是否适用于你的用例之前，你需要先了解数据集里实际包含什么。

AMB 附带一个数据集浏览器，可以查看任意数据集的完整内容：系统摄取的原始对话和文档、各条查询，以及用于评估的标准答案。你可以阅读实际问题，查看系统本应据此作答的来源材料，再自行判断这个基准是否反映了你的应用所面对的记忆问题。

这一点很重要，因为大多数基准测试都建立在对“记忆”含义的特定假设之上。由两人日常对话构建的数据集，和由长期研究会话或多来源文档集合构建的数据集，测试的并不是同一类问题。在一种数据集上的分数不会自动适用于另一种。

运行前先探索数据，是判断哪些基准测试值得投入时间的最快方法；等拿到结果后，这也有助于你如实解读结果。

## Hindsight 的新基线 {#hindsight-on-the-new-baseline}

为了建立 AMB 的参考基线，我们使用同一套工具重新评估了 Hindsight 在这些数据集上的表现。最近一次公开的结果来自[我们的论文](https://arxiv.org/abs/2512.12818)，当时使用的是 0.1.0 版本。此后我们发布了数十项功能和改进。以下是 v0.4.19 在单查询模式下的结果：

| 数据集 | 准确率 |
| --- | --- |
| LoComo | **92.0%** |
| LongMemEval | **94.6%** |
| LifeBench | **71.5%** |
| PersonaMem | **86.6%** |

这是我们迄今为止最好的成绩。很难把功劳明确归于数十项改动中的某一项，不过我们认为，最重要的三项因素是：

- **观测** — 自动整合知识，从累积的事实中综合出更高阶的见解，让 Recall 能够利用对智能体所学内容更丰富的表示。
- **改进 Retain 流程** — 更准确地提取事实，意味着一开始就能存入正确的信息；“垃圾进，垃圾出”同样适用于记忆召回。
- **检索算法** — 检索流程经过大幅改进，准确率显著提高，同时保留了用户一直依赖的同一套语义接口。

这些结果将成为 AMB 今后的参考基线。Hindsight 未来的每个版本都会以此为基准进行评估。

## 两种模式，两种权衡 {#two-modes-two-tradeoffs}

LLM 编排正在迅速发展，构建记忆增强型智能体并没有唯一正确的方法。AMB 通过支持两种不同的评估模式体现了这一点。

**单查询模式**：只调用记忆系统检索一次，然后将结果直接交给 LLM 生成答案。速度快、结果可预测、延迟低。代价在于覆盖面有限：对于答案需要关联记忆不同部分中事实的多跳问题，一次查询可能无法找出所有必要信息。

**智能体模式**：由 LLM 通过工具调用驱动检索，发出多次查询、检查结果，并判断何时已有足够信息作答。在复杂问题和多跳问题上，这种模式的表现始终更好。代价是延迟和成本——往返次数更多、token 更多、耗时也更长。

具体采用哪种架构取决于你正在构建什么，两种都合理。重视响应时间的客户支持智能体，与重视全面性的研究助理，需求并不相同。AMB 可以让你在同一数据集上运行两种模式，并直接对比准确率、延迟和 token 成本，从而主动权衡，而不是默认接受某一种模式的取舍。

## 接下来 {#whats-next}

我们希望 AMB 能发展成为最全面的智能体记忆数据集集合。我们已知的缺口确实存在：当前数据集没有一个能在大规模场景下对记忆进行压力测试；也没有考察由智能体自行决定存入哪些内容的场景；多语言记忆则完全没有覆盖。我们正在为这些维度补充数据集，也希望社区参与其中。

从长远来看，我们正在探索自助式数据集上传：让研究人员和从业者直接贡献基准测试数据集，使用同一套评估工具进行测试，并按照共享的方法论发布结果。如果你有某个数据集，能以当前数据集无法覆盖的方式对记忆系统进行压力测试，我们希望听到你的想法。
