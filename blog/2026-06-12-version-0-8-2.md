Hindsight 0.8.2 在 [0.8.1](/blog/2026/06/09/version-0-8-1) 的基础上带来了更大规模的更新：现在，您可以使用**记忆防护**避免秘密和 PII 进入记忆；**编辑、标记失效并恢复单条记忆**；使用**观测范围**组织记忆并限制其数量；还可以在嵌入式部署中运行**本地控制中心**。本版本还新增了 LLM 服务提供方和嵌入模型，并修复了多项运维与数据完整性问题。**所有自行管理 Hindsight 的用户都应升级**——本版本修复了会影响长期运行部署的并发和数据存储问题。

<!-- truncate -->

- [**记忆防护**](#memory-defense)：按记忆库清除已存入记忆中的秘密和 PII。
- [**可逆的记忆维护**](#reversible-memory-curation)：编辑、标记记忆单元失效并恢复其先前状态，同时保留历史记录。
- [**观测范围**](#observation-scopes)：按范围列出、筛选、可视化记忆并限制其数量。
- [**本地控制中心**](#local-control-center)：供嵌入式部署使用的内置 Web 应用。
- [**更多服务提供方和模型**](#more-providers-and-models)：原生 Nous Portal、用于 Retain 的 Gemini Batch API、Gemini embedding-2、按记忆库归因成本，以及连通性探测。
- [**运维与数据完整性修复**](#operational-and-data-integrity-fixes)：升级的原因。

## 记忆防护 {#memory-defense}

智能体经常会接触 API 密钥、令牌和个人数据；如果没有防护措施，这些内容都可能被直接写入长期记忆。**记忆防护**是一个新的开源层，会在内容存入之前清除其中的敏感数据。

在记忆库中启用后，智能体写入的每条记忆都会接受一组**45 种模式**的扫描，覆盖服务提供方 API 密钥（Anthropic、OpenAI、Google 等）、通用敏感凭据、数据库连接字符串和常见 PII。每个匹配项都会在内容进入记忆单元或文档正文之前替换为 `[REDACTED:type]` 标记，因此 Recall、导出和 Reflect 都不会接触原始秘密。您可以为每条规则选择操作：

- **`redact`**：将每个匹配项替换为 `[REDACTED:type]` 标记，并存储完成清理的记忆。
- **`block`**：丢弃包含匹配项的输入项；如果 Retain 请求中的所有输入项都被阻止，调用将返回 `422`。

记忆防护按记忆库配置，默认关闭。要启用，请在记忆库配置中设置策略：

```json
{
  "memory_defense": {
    "enabled": true,
    "rules": [{ "on": "sensitive_data", "action": "redact" }]
  }
}
```

该策略只影响此记忆库后续的 Retain 调用，不会追溯扫描已有记忆。

每次脱敏或阻止操作还可以通知您的安全工具：如果记忆库订阅了 `memory_defense.triggered` Webhook，Hindsight 就会触发事件，报告所执行的操作、文档 ID 以及匹配的模式。这些载荷现在还包含便于接入 SIEM 的补充字段，因此警报可以直接路由到 SIEM 或 Slack，无需额外处理。完整模式列表和策略选项请参阅[记忆防护指南](/developer/memory-defense)。

## 可逆的记忆维护 {#reversible-memory-curation}

记忆不再只能写入而无法修改。0.8.2 让您可以纠正智能体学到的内容并撤销错误：

- **编辑**记忆的文本、日期、事实类型或上下文。
- **标记失效**，让某条记忆不再出现在 Recall 结果中，同时保留该记忆。
- **恢复**编辑或失效操作，以还原先前状态。

失效的记忆会被移出常规路径，而不是彻底清除，因此 Recall 的热路径保持整洁，同时不会永久丢失任何内容。经过编辑的记忆会带有标记，让您可以快速查看哪些内容已更改。这样一来，长期维护记忆库的准确性就变得切实可行：修正错误事实或将已过时的事实移出当前结果，都可以通过可逆操作完成，而不必破坏性地删除。

## 观测范围 {#observation-scopes}

随着记忆库不断增长，观测会在许多不同情境中累积。0.8.2 让管理这些观测变得更容易：

- **按范围枚举和筛选**观测，查看不同范围内已获取的信息。
- 在控制台中**可视化**各个范围。
- **设置每个范围的上限**，限制该范围保留的观测数量；上限也可以设为 `0`，以完全停止在该范围内创建新观测。

这样，您就可以直接控制每种情境保留多少记忆，而不必依赖单一的全局设置。

## 本地控制中心 {#local-control-center}

现在，嵌入式部署会附带本地**控制中心** Web 应用。您可以用它管理和检查嵌入式 Hindsight 实例，无需另外部署完整的控制台，适用于本地和单节点设置。

## 更多服务提供方和模型 {#more-providers-and-models}

0.8.2 扩展了服务提供方和模型的支持范围：

- **原生 Nous Portal 服务提供方**，内置 OAuth 身份验证，无需依赖外部 CLI。
- **用于 Retain 的 Gemini Batch API**，让事实提取可以通过 Gemini 的批处理流程运行。
- **支持 Gemini embedding-2 模型系列**，并可为每个输入生成嵌入向量。
- **按记忆库归因服务提供方成本。** 设置 `HINDSIGHT_API_LLM_SEND_BANK_AS_USER=true` 后，系统会在出站的 OpenAI 兼容 LLM 和嵌入调用中，将记忆库 ID 写入 `user` 字段；这样，成本网关（OpenRouter、LiteLLM、Helicone）便可按记忆库统计服务提供方开销。此功能默认关闭。
- **按记忆库进行 LLM 连通性探测**，在依赖某个记忆库之前验证其服务提供方配置。
- **选择 Amazon Bedrock 服务层级**，以调整 Bedrock 请求的处理方式。

## 运维与数据完整性修复 {#operational-and-data-integrity-fixes}

多项修复让自行管理且长期运行的部署更加稳健，也是建议升级的原因：

- **并发情况下的 Torch 数据类型。** 并发初始化模型时，可能会改变 Torch 的全局默认数据类型；现在该类型会被重置为 `float32`，以保持行为一致。
- **取消 Recall 和 Reflect。** 客户端断开连接时，系统现在会可靠地取消已放弃的 Recall 和 Reflect 操作，避免它们继续运行到完成而浪费资源。
- **扩宽 PostgreSQL 中的历史记录 ID。** 历史记录表中的 `bank_id` 列现在使用 `TEXT`，避免较长记忆库标识符导致失败。
- **提高 Reflect 综合生成的忠实度。** 最终 Reflect 输出现在能更一致地遵循强制指令和语言规则。
- **JSONL Retain 分块。** JSONL 文件现在按行边界分块，摄取时不会从一行中间拆开记录。
- **控制台图谱视图。** 记忆库图谱视图不再重复加载数据，从而减少冗余请求。
- **滚动部署迁移。** 滚动部署期间，系统现在能更可靠地跳过已应用的迁移，包括迁移解析错误被包装在 `CommandError` 中的情况。
- **Webhook 载荷。** 事件载荷现在包含此前缺失的字段。
- **CLI `get-memory`。** CLI 现在可以正确解析 `get-memory` 响应。
