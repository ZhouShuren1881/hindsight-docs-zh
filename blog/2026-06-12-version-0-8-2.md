Hindsight 0.8.2 基于 [0.8.1](/blog/2026/06/09/version-0-8-1) 构建，并发布了更大的版本：您现在可以使用 **记忆防御**、**编辑、无效和恢复个人记忆** 将秘密和 PII 保留在记忆之外，使用 **观察范围** 组织和限制记忆，并在嵌入式部署旁边运行 **本地控制中心**。它还添加了新的 LLM 提供程序和嵌入模型，并发布了多个操作和数据完整性修复程序。 **任何自我管理Hindsight都应该升级** — 此版本包括影响长期运行部署的并发和数据存储修复。

<!-- truncate -->

- [**记忆防御**](#memory-defense)：根据记忆库，从保留的记忆中清除秘密和 PII。
- [**可逆记忆管理**](#reversible-memory-curation)：编辑、无效和恢复记忆单元而不丢失历史记录。
- [**观察范围**](#observation-scopes)：列出、过滤、可视化和限制每个范围的记忆。
- [**本地控制中心**](#local-control-center)：用于嵌入式部署的内置 Web 应用程序。
- [**更多提供商和型号**](#more-providers-and-models)：Native Nous Portal、Gemini Batch 记忆存储、Gemini embedding-2、每个记忆库成本归因和连接探针。
- [**操作和数据完整性修复**](#operational-and-data-integrity-fixes)：为什么你应该升级。

## 记忆防御 {#memory-defense}

智能体通常会看到API密钥、令牌和个人数据——并且在没有护栏的情况下，它们中的任何一个都可以直接写入长期记忆中。 **记忆防御** 是一个新的开源层，可在存储之前将敏感数据从保留内容中清除。

在记忆库上启用时，智能体写入的每个记忆都会针对**45图案套装**进行扫描，涵盖提供者API密钥（Anthropic、OpenAI、Google等）、通用机密、数据库连接字符串和常见 PII。每场比赛在内容到达记忆单元或文档正文之前都会被替换为`[REDACTED:type]`标记，因此记忆召回、导出和反思永远不会看到原始的秘密。您选择每个规则的操作：

- **`redact`** — 用 `[REDACTED:type]` 标记替换每场比赛并存储擦除的记忆。
- **`block`** — 删除任何包含匹配项的项目；如果记忆存储请求中的每个项目都被阻止，则调用返回`422`。

记忆防御是**每个记忆库，默认关闭**。使用记忆库配置上的策略将其打开：

```json
{
  "memory_defense": {
    "enabled": true,
    "rules": [{ "on": "sensitive_data", "action": "redact" }]
  }
}
```

策略仅影响对该记忆库的未来记忆存储调用——现有记忆不会被追溯扫描。

每个编辑或阻止决策也可以通知您的安全工具：当记忆库有订阅`memory_defense.triggered`的Webhook时，Hindsight会触发一个事件，报告操作、文档ID以及匹配的模式。这些有效负载现在携带**SIEM 友好的丰富字段**，因此警报可以干净地路由到 SIEM 或 Slack，无需额外的粘合。有关完整模式列表和策略选项，请参阅[记忆防御指南](/developer/memory-defense)。

## 可逆记忆管理 {#reversible-memory-curation}

记忆不再是只写的。 0.8.2 允许您纠正智能体所学的内容并撤消错误：

- **编辑** 记忆的文本、日期、事实类型或上下文。
- **无效**一个记忆，因此它停止在记忆召回中出现，而不删除它。
- **恢复** 编辑或失效以恢复之前的状态。

无效的记忆被移到一边而不是被清除，因此记忆召回热路径保持干净，而不会永久丢失任何内容。已编辑的记忆会被标记，因此您可以一目了然地看到更改的内容。这使得随着时间的推移保持记忆库的准确性变得切实可行——修复错误的事实或淘汰陈旧的事实现在是一种可逆的行为，而不是破坏性的行为。

## 观察范围 {#observation-scopes}

随着记忆库的增长，观察力在许多情境中积累。 0.8.2 使它们易于管理：

- **枚举和过滤** 按范围观察，看看在哪里学到了什么。
- **可视化
控制平面中的**范围。
- **设置每个范围的限制** 限制范围保留的观察数量 — 包括限制 `0` 以完全停止范围中的新观察。

这使您可以直接控制每个上下文保留的记忆量，而不是单个全局设置。

## 本地控制中心 {#local-control-center}

嵌入式部署现在附带本地**控制中心** Web 应用程序。它为您提供了一个 UI 来管理和检查嵌入式 Hindsight 实例，而无需单独建立完整的控制平面 - 对于本地和单节点设置非常有用。

## 更多提供商和型号 {#more-providers-and-models}

0.8.2 扩展了提供商和模型覆盖范围：

- **Native Nous 门户提供商** 具有内置 OAuth 身份验证 — 无需外部 CLI 依赖项。
- **Gemini Batch API 用于记忆存储**，因此事实提取可以通过Gemini的批处理路径运行。
- **Gemini embedding-2 模型系列** 支持，带有每个输入嵌入。
- **每个记忆库提供商的成本归因。** 设置 `HINDSIGHT_API_LLM_SEND_BANK_AS_USER=true` 标记出站 OpenAI 兼容 LLM 并在 `user` 字段中嵌入带有记忆库 ID 的调用，因此成本网关（OpenRouter、LiteLLM、Helicone）可以为每个记忆库花费密钥提供者。默认关闭。
- **每记忆库LLM连接探针** 在依赖记忆库之前验证它的提供者配置。
- **Amazon Bedrock 服务级别选择** 用于调整 Bedrock 请求处理。

## 操作和数据完整性修复 {#operational-and-data-integrity-fixes}

多项修复使自我管理和长期运行的部署更加健壮——升级的原因：

- **并发下的Torch dtype。** 并发模型初始化可能会更改全局 Torch 默认数据类型；现在已标准化回 `float32`，因此行为保持一致。
- **记忆召回/反思取消。** 当客户端断开连接时，现在可以可靠地取消被放弃的记忆召回和跳跃操作，而不是运行到完成并浪费工作。
- **PostgreSQL 上更广泛的历史 ID。** 历史记录`bank_id`列扩大为`TEXT`，防止记忆库标识符较长时出现故障。
- **反思合成保真度。** 最终输出现在更加一致地尊重指令和语言规则。
- **JSONL 记忆存储分块。** JSONL 文件在行边界上分块，因此记录在摄取期间永远不会在中线分割。
- **控制平面图形视图。** 记忆库图形视图不再双重加载其数据，从而减少冗余请求。
- **滚动部署迁移。** 在滚动部署期间，可以更可靠地跳过已应用的迁移，包括当解决错误包含在 `CommandError` 中时。
- ​​**Webhook 有效负载。** 事件负载现在包含之前缺失的字段。
- **CLI `get-memory`。** CLI 正确解析 `get-memory` 响应。
