Hindsight 0.6.2 是一个维护版本，重点关注 **安全** 和 **迁移可靠性**。它修复了 Python 和 npm 堆栈中的多个易受攻击的依赖项，修复了影响 0.6.x 上某些生产部署的卡住迁移状态，并为 Claude Code、智能体 SDK、CLI 和 Paperclip 提供了一些集成修复程序。我们建议所有用户升级 0.6.x。

<!-- truncate -->

- [**安全**](#security)：易受攻击的依赖项发生冲突 — litellm ≥1.83.14、urllib3 2.7.0 以及其他高/关键 pip 和 npm 软件包。
- [**迁移可靠性**](#migration-reliability)：修复了`mental_models.subtype`卡住状态，并强化了嵌入维度迁移以防止瞬态 OID 错误。
- [**集成修复**](#integration-fixes)：Claude CodeMCP请求超时、跨智能体SDK和Claude CodeMCP、`get_page`内容可靠性、CLI时间戳交付和Paperclip事件负载对齐的记忆召回参数重命名。

## 安全 {#security}

GitHub 在 0.6.1 默认分支上标记了四组漏洞（均为中等漏洞）。 0.6.2 在根锁定文件和集成锁定文件之间颠倒了受影响的依赖项：

- **小号**至`>=1.83.14`
- **urllib3**至`2.7.0`
- 堆栈中的其他高/关键pip和npm包

感谢[@dcbouius](https://github.com/dcbouius)推动这些顺利通过。

## 迁移可靠性 {#migration-reliability}

0.6.2 中出现了两个迁移端修复：

- **`mental_models.subtype` 头部修复。** 少数运行 0.6.x 的生产部署报告了 `column "subtype" of relation "mental_models" does not exist` 错误。这是由历史 `down_revision` 重写造成的，该重写绕过了最初通过某些 0.5.x 路径迁移的数据库上的特定迁移分支。 0.6.2 添加了一个 **当前头幂等迁移
尽管 Alembic 报告了正确的版本，但**，它使用 `IF NOT EXISTS` 添加了缺失的列，因此受影响的部署会在下次升级时自行脱离，并且已经正常运行的部署不受影响。
- **嵌入维度 OID 错误。** 嵌入维度迁移现在可以优雅地处理瞬态 PostgreSQL OID 错误，消除了一些用户在繁忙的集群上运行时遇到的片状故障模式。也感谢 [@dcbouius](https://github.com/dcbouius) 的帮助。

## 集成修复 {#integration-fixes}

- **Claude Code：可配置MCP请求超时。** 长时间运行的记忆召回和反思调用偶尔会在默认情况下超时。 Claude Code现在公开了可配置的 MCP 请求超时 — 请参阅 `requestTimeoutSeconds` 选项。感谢[@rsaulo](https://github.com/rsaulo)。
- ​​**`max_results` → `max_tokens` 在记忆召回中重命名。** 智能体SDK的`agent_knowledge_recall`参数之前以对默认配置用户施加10个token预算的方式映射，返回空的记忆召回结果。该参数现在命名为 `max_tokens`，智能体 SDK 和 Claude Code MCP 插件的默认值从 10 提高到 1024。默认配置用户在升级后将立即看到有用的记忆召回结果。感谢[@r266-tech](https://github.com/r266-tech)和[@offendingcommit](https://github.com/offendingcommit)。
- **`get_page` 可靠地返回完整内容。** Claude Code插件和智能体 SDK 现在都请求 `detail=content` 进行 `get_page` 调用并处理工具结果溢出，因此完整页面内容返回而不是被截断。感谢[@cdbartholomew](https://github.com/cdbartholomew)和[@r266-tech](https://github.com/r266-tech)。
- **CLI `memory retain --timestamp` 实际上到达了 API。** CLI 接受了 `--timestamp` 标志，但在发送到 API 之前将其丢弃。控制平面的“事件日期”字段也是如此。现在两者都正确转发时间戳。
- **Paperclip 与真实事件负载保持一致的集成。** Paperclip 集成的事件处理程序基于稍微过时的有效负载形状； 0.6.2 将其与 Paperclip 实际发出的内容保持一致，恢复正确的事实提取。感谢[@amirhmoradi](https://github.com/amirhmoradi)。
