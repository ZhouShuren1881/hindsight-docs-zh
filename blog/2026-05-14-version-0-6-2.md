Hindsight 0.6.2 是一个维护版本，重点修复 **安全问题** 并提升 **迁移可靠性**。此版本升级了 Python 和 npm 技术栈中的多个存在漏洞的依赖项，修复了影响部分 0.6.x 生产部署的迁移卡住问题，并修正了 Claude Code、Agent SDK、CLI 和 Paperclip 的若干集成问题。我们建议所有使用 0.6.x 的用户升级。

<!-- truncate -->

- [**安全性**](#security)：升级存在漏洞的依赖项，包括 litellm ≥1.83.14、urllib3 2.7.0，以及其他存在高危或严重漏洞的 pip 和 npm 软件包。
- [**迁移可靠性**](#migration-reliability)：修复 `mental_models.subtype` 卡住状态，并增强嵌入维度迁移，以妥善处理暂时性的 OID 错误。
- [**集成修复**](#integration-fixes)：包括 Claude Code MCP 请求超时设置、Agent SDK 和 Claude Code MCP 中 Recall（召回）参数重命名、`get_page` 内容可靠性、CLI 时间戳传递，以及 Paperclip 事件载荷对齐。

## 安全性 {#security}

GitHub 在 0.6.1 默认分支上标记了四组漏洞，严重程度均为中等。0.6.2 更新了根锁定文件和各集成锁定文件中受影响的依赖项：

- 将 **litellm** 升级至 `>=1.83.14`
- 将 **urllib3** 升级至 `2.7.0`
- 升级技术栈中其他存在高危或严重漏洞的 pip 和 npm 软件包

感谢 [@dcbouius](https://github.com/dcbouius) 推动这些修复落地。

## 迁移可靠性 {#migration-reliability}

0.6.2 包含两项迁移修复：

- **在当前迁移头部修复 `mental_models.subtype`。** 少数运行 0.6.x 的生产部署报告了 `column "subtype" of relation "mental_models" does not exist` 错误，尽管 Alembic 报告的版本正确。问题源于历史上的 `down_revision` 改写：对于最初沿某些 0.5.x 路径完成迁移的数据库，该改写绕过了一个特定的迁移分支。0.6.2 在当前迁移头部新增了一项 **幂等迁移**，使用 `IF NOT EXISTS` 添加缺失的列。因此，受影响的部署会在下次升级时解除卡住状态，已经正常运行的部署则不受影响。
- **嵌入维度迁移中的 OID 错误。** 嵌入维度迁移现在可以妥善处理暂时性的 PostgreSQL OID 错误，从而消除部分用户在繁忙集群上运行时遇到的不稳定故障。也感谢 [@dcbouius](https://github.com/dcbouius) 提供这项修复。

## 集成修复 {#integration-fixes}

- **Claude Code：可配置 MCP 请求超时。** 长时间运行的 Recall 和 Reflect（反思）调用有时会因默认超时设置而超时。现在可以在 Claude Code 中配置 MCP 请求超时，详见 `requestTimeoutSeconds` 选项。感谢 [@rsaulo](https://github.com/rsaulo)。
- **Recall 参数从 `max_results` 重命名为 `max_tokens`。** Agent SDK 的 `agent_knowledge_recall` 参数此前采用了一种映射方式，导致使用默认配置的用户受到 10 个 token 预算的限制，因而 Recall 结果为空。现在，该参数改名为 `max_tokens`，Agent SDK 和 Claude Code MCP 插件中的默认值也都从 10 提高到 1024。使用默认配置的用户升级后即可获得有用的 Recall 结果。感谢 [@r266-tech](https://github.com/r266-tech) 和 [@offendingcommit](https://github.com/offendingcommit)。
- **`get_page` 稳定返回完整内容。** Claude Code 插件和 Agent SDK 现在都会在调用 `get_page` 时请求 `detail=content`，并处理工具结果溢出的情况，因此会返回完整页面内容，而不再截断。感谢 [@cdbartholomew](https://github.com/cdbartholomew) 和 [@r266-tech](https://github.com/r266-tech)。
- **CLI 的 `memory retain --timestamp` 现在会传到 API。** CLI 过去虽然接受 `--timestamp` 标志，却在向 API 发送请求前丢弃了它。控制台的“事件日期”字段也有同样的问题。现在两者都会正确传递时间戳。
- **Paperclip 集成与实际事件载荷对齐。** Paperclip 集成的事件处理程序依据的载荷结构略有过时。0.6.2 已将其调整为与 Paperclip 实际发出的结构一致，恢复了正确的事实提取。感谢 [@amirhmoradi](https://github.com/amirhmoradi)。
