距上次 Cloud 汇总已过三个月，期间完成的工作远不止三个月的分量。上次更新时最新版本是 0.6.2，本次涵盖十三个版本：**v0.7.0 至 v0.9.2**。

重点是可在控制台浏览和编辑的**客户端管理知识库**。同时推出按指定计划刷新的心智模型、可全屏查看的星图、后台文档导出，以及全面重建的控制台视觉设计。

期间也完成了大量**企业版**功能：自带身份提供商的单点登录、组织级强制 MFA、按记忆库启用的审计日志，以及更深入的记忆防护。

## 可编辑的知识库 {#a-knowledge-base-you-can-edit}

最大的新增功能是**知识库**：一组由客户端管理、与记忆并存的页面，按你控制的文件夹层级组织。

![Hindsight 控制平面的知识库目录树](/img/blog/knowledge-pages-tree.webp)

首先要理解一个概念变化：知识页面**就是**心智模型，只是外面包装了简化的文档式配置。因此页面并非手动维护的静态文件，而是后台根据底层记忆重建的持续答案。应用可以直接读取它，而无需在请求路径上付费综合生成。

控制台提供：

- **文件夹树**，以层级而非平铺列表组织页面。
- **页面编辑器**，旁边同时显示渲染结果。
- 覆盖知识库的**页面级搜索**。
- **目录树可见的刷新触发器**，无需打开页面就能了解其更新方式。
- **按范围判断过时状态**：页面报告*自身*范围是否有新内容，不再继承会让所有页面同时过时的记忆库级统一标记。

![在控制台编辑知识页面](/img/blog/knowledge-pages-edit.webp)

两项能力将其扩展到控制台之外：`hindsight fs` 将知识库映射到文件系统，可在本地镜像页面并用 CLI 管理；知识库 CRUD 现在也作为**原生 MCP 工具**提供，连接 Cloud 的智能体可以创建、读取、更新和搜索自己的知识库，而非只能读取。

详细介绍见[编程智能体的知识页面](/blog/2026/08/13/knowledge-pages-coding-agents)和[通过 MCP 管理知识库](/blog/2026/08/26/knowledge-base-mcp-tools)。

## 心智模型定时刷新 {#mental-models-on-a-schedule}

[心智模型](/blog/2026/06/05/mental-models-deep-dive)新增第三种刷新方式：除手动和有新记忆时刷新外，现在可**按 cron 计划刷新**。

控制台将其呈现为单一的**刷新触发器**选择，包含*手动*、*有新记忆时*和*按计划*三种选项。仅选择第三项时显示 cron 字段，使用标准五字段 UTC cron 表达式，输入时实时验证，两种自动模式有意设计为互斥。

计划界面补足了这类界面常遗漏的细节：

- **实时预览**，以自然语言解释表达式，并同时按 UTC 和本地时间列出接下来的多次运行。
- 模型列表、仪表盘和详情对话框在“上次刷新”旁显示**“下次刷新”**。

此外还提供：

- **刷新试运行**：构建模型但不持久化，可选跟踪信息，便于正式执行前查看预计结果。这是 API 能力，控制台尚无按钮。
- 自动刷新之间的**最短间隔**，防止繁忙记忆库不断重新综合同一模型。
- **一致的过时状态报告**：各处均以相同方式计算和说明模型过时状态，修复此前不一致的问题。

## 全新外观 {#a-new-look}

控制台的设计系统全面更新，不只是换颜色。

组件库的默认灰色被 **Hindsight 配色**替代，通过设计 token 统一应用，无需逐组件修改，所有视图同时采用新外观。最明显的修复是浅色模式卡片原本与页面背景同色，**几乎不可见**；现在页面为 `#F3F5F9`、卡片为白色，深色模式则采用偏蓝配色，页面为 `#080C17`、卡片为 `#0F1724`。

另外两项小改动也让界面更舒适，虽然用户未必能指出原因：

- **字距从 `0.025em` 改为 `0`。** Inter 在正文字号下增加字距会影响阅读效果。
- **两种模式的正文都满足 WCAG AA。** 次要文字色调整为 `#525866`，与页面对比度为 5.3:1，与卡片为 7.1:1。

## 文档与实体 {#documents-and-entities}

数据视图的多项导航改进：

- **文档标签筛选**，各视图统一使用筛选标签，操作方式一致。
- **按关联实体筛选记忆**，并提供**实体时间线**，查看记忆库随时间了解到的实体信息。
- 正在被 retain 操作更新的文档显示**处理中标记**。

## 导出记忆库文档 {#exporting-a-banks-documents}

可从控制台导出记忆库文档，连同处理结果一起带走：提取的事实、实体名称、因果关联和分块均随文档导出。

- **后台运行。** 导出作为可跟踪操作提交，而非单次长请求；大型记忆库打包时不会持续占用连接。
- **观察可选。** 复选框控制是否在原始事实之外包含整合后的观察。

目前只有导出功能，Cloud 尚不提供对应的文档导入。

## 单点登录与 MFA {#single-sign-on-and-mfa}

需要控制访问方式的团队新增两项身份功能。

**单点登录**允许组织自带身份提供商，在设置的单点登录标签页配置一次即可：

- **OIDC 或 SAML**：支持 Okta、Entra、Google Workspace 和其他兼容标准的提供商。
- **声明邮件域名并通过 DNS 验证。** 域名验证且配置生效后，该域名邮箱的登录自动路由到你的 IdP，无需记住点击其他按钮。
- **首次登录自动创建成员**，团队列表标注为 SSO 创建，无需提前建账号。
- **客户端密钥静态加密**，API 从不返回密钥。

域名启用 SSO 后，该域名邮箱的密码登录和密码重置会被拒绝，无法绕开 IdP。

可在组织内强制启用**多因素认证**。所有者打开*要求所有成员使用 MFA* 后，成员必须先注册认证因素，并用它认证当前会话才能访问。支持**认证器应用（TOTP）、安全密钥和通行密钥（WebAuthn）、短信及邮件验证码**。

组织未强制要求时，个人也可从账户安全页面自愿注册。设置对话框显示二维码，并为无法扫码的设备提供手动密钥。

对 HIPAA 等要求会话管理的组织，还提供**30 分钟空闲超时**，无操作后自动退出。

这两项功能都在上次汇总后不久推出，均为按组织启用的企业版功能。

## 审计日志 {#audit-logging}

审计日志记录记忆库中发生的 retain、recall、reflect 等被审计操作，支持查询、按操作和严重程度筛选，并以图表展示请求量变化。

日志**按记忆库选择启用**，而非全部开启或关闭，这适合大规模部署。日志数据量很大，多数记忆库不需要，因此可在需要的记忆库审计区域开启。

这是 Cloud 企业版功能。

## 企业版记忆防护 {#memory-defense-enterprise}

记忆防护在 retain 期间检查内容，决定如何处理密钥、提示注入和超大请求体。

所有记忆库都具备基础功能：总开关、默认动作和**密钥脱敏**，写入前将检测到的 API 密钥和令牌替换为 `[REDACTED:github_token]` 等标记。

企业版新增可独立启用和调节的检测器：

| 能力 | 检测内容 |
|---|---|
| **提示注入防护** | 向记忆注入“忽略此前指令”或覆盖系统指令等尝试 |
| **大小异常** | 浪费 token、挤占排名或用于数据外传的超大请求体，默认阈值为 64 KB |
| **受保护文档标签** | 重新提交时剥离或替换受保护标签 |
| **广泛模式库** | 在基础检测之外增加 220 多种密钥检测模式 |
| **Base64 解码** | 解码 Base64 数据并重新扫描隐藏密钥 |
| **LLM 筛查** | 模式无法捕获的自然语言泄露，例如“密码是……” |

每个检测器都有独立动作和最低严重程度阈值，可阻止高置信度密钥，仅标记边界情况。授权在服务端和控制台同时执行，无法通过 API 绕过限制设置策略。

## 其他更新 {#also-shipped}

其他值得了解的小改动：

- **操作运行时报告进度。** 过去长期整合无论正常还是卡住，外观都相同。现在运行中记录粗粒度的阶段／已处理／总量快照，能区分缓慢与冻结。
- **事实提取试运行**：只读 API 预览 retain 将从文本中提取什么，不写入记忆库；返回候选事实和 token 用量，不执行实体解析、嵌入或持久化。
- **观察范围**可枚举、筛选和可视化，跨范围观察也支持 `shared` 关键字。
- **审计日志与观察**可按记忆库覆盖，而非只能部署级统一设置。
