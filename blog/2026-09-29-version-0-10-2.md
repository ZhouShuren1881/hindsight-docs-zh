## 记忆库别名 {#bank-aliases}

![记忆库同时接受旧 ID 和新别名，调用方可逐一迁移](/img/blog/0-10-2-bank-aliases.svg)

过去重命名需停止所有客户端并一次重定向，现在一个库可响应额外 ID：

```
POST   /v1/default/banks/{bank_id}/aliases     {"alias": "new-id"}
GET    /v1/default/banks/{bank_id}/aliases
DELETE /v1/default/banks/{bank_id}/aliases/{alias}
```

添加别名立即生效，不复制内容。两 ID 都可用，逐步迁移后再移除无人使用的旧名。

迁移后，可用 `PATCH .../aliases/{alias}` 配合 `{"primary": true}`，或 `hindsight bank alias primary <bank> <alias>`，使别名成为**显示名称**。真实 ID 仍显示，认证、计量、导出和日志继续使用它。

## 按范围整合策略 {#consolidation-strategies-per-scope}

![同一事实对用户保留完整细节，对公司只保留总体趋势](/img/blog/0-10-2-consolidation-strategies.svg)

同库可保存用户、团队和公司记忆，各自按规则整合。例如公司范围只记录趋势，用户范围保留细节：

```json
"consolidation_strategies": [
  {
    "scopes": [{ "tags": ["company:*"] }],
    "observations_mission": "仅记录概括性行业趋势，不提及具体公司。",
    "max_observations_per_scope": 20
  }
]
```

可按库配置，或使用全局 `HINDSIGHT_API_CONSOLIDATION_STRATEGIES`。首个匹配策略生效，未设置项回退记忆库配置。控制平面 **Bank → Configuration → Observations（记忆库 → 配置 → 观察）** 提供分标签编辑器和保存前范围匹配预览。`observation_scope_limits` 已弃用但仍有效。

任务也在范围组间公平分配，繁忙范围不再饿死其他范围。

## 心智模型独立刷新预算 {#a-refresh-budget-per-mental-model}

![心智模型触发器决定刷新预算，不使用记忆库反思默认值](/img/blog/0-10-2-refresh-budget.svg)

过去刷新静默使用 `low`，使反思步骤减半，不足以编写整页。现在每模型有**刷新预算** `low` / `mid` / `high`，未设默认为 `mid`。在触发器高级面板配置，或通过知识页面默认触发器设库级默认。

刷新也**不再读取 `reflect_default_options`**。这些用于回答问题，过去调优会悄然改变页面编写。

刷新失败会结束，不再循环重试增加费用；每个模型同时只运行一次刷新。

## 截图和文件提取测试 {#test-extraction-on-screenshots-and-files}

![提取测试器读取文字和图片，显示每条事实的来源文件](/img/blog/0-10-2-multimodal-extraction.svg)

控制平面**提取测试器**和试运行端点接受与 retain 相同的文本、图片和文件块，写入前查看截图或 PDF 将提取什么，每事实显示来源。

观察也展示来源事实附件，reflect 的 `based_on` 携带引用记忆的文档、标签、元数据和附件。知识文章里的截图可随依赖它的答案返回。

## 反思可区分来源 {#reflect-can-tell-sources-apart}

![反思识别手册和聊天来源，依据手册作答](/img/blog/0-10-2-reflect-metadata.svg)

手册规则与矛盾聊天变成事实后看似相同，反思常选更新的聊天。现在可见文档元数据，可在 `reflect_mission` 写明优先级，例如“优先 `source=handbook` 文档”。无需新增设置，无元数据的库无额外开销。

## 运维 {#operations}

![导出分批读取文档、流式传输附件，峰值内存约 25 MiB](/img/blog/0-10-2-streamed-export.svg)

- **流式导出。** 分段写而非内存构建，256 MiB 附件库从约 545 MiB 内存降至约 25 MiB，整库归档也按保留策略清理。
- **ONNX 嵌入 CUDA。** 设置 `HINDSIGHT_API_EMBEDDINGS_ONNX_DEVICE=cuda`，可选 `HINDSIGHT_API_EMBEDDINGS_ONNX_CUDA_DEVICE_ID`，在 GPU 运行进程内嵌入。默认仍为 `cpu`，镜像示例在 `docker/docker-compose/cuda-onnx/`。
- **整理扩展钩子。** 操作验证器可批准或拒绝编辑、失效、恢复，提交后获知哪些内容重新嵌入。
- **pg0** 将 URL 查询参数传给 PostgreSQL。
- **Helm** Ingress 正确路由 `/v1` 数据 API。

## 可靠性修复 {#reliability-fixes}

- **LLM 超时为真实截止时间。** 缓慢持续传输不再永久占用槽位，进程内重排序同样受墙钟时间限制。
- **来源事实调用期间被编辑时，整合丢弃该批次**，不从过时事实写观察，来源也只保存显示一次。
- **迁移失败释放锁**，下次启动可重试。
- **其他进程删除库后召回返回 404**，而非空结果或 500。
- **OpenAI GPT-6** 恢复正常，包括 Responses API。
- **Oracle**：原先仅 PostgreSQL 可用的存储路径、归档导入，以及 JSON 和时间戳边界问题已修复。
- **MCP** 列表工具与 HTTP 使用相同分页限制。

一项 schema 变化涉及大表：实体名称索引按记忆库限定，使模糊实体匹配留在同库。迁移启动时执行，大部署应预留更多时间。
