Hindsight 0.10.0 让你可以在一次调用中连同周围文字一起存入截图或 PDF；请求路径的开销降低了数倍；在操作消耗 token 之前，你还可以查看它将发送的准确提示词。本版也退役了两个已弃用多个版本的端点。

- [**图片和文件成为一等存入内容**](#images-and-files-are-first-class-retain-content)：`content` 接受按顺序排列的文本块、图片块和文件块，事实会引用其来源附件。
- [**相同机器带来更高吞吐量**](#more-throughput-out-of-the-same-box)：请求路径提速 3.2 倍，嵌入批次并发处理，token 计数成本降低。
- [**发送前查看提示词**](#see-the-prompt-before-you-send-it)：为存入、整合和反思提供提示词预览端点，控制平面还加入存入提示词测试器。
- [**召回：容错标签，以及无需预先枚举的标签值**](#recall-typo-tolerant-tags-and-labels-you-dont-have-to-enumerate)：新增 `fuzzy` 标签解析模式和开放词汇的 `multi-text` 实体标签。
- [**随身带走综合生成的知识层**](#take-the-synthesized-layer-with-you)：文档迁移现在会携带知识页和心智模型。
- [**一页查看所有记忆库**](#every-bank-on-one-page)：记忆库概览现为控制平面首页，并支持批量删除。
- [**不兼容变更**](#breaking-changes)：移除记忆库 profile 和 background 端点、Docker 镜像不再包含 `curl`、服务器过载时返回 503 而非无限排队，并移除一个扩展钩子。

## 图片和文件成为一等存入内容 {#images-and-files-are-first-class-retain-content}

`content` 现在可以接收按顺序排列的文本块、图片块和文件块，而不再局限于字符串。提取器会按附件在内容中的位置读取它们：例如，夹在两段文字之间的图表会被当作位于这两段文字之间的图表来读取。所有读取接口都会一并返回支撑结果的附件。来源追溯信息按事实记录，而非按文本分块记录：文字中陈述的一项事实不会把旁边的截图也算作证据。

普通字符串的行为逐字节保持不变。按内容哈希实现的幂等性、`update_mode=append`、基于文本分块增量进行的重新提取，以及 `reprocess_document` 都继续有效。这是因为内容块会在 API 边界展平为一个规范正文，文件字节则保存在现有文件存储中，并以 SHA-256 内容寻址。

**召回也会带上附件。** 召回的事实会连同支撑它的附件一起出现在 API 响应和控制平面中。这样，答案所依据的截图只需点击一次即可查看，不必再回到源文档中寻找。

本版还新增一次数据库迁移，创建 `attachments` 和 `document_attachments` 两张表。两张表都是空表，因此无论部署规模多大，迁移都很快。

## 相同机器带来更高吞吐量 {#more-throughput-out-of-the-same-box}

**请求路径提速 3.2 倍。** 两个 HTTP 中间件都改写成了纯 ASGI。Starlette 的 `BaseHTTPMiddleware` 会为每个请求创建一个子任务，并通过一对内存对象流传递响应；对于开销低的路由，这些机制本身比端点还耗资源。在 2 CPU 容器中，`/health/live` 的吞吐量从 2476 rps（p99 为 108 ms）升至 7917 rps（p99 为 17 ms），同时 CPU 使用量更低。召回没有变化——其瓶颈是端点内的 CPU 计算，远未达到这个上限；不过所有低开销路由、健康检查和轮询都显著降低了成本。原有功能没有删除：HTTP 指标和未知参数报告都迁移到了新实现中。

**嵌入批次现在会并发发送。** 此前，每个远程嵌入服务提供方都用普通循环逐批处理，因此无论文本量有多大，一次存入操作同一时间都只会保持一个嵌入请求处于进行中。现在，批处理和有界并发扇出由同一处逻辑管理。结果无论完成顺序如何，都会按输入顺序拼接。相同的 TEI 服务器在一个请求同时进行时可处理 903 texts/s，并发数为八时可处理 2080 texts/s。

**token 计数成本更低。** 过去，每次为候选事实、候选文本分块、来源事实和重排序文档计数时，都会先构造完整的 token ID 列表，再只取列表长度。现在使用我们为此开发的 BPE 分词器 [toktok](https://github.com/vectorize-io/toktok)，可直接替代 tiktoken；它无需生成 token ID 就能返回计数。一次召回中的四个计数阶段耗时由 34.2 ms 降至 5.0 ms；一个 77k-token 文档的处理耗时由 36 ms 降至 3 ms，内存分配也从 2.8 MB 降至近乎为零。

此外，只有在有人请求追踪记录时才构建追踪载荷；解析配置时不再每次都深拷贝全局配置；检查心智模型是否待更新时也不再遍历整个记忆库。

## 发送前查看提示词 {#see-the-prompt-before-you-send-it}

记忆库的任务说明和策略，只有在看到它们最终进入的提示词后才有意义。`POST /banks/{id}/prompts/preview` 会按发送顺序返回存入、整合或反思操作将会发送的消息；它不会调用 LLM，也不会写入数据，并会用固定占位符替换运行时数据。消息以内容块形式返回，活动内容块拼接后的文字与实际发送的文字完全一致。对于已关闭的设置，相应内容块会标记为非活动，因此即使没有设置任务说明，也能看到它本来会出现的位置。

控制平面在此基础上增加了**存入提示词测试器**：编辑输入、查看提示词，再运行提取以查看得到了哪些事实。

## 召回：容错标签，以及无需预先枚举的标签值 {#recall-typo-tolerant-tags-and-labels-you-dont-have-to-enumerate}

**模糊标签匹配。** 标签筛选原本要求数组中的值精确匹配。因此，调用方按 `typsecript` 筛选时，带有 `typescript` 标签的记忆会在排序开始前就被排除；无论排序改进多少都无济于事，因为匹配本身必须能容忍拼写错误。现在，`tag_groups` 的叶节点可以包含可选的 `resolve` 字段：保留 `exact` 时行为不变，设为 `fuzzy` 时，该叶节点中的标签会按三元组相似度与记忆库的标签匹配，而不是要求字面值完全相同。这就是全部 API 变化——没有新增配置，也没有新增响应字段。

它可以将 `typescropt`→`typescript`、`kubernets`→`kubernetes` 和 `user:alcie`→`user:alice`，并会刻意避免将 `mango`→`mongo`。需要预先了解一个限制：相似度会受标签长度影响。短标签包含的三元组较少，单次编辑就会破坏其中大部分，因此 `kakfa`→`kafka` 无法匹配。模糊匹配对描述性标签有效，对特别短的标签几乎不起作用；正是这一特性使无关的短词不容易彼此混淆。

**开放词汇的实体标签。** 实体标签可以根据固定词汇对事实分类，也可以捕获一个自由字符串。但这两种方式都无法覆盖这样的情形：配置记忆库时无法预先枚举、却希望记录_多个_值，例如某事物的各种名称（包括缩写和不同拼写）、事实引用的工单，以及产品代码。

新增的 `multi-text` 类型是一个没有固定词汇表的字符串列表，因此提取器会根据内容生成所需数量的值。每个值都会成为独立实体；设置 `tag: true` 时，每个值也会成为一个标签。这样，记忆库就能根据自身内容推导分类，并在召回时据此筛选，无需调用方事先提供词汇表。现在两个客户端包装器都支持这种配置；此前 TypeScript 客户端完全无法配置实体标签。

## 随身带走综合生成的知识层 {#take-the-synthesized-layer-with-you}

过去，文档迁移会移动文档和观测，也就是原始层内容。记忆库基于这些内容、耗费大量 LLM 预算综合生成的知识页和心智模型却会留在原处，迁移到另一端后只能从头重建。

在整库导出时传入 `include_knowledge_base`（或在控制平面中勾选对应选项），归档便会在文档之外一并携带知识页和心智模型。此选项需主动启用，默认关闭；它仅适用于整库导出，不适用于文档列表，因为基于整个记忆库综合生成的页面无法代表其中任意一个子集。清单会报告随归档导出的内容，因此导入前就能知道归档中是否包含知识库。

导入时会保留导出所包含的内容：心智模型内容在往返迁移后完整保留，观测也会保留其更新状态，不会被当作全部在导入时记录。

## 一页查看所有记忆库 {#every-bank-on-one-page}

控制平面过去会打开“欢迎使用 Hindsight”的占位页，因此要查看运行多个记忆库的服务器，就必须逐个切换记忆库。现在首页会列出所有记忆库，包括名称、记忆数量、最近活动时间和创建日期，并像其他表格一样支持分页。

<ZoomableMedia>
<StaticImage src="/img/blog/version-0-10-0-banks-overview.webp" alt="控制平面首页列出八个记忆库及其记忆数量、最近活动时间和创建日期；每行都有批量删除复选框，并提供搜索框和“创建记忆库”按钮" width="100%" style={{borderRadius: "8px"}} />

**批量删除。** 选中多行即可一并删除，无需逐个进入每个记忆库的危险操作区。某个删除操作失败不会影响其余操作：无法删除的记忆库会继续列出错误信息，并保持选中状态，以便重试。

页头标志现在会链接回此页，记忆库选择器则会将当前所在的记忆库固定在列表顶部。服务器中完全没有记忆库时，仍会显示欢迎卡片，并新增创建记忆库按钮。

## 本版其他内容 {#also-in-this-release}

- **为独立于服务器发布的扩展新增注册目录。** 现在，单独分发的扩展存放在 `hindsight-extensions/` 中；首个扩展是 Supabase 租户扩展（`hindsight-ext-supabase-tenant`），它将第三方 IdP 的 JWT 客户端从每个 Hindsight 安装的依赖关系图中移除。**如果你正在使用它，需要执行升级步骤：** 内置路径 `hindsight_api.extensions.builtin.supabase_tenant` 已不存在，安装仍指向此路径时会在启动时因 `ModuleNotFoundError` 失败。请将该扩展加入镜像，并设置 `HINDSIGHT_API_TENANT_EXTENSION=hindsight_ext_supabase_tenant:SupabaseTenantExtension`；所有 `HINDSIGHT_API_TENANT_*` 设置及 schema 命名均保持不变。同时新增 `StaticKeysTenantExtension`：通过环境变量配置按用户划分的 API 密钥，并按 schema 隔离，适用于完全不使用身份提供方、但需要多用户隔离的部署。
- **Meta Model API 成为一等 LLM 服务提供方。** `HINDSIGHT_API_LLM_PROVIDER=meta` 会将提取、反思和整合路由到 Muse 系列。请注意，Muse Spark 始终会进行推理，因此 `reasoning_effort: "none"` 会被拒绝；推理 token 会计入输出预算，请为每种操作的 token 限额预留余量。
- **Reflect 不再为数据空缺编造数字。** 当被问及记忆库没有数据的时段时，Reflect 过去可能会根据相邻时段推算出具体数值，并将其说成可靠推断。现在会说明该数值没有记录，同时仍会根据已有数据得出定性结论。本版还修复了心智模型和知识页的增量刷新问题：过去刷新可能只依据最新批次覆盖已存内容，例如用本批次数量替换累计数量，或因最新批次未提及而抹去早先记录的事件。
- **批量摄取不再让其他记忆库陷入资源饥饿。** 工作进程会在各记忆库之间轮换分配任务槽位，因此一个记忆库摄取大型语料时不会占满所有槽位，让其他记忆库一直等待。
- **列出心智模型时默认只返回元数据。** `GET .../mental-models` 过去默认返回每个模型的完整综合生成内容，这会膨胀调用方的上下文，并在一次调用中取回记忆库的全部综合知识。现在默认使用 `detail=metadata`；如需内容，请传入 `detail=content` 或 `detail=full`。MCP 工具 `list_mental_models` 只返回元数据；要读取某个模型，请使用 `get_mental_model`。
- 新增**企业高管**记忆库模板、Helm Chart 对 **Prometheus ServiceMonitor** 的支持及 `extraContainers`/`extraInitContainers`，还可选择通过环境变量控制 CPU 性能分析并将结果写入日志。

## 不兼容变更 {#breaking-changes}

**记忆库 profile 和 background 端点已移除。** `GET`/`PUT /v1/default/banks/{bank_id}/profile` 和 `POST /v1/default/banks/{bank_id}/background` 已弃用多个版本。现在这些端点会返回 `410 Gone`，详情中包含替代调用。路由仍以原有签名保留在 OpenAPI 规范中，因此调用方不会失去相应的生成 SDK 方法，只有端点行为发生变化。

性格倾向特征和反思任务说明本来就是记忆库配置，应通过记忆库配置 API 读取和写入。这些端点还会返回显示名称，而它已可在记忆库列表中查看。为使配置 API 能完全替代旧端点，读取 `GET .../config` 现在不再受 `HINDSIGHT_API_ENABLE_BANK_CONFIG_API` 限制；该标志目前只控制写入，因为记忆库必须始终能够读取自身解析后的设置。

控制平面和 CLI 也在同一项变更中更新。如果你曾针对它编写脚本，需要注意一处行为差异：`hindsight bank background` 现在会_替换_任务说明，而不是由 LLM 将其合并进去，并且会对此发出警告。

**Docker 镜像中不再包含 `curl`。** 镜像内唯一使用它的地方是独立镜像自身的就绪检查循环；该循环现在已被替换。`curl` 也是每个镜像中九项无法修复的 HIGH 漏洞发现的唯一原因。Hindsight 镜像没有定义 `HEALTHCHECK`，所以默认情况下不会有任何功能受影响；但如果 Compose `healthcheck` 或 Kubernetes `exec` 探针在 Hindsight 容器内部运行 `curl`，现在就会因找不到命令而失败。请改用 HTTP 探针（例如 Kubernetes `httpGet` 请求 `/health/live`），或在容器外部执行检查。

**服务器过载时会拒绝请求，而不是继续排队。** Recall、Reflect 和 Retain 现在默认经过准入控制。工作进程达到容量上限后，请求会等待可用槽位，最长不超过截止时间：Recall 为 30 s，Reflect 为 5 s，Retain 为 2 s；超时后会以 `503` 和 `Retry-After` 响应头拒绝请求。此前请求会在并发上限后无限排队，突发负载只会让延迟转移到队列中。Python 和 TypeScript 客户端会在 `503` 时重试 Recall 和 Reflect，并遵循 `Retry-After`；它们不会重试 Retain，因为重试同步存入操作可能造成重复写入。因此，**如果你在突发负载下运行同步 Retain，必须处理 `503`**：退避后重试，或改用异步 Retain；异步操作一入队就会返回，不受此限制。限额根据每个工作进程可用的 CPU 推导；可使用 `HINDSIGHT_API_ADMISSION_{RECALL,REFLECT,RETAIN}_MAX_IN_FLIGHT` 和 `_MAX_WAIT_MS` 调整。将某一通道的 `MAX_IN_FLIGHT` 设为负数即可关闭该通道的限制。

**记忆扩展 API 中的 `count_chunks` 钩子已移除。** 没有任何地方调用它。如果自定义记忆存储扩展实现了此方法，它现在已是无用代码，可以删除。
