Hindsight 0.10.0 允许在一次调用中同时存储截图或 PDF 与周围文字，将请求路径开销降低数倍，并在消耗 token 前展示操作将发送的准确提示词。同时移除两个已弃用多个版本的端点。

- [**图片和文件成为原生存储内容**](#images-and-files-are-first-class-retain-content)：`content` 接受有序的文本、图片和文件块，事实引用其来源附件。
- [**相同硬件获得更高吞吐量**](#more-throughput-out-of-the-same-box)：请求路径快 3.2 倍，并发嵌入批次和更低成本的 token 计数。
- [**发送前查看提示词**](#see-the-prompt-before-you-send-it)：存储、整合和反思预览端点，以及控制平面的存储提示词测试器。
- [**召回：容错标签与无需枚举的标签值**](#recall-typo-tolerant-tags-and-labels-you-dont-have-to-enumerate)：`fuzzy` 标签解析和开放词汇 `multi-text` 实体标签。
- [**带走综合知识层**](#take-the-synthesized-layer-with-you)：文档迁移包含知识页面和心智模型。
- [**一页查看所有记忆库**](#every-bank-on-one-page)：支持批量删除的记忆库概览成为控制平面首页。
- [**不兼容变更**](#breaking-changes)：移除 profile 和 background 端点、Docker 镜像不再包含 `curl`、过载返回 503 而非无限排队，以及移除一个扩展钩子。

## 图片和文件成为原生存储内容 {#images-and-files-are-first-class-retain-content}

`content` 现在接受有序文本、图片和文件块，而不只是字符串。提取器按附件所在位置读取，例如两段文字之间的图表仍在两段之间解读。所有读取接口都会返回结果所依赖的附件。来源按事实而非分块归属：文字中陈述的事实不会把旁边截图声称为证据。

普通字符串的行为逐字节保持不变。内容哈希幂等性、`update_mode=append`、分块增量提取和 `reprocess_document` 都继续有效，因为块在 API 边界展平为规范正文，附件字节保存在现有文件存储中，以 SHA-256 内容寻址。

**召回也携带附件。** 事实在 API 响应和控制平面中都带有其来源附件，用户从答案点击一次就能查看来源截图，无需在原文档中寻找。

配套迁移新增 `attachments` 和 `document_attachments` 两个空表，在任何规模部署中都很快。

## 相同硬件获得更高吞吐量 {#more-throughput-out-of-the-same-box}

**请求路径快 3.2 倍。** 两个 HTTP 中间件改写为纯 ASGI。Starlette 的 `BaseHTTPMiddleware` 每次请求创建子任务，并通过一对内存对象流传输响应；轻量路由中，这些机制比端点本身还贵。2 CPU 容器上的 `/health/live` 从 2476 rps、p99 108 ms 提升到 7917 rps、p99 17 ms，CPU 更低。召回不变，因为瓶颈在端点 CPU，远未达到此上限；轻量路由、健康检查和轮询都显著降低开销。HTTP 指标和未知参数报告均迁移保留，没有删除。

**嵌入批次并发发送。** 过去所有远程嵌入提供程序顺序处理批次，无论文字多少，一次 retain 都只保持一个嵌入请求。现在批处理和有界并发统一管理，结果始终按输入顺序拼接。相同 TEI 服务器一个并发请求为 903 文本／秒，八个并发为 2080 文本／秒。

**更低成本的 token 计数。** 过去为每个候选事实、分块、来源事实和重排序文档构建完整 token ID 列表，只为取长度。现在使用我们为此开发的 BPE 分词器 [toktok](https://github.com/vectorize-io/toktok)，可直接替代 tiktoken，不生成 ID 即返回计数。一次召回的四阶段计数从 34.2 ms 降为 5.0 ms；77k token 文档从 36 ms、分配 2.8 MB 降为 3 ms，几乎无分配。

此外，未请求跟踪时不构建跟踪数据，配置解析不再每次深拷贝全局配置，心智模型过时检查不再遍历整个记忆库。

## 发送前查看提示词 {#see-the-prompt-before-you-send-it}

记忆库的使命和策略只有在能看到最终提示词时才有实际意义。`POST /banks/{id}/prompts/preview` 按发送顺序返回存储、整合或反思_将要_发送的消息，不调用 LLM、不写入，运行时数据用固定占位符替换。消息以块返回，活动块拼接后与实际发送文字完全一致；已关闭设置的块标为非活动，因此未设置的使命仍可在其原本位置看到。

控制平面在此基础上提供**存储提示词测试器**：编辑输入、查看提示词，再运行提取以观察生成的事实。

## 召回：容错标签与无需枚举的标签值 {#recall-typo-tolerant-tags-and-labels-you-dont-have-to-enumerate}

**模糊标签匹配。** 原来标签筛选是精确数组包含，`typsecript` 在排名前就排除了 `typescript`，再好的排名也无用。现在 `tag_groups` 叶节点支持可选 `resolve`：默认 `exact` 不改变行为，`fuzzy` 则按三元组相似度匹配记忆库标签，而非字面值。这就是全部 API 变化，没有新增配置或响应字段。

可解析 `typescropt`→`typescript`、`kubernets`→`kubernetes`、`user:alcie`→`user:alice`，有意不解析 `mango`→`mongo`。相似度受长度影响，短标签三元组少，一次编辑破坏大部分，因此 `kakfa`→`kafka` 不匹配。它对描述性标签有效，对极短标签几乎无效，同一特性也避免无关短词混淆。

**开放词汇实体标签。** 原来实体标签可按固定词汇分类，或提取一个自由字符串，却不能表示配置时无法枚举的_多个_值，例如名称、缩写、不同拼写、引用的工单和产品代码。

新增 `multi-text` 类型是无固定词汇的字符串列表，提取器按内容生成所需数量的值。每个值成为独立实体，使用 `tag: true` 时也成为标签。因此记忆库可从自身内容推导分类，再按其召回筛选，无需调用方预先提供词汇。两个客户端包装均支持，TypeScript 此前完全无法配置实体标签。

## 带走综合知识层 {#take-the-synthesized-layer-with-you}

文档迁移过去只移动文档和观察这些原始层内容，花费 LLM 预算构建的知识页面与心智模型留在原处，另一端必须重建。

整库导出传入 `include_knowledge_base`，或勾选控制平面选项，归档就会连同文档携带知识页面和心智模型。默认关闭，需主动启用；只适用于整库导出，不适用于任意文档列表，因为全库综合页面不能代表任意子集。清单报告包含内容，导入前即可知道是否有知识库。

## 一页查看所有记忆库 {#every-bank-on-one-page}

控制平面过去打开“欢迎使用 Hindsight”占位页，查看多记忆库服务器需要逐库切换。现在首页按表格分页显示所有记忆库的名称、记忆数、最近活动和创建日期。

**批量删除。** 选择多行一起删除，无需逐库进入危险操作区。一个删除失败不会阻止其他库；失败项仍保留错误和选择状态，可直接重试。

页头标志链接回此页，选择器将当前记忆库置顶。服务器没有记忆库时仍显示欢迎卡片，现在有创建按钮。

## 本版其他内容 {#also-in-this-release}

- **独立发布扩展的注册目录。** `hindsight-extensions/` 保存单独分发的扩展，首个为 Supabase 租户扩展（`hindsight-ext-supabase-tenant`），不再让每次 Hindsight 安装都依赖第三方 IdP 的 JWT 客户端。**使用它的用户必须执行升级步骤：** 内置路径 `hindsight_api.extensions.builtin.supabase_tenant` 已移除，仍引用它会在启动时报 `ModuleNotFoundError`。将扩展加入镜像，并设置 `HINDSIGHT_API_TENANT_EXTENSION=hindsight_ext_supabase_tenant:SupabaseTenantExtension`；所有 `HINDSIGHT_API_TENANT_*` 设置和 schema 命名不变。新增 `StaticKeysTenantExtension`，通过环境变量配置按用户 API 密钥和按 schema 隔离，适合无需 IdP 的多用户部署。
- **Meta Model API 成为原生 LLM 提供程序。** `HINDSIGHT_API_LLM_PROVIDER=meta` 将提取、反思和整合路由到 Muse 模型。Muse Spark 始终推理，拒绝 `reasoning_effort: "none"`，推理 token 计入输出预算，应为每种操作预留足够 token。
- **Reflect 不再为数据空缺编造数字。** 查询没有记录的时期时，过去可能从相邻时期推算具体数字并当作可靠推断，现在会说明该值未记录，同时仍依据现有信息给出定性结论。心智模型与知识页面增量刷新也不再仅凭最新批次覆盖已有内容，例如用批次数替换累计数，或因未提及而删除早期事件。
- **批量摄取不再饿死其他记忆库。** 工作进程轮流分配各记忆库的任务槽位，避免一个大语料摄取占用全部槽位。
- **心智模型列表默认返回元数据。** `GET .../mental-models` 原来返回每个模型的完整内容，膨胀上下文并一次取出全部综合知识。现在默认 `detail=metadata`，需要内容时传 `detail=content` 或 `detail=full`。MCP `list_mental_models` 仅返回元数据，读取特定模型使用 `get_mental_model`。
- 新增**企业高管**记忆库模板、Helm Chart 的 **Prometheus ServiceMonitor** 及 `extraContainers`/`extraInitContainers` 支持，以及通过环境变量控制、写入日志的可选 **CPU 性能分析**。

## 不兼容变更 {#breaking-changes}

**移除记忆库 profile 和 background 端点。** `GET`/`PUT /v1/default/banks/{bank_id}/profile` 和 `POST /v1/default/banks/{bank_id}/background` 已弃用多个版本，现在返回 `410 Gone`，详情包含替代调用。路由及签名仍保留在 OpenAPI，生成的 SDK 方法不会消失，只改变行为。

性格倾向与反思使命原本就属于记忆库配置，应通过配置 API 读写；这些端点原来返回的显示名称位于记忆库列表。为完整替代旧端点，**读取** `GET .../config` 不再受 `HINDSIGHT_API_ENABLE_BANK_CONFIG_API` 限制，该标志仅控制写入，因为记忆库必须能读取自己解析后的设置。

控制平面和 CLI 同步迁移。编写脚本时注意：`hindsight bank background` 现在_替换_使命，而非用 LLM 合并，并会提示此行为。

**Docker 镜像不再包含 `curl`。** 唯一的镜像内使用方是独立镜像的就绪循环，现已替换；它也是每个镜像中九项无法修复的 HIGH 漏洞的唯一来源。镜像没有定义 `HEALTHCHECK`，默认不会出问题，但 Compose `healthcheck` 或 Kubernetes `exec` 探针若在容器内运行 `curl`，会报“command not found”。改用 HTTP 探针，例如 Kubernetes `httpGet` 请求 `/health/live`，或在容器外检查。

**过载服务器拒绝请求，不再无限排队。** Recall、reflect 和 retain 默认经过准入控制。工作进程满载时，请求等待槽位至截止时间：recall 30 秒、reflect 5 秒、retain 2 秒，随后返回 `503` 和 `Retry-After`。过去并发上限后无限排队，突发流量的延迟只是积压在队列中。Python 和 TypeScript 客户端遵循 `Retry-After` 重试 recall 和 reflect，但不重试 retain，以免同步写入重复。**突发执行同步 retain 时，必须处理 `503`**：退避重试，或改用入队即返回、不受此限制的异步 retain。限制按各工作进程可用 CPU 推导，可通过 `HINDSIGHT_API_ADMISSION_{RECALL,REFLECT,RETAIN}_MAX_IN_FLIGHT` 和 `_MAX_WAIT_MS` 调整；将某通道的 `MAX_IN_FLIGHT` 设为负数可关闭。

**记忆扩展 API 移除 `count_chunks` 钩子。** 没有任何地方调用它，自定义记忆存储扩展中的该方法现在是死代码，可删除。
