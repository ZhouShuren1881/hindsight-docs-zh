Hindsight 0.8.4 建立在 [0.8.3](/blog/2026/06/18/version-0-8-3) 的基础上，重点关注 **可靠性和控制**：当提供者因 **多LLM故障转移和循环路由** 降级时保持记忆操作运行，用 **更精细的记忆控制** 更精确地调整检索，用 **预定心智模型刷新** 保持知识最新，并获得 **更准确的token记账**。它还登陆了一批**数据完整性和稳健性修复**。 **自我管理部署应该升级。**

- [**Multi-LLM 故障转移和路由**](#multi-llm-failover--routing)：通过法学硕士之间的故障转移和循环，避免提供商中断。

## Multi-LLM 故障转移和路由 {#multi-llm-failover--routing}

您现在可以配置**多个法学硕士，并自动通过Hindsight路线**，当一个提供者出错时使用**故障转移**，并使用**循环赛**来分散负载。单个提供商中断或速率限制不再需要停止记忆操作。

多LLM配置的每个成员都可以单独调整 - 包括**LiteLLM 路由器设置**、**Vertex AI 服务帐户密钥**和**每个成员 Vertex 项目和区域** - 因此您可以将提供者和帐户与每个人所需的控件混合使用。

此版本还添加了两个新的OpenAI兼容提供程序，**请求**和**阿特拉斯云**，因此您可以直接将Hindsight指向它们。

## 更精细的记忆召回控制 {#finer-recall-control}

一些变化让您可以更精确地控制记忆召回返回的内容及其排名：

- **每阶段分数和两级过滤。** 记忆召回现在公开结构化的每阶段分数，并且 `min_scores` 支持两级过滤 - 因此您可以在每个检索阶段要求最小的相关性，而不是单一的生硬截止。 （现在也正确地穿过维护的 Python 和 TypeScript SDK 包装器。）
- **可配置的新近度衰减。** 选择新近度对排名的影响程度 - `linear`、`exponential` 或 `none`。
- ​​**观察感知的重复数据删除。** 新的`prefer_observations`选项删除了已被综合观察取代的原始事实，因此结果有利于综合视图。
- **全局观察的精确过滤。** 您现在可以精确过滤未标记/全局观察。

## 预定心智模型刷新 {#scheduled-mental-model-refresh}

心智模型现在可以是**按 cron 计划刷新**。您可以按照您定义的节奏保持记忆库的综合知识最新，而不是仅仅依赖活动触发的刷新。

## Sharper LLM 控制与会计 {#sharper-llm-control--accounting}

- **每次操作温度。** 每次操作设置不同的温度，以更严格地控​​制记忆存储、记忆召回和反思的反应方式。
- **每范围超时和重试。** 每个范围 LLM 超时和重试策略现在跨提供商一致应用。
- **更丰富的token记账。** 使用总计现在包括支持的缓存和“想法”令牌，并跟踪OpenAI兼容提供商的推理令牌 - 以获得更准确的成本报告。
- **更可靠的结构化输出。** Anthropic 严格的结构化输出现在会强制使用工具，并且 Ф 的结构化输出重试次数会受到限制，以避免失控的重试循环。
- **可配置的上传大小。** 现在可以在控制平面中配置最大上传大小。
- **更快、更可扩展的记忆库统计数据。** 记忆库统计信息现在可扩展到大型部署，并且按需刷新可让您在需要时强制进行精确的重新计数。
- **资源管理器中的完整记忆细节。** 控制平面的记忆浏览器现在显示每个记忆的完整细节，使检查和调试更加容易。

## 数据完整性和稳健性修复 {#data-integrity--robustness-fixes}

升级的原因 — 一组保护存储内容并保持后台工作正常运行的修复程序：

- **追加模式分块。** 记忆存储追加模式现在合并 JSON 数组，因此保留了对话感知分块。
- **观察搜索向量。** 搜索向量现在在观察插入/更新上维护，保持搜索和整合正确。
- **集成安全。** 集成现在在缺少重复数据删除操作时默认保留项目，从而防止意外丢失。
- ​​**迁移引导程序。** 迁移引导现在遵循配置的矢量扩展。
- **准确的记忆库统计数据。** 记忆库统计缓存在删除和清除后正确失效，因此计数保持准确。
- **图维护死锁。** 并发插入在图维护期间不再触发队列死锁。

其他值得注意的修复：

- **解析失败时的令牌使用情况。** 即使工具调用参数解析或验证失败，现在也会保留提供者令牌的使用情况，因此成本报告保持准确。
- **JSON 信封。** 现在会打开某些模型返回的 JSON 包装答案。
- **更清晰的错误路径。** 列表端点拒绝负`limit`/`offset`，并使用`422`而不是服务器错误，当记忆库不存在时，异步操作返回`404`，并且`PATCH bank`/空运行提取不再无意中创建记忆库。
- **记忆存储错误消息。** 记忆存储错误摘要现在保留底层异常消息以便于调试。
