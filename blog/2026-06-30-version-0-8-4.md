Hindsight 0.8.4 在 [0.8.3](/blog/2026/06/18/version-0-8-3) 的基础上，重点提升**可靠性和可控性**：通过**多 LLM 故障切换与轮询路由**，在某个服务提供方性能下降时继续执行记忆操作；通过**更精细的召回控制**，更准确地调整检索；通过**定时刷新心智模型**，保持知识更新；并提供**更准确的 token 用量统计**。此版本还修复了一批**数据完整性和稳健性问题**。**自托管部署建议升级。**

- [**多 LLM 故障切换与路由**](#multi-llm-failover--routing)：通过在 LLM 之间进行故障切换和轮询调度，应对服务提供方中断。
- [**更精细的召回控制**](#finer-recall-control)：逐阶段分数、两级分数筛选、可配置的近期性衰减，以及感知观测的去重。

## 多 LLM 故障切换与路由 {#multi-llm-failover--routing}

现在可以配置多个 LLM，由 Hindsight 自动在它们之间路由；一个服务提供方出错时会进行**故障切换**，也可以通过**轮询调度**分散负载。单个服务提供方中断或触发速率限制，不再必然导致记忆操作停滞。

多 LLM 配置中的每个成员都可以单独调整，包括 **LiteLLM Router 设置**、**Vertex AI 服务账号密钥**，以及**各成员对应的 Vertex 项目和区域**。因此，你可以组合不同的服务提供方和账号，并为每个成员配置所需的控制项。

此版本还新增了两个兼容 OpenAI API 的服务提供方：**Requesty** 和 **Atlas Cloud**，现在可以直接将 Hindsight 指向它们。

## 更精细的召回控制 {#finer-recall-control}

以下改动让你可以更精确地控制召回结果及其排名：

- **逐阶段分数与两级筛选。** Recall 现在会公开结构化的逐阶段分数；`min_scores` 也支持两级筛选，因此你可以为每个检索阶段分别设定最低相关性要求，而不必只设一个笼统的阈值。（此功能现已正确贯通维护中的 Python 和 TypeScript SDK 封装。）
- **可配置的近期性衰减。** 选择近期性对排名的影响方式：`linear`、`exponential` 或 `none`。
- **感知观测的去重。** 新增的 `prefer_observations` 选项会移除已由整合后观测取代的原始事实，让结果优先呈现综合后的视图。
- **精确筛选全局观测。** 现在可以精确筛选无标签的全局观测。

## 定时刷新心智模型 {#scheduled-mental-model-refresh}

现在可以按 cron 计划刷新心智模型。除了依赖活动触发的刷新之外，你还可以按自定频率更新记忆库中的整合知识。

## 更精细的 LLM 控制与用量统计 {#sharper-llm-control--accounting}

- **按操作设置温度。** 为不同操作设置不同的温度，从而更细致地控制 Retain、Recall 和 Reflect 的响应风格。
- **按范围设置超时与重试。** 现在，各服务提供方都会一致应用按范围配置的 LLM 超时和重试策略。
- **更丰富的 token 用量统计。** 在支持的情况下，用量总计现在会包含缓存 token 和“思考” token；兼容 OpenAI API 的服务提供方还会统计推理 token，从而更准确地报告成本。
- **更可靠的结构化输出。** Anthropic 的严格结构化输出现在通过强制工具调用实现；Reflect 的结构化输出重试也设有上限，以避免重试循环失控。
- **可配置的上传大小。** 现在可以在控制台配置最大上传大小。
- **更快且可扩展的记忆库统计。** 记忆库统计现在可以扩展到大型部署；需要时还可按需刷新，强制执行精确的重新计数。
- **资源浏览器中的完整记忆详情。** 控制台中的记忆浏览器现在会显示每条记忆的完整详情，便于检查和调试。

## 数据完整性与稳健性修复 {#data-integrity--robustness-fixes}

建议升级的原因之一，是此版本包含一系列保护已存储内容、维持后台工作正常运行的修复：

- **追加模式分块。** Retain 的追加模式现在会合并 JSON 数组，从而保留按对话进行分块的能力。
- **观测搜索向量。** 插入或更新观测时，现在会维护搜索向量，确保搜索和整合正常工作。
- **整合安全性。** 缺少去重操作时，整合现在默认保留条目，避免意外丢弃内容。
- **迁移初始化。** 迁移初始化现在会遵循已配置的向量扩展。
- **准确的记忆库统计。** 删除和清空操作后，记忆库统计缓存现在会正确失效，确保计数准确。
- **图维护死锁。** 并发插入不再会在图维护期间触发入队死锁。

其他值得关注的修复：

- **解析失败时保留 token 用量。** 即使工具调用参数解析或验证失败，现在仍会保留服务提供方报告的 token 用量，确保成本报告准确。
- **Reflect 的 JSON 信封。** Reflect 现在会解包某些模型返回的 JSON 包装答案。
- **更清晰的错误处理。** 列表端点现在会对负数 `limit`/`offset` 返回 `422`，而不是服务器错误；记忆库不存在时，异步操作会返回 `404`；`PATCH bank` 和 `dry-run extract` 也不再意外创建记忆库。
- **保留 Retain 错误消息。** Retain 的错误摘要现在会保留底层异常消息，便于调试。
