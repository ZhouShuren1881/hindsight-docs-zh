Hindsight 0.8.5 基于 [0.8.4](/blog/2026/06/30/version-0-8-4) 构建，重点关注 **成本、弹性和运营完整性**：削减 LLM **Anthropic批量和提示缓存** 和 **Gemini 上下文缓存** 的支出，并保持运营贯穿 **更具弹性的模型输出解析**。它还登陆了大量的**记忆存储、整合和记忆召回完整性修复**。 **自我管理部署应该升级**，尤其是那些大规模进行整合的人。

<!-- truncate -->

- [**降低LLM成本**](#lower-llm-costs)：Anthropic批处理API和提示缓存，以及Gemini的逐步上下文缓存。
- [**更具弹性的模型输出**](#more-resilient-model-output)：从格式错误且受隔离的JSON 中恢复，而不是使操作失败。
- [**每个记忆库审计和运营控制**](#per-bank-audit--operations-control)：切换每个记忆库的审核日志记录、删除终端操作以及更安全的数据库配置。
- [**记忆存储、整合和记忆召回完整性**](#retain-consolidation--recall-integrity)：为什么你应该升级。

## 降低LLM成本 {#lower-llm-costs}

三个变化有意义地减少了提取、整合和反思背后的token支出：

- **Anthropic 消息批次。** 记忆存储和集成现在可以在符合条件的工作负载上通过批处理 API 运行Anthropic 调用，以实现 **50%token折扣**。
- **Anthropic提示缓存。** 重复的提示前缀会被缓存，因此大容量工作负载不再为每次调用的相同上下文支付全价 - 包括批量系统提示。
- **Gemini上下文缓存。** 的多步工具循环现在逐步缓存上下文，从而降低了 Gemini 上长时间、多轮推理的成本。

如果您在 Anthropic 或 Gemini 上运行，这些是您可以选择加入的胜利，无需更改您调用 API 的方式。

## 更具弹性的模型输出 {#more-resilient-model-output}

语言模型偶尔会发出JSON，它被包裹在代码围栏中、被截断或稍微畸形——而以前这可能会导致良好的操作失败。 0.8.5 添加了多个恢复层，因此单个格式化单不再花费您整个通话的费用：

- **畸形JSON的最后手段修复。** 当模型返回结构性损坏的 JSON 时，Hindsight 现在会在放弃之前尝试修复和解析它，但当确实没有任何内容可恢复时，仍然会严重失败。
- **从代码围栏和杂散文本中恢复。
现在可以正确提取被散文包围、包围或包含内部反引号的**JSON，而不是被截断。
被围起来、被散文包围或包含内部反引号的
- **更严格的结构化输出有帮助。** 每个操作严格的 JSON 模式（具有显式的每次调用选择退出）和规范的工具结果消息使结构化响应在OpenAI兼容和Anthropic提供商之间更加可靠。
- **更轻松地调试被拒绝的调用。** 新的选择加入模式会在所有提供商中转储 4xx 拒绝时的确切请求负载，因此您可以准确地看到提供商拒绝的内容。

最终效果：由提供者格式怪异引起的失败保留和反映减少。

## 每个记忆库审计和运营控制 {#per-bank-audit--operations-control}

- **​​每记忆库审计日志记录。**`audit_log_enabled`现在是分层的，因此您可以按记忆库而不是全局打开或关闭审核日志记录。
- **删除终端操作。** 现在可以在控制平面支持下删除已完成和失败的记忆库操作，以保持操作历史记录易于管理。
- **更安全的数据库配置。** 通过迁移保留百分比编码的数据库 URL，`pg0://` URL 可以携带用户和密码凭据，嵌入的 Postgres 在数据库 URL 中尊重凭据，并且在获取池连接时正确地重新应用会话设置。
- **架构范围内的维护例程。** 维护例程安装到配置的架构中，过期操作清理会在默认情况下保留关闭的单个查询中发现架构。
- **向量索引恢复。** 在数据库恢复、升级或向量扩展切换后，每个记忆库向量索引最终不完整的罕见情况下，Hindsight 现在修复其覆盖范围，使记忆召回保持完整，并且可重新运行的 `repair-bank` 管理命令可让您按需协调记忆库。

## 记忆存储、整合和记忆召回完整性 {#retain-consolidation--recall-integrity}

升级的核心原因 - 一系列广泛的修复，可以保护存储的内容并保持后台工作的健康：

- ​​**实体链接正确性。** 解析的实体在链接单元之前重新断言，并且在规范化时保留每个共现对，因此链接落在正确的已提交实体上。
- **退化文本被拒绝，不被存储。** 记忆存储现在在存储之前拒绝退化事实文本，同时在过滤掉事实文本时保留事实对齐。
- **原子记忆库创建。** 惰性记忆库创建现在是原子的，在并发首次写入下结束了竞争。
- **无卡顿操作。** 操作完成与尽力而为的副作用隔离，因此失败的 Webhook 或聚合不会再让操作陷入`processing`；崩溃恢复尝试现在计入重试预算。
- **可靠的网络钩子和水印。**`retain.completed` webhooks 即使在边界和零事实批次上也会排队，并且无操作增量刷新会提前水印而不是重新处理。
- **更强的整合。** 重复数据删除决策被请求为 JSON 并标准化，默认保留无效操作，并且修复了并行集成期间的外键违规。
- **策展和元数据保真度。** 记忆库属性在管理过程中被保留，搜索向量在编辑时刷新，发生的日期可以使用`null`清除，浏览端点返回完整的元数据。

其他值得注意的变化：

- **列表端点上的标签过滤。** `list_memories` 和 `list_memory_units` 现在接受标签过滤器。
- **记忆调节调整。** 选择加入BM25 查询项上限、保留的组合图激活分数和事实类型范围的实体扇出提供了更可预测的检索。
- **反思抛光。** 答案长度有上限，扩展的记忆与正确的记忆配对，水平规则保留在围栏代码块内，并且记忆库属性保留在提供者调用中。
- **日期解析。** 现在最强的日期匹配获胜，并且日-月-年日期不再折叠到整个月。
- **安全更新。** 易受攻击的 API 运行时包已被删除，并且为了安全起见，还增加了多个依赖项。
