Hindsight 0.4.19 添加了 Agno 和 Hermes 智能体集成、三种新的记忆存储提取模式（具有命名的每次调用策略）、对 TypeScript 客户端的 Deno 支持以及集成故障的恢复机制。

<!-- truncate -->

- [**Agno 整合**](#agno-integration)：使用原生工具包将持久记忆添加到Agno智能体。
- [**Hermes智能体集成**](#hermes-agent-integration)：通过零配置插件赋予Hermes智能体长期记忆。
- [**新的记忆存储模式**](#new-retain-modes)：`verbatim`、`chunks`，以及混合内容记忆库的命名策略。
- [**TypeScript Deno 兼容性**](#typescript-deno-compatibility)：在 Deno 环境中使用 TypeScript 客户端。

## Agno 整合 {#agno-integration}

`hindsight-agno`是一个新的集成包，它使用Hindsight的原生工具包模式将持久记忆添加到[Agno](https://github.com/agno-agi/agno)智能体中​​——与Agno的内置`Mem0Tools`相同的模式。

```bash
pip install hindsight-agno
```

将`HindsightTools`直接传递到您智能体的`tools`列表：

```python
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from hindsight_agno import HindsightTools

agent = Agent(
    model=OpenAIChat(id="gpt-4o-mini"),
    tools=[HindsightTools(
        bank_id="user-123",
        hindsight_api_url="http://localhost:8888",
    )],
)

agent.print_response("记住我更喜欢深色模式")
agent.print_response("我的偏好是什么？")
```

该工具包注册了智能体可以调用的三个工具：`retain_memory`（存储）、`recall_memory`（搜索）和`reflect_on_memory`（合成）。您可以通过切换 `enable_retain`、`enable_recall` 和 `enable_reflect` 来包含任意组合。

**每用户记忆库隔离** 是内置的。如果您没有传递 `bank_id`，工具包会自动从 `RunContext.user_id` 解析它，因此每个用户都可以获得自己独立的记忆库，无需额外的代码。还支持自定义 `bank_resolver` 可调用，以实现更复杂的路由：

```python
tools=[HindsightTools(bank_resolver=lambda ctx: f"team-{ctx.user_id}")]
```

**记忆说明**让您在启动时预记忆相关上下文并将其注入智能体的系统提示符中，以便智能体以已加载的相关记忆开始每次对话：

```python
from hindsight_agno import HindsightTools, memory_instructions

agent = Agent(
    model=OpenAIChat(id="gpt-4o-mini"),
    tools=[HindsightTools(bank_id="user-123", hindsight_api_url="http://localhost:8888")],
    instructions=[memory_instructions(
        bank_id="user-123",
        hindsight_api_url="http://localhost:8888",
    )],
)
```

请参阅 [Agno集成文档](/sdks/integrations/agno) 以获取完整的 API 参考。

## Hermes智能体集成 {#hermes-agent-integration}

`hindsight-hermes` 是[Hermes智能体](https://github.com/NousResearch/hermes-agent) (NousResearch) 的新插件包。它使用 Hermes 的插件发现系统（无需更改代码），并在 `[hindsight]` 工具集下注册三个工具。

```bash
uv pip install hindsight-hermes --python $HOME/.hermes/hermes-agent/venv/bin/python
```

设置环境变量并启动Hermes：

```bash
export HINDSIGHT_API_URL=http://localhost:8888
export HINDSIGHT_BANK_ID=my-agent
hermes
```

键入 `/tools` 验证已加载的插件：

```
[hindsight]
  * hindsight_recall     - Search long-term memory for relevant information.
  * hindsight_reflect    - Synthesize a thoughtful answer from long-term memories.
  * hindsight_retain     - Store information to long-term memory for later retrieval.
```

Hermes 有自己的内置记忆存储，可写入本地文件。由于 LLM 会更喜欢它最熟悉的那个，请将其关闭，以便 Hermes 使用 Hindsight 代替：

```bash
hermes config set memory.memory_enabled false        # MEMORY.md
hermes config set memory.user_profile_enabled false  # USER.md (optional)
```

如果`HINDSIGHT_API_URL`和`HINDSIGHT_API_KEY`都没有设置，插件会默默地跳过注册，Hermes正常启动。

有关设置和故障排除，请参阅[Hermes集成文档](/sdks/integrations/hermes)。

## 新的记忆存储模式 {#new-retain-modes}

`retain_extraction_mode` 的三项新增功能让您可以控制每个摄取文档发生的 LLM 工作量 — 从完全提取到零。

### `verbatim` — 保留原始文本，仅提取元数据 {#verbatim--preserve-original-text-extract-metadata-only}

在默认（`concise`）模式下，LLM将每个块重写为紧凑的提取事实。 `verbatim` 模式跳过重写步骤：每个块都按照源中的显示方式存储，每个块一个记忆。 LLM 仍在运行，但只是为了提取实体、时间信息和位置，而不是解释内容。事实文本是原始块的逐字记录。

这对于保留源措辞很重要的RAG式索引和基准，或者当下游系统需要在记忆召回结果中显示准确的原始文本时非常有用。

```bash
HINDSIGHT_API_RETAIN_EXTRACTION_MODE=verbatim
```

### `chunks` — 零 LLM 成本 {#chunks--zero-llm-cost}

`chunks` 完全跳过LLM。块按原样存储，没有实体提取，也没有时间索引——仅生成用于语义搜索的嵌入。您通过 `RetainContent.entities` 传递的任何实体都将直接使用。这是最快、最便宜的记忆存储模式；当摄取速度和成本比结构化元数据更重要时使用它。

```bash
HINDSIGHT_API_RETAIN_EXTRACTION_MODE=chunks
```

### 命名记忆存储策略——在一个记忆库中混合内容类型 {#named-retain-strategies--mix-content-types-in-one-bank}

命名策略允许您在单个记忆库上配置多个提取配置文件，并在记忆存储时在其中进行选择。每个策略都可以覆盖任何分层配置字段，包括 `retain_extraction_mode`、`retain_chunk_size`、`entity_labels`、`retain_mission` 等。

通过记忆库配置API配置策略：

```json
{
  "retain_default_strategy": "conversations",
  "retain_strategies": {
    "conversations": {
      "retain_extraction_mode": "concise",
      "retain_chunk_size": 3000
    },
    "documents": {
      "retain_extraction_mode": "verbatim",
      "retain_chunk_size": 800
    }
  }
}
```

然后指定每个记忆存储调用的策略：

```python
#使用默认策略（“对话”）
client.retain(bank_id, items=[{"content": "Alice 今天加入团队"}])

#使用该项目的文档策略
client.retain(bank_id, items=[{"content": "...文档文本..."}], strategy="documents")
```

如果未指定`strategy`，则使用`retain_default_strategy`。如果两者均未设置，则直接应用记忆库/全局配置。批次中的每个项目还可以携带自己的 `strategy` 字段，以进行细粒度控制。


## TypeScript Deno 兼容性 {#typescript-deno-compatibility}

TypeScript 客户端 (`hindsight-client`) 现在可以在 Deno 环境中运行。该构建已从 `tsc` 迁移到 `tsup`，生成具有适当 `exports` 字段的双 CJS + ESM 输出。 AI SDK 和聊天集成在同一次更新。

无需安装 - 直接通过 `npm:` 说明符导入：

```typescript
import { HindsightClient } from "npm:@vectorize-io/hindsight-client";
```

导入路径和API在其他方面保持不变。如果您要将现有项目从 Node.js 迁移到 Deno，则无需更改代码。

## 其他更新 {#other-updates}

**改进**
- 本地重排序器性能：FP16 推理 (`HINDSIGHT_API_RERANKER_LOCAL_FP16=true`) 和长度排序桶批处理 (`HINDSIGHT_API_RERANKER_LOCAL_BUCKET_BATCHING=true`) 现在可作为选择加入标志使用。两者都默认关闭以保留现有行为。 FP16有利于GPU/MPS硬件；桶批处理减少了填充开销，并使基准测试速度提高了 36-54%。还修复了 Transformers 5.x 下的 XLM-RoBERTa 模型加载问题。

**错误修复**
- 当整合LLM调用失败时，防止静默记忆丢失。以前，用尽所有重试的批次会被标记为合并，并从未来的运行中永久排除 - 默默地丢失这些记忆。现在：批处理被分成两半并递归重试到单个项目（恢复大多数暂时性故障）；仅在新的 `consolidation_failed_at` 列中跟踪所有重试仍失败的单个项目。新的API端点`POST /v1/default/banks/{bank_id}/consolidation/recover`重置失败的记忆，以便在下一次集成运行时拾取它们。
- 修复了Docker控制平面启动，以在构造API URL时尊重`HINDSIGHT_CP_HOSTNAME`。
- 数据库清理迁移会删除孤立的观察记忆单元（在 0.4.18 中修复文档删除级联之前留下的行），以防止现有安装上出现不一致的记忆状态。
