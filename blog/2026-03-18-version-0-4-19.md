Hindsight 0.4.19 新增了 Agno 和 Hermes Agent 集成、三种新的 Retain（存入）提取模式及具名的单次调用策略、TypeScript 客户端对 Deno 的支持，以及一种用于恢复观测整合失败的机制。

<!-- truncate -->

- [**Agno 集成**](#agno-integration)：通过原生工具包为 Agno 智能体添加持久记忆。
- [**Hermes Agent 集成**](#hermes-agent-integration)：通过零配置插件为 Hermes 智能体提供长期记忆。
- [**新的 Retain 模式**](#new-retain-modes)：为混合内容的记忆库使用 `verbatim`、`chunks` 和具名策略。
- [**TypeScript 对 Deno 的兼容性**](#typescript-deno-compatibility)：在 Deno 环境中使用 TypeScript 客户端。

## Agno 集成 {#agno-integration}

`hindsight-agno` 是一个新的集成包，它使用 Hindsight 的原生 Toolkit 模式为 [Agno](https://github.com/agno-agi/agno) 智能体添加持久记忆。这与 Agno 内置 `Mem0Tools` 使用的是同一种模式。

```bash
pip install hindsight-agno
```

将 `HindsightTools` 直接传入智能体的 `tools` 列表：

```python
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from hindsight_agno import HindsightTools

agent = Agent(
    model=OpenAIChat(id="gpt-4o-mini"),
    tools=[HindsightTools(
        bank_id="user-123",
        hindsight_api_url="http://localhost:8888",
    )],
)

agent.print_response("Remember that I prefer dark mode")
agent.print_response("What are my preferences?")
```

该工具包会注册三个可供智能体调用的工具：`retain_memory`（存入）、`recall_memory`（搜索）和 `reflect_on_memory`（综合生成）。您可以通过切换 `enable_retain`、`enable_recall` 和 `enable_reflect`，按需启用其中任意组合。

**每位用户的记忆库隔离**是内置功能。如果不传入 `bank_id`，工具包会自动从 `RunContext.user_id` 解析记忆库 ID，因此每位用户都会获得独立的记忆库，无需额外代码。对于更复杂的路由方式，也支持自定义的 `bank_resolver` 可调用对象：

```python
tools=[HindsightTools(bank_resolver=lambda ctx: f"team-{ctx.user_id}")]
```

**记忆指令**可以在启动时预先召回相关上下文，并将其注入智能体的系统提示中。这样，智能体每次开始对话时，相关记忆就已经载入：

```python
from hindsight_agno import HindsightTools, memory_instructions

agent = Agent(
    model=OpenAIChat(id="gpt-4o-mini"),
    tools=[HindsightTools(bank_id="user-123", hindsight_api_url="http://localhost:8888")],
    instructions=[memory_instructions(
        bank_id="user-123",
        hindsight_api_url="http://localhost:8888",
    )],
)
```

完整 API 参考请参阅 [Agno 集成文档](/sdks/integrations/agno)。

## Hermes Agent 集成 {#hermes-agent-integration}

`hindsight-hermes` 是面向 [Hermes Agent](https://github.com/NousResearch/hermes-agent)（NousResearch）的新插件包。它使用 Hermes 的插件发现系统，无需更改代码，并在 `[hindsight]` 工具集中注册三个工具。

```bash
uv pip install hindsight-hermes --python $HOME/.hermes/hermes-agent/venv/bin/python
```

设置环境变量并启动 Hermes：

```bash
export HINDSIGHT_API_URL=http://localhost:8888
export HINDSIGHT_BANK_ID=my-agent
hermes
```

输入 `/tools`，确认插件已加载：

```
[hindsight]
  * hindsight_recall     - Search long-term memory for relevant information.
  * hindsight_reflect    - Synthesize a thoughtful answer from long-term memories.
  * hindsight_retain     - Store information to long-term memory for later retrieval.
```

Hermes 自带的记忆存储会将内容写入本地文件。由于 LLM 会倾向于使用自己最熟悉的记忆存储，请关闭 Hermes 的内置存储，让它改用 Hindsight：

```bash
hermes config set memory.memory_enabled false        # MEMORY.md
hermes config set memory.user_profile_enabled false  # USER.md (optional)
```

如果既未设置 `HINDSIGHT_API_URL`，也未设置 `HINDSIGHT_API_KEY`，插件会静默跳过注册，Hermes 仍会正常启动。

设置说明和故障排查请参阅 [Hermes 集成文档](/sdks/integrations/hermes)。

## 新的 Retain 模式 {#new-retain-modes}

`retain_extraction_mode` 新增三种模式，让您可以控制每份摄取文档需要多少 LLM 处理，从完整提取到完全不使用 LLM。

### `verbatim` — 保留原文，仅提取元数据 {#verbatim--preserve-original-text-extract-metadata-only}

在默认的 `concise` 模式下，LLM 会将每个文本分块改写为精简的提取事实。`verbatim` 模式会跳过改写步骤：每个文本分块都按源文原样存储，每个分块对应一条记忆。LLM 仍会运行，但只用于提取实体、时间信息和地点，不会改述内容。事实文本就是原始分块的逐字内容。

当 RAG 式索引或基准测试要求保留源文措辞时，这种模式很有用；如果下游系统需要在召回结果中显示准确的原文，也可以使用它。

```bash
HINDSIGHT_API_RETAIN_EXTRACTION_MODE=verbatim
```

### `chunks` — LLM 成本为零 {#chunks--zero-llm-cost}

`chunks` 模式会完全跳过 LLM。文本分块原样存储，不提取实体，也不建立时间索引；系统只会生成用于语义检索的嵌入向量。通过 `RetainContent.entities` 传入的实体会直接使用。这是速度最快、成本最低的 Retain 模式；当摄取速度和成本比结构化元数据更重要时，可以使用它。

```bash
HINDSIGHT_API_RETAIN_EXTRACTION_MODE=chunks
```

### 具名 Retain 策略 — 在一个记忆库中混合多种内容 {#named-retain-strategies--mix-content-types-in-one-bank}

具名策略允许您在同一个记忆库中配置多个提取配置，并在调用 Retain 时选择所用策略。策略可以覆盖任意分层配置字段，包括 `retain_extraction_mode`、`retain_chunk_size`、`entity_labels`、`retain_mission` 等。

通过记忆库配置 API 设置策略：

```json
{
  "retain_default_strategy": "conversations",
  "retain_strategies": {
    "conversations": {
      "retain_extraction_mode": "concise",
      "retain_chunk_size": 3000
    },
    "documents": {
      "retain_extraction_mode": "verbatim",
      "retain_chunk_size": 800
    }
  }
}
```

然后在每次 Retain 调用中指定策略：

```python
# 使用默认策略（“conversations”）
client.retain(bank_id, items=[{"content": "Alice joined the team today"}])

# 为此条目使用文档策略
client.retain(bank_id, items=[{"content": "...document text..."}], strategy="documents")
```

如果未指定 `strategy`，则使用 `retain_default_strategy`。如果两者都未设置，则直接应用记忆库或全局配置。批次中的每个条目也可以携带自己的 `strategy` 字段，以便进行更精细的控制。


## TypeScript 对 Deno 的兼容性 {#typescript-deno-compatibility}

TypeScript 客户端（`hindsight-client`）现在可在 Deno 环境中运行。构建工具已从 `tsc` 迁移到 `tsup`，生成兼容 CJS 和 ESM 的双格式输出，并提供正确的 `exports` 字段。AI SDK 和聊天集成也在此次改动中更新。

无需安装，直接通过 `npm:` 说明符导入：

```typescript
import { HindsightClient } from "npm:@vectorize-io/hindsight-client";
```

除此之外，导入路径和 API 均保持不变。将现有项目从 Node.js 迁移到 Deno 时，无需修改代码。

## 其他更新 {#other-updates}

**改进**
- 本地重排序模型性能：现在可选择启用 FP16 推理（`HINDSIGHT_API_RERANKER_LOCAL_FP16=true`）和按长度排序的分桶批处理（`HINDSIGHT_API_RERANKER_LOCAL_BUCKET_BATCHING=true`）。这两个标志默认都关闭，以保持现有行为。FP16 对 GPU/MPS 硬件有益；分桶批处理可减少填充开销，在基准测试中提速 36–54%。此外，还修复了 Transformers 5.x 下加载 XLM-RoBERTa 模型的问题。

**错误修复**
- 修复了观测整合 LLM 调用失败时可能导致记忆静默丢失的问题。此前，重试次数耗尽的批次会被标记为已整合，并永久排除在后续运行之外，导致其中的记忆悄无声息地丢失。现在，系统会将批次拆分为两半并递归重试，直至单个条目，从而恢复大多数临时性故障。所有重试后仍失败的单个条目，则会通过新增的 `consolidation_failed_at` 列进行跟踪。新的 API 端点 `POST /v1/default/banks/{bank_id}/consolidation/recover` 会重置失败记忆的状态，使其在下一次观测整合运行时重新进入处理流程。
- 修复了 Docker 控制台启动时构造 API URL 未遵循 `HINDSIGHT_CP_HOSTNAME` 设置的问题。
- 数据库清理迁移会移除孤立的观测记忆单元。这些行是在 0.4.18 修复文档删除级联之前遗留下来的；清理它们可防止现有安装中的记忆状态不一致。
