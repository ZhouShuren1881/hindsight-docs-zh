Hindsight 0.4.22 主要是一个错误修复版本，修复了跨提供商、集成和记忆召回管道的问题。它还添加了心智模型触发标签过滤，并通过API和控制平面公开文档元数据。

<!-- truncate -->

- [**心智模型标签过滤**](#mental-model-tag-filtering)：通过`tags_match`和`tag_groups`控制心智模型刷新期间记忆的过滤方式。
- [**文档元数据API**](#document-metadata-api)：保留的文档元数据现在在列表/获取端点和控制平面 UI 中公开。

## 心智模型标签过滤 {#mental-model-tag-filtering}

刷新带有标签的心智模型时，Hindsight之前硬编码了`all_strict`标签匹配，这会默默地从刷新中排除所有未标记的记忆。 心智模型触发器现在支持`tags_match`和`tag_groups`字段，让您可以明确控制刷新期间如何过滤记忆。

例如，您可以使用`any`匹配将未标记的记忆与标记的记忆一起包含在内，或者为复杂的过滤逻辑定义标记组。控制平面 UI 为这些新字段添加了相应的下拉列表和输入。

没有这些字段的现有心智模型保留之前的`all_strict`行为 - 无需迁移。

## 文档元数据API {#document-metadata-api}

`retain`端点始终接受`metadata`字典，但该数据从未通过API返回。此版本在列表和获取文档端点中正确公开`document_metadata`，并将其显示在控制平面文档表和详细信息面板中。

这对于在摄取时标记文档的任何工作流程都很有用 - 例如，通过源系统、用户或会话 ID。

## 其他更新 {#other-updates}

**改进**
- 定制LLM参数通过`HINDSIGHT_API_LLM_EXTRA_BODY`— 任意传递JSON至`extra_body`每个OpenAI兼容API调用，对于 vLLM 和自定义模型服务器很有用。*（@emirhan-gazi.贡献）*
- Codex集成现在保留结构化工具调用（`function_call`、`local_shell_call`、`web_search_call`等）作为JSON内容块，默认启用。
- API 响应现在包含一个 `X-Ignored-Params` 标头，以在未知请求参数被静默忽略时发出警告。
- LiteLLM嵌入支持可选的输出维度`HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_OUTPUT_DIMENSIONS`。*（@bullbo.贡献）*
- ZeroEntropy 重排序器现在支持自托管部署的可配置基本 URL。*（@iskhakovt.贡献）*
- 体验事实分类现在可以正确地将第一人称智能体操作（代码更改、调试、发现）分类为`experience`事实而不是`world`事实，从而提高编码智能体和代理工作流程的记忆精度。
- LLM 提供程序初始化重构为使用具有适当配置常量的集中式 `from_env()` 模式。
- 13 以前未记录的配置字段现在已记录（Gemini 安全设置、记忆存储批量令牌、webhook 设置、审核日志设置等）。

**错误修复**
- Azure 上的 Cohere 重排序器AIFoundry 端点不再遇到来自双路径 URL 的 404 错误 - 当自定义时直接使用 httpx`base_url`已配置。  当加载太多内置工具时，*（@kagura-agent.贡献）*
- Claude CodeLLM提供商不再遭受  当加载太多内置工具时MCP工具延迟 - 内置工具现在被禁用，因此MCP工具急切加载。*（@mkremnev.贡献）*
- 记忆召回端点不再从响应中删除元数据。
- Codex 集成在升级时合并新设置，而不是覆盖现有配置。
- ​​LlamaIndex 集成修复了 `document_id` 处理、记忆 API 和 ReAct 跟踪格式。
- OpenClaw 将大量初始化推迟到 `service.start()` 以避免 CLI 速度变慢。
- Gemini `thought_signature`。 现在，对于 3.1+ 工具调用，可以从正确的对象中读取
