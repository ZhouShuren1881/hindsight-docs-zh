Hindsight 0.4.22 主要是一个错误修复版本，修复了多个服务提供方、集成和召回流程中的问题。此版本还为心智模型触发器增加了标签过滤，并通过 API 和控制台公开文档元数据。

<!-- truncate -->

- [**心智模型标签过滤**](#mental-model-tag-filtering)：使用 `tags_match` 和 `tag_groups` 控制心智模型刷新期间如何过滤记忆。
- [**文档元数据 API**](#document-metadata-api)：现在可通过列表和获取端点以及控制台 UI 查看存入时保留的文档元数据。

## 心智模型标签过滤 {#mental-model-tag-filtering}

此前，使用标签刷新心智模型时，Hindsight 会将标签匹配方式硬编码为 `all_strict`，因此所有未标记的记忆都会在刷新时被静默排除。现在，心智模型触发器支持 `tags_match` 和 `tag_groups` 字段，让你可以明确控制刷新期间如何过滤记忆。

例如，可以使用 `any` 匹配方式，将未标记的记忆与已标记的记忆一并纳入；也可以定义标签组，实现复杂的过滤逻辑。控制台 UI 也为这些新字段添加了对应的下拉菜单和输入项。

不含这些字段的现有心智模型会继续采用原先的 `all_strict` 行为，无需迁移。

## 文档元数据 API {#document-metadata-api}

`retain` 端点一直接受 `metadata` 字典，但此前 API 从未返回这些数据。此版本会在文档列表和获取端点中正确公开 `document_metadata`，并在控制台的文档表格和详情面板中显示该字段。

这对任何在摄取时为文档添加标签的工作流都很有用，例如使用来源系统、用户或会话 ID 添加标签。

## 其他更新 {#other-updates}

**改进**

- 通过 `HINDSIGHT_API_LLM_EXTRA_BODY` 设置自定义 LLM 参数：每次 OpenAI 兼容 API 调用时，都会将任意 JSON 传入 `extra_body`，这对 vLLM 和自定义模型服务器很有用。（由 @emirhan-gazi 贡献。）
- Codex 集成现在会将结构化工具调用（`function_call`、`local_shell_call`、`web_search_call` 等）作为 JSON 内容块存入，且默认启用。
- API 响应现在包含 `X-Ignored-Params` 标头；当未知请求参数被静默忽略时，该标头会发出警告。
- LiteLLM 嵌入现在支持通过 `HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_OUTPUT_DIMENSIONS` 设置可选的输出维度。（由 @bullbo 贡献。）
- ZeroEntropy 重排序模型现在支持为自托管部署配置基础 URL。（由 @iskhakovt 贡献。）
- 经历事实分类现在可以正确地将智能体以第一人称执行的操作（代码更改、调试和发现）归类为 `experience` 事实，而不是 `world` 事实，从而提高编程智能体和智能体工作流的召回准确率。
- LLM 服务提供方的初始化逻辑已重构，改为采用集中式 `from_env()` 模式，并使用适当的配置常量。
- 现在为 13 个此前未记录的配置字段补充了文档，包括 Gemini 安全设置、Retain 批次 token 数、Webhook 设置、审计日志设置等。

**错误修复**

- Azure AI Foundry 端点上的 Cohere 重排序模型不再因双路径 URL 返回 404；配置了自定义 `base_url` 时，现在会直接使用 httpx。（由 @kagura-agent 贡献。）
- 当加载过多内置工具时，Claude Code 的 LLM 服务提供方不再出现 MCP 工具延迟加载的问题：现在会禁用内置工具，使 MCP 工具能够及时加载。（由 @mkremnev 贡献。）
- Recall 端点不再从响应中丢弃元数据。
- Codex 集成在升级时会合并新设置，而不是覆盖现有配置。
- LlamaIndex 集成修复了 `document_id` 处理、记忆 API 和 ReAct 跟踪格式方面的问题。
- OpenClaw 将耗时较多的初始化推迟到 `service.start()`，以避免 CLI 变慢。
- 对于 3.1 及更高版本的工具调用，Gemini 现在会从正确的对象中读取 `thought_signature`。
