Hindsight 0.5.3 专注于多租户公平性和运营弹性。新的整合回合限制防止单个记忆库独占工作槽，心智模型获得更智能的基于增量的刷新，OpenAI智能体SDK获得一流的支持，一批修复强化了文件记忆库、迁移路径和GPU重排序。

<!-- truncate -->

- [**整合回合限制**](#consolidation-round-limit)：每轮限制记忆，这样就不会出现单个记忆库占用工人的情况。
- [**OpenAI智能体SDK集成**](#openai-agents-sdk-integration)：适用于OpenAI智能体SDK的一流记忆工具。
- [**心智模型Delta刷新**](#mental-model-delta-refresh)：较小的结构化更新，而不是完全重写。
- [**CLI 连接配置文件**](#cli-connection-profiles)：在具有命名配置文件的环境之间切换。
- [**工人公平性和可靠性**](#worker-fairness--reliability)：租户公平批量声明、幂等任务提交和扩展驱动的重新排队。
- [**可靠性修复**](#reliability-fixes)：迁移链、GPU崩溃、Ollama、文件记忆存储等等。

## 整合回合限制 {#consolidation-round-limit}

当记忆库有数千个未整合的记忆时（例如，在批量摄取后），整合作业可能会占用其工作槽数分钟，从而导致其他记忆库挨饿。新的 `HINDSIGHT_API_CONSOLIDATION_MAX_MEMORIES_PER_ROUND` 设置（默认值：100）限制了单轮整合将处理的记忆数量。当达到限制时，作业将让出其位置并重新排队，以便轮到其他记忆库。 心智模型的更新推迟到最后一轮，以避免重复工作。

该设置可通过配置API对每个记忆库进行配置，因此高优先级记忆库可以无限运行（`0`），而共享部署则保持默认上限。

## OpenAI智能体SDK集成 {#openai-agents-sdk-integration}

新的`hindsight-openai-agents`包提供了`FunctionTool`记忆存储、记忆召回和回忆的实例，可直接插入OpenAI智能体SDK`Agent`。使用`configure()`配置一次，在任何地方创建工具，SDK的异步运行时处理其余的事情。开箱即用地支持选择性工具包含、基于标签的范围界定和全局配置。

```python
from hindsight_openai_agents import configure, create_tools

configure(base_url="http://localhost:8888", bank_id="my-bank")
tools = create_tools()
agent = Agent(name="assistant", tools=tools)
```

## 心智模型Delta刷新 {#mental-model-delta-refresh}

心智模型刷新现在使用结构化增量操作（插入、更新、删除、重新排序部分），而不是从头开始重新生成整个文档。这意味着更小、更便宜的 LLM 调用，观察支持的模型中更少的流失，以及更清晰的历史轨迹显示到底发生了什么变化以及原因。控制平面中的 UI 也已更新，以显示陈旧信号和每次刷新历史快照。

## CLI 连接配置文件 {#cli-connection-profiles}

CLI 现在通过`-p`/`--profile` 支持命名连接配置文件。使用不同的基本 URL、API 密钥和默认记忆库在 `~/.hindsight/profiles.toml` 中定义配置文件，然后使用单个标志在本地、暂存和生产之间切换。不再需要处理环境变量。

## 工人公平性和可靠性 {#worker-fairness--reliability}

三个变化改善了工人分配和处理任务的方式：

- **每租户公平轮换。**`claim_batch`现在在租户架构中循环轮换，因此即使在负载不平衡的情况下，也不会出现任何单个租户垄断工作插槽的情况。
- ​​**幂等任务提交。** `submit_task` 优雅地处理已设置有效负载的情况，防止并发调用者重复或无效提交。
- **扩展驱动的重新排队。** 新的 `DeferOperation` 异常允许扩展显式请求任务重新排队而不是失败，这对于速率限制回退或依赖等待模式很有用。

## 可靠性修复 {#reliability-fixes}

- **迁移链已恢复。** 从 v0.4.22 升级到 v0.5.x 现在遵循正确的迁移路径，无需手动干预。
- **Apple Metal GPU 崩溃。** jina-mlx 重排序器序列化 Metal GPU 操作以防止 SIGSEGV 在 macOS 上崩溃。
- **Ollama思考模式。** Native Ollama 调用现在显式禁用“思考”模式，修复在输出中包含推理跟踪的响应。
- **TEI 重排序器超时。** TEI 重排序器超时现在可配置 (`HINDSIGHT_API_RERANKER_TEI_HTTP_TIMEOUT`)，在触发时会显示更好的错误消息。
- **文件记忆存储。** 修复了上传失败和孤立保留，包括正确处理文件记忆存储API中的`timestamp`字段。
- **孤儿观察。** 当源记忆在运行中被删除时，整合不再创建孤儿观察。
- **​​心智模型 max_tokens。** 配置的`max_tokens` 设置现在可以在心智模型刷新期间正确转发。
- **控制平面记忆库ID。** 记忆库 具有特殊字符的 ID 现在可以在 URL 中端到端正确编码。
- **LLM 重试默认值。** 默认 LLM 最大重试次数从 10 次减少到 3 次，以避免提供程序发生故障时出现长时间延迟。
- **每个记忆库的记忆召回预算。** 记忆召回思维预算映射现在可根据记忆库进行配置，以实现细粒度的成本控制。
- **整合深入分析。** 现在可以通过控制平面中的向下钻取来查看失败的整合计数。
- **JSON 记录租户字段。** JSON 日志现在包含租户标识符并支持可配置的字段白名单。
