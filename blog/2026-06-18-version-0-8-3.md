Hindsight 0.8.3 在 [0.8.2](/blog/2026/06/12/version-0-8-2) 的基础上，增加了检查和调整记忆内容的新方式：**在存入前预览事实提取结果**、**通过 OCR 从文档中提取文本**，并提升基于时间和标签的查询的**检索效果**。此外，本版本还新增了用于监控异步工作的运维指标，并修复了一个会影响大型文档摄取的**存入数据完整性问题**。**摄取大型文档的用户应升级。**

<!-- truncate -->

- [**试运行事实提取**](#dry-run-fact-extraction)：预览一段内容会提取出哪些事实，而不存储任何内容。
- [**文档 OCR**](#document-ocr)：基于 MarkItDown 的可选文档文本提取功能。
- [**检索效果提升**](#sharper-retrieval)：改进中文时间查询、精确标签匹配和近期性评分。
- [**运维可见性**](#operational-visibility)：新增异步队列和观测整合积压的监控指标，并支持并行执行租户迁移。
- [**存入数据完整性修复**](#retain-data-integrity-fix)：说明升级的原因。

## 试运行事实提取 {#dry-run-fact-extraction}

新增的试运行提取端点可以让你在将内容存入记忆库之前，准确查看它会产生哪些事实。此操作不会持久化任何内容；端点会返回提取出的事实供预览，让你无需写入临时记忆或事后清理，就能调整提示、任务说明和输入。空内容或仅含空白字符的输入会在处理开始前被拒绝。保护真实 Retain（存入）调用的同一项操作预检查也会在这里执行，因此预览结果与真实调用的行为一致。

## 文档 OCR {#document-ocr}

Hindsight 0.8.3 新增了**基于 MarkItDown 的可选 OCR**，可以在摄取过程中从文档中提取文本。启用后，以前必须以纯文本形式提供的内容，也可以从格式更丰富的文档中提取，从而扩大了可存入记忆的内容范围。

## 检索效果提升 {#sharper-retrieval}

以下三项改进让记忆的查找和排序效果更好：

- **改进中文时间查询。** 系统能更准确地解析中文时间表达，因此带时间范围的查询可以返回正确的时间窗口。
- **精确标签匹配。** `tags_match=exact` 现已正式开放给 UI、文档和客户端库使用，因此可以要求标签集合完全匹配，而不是采用较宽松的匹配方式。
- **更智能的近期性评分。** 如果缺少主要时间戳，近期性评分现在会回退到有效时间，例如事件被提及的时间或事件结束的时间，从而更合理地排列与时间相关的结果。

## 运维可见性 {#operational-visibility}

自托管部署现在可以更清楚地了解后台工作情况：

- **异步操作和积压量指标。** 新增的瞬时值指标会显示异步操作队列深度和观测整合积压量；异步工作进程的完成路径也加入了操作指标，便于查看记忆处理是否跟得上。
- **并行租户迁移。** 数据库模式迁移现在会在多个租户之间并行运行，缩短多租户部署的迁移时间。
- **Gemini 服务层级。** 新增配置选项，可选择 Gemini 服务层级，以调整请求处理方式。
- **更精简的响应。** API 响应会省略可安全省略的 `null` 字段，从而减小载荷大小。

## 存入数据完整性修复 {#retain-data-integrity-fix}

升级的原因：修复了 Retain（存入）过程中的文本分块逻辑，确保超大型文档在摄取期间拆分为多个子批次后不会丢失内容。如果你需要存入大型文档，请升级到 0.8.3，确保内容不会被遗漏。

本版本中的其他重要修复：

- **LiteLLM 超时。** LiteLLM 调用即使卡住，也不会再无限期阻塞；请求完成时间现在有硬性超时上限。
- **记忆库列表覆盖项。** 列出记忆库时，现在会一致地应用记忆库配置中的性格倾向和任务说明覆盖项。
- **观测整合稳健性。** 即使 LLM 返回单值的 `source_fact_ids`，观测整合也能正常处理，不会失败。
- **延后配额重试。** 模型供应商配额重置后的重试会延后执行，以避免重试风暴。
- **输出清理。** 非结构化输出中的格式错误推理标签和未闭合块会被剥除。
