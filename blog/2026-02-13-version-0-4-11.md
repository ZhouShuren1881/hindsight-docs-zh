## 分层配置 {#hierarchical-configuration}

您现在可以自定义每个记忆库的操作设置。独立配置每个记忆库的保留行为、提取模式和自定义指令。

```bash
#更新特定记忆库的保留设置
curl -X PATCH http://localhost:8888/v1/default/banks/my-bank/config \
  -H "Content-Type: application/json" \
  -d '{
    "updates": {
      "retain_chunk_size": 1000,
      "retain_extraction_mode": "custom",
      "retain_custom_instructions": "保留事件的具体细节，忽略投诉。"
    }
  }'
```

从系统默认值（环境变量）→ 租户覆盖→ 记忆库特定设置进行配置级联。记忆库配置API默认启用，可以使用`HINDSIGHT_API_ENABLE_BANK_CONFIG_API=false`禁用。

类型安全访问可防止在记忆库覆盖存在时意外使用全局默认值。有关分层配置的详细信息，请参见配置指南。

## LiteLLM SDK 积分 {#litellm-sdk-integration}

Hindsight 已通过代理模式支持 LiteLLM（通过 LiteLLM 代理服务器路由请求）。现在，您可以通过 Python SDK 直接使用 LiteLLM 进行嵌入和重排序，无需代理服务器。

这意味着更简单的设置、更低的延迟和更少的基础设施组件，同时仍然获得LiteLLM的好处：统一的可观察性、模型回退和多提供商支持。

```bash
#之前：需要运行单独的LiteLLM代理服务器
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm
export HINDSIGHT_API_EMBEDDINGS_LITELLM_API_BASE=http://localhost:4000

#现在：直接SDK访问，无需代理
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm-sdk
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_API_KEY=your-api-key
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=cohere/embed-english-v3.0
```

对于`HINDSIGHT_API_RERANKER_PROVIDER=litellm-sdk`的重排序也是如此。当需要集中限速和缓存时使用代理模式；使用 SDK 模式可以实现更简单的部署。

## 扩展数据库支持 {#expanded-database-support}

PostgreSQL 搜索支持现在包括：

- **TimescaleDB pg_textsearch** 在时间序列工作负载中实现更好的全文搜索 ([docker-compose 示例](https://github.com/vectorize-io/hindsight/tree/main/docker/docker-compose/pg_textsearch))
- **v和弦和pgvector** 用于灵活的矢量存储选项 ([docker-compose 示例](https://github.com/vectorize-io/hindsight/tree/main/docker/docker-compose/vchord))
- 更好地支持具有自定义配置的外部Postgres实例

无论您是在云端、本地还是在专门环境中运行，这都为您提供了更多部署选项。

## 开放遥测追踪 {#opentelemetry-tracing}

Hindsight 现在为所有操作发出 OpenTelemetry 跟踪，提供跨分布式系统的请求级可观察性。结合实际的 LLM 令牌使用情况（而非估计）以及请求上下文中改进的用户发起的归因，您可以全面了解成本和性能。

对于本地开发，运行 `./scripts/dev/start-monitoring.sh` 启动即用型 Grafana LGTM 堆栈（Loki、Grafana、Tempo、Mimir），并在单个容器中包含预配置的仪表板 - 跟踪、指标和日志。

异步后台操作也得到了正确的归因，从而可以更轻松地跟踪生产中的使用情况和调试问题。

## MCP心智模型 {#mcp-mental-models}

模型上下文协议服务器现在支持完整的心智模型生命周期管理。 通过MCP使用Hindsight的智能体可以创建、读取、更新和删除心智模型——而不仅仅是查询它们。

## 文档技巧 {#documentation-skill}

新的“文档”技能可实现面向文档的功能，从而更轻松地构建可访问文档并进行推理的文档感知助手。

## 反向代理支持 {#reverse-proxy-support}

在反向代理后面或非根路径上运行Hindsight？配置基本路径，Hindsight 正确处理路由，从而更轻松地与现有基础设施集成。

有关即用型设置，请参阅[nginx docker-compose 示例](https://github.com/vectorize-io/hindsight/tree/main/docker/docker-compose/nginx)。

## 其他更新 {#other-updates}

- **舵图改进**：用于嵌入和重排序、PodDisruptionBudgets、每个组件关联性控制和固定 GKE 端口配置的拆分 TEI 部署。
- **修身Docker形象**：Slim 镜像现在包含 tiktoken 以防止下载错误。
