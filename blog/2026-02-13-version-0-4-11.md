Hindsight 0.4.11 聚焦于适用于生产环境的部署，同时提升了灵活性和可观测性。

<!-- truncate -->

- [**分层配置**](#hierarchical-configuration)：按记忆库自定义运行设置。
- [**LiteLLM SDK 集成**](#litellm-sdk-integration)：无需代理服务器即可直接访问 API。
- [**扩展数据库支持**](#expanded-database-support)：支持 TimescaleDB pg_textsearch 和更多 Postgres 扩展。
- [**OpenTelemetry 追踪**](#opentelemetry-tracing)：借助开箱即用的 Grafana 堆栈实现请求级可观测性。
- [**MCP 心智模型**](#mcp-mental-models)：通过模型上下文协议管理完整生命周期。
- [**文档技能**](#documentation-skill)：构建能够理解文档的助手。

## 分层配置 {#hierarchical-configuration}

现在可以按记忆库自定义运行设置，分别配置每个记忆库的保留行为、提取模式和自定义指令。

```bash
# 更新特定记忆库的保留设置
curl -X PATCH http://localhost:8888/v1/default/banks/my-bank/config \
  -H "Content-Type: application/json" \
  -d '{
    "updates": {
      "retain_chunk_size": 1000,
      "retain_extraction_mode": "custom",
      "retain_custom_instructions": "Keep specific details about incidents, ignore complaints."
    }
  }'
```

配置按系统默认值（环境变量）→ 租户覆盖项 → 记忆库级设置的顺序逐层生效。记忆库配置 API 默认启用，也可以通过 `HINDSIGHT_API_ENABLE_BANK_CONFIG_API=false` 禁用。

类型安全的访问方式可防止记忆库存在覆盖项时误用全局默认值。有关分层配置的详细信息，请参阅《配置指南》。

## LiteLLM SDK 集成 {#litellm-sdk-integration}

Hindsight 原先已通过代理模式支持 LiteLLM（即通过 LiteLLM 代理服务器转发请求）。现在还可以通过 Python SDK 直接使用 LiteLLM 来生成嵌入向量和进行重排序，无需代理服务器。

这样可以简化设置、降低延迟并减少基础设施组件，同时仍可使用 LiteLLM 的优势：统一的可观测性、模型回退和多服务提供方支持。

```bash
# 之前：必须单独运行 LiteLLM 代理服务器
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm
export HINDSIGHT_API_EMBEDDINGS_LITELLM_API_BASE=http://localhost:4000

# 现在：直接通过 SDK 访问，无需代理
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm-sdk
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_API_KEY=your-api-key
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=cohere/embed-english-v3.0
```

重排序也可以使用 `HINDSIGHT_API_RERANKER_PROVIDER=litellm-sdk`。需要集中进行速率限制和缓存时使用代理模式；需要简化部署时使用 SDK 模式。

## 扩展数据库支持 {#expanded-database-support}

PostgreSQL 搜索现在支持：

- **TimescaleDB pg_textsearch**：改善时间序列工作负载中的全文检索（[docker-compose 示例](https://github.com/vectorize-io/hindsight/tree/main/docker/docker-compose/pg_textsearch)）
- **vchord 和 pgvector**：提供灵活的向量存储选项（[docker-compose 示例](https://github.com/vectorize-io/hindsight/tree/main/docker/docker-compose/vchord)）
- 更好地支持带自定义配置的外部 Postgres 实例

无论是在云端、本地部署环境还是专用环境中运行，这些支持都为部署提供了更多选择。

## OpenTelemetry 追踪 {#opentelemetry-tracing}

Hindsight 现在会为所有操作生成 OpenTelemetry 追踪记录，从而在分布式系统中提供请求级可观测性。结合实际的 LLM token 用量（而非估算值），以及请求上下文中对用户发起操作更准确的归因，你可以全面了解成本和性能。

本地开发时，运行 `./scripts/dev/start-monitoring.sh` 即可启动开箱即用的 Grafana LGTM 堆栈（Loki、Grafana、Tempo、Mimir）。该堆栈在单个容器中提供预先配置的仪表板，可查看追踪记录、指标和日志。

异步后台操作现在也能正确归因，因此在生产环境中更容易跟踪用量和排查问题。

## MCP 心智模型 {#mcp-mental-models}

模型上下文协议服务器现在支持完整的心智模型生命周期管理。通过 MCP 使用 Hindsight 的智能体可以创建、读取、更新和删除心智模型，而不只是查询它们。

## 文档技能 {#documentation-skill}

新增的 `docs` 技能提供面向文档的能力，让你更容易构建能够访问文档并基于文档进行推理的助手。

## 反向代理支持 {#reverse-proxy-support}

如果在反向代理之后运行 Hindsight，或将其部署在非根路径下，现在可以配置基础路径，由 Hindsight 正确处理路由，便于将其接入现有基础设施。

有关可直接使用的配置，请参阅 [nginx docker-compose 示例](https://github.com/vectorize-io/hindsight/tree/main/docker/docker-compose/nginx)。

## 其他更新 {#other-updates}

- **Helm chart 改进**：将 TEI 部署拆分为嵌入向量和重排序两部分；增加 PodDisruptionBudgets 和逐组件的亲和性控制；修复 GKE 端口配置。
- **精简版 Docker 镜像**：现在包含 tiktoken，可避免下载错误。
