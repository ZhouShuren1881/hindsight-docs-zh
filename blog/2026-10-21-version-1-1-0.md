Hindsight 1.1.0 支持查看每份文档随时间发生的变化，让你更灵活地控制观测的分组方式，新增 LLM、嵌入和重排序服务提供方，并支持下载知识页。本次发布的大部分改动是针对 Retain、整合、Reflect 和工作进程的可靠性改进。**所有使用 1.0.x 的用户都应升级**；完整列表请参阅[变更日志](/changelog)。

<!-- truncate -->

- [**文档变更历史**](#document-change-history)：查看文档发生了哪些变化，以及这些变化导致了哪些观测重建。
- [**观测范围：标签 glob 模式和记忆库默认值**](#observation-scopes-tag-globs-and-bank-defaults)：按事先未知的标签对观测分组，无需更改客户端。
- [**新增服务提供方**](#new-providers)：通过 ChatGPT 登录，使用 NVIDIA NIM、ONNX 重排序器，以及无需静态密钥的 Anthropic 身份认证。
- [**知识页下载**](#knowledge-page-downloads)：将知识页或心智模型保存为 PDF 或 Markdown。
- [**更好的文档搜索**](#better-document-search)：搜索文档文本，并查看匹配的字段。
- [**`prefer_observations` 的记忆库默认值**](#a-bank-default-for-prefer_observations)：为从不传入此标志的客户端去重 Recall 结果。
- [**Helm**](#helm)：Gateway API 路由、修订历史限制和额外清单。

## 文档变更历史 {#document-change-history}

观测会重建，而不会保留版本：编辑、追加、重新存入或标记某项事实为失效时，基于该事实构建的观测会被删除并重新构建。此前，这些变化不会留下记录。现在，每份文档都有变更历史，显示文档发生了什么，以及每次变化导致了哪些重建；你可以据此追查观测为何呈现为当前状态。历史从升级后发生的变化开始记录。

## 观测范围：标签 glob 模式和记忆库默认值 {#observation-scopes-tag-globs-and-bank-defaults}

现在，`observation_scopes` 中的标签可以使用 glob 模式。`[["topic:*"]]` 会根据每条记忆携带的 `topic:` 标签对其分组，适合在提取过程中才添加这些标签、而客户端发送请求时无法预先知道标签值的情况。

记忆库还新增了 `default_observation_scopes`，用于所有未指定范围的 Retain 请求。设置一次后，不同智能体或会话中关于同一主题的记忆就可以整合到一起，无需更改客户端。你也可以通过 `PATCH` 修改现有文档的范围；只有范围实际发生变化的记忆才会重建。

## 新增服务提供方 {#new-providers}

- **ChatGPT**（`HINDSIGHT_API_LLM_PROVIDER=chatgpt`）：通过 Sign in with ChatGPT 使用 ChatGPT 方案。只需运行一次 `hindsight-admin chatgpt login`。
- 用于嵌入和重排序的 **NVIDIA NIM**。
- **ONNX 重排序器**：在进程内运行任何导出为 ONNX 格式的交叉编码器。
- **Anthropic 工作负载身份联合**：将 `HINDSIGHT_API_LLM_API_KEY` 留空，改用云身份进行身份认证，无需静态密钥。

## 更好的文档搜索 {#better-document-search}

此前，文档搜索只匹配文档 ID。现在也会匹配文档文本，并指出匹配了哪些字段，因此控制台的搜索框可以根据文档内容找到文档。搜索结果数量设有上限；如果匹配项超过上限，显示的总数会标明为下限，避免执行缓慢的精确计数。

## `prefer_observations` 的记忆库默认值 {#a-bank-default-for-prefer_observations}

Recall 的 `prefer_observations` 会从返回结果中移除已被某条观测涵盖的原始事实。设置 `HINDSIGHT_API_RECALL_PREFER_OBSERVATIONS`（或记忆库的 `recall_prefer_observations`），即可为从不传入此参数的调用方（例如 MCP 连接器）启用该功能。未进行配置时，此功能仍处于关闭状态；如果请求中提供了该值，则以请求中的值为准。

## Helm {#helm}

该 chart 新增了 Gateway API `HTTPRoute`、可配置的 `revisionHistoryLimit`，以及用于在 Hindsight 旁部署任意额外清单的 `extraObjects`。

---

**一项不兼容变更：** 新记忆库 ID 不能再以下划线 `_` 开头，因为该前缀现已保留。将归档导入新记忆库时，现在也会检查其 ID；如果 ID 无效，会立即返回 400 错误。现有记忆库不受影响。

本次发布还修复了许多正确性和稳定性问题：整合、Retain 和删除操作之间的数据库死锁；失败的文本分块替换已存储文档；LLM 密钥被拒后 Retain 请求仍被重放；大型图谱读取导致 API 卡住；以及工作进程现在能在收到单个 `SIGTERM` 后平稳关闭。当 LLM 并发上限已满时，在线 API 请求现在会优先获得下一个空闲槽位，而不是后台作业；这样一来，即使整合任务积压，Reflect 和同步 Retain 仍能及时响应。失败的 LLM 链成员会进入冷却期，不会在每次请求时都重试；心智模型刷新现在也会使用全局故障切换链。启动时会运行五项数据库迁移，全部都很快；其中一项会清除 `memory_units` 中的占位日期，并通过索引完成，而非扫描整张表。完整列表请参阅[变更日志](/changelog)。
