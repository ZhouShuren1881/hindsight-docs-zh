## 按实体和标签浏览记忆 {#browse-memory-by-entity-and-tag}

记忆的有用程度取决于你检查它的能力。此版本使浏览记忆库变得更加直接：

- **实体时间线。** 选择一个实体——一个人、一家公司、一个项目——然后查看 Hindsight 从第一次提及开始按顺序排列的所有内容。这是检查您的智能体实际了解某人的情况以及时间的最快方法。
- **按链接实体过滤记忆。** 时间线由 API 过滤器支持，因此相同的“有关此实体的所有内容”视图可用于您自己的工具，而不仅仅是控制平面。
- **API版本。
侧栏中的** 控制平面显示它正在与哪个 API 版本通信，因此您始终知道自己所指向的内容。

## 专为扫描而设计的文档桌 {#a-documents-table-built-for-scanning}

文档列表是你去回答“这个记忆库实际上摄取了什么？”的地方。 — 到目前为止，它只允许您通过文档 ID 进行搜索。

- **按标签过滤。** 具有自动完成功能和任意/全部切换功能的标签过滤器，因此您可以将记忆库缩小到您关心的文档，而无需滚动。
- **围绕您扫描的内容组织的表格。** 最后更新时间现在位于文档 ID 下方，标签和元数据共享一列，并且大小和记忆单元计数拥有自己的对齐列。长文档 ID 不再将其他所有内容推离该行。
- **您可以随时清除的过滤器。** 当过滤器没有匹配任何内容时，过滤器工具栏就会消失，这会让你陷入一个空列表而没有出路。
- **​​标签、实体和元数据的一致芯片。** 这三个过去在几乎每个视图中的样式都不同 - 标签在一个地方是蓝色的，在另一个地方是琥珀色的，并且实体与标签无法区分。现在，它们在任何地方都以相同的方式渲染，通过形状而不是颜色来区分，并为实际活动的过滤器保留强调色。

## 每操作模型控制 {#per-operation-model-control}

推理模型在记忆管道的每个阶段并不是同样有用。从护理中提取福利；一个简短的反思答案通常不会，并且为推理token付费纯粹是延迟和成本。

0.8.6 允许您使用 `HINDSIGHT_API_RETAIN_LLM_REASONING_EFFORT`、`HINDSIGHT_API_REFLECT_LLM_REASONING_EFFORT` 和 `HINDSIGHT_API_CONSOLIDATION_LLM_REASONING_EFFORT` 设置推理工作 **每次操作**，而不是为整个部署设置一次。您未设置的任何内容都会遵循全局 `HINDSIGHT_API_LLM_REASONING_EFFORT`，因此现有部署的行为与以前完全相同。

更多管道变得可调整：

- **可配置的嵌入阈值**，因此您可以决定数据的相似程度如何。
- **`store_document_text`每个记忆库
每个记忆库**，因此您可以将原始文档文本保留在特定记忆库之外，同时将其保留在其他地方。

## 以更多信号运行 {#operate-with-more-signal}

- **健康检查可以自我解释。** 当 `/health` 停止时，Hindsight 现在会报告事件循环是否被阻塞或数据库连接池是否已耗尽——这是有帮助的重新启动和颠簸的重新启动之间的区别。
- **​​工作槽设置说明了它们的作用。** 每个类型的插槽设置现在是`HINDSIGHT_API_WORKER_<TYPE>_RESERVED_SLOTS`：它们为操作类型保留有保证的_最小值_，并且从不限制它。旧的 `*_MAX_SLOTS` 名称继续有效并记录弃用警告，因此在您重命名它们之前不会发生任何变化。

## 构建于Hindsight {#build-on-hindsight}

- **扩展拥有的表。** 扩展可以声明记忆库范围的表，Hindsight 自动为每个记忆库提供。
- **TypeScript客户端中的自定义标头**，适用于需要它们的网关和代理。
- **俄罗斯时间周期规则**，用于解析俄语内容中的日期和句点。
- **Python 3.14**。
