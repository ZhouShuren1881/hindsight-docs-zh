## 按实体和标签浏览记忆 {#browse-memory-by-entity-and-tag}

记忆是否有用，取决于你能否检查它们。本次发布让浏览记忆库变得直接得多：

- **实体时间线。** 选择一个实体（例如某个人、公司或项目），即可按顺序查看 Hindsight 记录的所有相关信息，从首次提及开始排列。这是检查智能体实际了解某个人什么信息以及何时了解的最快方式。
- **按关联实体筛选记忆。** 时间线由 API 筛选器提供支持，因此你自己的工具也能查看同一份“关于此实体的所有信息”，不必只在控制台中查看。
- **侧边栏显示 API 版本。** 控制台会显示当前连接的 API 版本，让你随时知道自己连接到了哪个版本。

## 便于浏览的文档表格 {#a-documents-table-built-for-scanning}

文档列表用于回答“这个记忆库实际摄取了哪些内容？”。此前，你只能按文档 ID 搜索。

- **按标签筛选。** 标签筛选器支持自动补全，并可切换任一匹配或全部匹配。你可以直接筛出所需文档，无需逐项滚动浏览。
- **表格按常用信息重新组织。** 最近更新时间现在显示在文档 ID 下方；标签和元数据共用一列；大小和记忆单元数量分别显示在对齐的列中。较长的文档 ID 不会再挤走同一行中的其他内容。
- **筛选器始终可以清除。** 以前，如果筛选结果为空，筛选工具栏就会消失，导致列表空空如也，也无法清除筛选条件。现在可以随时清除筛选器。
- **标签、实体和元数据的芯片样式保持一致。** 过去，这三者在几乎每个视图中的样式都不一样：标签有时是蓝色，有时是琥珀色，实体也与标签难以区分。现在它们在各处都以相同方式呈现，通过形状而非颜色来区分，并且只有筛选器确实处于启用状态时才使用强调色。

## 按操作控制模型 {#per-operation-model-control}

推理模型在记忆处理流程的不同阶段并非同样有用。提取阶段适合仔细推理；简短的 Reflect 答案通常用不着这么做，在这类操作上消耗推理 token 只会增加延迟和成本。

0.8.6 支持**按操作**设置推理强度，而不必在整个部署中统一设置。可分别配置 `HINDSIGHT_API_RETAIN_LLM_REASONING_EFFORT`、`HINDSIGHT_API_REFLECT_LLM_REASONING_EFFORT` 和 `HINDSIGHT_API_CONSOLIDATION_LLM_REASONING_EFFORT`。未单独设置的操作仍使用全局配置 `HINDSIGHT_API_LLM_REASONING_EFFORT`，因此现有部署的行为与以前完全相同。

此外，流程中还有更多部分可以调整：

- **可配置的嵌入阈值**，让你根据自己的数据决定达到什么相似度才算足够相似。
- **按记忆库配置 `store_document_text`**，让你可以选择不在特定记忆库中保存原始文档文本，同时在其他记忆库中继续保存。

## 运维时获取更多信息 {#operate-with-more-signal}

- **健康检查会说明问题所在。** 如果 `/health` 响应停滞，Hindsight 现在会报告是事件循环遭到阻塞，还是数据库连接池已耗尽。了解两者的区别，有助于判断重启能否解决问题，还是只会让系统反复重启却无法恢复。
- **工作进程槽位设置会明确说明作用。** 每种操作类型的槽位设置现在使用 `HINDSIGHT_API_WORKER_<TYPE>_RESERVED_SLOTS`。它们为相应操作类型预留有保障的**最低槽位数**，绝不会限制该类型可使用的槽位数。旧的 `*_MAX_SLOTS` 名称仍然有效，但会记录弃用警告；在你重命名之前，行为不会改变。

## 基于 Hindsight 进行扩展 {#build-on-hindsight}

- **扩展自有表。** 扩展可以声明作用于特定记忆库的表，Hindsight 会自动为每个记忆库配置这些表。
- **TypeScript 客户端支持自定义请求头**，供需要自定义请求头的网关和代理使用。
- **俄语时间表达规则**，用于解析俄语内容中的日期和时间段。
- **支持 Python 3.14。**
