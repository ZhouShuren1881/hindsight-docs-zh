Hindsight 0.4.15 新增了 PydanticAI 集成、观测范围、更丰富的实体标签和多项性能改进，同时还修复了一系列可靠性与稳定性问题。

<!-- truncate -->

- [**PydanticAI 集成**](#pydanticai-integration)：为 PydanticAI 智能体添加持久记忆。
- [**观测范围**](#observation-scopes)：控制事实如何跨不同标签维度整合为观测。
- [**更丰富的实体标签**](#richer-entity-labels)：为实体提取提供可选标签、自由格式值和多值字段。
- [**未设置时间戳**](#timestamp-unset)：存入没有日期的无时间性内容。
- [**性能**](#performance)：提升大型记忆库的召回和存入速度及可扩展性。

## PydanticAI 集成 {#pydanticai-integration}

Hindsight 现已集成 [PydanticAI](https://ai.pydantic.dev/)，只需几行代码即可为任意 PydanticAI 智能体接入持久记忆。

```python
from hindsight_client import Hindsight
from hindsight_pydantic_ai import create_hindsight_tools, memory_instructions
from pydantic_ai import Agent

client = Hindsight(base_url="http://localhost:8888")

agent = Agent(
    "openai:gpt-4o",
    tools=create_hindsight_tools(client=client, bank_id="user-123"),
    instructions=[memory_instructions(client=client, bank_id="user-123")],
)

result = await agent.run("What do you remember about my preferences?")
print(result.output)
```

`create_hindsight_tools` 会在智能体上注册三个异步工具：

- **`hindsight_retain`**：将信息存入长期记忆
- **`hindsight_recall`**：在记忆中搜索相关事实
- **`hindsight_reflect`**：根据已存储的记忆综合推理并生成答案

`memory_instructions` 会在每次运行开始时将召回的上下文作为指令注入，因此即使智能体不显式调用工具，相关历史也始终会出现在它的上下文窗口中。

这两种方式都支持完整的 Hindsight 检索参数集：`budget`、`max_tokens`、`tags`、`recall_tags` 和 `recall_tags_match`，便于精细控制存储和检索的内容。

你也可以全局配置默认值：

```python
from hindsight_pydantic_ai import configure, create_hindsight_tools

configure(
    hindsight_api_url="http://localhost:8888",
    api_key="your-api-key",       # 或设置 HINDSIGHT_API_KEY 环境变量
    budget="mid",                  # 召回预算：low/mid/high
    max_tokens=4096,               # 召回结果的最大 token 数
    tags=["env:prod"],             # 存入记忆时使用的标签
    recall_tags=["scope:global"],  # 用于筛选召回结果的标签
    recall_tags_match="any",       # 标签匹配模式：any/all/any_strict/all_strict
)

# 现在创建工具时无需传入客户端，它会使用全局配置
tools = create_hindsight_tools(bank_id="user-123")
```

完整的快速入门指南请参阅 [PydanticAI 集成文档](/sdks/integrations/pydantic-ai)。

## 观测范围 {#observation-scopes}

观测是 Hindsight 根据原始事实得出的更高层次概括。此前，观测始终会一次性跨所有标签进行整合。现在，你可以用 `observation_scopes` 控制每轮整合的_粒度_。

如果记忆带有多个维度的标签，这项功能就很有用，例如 `student:alice`、`teacher:bob` 和 `session-id:s1`。你可能希望分别针对每位学生、每位教师和每节课生成观测，而不是把这三个维度合并成一条观测。

`observation_scopes` 是在 Retain（存入）请求中按输入项传递的参数。以下示例使用一份课程记录，其标签为 `tags: ["student:alice", "teacher:bob", "session-id:s1"]`。

**`per_tag`**：每个单独的标签各执行一轮整合。这是处理多方内容时最常见的选择。

- 创建的观测：`["student:alice"]` · `["teacher:bob"]` · `["session-id:s1"]`
- _“What does Alice struggle with?”_ 和 _“How does Bob teach?”_ 这类查询可以匹配。
- _“How does Alice perform specifically with Bob?”_ 这类查询无法匹配，因为系统没有为这组标签生成观测。

**`combined`**（默认）：使用全部标签执行一轮整合。

- 创建的观测：`["student:alice", "teacher:bob", "session-id:s1"]`
- 只有标签完全相同的组合可以匹配。单独使用 `["student:alice"]` 这样的标签无法匹配。

**`all_combinations`**：为每个子集各执行一轮整合。3 个标签会执行 7 轮。

- 创建的观测：包括 `per_tag` 的所有范围，以及每一对标签和全部标签组成的范围。

**`custom`**：显式指定标签组列表：

```json
[["student:alice"], ["teacher:bob"], ["teacher:bob", "session-id:s1"]]
```

系统只会为这三组标签生成观测，不会处理其他组合。

整合过程中，各范围彼此完全隔离：在 `["student:alice"]` 范围内整合的记忆绝不会混入带有 `["student:alice", "teacher:bob"]` 标签的观测。

## 更丰富的实体标签 {#richer-entity-labels}

`entity_labels` 是一项新的记忆库配置选项，用于定义受控的 `key:value` 分类标签词汇表。执行 Retain 时，LLM 会从每段内容中提取这些标签，并将其存储为实体。由于标签会成为实体，它们会自动在知识图谱中关联记忆，并提升语义检索和 BM25 检索的效果。

支持三种字段类型：

| 类型 | 行为 |
|------|----------|
| `"value"` | 从固定列表中取一个值 |
| `"multi-values"` | 从固定列表中取一个或多个值 |
| `"text"` | 自由格式字符串（无固定值）|

字段也可以标记为 `optional: true`。如果内容未提供足够信息，LLM 就会跳过这些字段。

```json
{
  "entity_labels": [
    {
      "key": "engagement",
      "description": "Student engagement level during the session",
      "type": "value",
      "optional": true,
      "values": [
        { "value": "active",  "description": "Student is actively participating" },
        { "value": "passive", "description": "Student is listening but not participating" }
      ]
    },
    {
      "key": "pedagogy",
      "description": "Teaching strategies used",
      "type": "multi-values",
      "values": [
        { "value": "scaffolding",          "description": "Breaking complex tasks into smaller steps" },
        { "value": "direct_instruction",   "description": "Explicit explanation by the teacher" },
        { "value": "socratic_questioning", "description": "Guiding through questions rather than answers" }
      ]
    },
    {
      "key": "topic",
      "description": "Specific subject being discussed. Examples: algebra, quadratic equations, geometry.",
      "type": "text",
      "optional": true
    }
  ]
}
```

对于枚举类型（`"value"`、`"multi-values"`），`values` 列表以外的值会被静默丢弃，从而保持词汇表稳定，并让图谱关联更紧密。对于 `"text"` 类型，LLM 可以写入任意字符串；你可以通过 `description` 提供示例和指导。

可通过[记忆库配置 API](/developer/api/memory-banks#entity-labels)设置 `entity_labels`。控制台现已更新，可以清晰显示多值和自由格式标签。

## 未设置时间戳 {#timestamp-unset}

存入文档、书籍等参考资料，或任何没有明确事件日期的内容时，现在可以传入 `timestamp="unset"`，告知 Hindsight 不应为该内容关联实际日期。

```python
# 无时间属性的参考资料
client.retain(
    bank_id="my-bank",
    content="The quick sort algorithm has O(n log n) average-case time complexity.",
    timestamp="unset"
)

# 在同一批次中混合无时间属性和带时间戳的内容
client.retain_batch(
    bank_id="my-bank",
    items=[
        {"content": "Meeting notes...", "timestamp": "2026-03-01T14:00:00Z"},
        {"content": "Company handbook...", "timestamp": "unset"},
    ]
)
```

传入 `"unset"` 后，事实提取提示中会显示 `Event Date: Unknown`，这样模型就能在每条提取出的事实的 `when` 字段中正确返回 `N/A`，而不会把事实锚定到任意日期。

## 性能 {#performance}

此版本针对大型记忆库进行了大量数据库层面的优化，包括改进索引和查询规划、减少锁争用、修复死锁，以及改进连接预热。我们使用最多包含 100,000 条记忆和 100 million 个实体连接的记忆库进行了基准测试：

- **Retain**：在大规模场景下，速度最高提升 **10 倍**。
- **Recall**：在超大规模场景下，效果最高提升 **约 20 倍**；图检索器和时间检索器的提升最明显。

无需进行任何配置。

## 其他更新 {#other-updates}

**功能**
- **OpenClaw 自动存入**：OpenClaw 现在每隔 N 轮存入最近的 `N*2 + 4` 条消息（默认 N=10），而不是每轮都存入。滑动窗口可确保对话上下文不会在窗口边界处丢失，同时大幅减少每个会话的 LLM 调用次数。可在插件配置中通过 `retainEveryNTurns` 进行设置。
- **Gemini/Vertex AI 安全设置**：现在可以配置 Gemini 和 Vertex AI 的 LLM 调用安全设置。对于需要放宽或收紧 LLM 调用内容过滤的部署，这项功能很有用。
- **文档标签筛选**：文档列表 API 现在支持按标签筛选，因此可以更方便地查询哪些文档是在给定标签下存入的。
- **扩展钩子**：新增了自定义根路由行为和添加自定义错误标头的钩子，适用于需要在传输层拦截请求或为响应添加信息的部署。

**错误修复**
- 修复大型记忆库上 Reflect（反思）因 `context_length_exceeded` 失败的问题，方法是正确截断上下文窗口。
- 修复僵尸处理任务重试后导致的观测整合死锁。
- 修复控制台中的观测数量始终显示为 0 的问题。
- 修复 `claude_code` LLM 提供方相关的 JSON 序列化问题和日志异常传播问题。
- 修复 ZeroEntropy 重排序端点 URL。
- 修复 MCP `async_processing` 参数处理。
- 增加记忆库范围的请求验证，防止跨记忆库操作。
- 修复 TypeScript SDK 在 `includeEntities` 为 `false` 时发送 `null`（而不是 `undefined`）的问题。
