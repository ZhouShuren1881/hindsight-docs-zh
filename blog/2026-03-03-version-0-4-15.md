Hindsight 0.4.15 添加了 PydanticAI 集成、观察范围、更丰富的实体标签和多项性能改进，以及一组可靠性和稳定性修复。

- [**PydanticAI 整合**](#pydanticai-integration)：为PydanticAI智能体添加持久记忆。
- [**观察范围**](#observation-scopes)：控制事实如何跨标签维度整合到观察中。
- [**更丰富的实体标签**](#richer-entity-labels)：用于实体提取的可选标签、自由格式值和多值字段。

- [**性能**](#performance)：记忆召回和记忆存储对于大型记忆库来说更快、更可扩展。

## PydanticAI 整合 {#pydanticai-integration}

Hindsight现已与[PydanticAI](https://ai.pydantic.dev/)集成，让您只需几行代码即可将持久记忆附加到任何PydanticAI智能体上。

```python
from hindsight_client import Hindsight
from hindsight_pydantic_ai import create_hindsight_tools, memory_instructions
from pydantic_ai import Agent

client = Hindsight(base_url="http://localhost:8888")

agent = Agent(
    "openai:gpt-4o",
    tools=create_hindsight_tools(client=client, bank_id="user-123"),
    instructions=[memory_instructions(client=client, bank_id="user-123")],
)

result = await agent.run("关于我的喜好，你还记得什么？")
print(result.output)
```

`create_hindsight_tools` 在智能体上注册了三个异步工具：

- **`hindsight_retain`** — 将信息存储到长期记忆中
- **`hindsight_recall`** — 在记忆中搜索相关事实
- **`hindsight_reflect`** — 从存储的记忆中合成一个合理的答案

`memory_instructions` 在每次运行开始时将调用的上下文作为指令注入，因此智能体始终在其上下文窗口中具有相关历史记录，而无需显式调用工具。

​​两者都接受完整的Hindsight检索参数—`budget`、`max_tokens`、`tags`、`recall_tags`和`recall_tags_match`—用于对存储和检索的内容进行细粒度控制。

您还可以全局配置默认值：

```python
from hindsight_pydantic_ai import configure, create_hindsight_tools

configure(
    hindsight_api_url="http://localhost:8888",
    api_key="your-api-key",       # Or set HINDSIGHT_API_KEY env var
    budget="mid",                  # Recall budget: low/mid/high
    max_tokens=4096,               #记忆召回结果的最大令牌数
    tags=["env:prod"],             #存储记忆的标签
    recall_tags=["scope:global"],  #要过滤的标签 记忆召回
    recall_tags_match="any",       # Tag match mode: any/all/any_strict/all_strict
)

#现在创建工具而无需传递客户端 - 使用全局配置
tools = create_hindsight_tools(bank_id="user-123")
```

请参阅 [PydanticAI集成文档](/sdks/integrations/pydantic-ai) 以获得完整的快速入门。

## 观察范围 {#observation-scopes}

观察是Hindsight从原始事实中得出的更高层次的总结。以前，观察总是同时跨所有标签进行整合。现在，您可以使用 `observation_scopes` 控制每个集成过程的_粒度_。

当记忆被跨多个维度标记时（例如，`student:alice`、`teacher:bob` 和 `session-id:s1`），这一点很重要。您可能需要对每个学生、每个老师和每个课程进行独立的观察，而不是对这三者进行一次组合观察。

`observation_scopes` 是在记忆存储请求中传递的每个项目的参数。下面的示例使用通过 `tags: ["student:alice", "teacher:bob", "session-id:s1"]` 保留的课程记录。

**`per_tag`** — 每个单独标签一次整合。多方内容最常见的选择。

- 创建观察：`["student:alice"]` · `["teacher:bob"]` · `["session-id:s1"]`
- 诸如 _“爱丽丝遇到什么困难？”_ 和 _“鲍勃如何教学？”_ 之类的查询匹配。
- 诸如“爱丽丝与鲍勃具体表现如何？”之类的查询不会——没有为该组合构建观察。

**`combined`** *（默认）* — 一次使用所有标签。

- 创建观察：`["student:alice", "teacher:bob", "session-id:s1"]`
- 只有精确的组合才能匹配。像 `["student:alice"]` 这样的单独标签则不然。

**`all_combinations`** — 每个子集一次通过。对于 3 个标签，即 7 次通过。
创建

- 观察：所有`per_tag`范围加上每对和全套。

**`custom`** — 标签集的显式列表：

```json
[["student:alice"], ["teacher:bob"], ["teacher:bob", "session-id:s1"]]
```

仅构建了这三个范围 - 仅此而已。

范围在整合过程中完全隔离——在`["student:alice"]`下整合的记忆永远不会渗透到标记为`["student:alice", "teacher:bob"]`的观察中。

## 更丰富的实体标签 {#richer-entity-labels}

`entity_labels`是一个新的记忆库配置选项，它定义了`key:value`分类标签的受控词汇表。在记忆存储过程中，LLM从每段内容中提取这些标签并将它们存储为实体。由于标签成为实体，它们会自动链接知识图中的记忆，并改善语义和 BM25 检索。

支持三种字段类型：

|类型|行为|
|------|----------|
|`"value"`|固定列表中的单个值|
|`"multi-values"`|固定列表中的一个或多个值|
|`"text"`|自由格式字符串（无固定值）|

字段也可以标记为`optional: true`，因此当内容没有足够的信息时，LLM会跳过它们。

```json
{
  "entity_labels": [
    {
      "key": "engagement",
      "description": "课程期间学生的参与程度",
      "type": "value",
      "optional": true,
      "values": [
        { "value": "active",  "description": "学生积极参与" },
        { "value": "passive", "description": "学生在听但没有参与" }
      ]
    },
    {
      "key": "pedagogy",
      "description": "使用的教学策略",
      "type": "multi-values",
      "values": [
        { "value": "scaffolding",          "description": "将复杂的任务分解为更小的步骤" },
        { "value": "direct_instruction",   "description": "老师的明确讲解" },
        { "value": "socratic_questioning", "description": "通过问题而不是答案进行指导" }
      ]
    },
    {
      "key": "topic",
      "description": "正在讨论的具体主题。例如：代数、二次方程、几何。",
      "type": "text",
      "optional": true
    }
  ]
}
```

对于枚举类型（`"value"`、`"multi-values"`），`values`列表之外的任何内容都会被悄悄删除——词汇保持稳定，图形链接保持紧密。对于`"text"`类型，LLM写入任意字符串；使用`description`提供示例和指导。

通过[记忆库配置API](/developer/api/memory-banks#entity-labels)设置`entity_labels`。控制平面 UI 已更新，可以清晰地显示多值和自由格式标签。

## 时间戳未设置 {#timestamp-unset}

当保留参考资料（文档、书籍或任何没有有意义的事件日期的内容）时，您现在可以通过 `timestamp="unset"` 告诉 Hindsight 没有与内容关联的真实日期。

```python
#永恒的参考内容
client.retain(
    bank_id="my-bank",
    content="快速排序算法的平均时间复杂度为O(n log n)。",
    timestamp="unset"
)

#在单个批次中混合永恒和带有时间戳的内容
client.retain_batch(
    bank_id="my-bank",
    items=[
        {"content": "会议记录...", "timestamp": "2026-03-01T14:00:00Z"},
        {"content": "公司手册...", "timestamp": "unset"},
    ]
)
```

当传递`"unset"`时，事实提取提示会显示`Event Date: Unknown`，允许模型为每个提取事实的`when`字段正确返回`N/A`，而不是将事实锚定到任意日期。

## 性能 {#performance}

此版本包括针对大规模记忆库的重要数据库级工作——更好的索引、改进的查询规划、减少锁争用、死锁修复和连接预热改进。我们以记忆库为基准，拥有多达 10 万条记忆和 1 亿条实体链接：

- **记忆存储**：大规模时可达**快 10 倍**。
- **记忆召回**：在非常大的范围内达到**~20 倍好**，在图和时间检索器中增益最大。

无需配置。

## 其他更新 {#other-updates}

**特点**
- **OpenClaw自动记忆存储**：OpenClaw现在每N轮（默认N=10）而不是每轮保留最后的`N*2 + 4`消息。滑动窗口确保对话上下文永远不会在边界丢失，同时显著减少每个会话的 LLM 调用。在插件配置中使用`retainEveryNTurns`进行配置。
- **Gemini/顶点AI安全设置**：Gemini 和 Vertex AI LLM 调用的安全设置现在可配置。对于需要放宽或加强 LLM 调用内容过滤的部署非常有用。
- **文档标签过滤**：列表文档API现在支持按标签过滤，可以更轻松地查询给定标签下保留了哪些文档。
- **延长挂钩**：用于自定义根路由行为并添加自定义错误标头的新挂钩，适用于需要在传输层拦截请求或装饰响应的部署。

**错误修复**
- 通过正确截断上下文窗口，修复了大型记忆库上`context_length_exceeded`失败的问题。
- 修复了僵尸处理任务后重试导致的整合死锁。
- 修复了控制平面中的观察计数始终显示0的问题。
- 修复了JSON序列化问题以及与`claude_code`LLM提供程序相关的日志记录异常传播。
- 修复了 ZeroEntropy 重新排名端点 URL。
- 修复了MCP`async_processing`参数处理。
- 添加了记忆库范围的请求验证以防止跨记忆库操作。
- 修复了当`includeEntities`为`false`时，TypeScriptSDK发送`null`（不是`undefined`）。
