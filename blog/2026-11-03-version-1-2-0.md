Hindsight 1.2.0 新增对 Hindsight 模型的支持，将 `hs-rerank-1` 设为默认重排序模型，为 Recall（召回）中决策模型保留哪些内容提供更精细的控制，在知识页展示相关图片，并让 LLM 请求视图更易读。现在所有服务提供方的工具调用都通过响应模式进行，大幅提高了 Reflect（反思）在自托管模型上的可靠性。本次发布的大部分工作是针对 Retain（存入）、整合、Reflect、刷新和工作进程的可靠性改进。**所有使用 1.1.x 的用户都应升级**——完整列表请参阅[更新日志](/changelog)。

<!-- truncate -->

- [**Hindsight 模型**](#hindsight-models)：专为智能体记忆构建的决策模型、重排序模型和嵌入模型；`hs-rerank-1` 是新的默认重排序模型。
- [**决策模型召回：剪枝与去重**](#decision-model-recall-prune-and-dedup)：按请求或记忆库移除无关和重复的记忆。
- [**通过响应模式进行工具调用**](#tool-calls-through-a-response-schema)：Reflect 可在忽略强制工具选择的服务器上运行。
- [**知识页中的图片**](#images-on-knowledge-pages)：查看页面证据对应的图片。
- [**改进的 LLM 请求视图**](#a-better-llm-request-view)：保留期限、按小时统计的图表，以及按模型或操作划分的用量。
- [**更多设置**](#more-settings)：视觉调用设置、嵌入请求的额外请求体、默认时区。
- [**Helm**](#helm)：可选的 API 命令、启动探针、部署策略和令牌挂载设置。

## Hindsight 模型 {#hindsight-models}

1.2.0 支持 Hindsight 模型：决策模型 `hs-decide-1-flash` 接管整合、Reflect 和知识页中的小型判断任务，另外还支持 `hs-rerank-1` 和 `hs-embed-1`。这些模型默认未启用，需要先运行 `hindsight-admin cloud login` 并设置 `HINDSIGHT_API_DECISION_MODEL_PROVIDER=hindsight`。所有设置请参阅[决策模型](/developer/decision-models)。

**默认重排序模型发生变化。** 本地和 ONNX 重排序模型现在使用 `hindsight-ai/hs-rerank-1`，替代 `cross-encoder/ms-marco-MiniLM-L-6-v2`。该模型支持八种语言，针对 Hindsight 召回训练，首次启动时会下载。如需在本地提供方继续使用旧模型，请设置 `HINDSIGHT_API_RERANKER_LOCAL_MODEL=cross-encoder/ms-marco-MiniLM-L-6-v2`。

`typesafe` 重排序模型提供方已弃用，推荐使用共享的决策模型。

## 决策模型召回：剪枝与去重 {#decision-model-recall-prune-and-dedup}

决策模型对召回结果重排序时，现在还可以移除无助于回答查询的记忆（`prune`），以及与已返回记忆重复的记忆（`dedup`）。可以针对单次请求（HTTP 和 MCP Recall）启用，也可以通过 `HINDSIGHT_API_RECALL_DECISION_MODEL_PRUNE` 和 `HINDSIGHT_API_RECALL_DECISION_MODEL_DEDUP` 按记忆库启用。决策模型现在还能看到每条记忆的日期，因此对时间敏感的问题排序效果更好。

## 通过响应模式进行工具调用 {#tool-calls-through-a-response-schema}

Reflect 的工具调用现在通过响应模式进行，而不是使用服务提供方原生的工具调用。部分兼容 OpenAI 的服务器（例如使用某些开放模型的 vLLM）接受工具，但不遵从强制工具选择，因此 Reflect 的强制步骤过去经常被跳过。这些服务器遵从响应模式，因此 Reflect 现在在所有服务提供方上的行为一致。

## 知识页中的图片 {#images-on-knowledge-pages}

当知识页的证据来自存入的图片时，控制台现在会在证据旁边展示这些图片。

## 改进的 LLM 请求视图 {#a-better-llm-request-view}

LLM 请求视图现在显示历史记录保留的天数，新增过去 24 小时按小时统计的图表，并按模型或操作划分用量。它现在还会记录嵌入、重排序和决策模型调用，而不只记录 LLM 调用。设置 `HINDSIGHT_API_LLM_TRACE_DELETE_WITH_DOCUMENT=true` 可在删除文档时删除其请求历史；删除记忆库时始终会删除其历史记录。

## 更多设置 {#more-settings}

- **视觉调用**有独立的推理强度、超时、重试和额外请求体设置（`HINDSIGHT_API_VLM_*`）。
- **兼容 OpenAI 的嵌入服务**可以发送额外请求体（`HINDSIGHT_API_EMBEDDINGS_OPENAI_EXTRA_BODY`）。
- **默认时区**（`HINDSIGHT_API_DEFAULT_TIMEZONE`）：没有 UTC 偏移量的 Retain 时间戳按此时区读取。

## Helm {#helm}

Chart 新增可选的 API `command`、`startupProbe`、部署 `strategy`，以及对 `automountServiceAccountToken` 的控制。Docker 和 Helm 在关闭时为 API 提供 60 秒完成正在处理的工作。

---

**破坏性变更：** 不再向任何服务提供方发送原生工具，因此兼容 OpenAI 的服务器必须支持响应模式（结构化输出）。`HINDSIGHT_API_LLM_SUPPORTS_MAX_ITEMS`、`HINDSIGHT_API_LLM_STRUCTURED_OUTPUT_FORCED_TOOL` 和 `HINDSIGHT_API_REFLECT_PROMPT_CACHE_ENABLED` 已移除；请从配置中删除这些设置。对于基于 LiteLLM 的服务提供方（`litellm`、`litellmrouter`、`bedrock`），可设置 `HINDSIGHT_API_LLM_STRUCTURED_OUTPUT_IN_PROMPT=true`，改为在提示中提供模式。
