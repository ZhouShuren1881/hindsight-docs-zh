“开源”和“自托管”被用作同义词，但它们并不是同一个承诺。许多自称为开源的智能体记忆工具仍然期望您建立外部矢量数据库，在其旁边运行图形数据库，或者在生产中实际需要的级别使用信用卡。

如果你选择一个可以自己运行的记忆层，那么这个差距比星星数更重要。这是诚实的版本：每个开源智能体记忆系统的运行实际成本是多少，它们是如何构建的，以及当您测量而不是猜测时它们的得分如何。

<!-- truncate -->

该类别的新手？从[什么是智能体记忆](https://vectorize.io/what-is-agent-memory)开始。这篇文章是[各大框架全面对比](https://vectorize.io/articles/best-ai-agent-memory-systems)的开源剪辑；在这里，我们仅介绍您可以自行托管的系统。

对该类型的公平警告：大多数“最佳开源记忆”综述都是由其中一个供应商发布的，并且方便地将该供应商排名第一。这也是一个人写的。因此，它不是断言获胜者，而是依赖于您可以自己检查的两件事：**发布的基准数据**和**每个系统实际运行需要什么**。

## 如何比较开源智能体记忆 {#how-to-compare-open-source-agent-memory}

五个轴决定这一点，并且只有其中两个显示在登陆页面上：

1. **检索精度**——它是否返回正确的记忆，根据公共基准测量，而不是断言。完整的标题请参见[如何评估智能体记忆系统](/blog/2026/07/31/evaluate-agent-memory-system)。
2. **自托管现实** — 你能用自己的基础设施运行它吗？“你自己的基础设施”包括什么？一个容器，还是一个矢量数据库加一个图数据库加一个队列？
3. **自托管时的功能平等** — 您获得的是整个产品，还是一个将您推向付费云的剥离核心？
4. **执照** — 足够允许实际部署。
5. **建筑** — 向量、图形或混合，以及这对您可以提出的查询意味着什么。

根据您的情况称重它们。审计追踪智能体最关心的是时间建模；精益的自我托管者最关心的是有多少数据库落在他们的操作板上。

简介前的两个诚实的注释。 Hindsight是**不是**这里星级最高的项目； Mem0、Cognee 和 Graphiti 都有更大的社区，这值得一些真正的东西。此表中的每个系统都经过许可，因此“它是开源的”是赌注，而不是差异化因素。重要的区别在于准确性和运行所需的条件。

## 系统，一一 {#the-systems-one-by-one}

### Mem0——最大的社区 {#mem0--the-biggest-community}

Mem0 是 GitHub 上最受欢迎的智能体记忆项目（约 63.0K 颗星），并且受欢迎度复合：更多集成、更多示例、当您遇到困难时更多 Stack Overflow 答案。它确实擅长对话个性化：记忆范围由 `user_id`、`agent_id` 和 `run_id` 组成，因此跨会话回忆一个人的偏好是铺好的道路，您可以从库开始，升级到自托管服务器，或使用托管平台。写入端从回合中提取事实，而不是存储原始记录，这可以防止存储膨胀。

权衡不是关于昼夜准确度差距，而是更多关于您信任的基准和部署形状。 Mem0 发布了强大的 LongMemEval 数据，与该领域的顶尖产品竞争，但 LongMemEval 现在接近饱和：严肃的系统都在 90 年代集群，所以它几乎无法将它们分开。更尖锐的测试是 1000 万个token的 BEAM，其中 Hindsight 是 #1，并且 Mem0 没有发布可比较的结果。在部署时，Mem0 的开源核心默认与嵌入式存储一起运行，尽管生产设置通常会移动到外部矢量数据库，并且最平滑的路径会向托管平台推进。如果社区规模和个性化优先的设计是您的首要任务，那么 Mem0 是显而易见的选择。

### Graphiti / Zep — 时间专家 {#graphiti--zep--the-temporal-specialist}

当*事实何时成立*就是任务核心时，可以选择 Graphiti。它是 Zep 背后的开源引擎，原生建模时间：知识图中的每条边都带有效性元数据，因此能准确回答“第二季度变更前，客户采用什么方案？”。对于合规时间线和审计轨迹，这种时间深度难以匹敌，也是 Graphiti 明显领先的维度。

自助托管的两个注意事项。 **Zep 社区版已于 2025 年弃用**，所以“自托管具有完整功能的 Zep”的免费、开源路径已经消失了——您自托管的是 Graphiti，引擎，而不是整个产品（企业 BYOC 除外）。 Graphiti 通常将其图形存储在外部数据库中（Neo4j 或 FalkorDB，尽管存在嵌入式 FalkorDB lite 模式），因此在大多数部署中，您都会与应用程序一起运行和操作它。

### Letta — 智能体运行时 {#letta--the-agent-runtime}

Letta（以前的 MemGPT）在这里很奇怪，以一种有用的方式：它并不是真正的嵌入式记忆*层*，它是一个内置记忆的**智能体运行时**。如果你想要整个框架——智能体循环、工具使用和记忆作为一个固执己见的系统——Letta 是一个强大的、可自我托管的选择，具有真正的研究血统。它的记忆模型值得了解：智能体保持可编辑的**记忆块**（智能体重写自身的一个小的、始终处于上下文中的核心）加上长尾的**档案记忆**，这是直接来自MemGPT论文的想法。如果您已经拥有智能体并且只想增加记忆功能，那么它比您需要的要重，因为您正在采用运行时来获得记忆功能。

### Cognee — 图管道选项 {#cognee--the-graph-pipeline-option}

Cognee 的角度是一个 ECL（提取-认知-加载）图形管道，具有可插入的默认嵌入式存储（SQLite、LanceDB、Kuzu），这使得真正的低摩擦本地启动无需强制云。如果您喜欢对数据进行可配置图形构建管道的想法，那么值得一看。

值得怀疑的是排名。 Google 顶部的几个“最佳开源记忆”综述都是 Cognee 自己的，他们将 Cognee 放在第一位，但没有独立的基准数据。这就是整篇文章所要讨论的差距：更喜欢一个在基准上发布分数的系统，您可以重现它，而不是在它控制的博客中对自己进行排名的系统。

### Hindsight — 准确性和最简单的自托管 {#hindsight--accuracy-and-the-simplest-self-host}

全面披露，这是我们的项目，因此请根据来源而不是署名权衡声明。 Hindsight的赌注是上面的两个轴：检索准确性和部署简单性。

在准确性方面，它在这些系统中发布了最高的已公布分数 —**94.6%LongMemEval-s**，以及**#1 [BEAM](/blog/2026/04/02/beam-sota)**，在 1000 万个标记下测试记忆的基准，其中上下文填充是不可能的。两者都以可重复的方法出现在公共排行榜上，这就是重点。它通过运行到达那里[四种并行检索策略 [BEAM](/blog/2026/04/02/beam-sota)-s 上](/blog/2026/07/31/evaluate-agent-memory-system)（语义，BM25关键词、图遍历、时间）用跨编码器重排序，而不是押注于一个。

部署时，它是一个**带有嵌入式PostgreSQL的单个Docker命令**——没有外部矢量数据库，没有单独的图形数据库，根本就是[没有自带数据存储](/blog/2026/05/12/case-against-external-vector-dbs-agent-memory)。它获得了 MIT 许可，并且自托管版本具有与托管云相同的完整功能；没有什么是门控的。它不领先的是社区规模和本地时间有效性建模，这正是 Graphiti 出现在这个列表中的原因。

## “自托管”的真正成本是多少 {#what-self-hosted-really-costs}

星星计数隐藏了达到您的运营预算的数字：您最终运行了多少有状态服务。按其对字段进行分组。

- **一个嵌入式存储：** Hindsight 将所有内容（记忆、实体、图形、向量）保存在单个嵌入式 PostgreSQL 中。 Cognee 也以嵌入式方式运行，跨三个存储（SQLite、LanceDB、Kuzu）。 Mem0 还附带嵌入式默认值（磁盘上的 Qdrant）。
- **用于生产的外部数据库：** Graphiti 通常在外部图形数据库（Neo4j 或 FalkorDB）上运行，而 Mem0 部署通常大规模移动到外部向量存储。这些是真正需要运行、备份和保护的服务。
- **云压：** 既然 CE 已弃用，Zep 的完整产品就是云，而 Mem0 最顺畅的路径是其托管平台。开源核心是真实的，但铺好的道路通常通向外部。

所有这些都不是取消资格——已经运行 Neo4j 的团队只需支付很少的边际成本即可添加 Graphiti。但“自托管智能体记忆”应该意味着您对整个部署（包括外部依赖项）进行了定价，并且在连接它们之前知道[外部数据存储带来实际成本](/blog/2026/07/28/migrate-agent-memory-off-vector-database)。

## 何时选择每个 {#when-to-pick-each}

- **Mem0** — 您想要最大的社区和个性化优先的设计。
- **Graphiti / Zep**——你的智能体的核心工作是时间推理（审计跟踪、不断发展的记录），你可以很好地运行外部图形数据库。
- **莱塔**——你想要一个完整的、可自托管的智能体运行时，而不仅仅是一个记忆层。
- **科涅** — 您想要一个具有嵌入式本地默认值的可配置图形管道，并且您将自己对其进行基准测试。
- **Hindsight** — 您想要最高的已发布检索精度和最简单的部署（一个容器，无外部数据库），并且不需要本机事实有效性窗口。
- **LangMem** — 您已经全力投入LangGraph。

## 常见问题 {#frequently-asked-questions}

**Mem0真的开源吗？**
是的，Mem0 核心是 Apache-2.0 且可自托管，并且默认情况下与嵌入式存储一起运行。但最顺畅的生产路径是其托管平台，并且大多数部署都转移到外部矢量数据库，因此“开源”和“生产中无外部服务”在这里并不是一回事。

**Zep 开源吗？**
​​部分。 Zep 的开源引擎是 Graphiti (Apache-2.0)，您可以自行托管。 Zep 该产品是一项云服务，Zep Community Edition（可自托管的完整产品）已被弃用。如果您需要在自己的基础设施上使用整个 Zep 功能集，那么这条路就消失了；保持开放的是 Graphiti，引擎。

**哪种开源智能体记忆最容易自行托管？**
根据必须运行的有状态服务的数量，嵌入式存储选项获胜：Hindsight（一个Docker容器，嵌入式PostgreSQL，无外部数据库）和Cognee（嵌入式SQLite/LanceDB/Kuzu默认值）。 Graphiti 添加了一个外部图形数据库，Mem0 添加了一个向量存储，您可以对这两个数据库进行操作、备份和保护。

**哪个开源智能体记忆最准确？**
在 LongMemEval 上，大多数严肃的系统现在的得分都在 90 左右（Hindsight 在 LongMemEval-s 上的得分为 94.6%），因此基准测试几乎无法将它们分开。更尖锐的测试是BEAM，它在不可能进行上下文填充的情况下评估 1000 万个标记的记忆：Hindsight 在那里排名第一，并且大多数竞争对手没有发布可比较的结果。当综述宣布获胜者时，询问哪个基准、规模和方法。

**我需要矢量数据库来实现智能体记忆吗？**
不一定。有些将其图形存储在外部数据库（Graphiti）中，有些在生产中运行单独的向量存储（Mem0，尽管其默认值是嵌入的）。其他的，如Hindsight，将所有内容保存在单个嵌入式PostgreSQL中。这就是为什么部署形状（而不仅仅是许可证）属于您的比较。

**LangMem、Memobase 和 Memary 怎么样？ 如果您已经在 **LangMem、Memobase 和 Memary 怎么样？
如果您已经在 LangGraph 上，** 上，** LangMem 是生态系统内的选择LangGraph。 Memobase（约 2.8K 颗星）是一个较小的、以用户配置文件为中心的选项。 Memary 自 2024 年以来一直处于休眠状态，因此请将其视为参考而不是构建的基础。

## 诚实的判决 {#the-honest-verdict}

没有万能的赢家，只有最适合您正在优化的内容。如果你想要最大的社区，Mem0。如果您正在构建审计级时间推理，Graphiti。如果你想要整个智能体框架，Letta。如果您想要一个可配置的图形管道，Cognee。

如果您是自托管并且您关心的是检索准确性以及无聊的单容器部署，您可能会在一分钟内站起来然后忘记，Hindsight正是为此而构建的。它使用一个 Docker 命令进行自托管，并嵌入 PostgreSQL（获得 MIT 许可），或在具有相同功能集的 [Hindsight Cloud](https://hindsight.vectorize.io) 上托管运行。无论您选择哪一个，请根据您可以重现的基准和您实际定价的部署来选择它，而不是根据谁的博客排名第一。
