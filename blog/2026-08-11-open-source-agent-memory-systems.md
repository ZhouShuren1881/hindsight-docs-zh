“开源”和“可自托管”常被当作同一回事，但两者承诺的并不相同。许多自称开源的智能体记忆工具，仍要求你搭建外部向量数据库、另行运行图数据库，或者在生产环境真正需要的功能层级上付费。

如果你正在挑选可以自行运行的记忆层，这种差别比星标数量更重要。下面会如实说明每种开源智能体记忆系统的实际运行成本、架构，以及经过测量而非猜测后得到的成绩。

<!-- truncate -->

刚接触这个领域？可以先了解[什么是智能体记忆](https://vectorize.io/what-is-agent-memory)。本文是[各大框架全面对比](https://vectorize.io/articles/best-ai-agent-memory-systems)中的开源部分，只讨论可自行托管的系统。

先说明这类文章的一个常见问题：大多数“最佳开源记忆”盘点都由某家供应商发布，而那家供应商往往恰好排在第一。这篇文章也是供应商撰写的。因此，我们不直接宣称谁是赢家，而是依靠两项你可以自行核查的依据：**已发布的基准测试数据**，以及**各系统实际运行所需的条件**。

## 如何比较开源智能体记忆系统 {#how-to-compare-open-source-agent-memory}

比较结果取决于五个维度，其中只有两个会出现在产品落地页上：

1. **检索准确率**——它能否返回正确的记忆？要看公开基准测试的测量结果，而不是口头宣称。完整评估框架见[如何评估智能体记忆系统](/blog/2026/07/31/evaluate-agent-memory-system)。
2. **自托管的实际情况**——你能否用自己的基础设施运行它？这里的“自己的基础设施”包括什么：一个容器，还是向量数据库、图数据库和队列各一个？
3. **自托管时的功能完整性**——你获得的是完整产品，还是功能精简版，目的是引导你转向付费云服务？
4. **许可证**——是否足够宽松，能让你实际部署？
5. **架构**——采用向量、图还是混合架构？这会怎样影响你能提出的查询？

根据你的场景为这些维度设定权重。审计追踪智能体最看重时间建模；精简自托管方案的用户则最关心运维团队要接手多少个数据库。

## 开源记忆系统一览 {#the-open-source-memory-systems-at-a-glance}

表中数据已对照 GitHub 和截至 2026 年 8 月发布的基准测试核实。

| 系统 | GitHub ★ | 许可证 | 自托管实际情况 | 存储 | 最擅长的方面 |
|---|---:|---|---|---|---|
| **Mem0** | ~63.0K | Apache-2.0 | 开源核心；默认使用嵌入式存储，生产环境可接入外部向量数据库；另有托管版 | 向量（可选图） | 社区生态与对话个性化 |
| **Cognee** | ~30.0K | Apache-2.0 | 默认使用嵌入式存储，无强制云服务 | 图管道（SQLite/LanceDB/Kuzu） | 图 ECL 管道 |
| **Graphiti / Zep** | ~29.8K | Apache-2.0 | Graphiti 可自托管；Zep CE 已弃用 | 时态知识图谱（Neo4j/FalkorDB） | 时间推理 |
| **Letta**（前身为 MemGPT） | ~24.2K | Apache-2.0 | 可自托管的服务器 | 智能体运行时与记忆 | 完整智能体运行时 |
| **Hindsight** | ~19.6K | MIT | 一条 Docker 命令即可启动，内嵌 PostgreSQL，无需外部数据库 | 单个嵌入式 Postgres，采用多种策略 | 准确率与部署简便性 |

介绍各系统之前，先诚实说明两点。Hindsight **不是**这里星标最多的项目；Mem0、Cognee 和 Graphiti 的社区都更大，而社区规模确实有价值。表中每个系统都采用宽松许可证，因此“它是开源的”只是基本条件，并非区分优势。真正重要的差异在于准确率和运行成本。

## 逐一介绍各系统 {#the-systems-one-by-one}

### Mem0——社区规模最大 {#mem0--the-biggest-community}

Mem0 以很大优势成为 GitHub 上最受欢迎的智能体记忆项目（约 63.0K 个星标）。受欢迎程度会不断累积优势：集成更多、示例更多，遇到问题时 Stack Overflow 上可参考的答案也更多。它确实擅长对话个性化：记忆按 `user_id`、`agent_id` 和 `run_id` 限定范围，因此跨会话回忆某个人的偏好是它的默认路径。你可以先用库，之后转为自托管服务器，也可以使用托管平台。写入时，它会从对话轮次中提取事实，而不是存储原始对话记录，从而避免存储不断膨胀。

两者的取舍与其说是准确率有天壤之别，不如说取决于你信任哪个基准测试，以及选择哪种部署方式。Mem0 发布的 LongMemEval 成绩很强，与领域内顶尖系统不相上下；不过 LongMemEval 现在已经接近饱和：严肃的系统得分都集中在 90 多分，几乎无法将它们区分开来。区分度更高的测试是 1000 万 tokens 规模的 BEAM；Hindsight 在这项测试中排名第一，而 Mem0 没有发布可比结果。在部署方面，Mem0 的开源核心默认使用嵌入式存储，但生产环境通常会改用外部向量数据库；最便捷的使用路径也会引导用户转向托管平台。如果你最看重社区规模和个性化优先的设计，Mem0 是显而易见的选择。

### Graphiti / Zep——时间建模专家 {#graphiti--zep--the-temporal-specialist}

当“某项事实在什么时间成立”就是核心任务时，可以考虑 Graphiti。它是 Zep 背后的开源引擎，原生支持时间建模：知识图谱中的每条边都携带有效性元数据，因此它可以清楚地回答“第二季度调整之前，客户的计划是什么？”对于合规时间线和审计追踪，这种时间建模能力很难匹敌，也是 Graphiti 真正领先的维度。

自托管时有两点需要注意。**Zep Community Edition 已于 2025 年弃用**，所以“自托管功能完整的 Zep”这条免费开源路径已经不复存在——你能自托管的是引擎 Graphiti，而不是完整产品（企业版 BYOC 除外）。此外，Graphiti 通常将图数据存储在外部数据库中（Neo4j 或 FalkorDB，不过也有嵌入式 FalkorDB lite 模式），因此在大多数部署中，你还需要与应用一起运行和运维这个数据库。

### Letta——智能体运行时 {#letta--the-agent-runtime}

Letta（原名 MemGPT）在这里显得与众不同，但这也有其用处：它并不是可以直接接入的记忆*层*，而是一个内置记忆的**智能体运行时**。如果你想采用完整框架，让智能体循环、工具调用和记忆整合为一套有明确设计取舍的系统，Letta 是一个功能强大、可自托管且有扎实研究渊源的选择。它的记忆模型值得了解：智能体持有可编辑的**记忆块**（一个小型、始终保留在上下文中的核心，智能体会自行改写），以及用于存放长期内容的**归档记忆**。这个想法直接来自 MemGPT 论文。如果你已经有智能体，只是想为它加上记忆，那么 Letta 会比你所需的更重，因为为了获得记忆功能，你还得采用整个运行时。

### Cognee——图管道方案 {#cognee--the-graph-pipeline-option}

Cognee 的核心思路是 ECL（提取-认知化-加载）图管道，并提供可插拔的存储，默认采用嵌入式方案（SQLite、LanceDB、Kuzu）。这让你可以轻松地在本地启动，无需强制使用云服务。如果你希望通过可配置的图构建管道处理数据，Cognee 值得一看。

排名方面则要保持审慎。Google 搜索结果靠前的几篇“最佳开源记忆”盘点出自 Cognee 自己，在没有独立基准数据的情况下把 Cognee 排在第一。这正是本文要讨论的问题：优先选择在可复现基准测试上公布成绩的系统，而不是在自己运营的博客中给自己排名的系统。

### Hindsight——准确率高，自托管最简单 {#hindsight--accuracy-and-the-simplest-self-host}

先充分披露：这是我们自己的项目，因此请结合来源而非作者署名来判断这些说法。Hindsight 重点押注于上文的两个维度：检索准确率和部署简便性。

在准确率方面，它在这些系统中发布了最高成绩：LongMemEval-s 上为 **94.6%**，并在 [BEAM](/blog/2026/04/02/beam-sota) 上排名 **第一**。BEAM 在 1000 万 tokens 规模下测试记忆能力，此时不可能靠塞满上下文来应对。两项成绩都有公开排行榜和可复现的方法，这正是重点。Hindsight 通过[并行运行四种检索策略](/blog/2026/07/31/evaluate-agent-memory-system)（语义检索、BM25 关键词检索、图遍历和时间检索），再使用交叉编码器重排序来取得这些成绩，而不是只押注一种策略。

部署方面，它只需**一条 Docker 命令即可启动，内嵌 PostgreSQL**——无需外部向量数据库，也无需单独的图数据库，完全[不必自备数据存储](/blog/2026/05/12/case-against-external-vector-dbs-agent-memory)。它采用 MIT 许可证，自托管版本与托管云服务功能完整一致，没有任何功能被限制。它的弱项是社区规模和原生的时间有效性建模，这也正是列表中纳入 Graphiti 的原因。

### 其他值得了解的方案 {#also-worth-knowing}

如果你已经采用 LangGraph，**LangMem** 是稳妥的默认选择，因为它是生态内方案，而非独立服务。**Memobase**（约 2.8K 个星标）侧重用户档案记忆，适合这类需求。**Memary** 仍然存在，但自 2024 年以来一直没有活跃，因此应把它当作参考，而不是依赖项。

## “自托管”的实际成本 {#what-self-hosted-really-costs}

星标数量掩盖了一个会影响运维预算的数字：最终需要运行多少个有状态服务。可以据此将这些系统分组。

- **一个嵌入式存储：** Hindsight 将记忆、实体、图和向量全部存放在单个嵌入式 PostgreSQL 中。Cognee 也使用嵌入式存储，不过分布在三种存储上（SQLite、LanceDB、Kuzu）。Mem0 默认也提供嵌入式存储（磁盘上的 Qdrant）。
- **生产环境使用外部数据库：** Graphiti 通常依赖外部图数据库（Neo4j 或 FalkorDB）；Mem0 部署在规模扩大后通常会改用外部向量存储。这些都是需要实际运行、备份和保护的服务。
- **云服务牵引：** Zep 的 CE 已弃用，因此其完整产品现在只有云服务；Mem0 最便捷的路径则是使用其托管平台。它们的开源核心都确实可用，但最顺畅的使用路径往往会把你带到本地环境之外。

这些都不是否决理由——已经在运行 Neo4j 的团队添加 Graphiti，边际成本就很低。不过，“自托管智能体记忆”应该意味着你已经核算了整个部署的成本，包括外部依赖，并且在接入之前了解[外部数据存储确实会带来成本](/blog/2026/07/28/migrate-agent-memory-off-vector-database)。

## 如何选择 {#when-to-pick-each}

- **Mem0**——你需要最大的社区，以及个性化优先的设计。
- **Graphiti / Zep**——智能体的核心任务是时间推理（审计追踪、不断演变的记录），而且你愿意运行外部图数据库。
- **Letta**——你需要完整、可自托管的智能体运行时，而不只是记忆层。
- **Cognee**——你需要可配置的图管道和默认的嵌入式本地存储，并愿意自行进行基准测试。
- **Hindsight**——你需要最高的已发布检索准确率和最简单的部署方式（一个容器，无外部数据库），并且不需要原生的事实有效期窗口。
- **LangMem**——你已经全面采用 LangGraph。

## 常见问题 {#frequently-asked-questions}

**Mem0 真的是开源的吗？**
是的，Mem0 核心采用 Apache-2.0 许可证，可自托管，并且默认使用嵌入式存储。但最便捷的生产环境路径是它的托管平台，而且多数部署在规模扩大后会改用外部向量数据库。因此，这里的“开源”和“生产环境无需外部服务”并不是一回事。

**Zep 是开源的吗？**
部分开源。Zep 的开源引擎是 Graphiti（Apache-2.0），可以自行托管。Zep 产品本身是云服务，而 Zep Community Edition（可自托管的完整产品）已经弃用。如果你需要在自己的基础设施上使用完整的 Zep 功能，这条路已经不通；仍保持开源的是作为引擎的 Graphiti。

**哪种开源智能体记忆最容易自托管？**
如果按需要运行的有状态服务数量衡量，嵌入式存储方案最省事：Hindsight（一个 Docker 容器、内嵌 PostgreSQL，无外部数据库）和 Cognee（默认使用嵌入式 SQLite/LanceDB/Kuzu）。Graphiti 需要外部图数据库，Mem0 需要外部向量存储；这两者都需要你负责运维、备份和保护。

**哪种开源智能体记忆最准确？**
在 LongMemEval 上，大多数成熟系统目前的得分都在 90 多分（Hindsight 在 LongMemEval-s 上为 94.6%），因此这项基准测试几乎无法再把它们区分开来。区分度更高的是 BEAM：它在 1000 万 tokens 规模下评估记忆能力，此时不可能靠塞满上下文来应对。Hindsight 在 BEAM 上排名第一，而大多数竞争者没有发布可比结果。看到盘点文章宣布赢家时，应追问它使用了哪项基准测试、测试规模有多大、采用了什么方法。

**智能体记忆需要向量数据库吗？**
不一定。有些方案将图存储在外部数据库中（Graphiti），有些在生产环境运行独立的向量存储（Mem0，不过默认存储是嵌入式的）。还有一些方案，例如 Hindsight，把所有内容都存储在单个嵌入式 PostgreSQL 中。因此，比较时应考虑部署形态，而不只是许可证。

**LangMem、Memobase 和 Memary 呢？**
如果你已经在使用 LangGraph，LangMem 是生态内方案。Memobase（约 2.8K 个星标）规模较小，专注于用户档案记忆。Memary 自 2024 年以来一直没有活跃，因此应把它当作参考，而不是后续开发的基础。

## 坦诚的结论 {#the-honest-verdict}

没有放之四海皆准的赢家，只有最符合你优化目标的方案。想要最大的社区，选 Mem0；要构建审计级别的时间推理，选 Graphiti；需要完整的智能体框架，选 Letta；需要可配置的图管道，选 Cognee。

如果你选择自托管，最看重检索准确率和简单可靠的单容器部署，希望一分钟内就能启动并省心运行，那么 Hindsight 正是为此打造的。它只需一条 Docker 命令即可自托管，并内嵌 PostgreSQL，采用 MIT 许可证；也可以通过 [Hindsight Cloud](https://hindsight.vectorize.io) 托管运行，功能集完全相同。无论选择哪种方案，都应依据可复现的基准测试和实际核算过成本的部署来决定，而不是看谁在自己的博客上把谁排在第一。
