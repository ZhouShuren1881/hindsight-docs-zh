Hindsight 0.7.1 是紧随 0.7.0 发布的快速更新，重点提升 **可靠性**：其中包括一项针对超大 Retain 操作导致记忆损坏的 **关键修复**，以及更稳健的整合机制；此外还新增了一些实用的调节选项（LLM 推理强度、按服务提供方配置的重排序器超时），并进一步完善了国际化。**所有使用 0.7.0 的用户都应升级**，尤其是摄取大型文档的用户。

<!-- truncate -->

- [**关键修复：超大 Retain 操作导致的记忆损坏**](#critical-oversized-retain-corruption-fix)：大型文档可能丢失记忆，因为并发的子操作会级联删除彼此创建的 `memory_units`。
- [**更稳健的整合**](#tougher-consolidation)：支持带退避的无限期重试、按记忆库去重和基于优先级的调度，让工作进程在负载较高时也能持续推进。
- [**新增调节选项**](#new-tuning-knobs)：可通过环境变量配置 LLM 推理强度，以及各服务提供方的重排序器 HTTP 超时。
- [**新增中文语言区域**](#more-chinese-locales)：增加了其他中文语言区域变体，并润色了现有翻译。

## 关键修复：超大 Retain 操作导致的记忆损坏 {#critical-oversized-retain-corruption-fix}

当一次 Retain 操作处理的单个文档过大，无法由一次 LLM 调用完成时，0.7.0 可能只保存本应提取出的部分记忆：同一文档的不同文本分块并行处理，结果相互覆盖。0.7.1 改为在单个工作进程内按顺序处理大型文档，以保留所有提取出的记忆。

如果你在 0.7.0 上摄取过大型文档，请升级并重新存入受影响的文档，以恢复丢失的记忆。

## 更稳健的整合 {#tougher-consolidation}

整合工作进程获得了两项相互配合的修复，让它在高负载下也能保持正常运行：

- **带退避的无限期重试。** 过去，整合过程中发生暂时性故障后，工作进程可能会放弃处理该记忆库，直到下一次触发。0.7.1 会以指数退避方式无限期重试整合，并为每个记忆库设置去重保护，避免同一记忆库被并发领取多次、造成资源浪费。
- **按优先级调度记忆库。** 有多个记忆库等待整合时，工作进程现在会按优先级依次领取。在混合工作负载的部署中，优先级较高的记忆库可以更好地控制整合延迟，无需排在大型低优先级记忆库之后等待。

## 新增调节选项 {#new-tuning-knobs}

新增了两个环境变量，让你无需修改代码即可调整模型行为：

- **`HINDSIGHT_API_LLM_REASONING_EFFORT`** — 设置推理模型的推理强度（例如 `low`、`medium`、`high`）。在提取和 Reflect 调用中，可用它权衡延迟与质量。感谢 [@s9rkn](https://github.com/s9rkn)。
- **按服务提供方配置重排序器 HTTP 超时** — 每个重排序器服务提供方都有单独的超时环境变量，因此可以为响应较慢的服务提供方留出更多时间，而无需对所有服务提供方统一放宽超时。

## 新增中文语言区域 {#more-chinese-locales}

在 0.7.0 发布的支持 8 种语言的控制台基础上：

- 新增了其他中文语言区域变体。感谢 [@MapleEve](https://github.com/MapleEve)。
- 润色了现有的 `zh` 翻译，使措辞更加自然。

## 其他值得关注的改动 {#other-notable-changes}

- **Recall 的近期性以查询时间戳为基准**，因此对历史查询重新运行 Recall 时，无论何时执行都能得到相同结果。感谢 [@Sanderhoff-alt](https://github.com/Sanderhoff-alt)。
- **刷新 Codex OAuth 嵌入令牌** — 0.7.0 中新增的 Codex OAuth 嵌入服务提供方现在会自动刷新访问令牌，因此长时间运行的嵌入工作负载不会因令牌过期而失败。感谢 [@DK09876](https://github.com/DK09876)。
- **控制台操作下拉菜单中的 `graph_maintenance` 筛选项**，可与其他操作类型一起筛选图修复任务。
- **OpenClaw**：在 `session_end` 时刷新尚未存入的对话轮次；在 synthetic-main + static-banking 配置中不再悄悄跳过调度；并在注入的记忆上下文中将“Current time”标注为 UTC。
- **文档**：新增了使用 docker-compose 通过本地 llama.cpp sidecar 运行 Hindsight 的示例、用于 Claude Code 集成的 Codex Docker 配方；BM25 后端表格现在也列出了 PGroonga 和 pg_search 的 tokenizer 选项。
