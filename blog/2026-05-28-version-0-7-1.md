Hindsight 0.7.1 是 0.7.0 的快速后续版本，专注于 **可靠性** — 包括用于超大保留记忆损坏的 **关键修复** 和更严格的集成 — 加上一些有用的调整旋钮（LLM 推理工作、每个提供者的重排序器超时）和更多的 i18n 优化。 **0.7.0 上的所有用户都应该升级**，尤其是那些摄取大型文档的人。

<!-- truncate -->

- [**严重：超大记忆存储损坏修复**](#critical-oversized-retain-corruption-fix)：大文档可能会丢失记忆，因为并发子操作会级联删除彼此的`memory_units`。
- [**更强的整合**](#tougher-consolidation)：无限期重试，带有退避、记忆库重复数据删除和基于优先级的调度，使工作人员在压力下不断取得进展。
- [**新调音旋钮**](#new-tuning-knobs)：从 env 配置 LLM 推理工作和每个提供商重排序器 HTTP 超时。
- [**更多中文语言环境**](#more-chinese-locales)：额外的 zh 变体和对现有翻译的波兰通行证。

## 严重：超大记忆存储损坏修复 {#critical-oversized-retain-corruption-fix}

当您保留的单个文档对于一次 LLM 调用来说太大时，0.7.0 最终可能只保存应提取的记忆的一小部分 - 同一文档的不同块并行运行并覆盖彼此的结果。 0.7.1 使大型文档在单个工作程序中按顺序处理，以便保留所有提取的记忆。

如果您在0.7.0上摄取了大型文档，请升级并重新记忆存储受影响的文档以恢复丢失的记忆。

## 更强的整合 {#tougher-consolidation}

整合工作人员获得两个相关的修复，共同保持其在负载下的健康：

- **带退避的无限期重试。** 以前，整合过程中的短暂故障可能会导致工作人员放弃记忆库，直到下一次触发。 0.7.1 使用指数退避和每个记忆库重复数据删除防护来无限期地重试集成，因此同一记忆库不能同时被拾取两次并浪费周期。
- **基于优先级的记忆库调度。** 当多个记忆库有待整合时，工作人员现在按优先顺序拉取它们。较高优先级的记忆库可以在混合工作负载部署中重新控制其集成延迟，而不是等待大型、低优先级的记忆库。

## 新调音旋钮 {#new-tuning-knobs}

两个新的环境变量让您无需更改代码即可调整模型行为：

- **`HINDSIGHT_API_LLM_REASONING_EFFORT`** — 设置推理模型的推理工作量（例如`low`、`medium`、`high`）。对于在提取和反思调用时用延迟与质量进行交易非常有用。感谢[@s9rkn](https://github.com/s9rkn)。
- **每个提供商重排序器 HTTP 超时** — 每个重排序器提供程序都有单独的超时环境变量，这样您就可以为较慢的提供程序提供更多空间，而无需全局放松每个人的超时。

## 更多中文语言环境 {#more-chinese-locales}

基于 0.7.0 中提供的 8 种语言控制平面构建：

- 添加了额外的中文语言环境变体。感谢[@MapleEve](https://github.com/MapleEve)。
- 对现有的`zh`翻译进行了润色，以获得更自然的措辞。

## 其他显著变化 {#other-notable-changes}

- **记忆召回锚定到查询时间戳** 因此，无论您何时重新运行历史查询，记忆召回都会返回相同的结果。感谢[@Sanderhoff-alt](https://github.com/Sanderhoff-alt)。
- **Codex OAuth 嵌入令牌刷新** — 0.7.0 中添加的 Codex OAuth 嵌入提供程序现在会自动刷新其访问令牌，因此长时间运行的嵌入工作负载在令牌过期时不会失败。感谢[@DK09876](https://github.com/DK09876)。
- **`graph_maintenance`滤镜
控制平面操作下拉列表中的**，以便您可以与其他操作类型一起过滤图形修复运行。
- **OpenClaw**：刷新未保留的`session_end`，不再默默地跳过合成主+静态存储设置上的调度，并在注入的记忆上下文中将“当前时间”标记为UTC。
- **文档**：针对本地 llama.cpp sidecar 运行 Hindsight 的 docker-compose 示例，Codex Docker Claude Code集成配方，BM25 后端表现在列出了 PGroonga 和 pg_search tokenizer 选项。
