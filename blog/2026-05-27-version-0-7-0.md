Hindsight 0.7.0 是一个主要版本，它使 Hindsight 更快、更精简、可部署范围更广。多语言部署获得一流的语言调整和多语言 CJK 后端，图形层的大小大约是以前的一半，并且删除后可以自我修复，控制平面提供八种语言版本，集成在维护干净的观察集方面变得有意义更好，记忆库现在可以在水平扩展的 Postgres 集群上运行，并具有真正的 BM25 搜索。

<!-- truncate -->

- [**更好的多语言搜索**](#better-multilingual-search)：针对本地后端的每种语言BM25调整以及用于混合语言记忆库的新多语言PGroonga后端。
- [**更精简、自我修复的图**](#leaner-self-healing-graph)：大约一半的存储空间和删除后的自动图形修复。
- [**8 种语言的控制平面**](#control-plane-in-8-languages)：英语、西班牙语、法语、德语、葡萄牙语、日语、韩语和中文。
- [**更智能的整合**](#smarter-consolidation)：减少重复观察，加上通过标签范围进行有针对性的重新整合。
- [**新的嵌入选项**](#new-embedding-options)：零熵和Codex-OAuth 支持的OpenAI 嵌入。
- [**用于 Citus 的 ParadeDB pg_search**](#paradedb-pg_search-for-citus)：在水平缩放的Postgres集群上为真BM25。

## 更好的多语言搜索 {#better-multilingual-search}

Hindsight 已经检测到传入内容的语言，并通过记忆存储/记忆召回保存它 - 但 BM25 搜索实际上仅限于英语。无论记忆库的实际语言如何，原生 tsvector 索引都应用英语词干提取，这会损害非英语内容上的关键字记忆召回，对于需要二元样式标记化才能工作的 CJK 语言来说尤其痛苦。

0.7.0 在两个方面解决了这个问题：

- **原生BM25后端** 现在使用可配置的语言词典，因此西班牙语、法语或德语记忆库可以立即获得正确的词干。
- 新的选择加入**PGroonga 后端**使用单个多语言索引来处理英语、中文、日语、韩语等*同时*——混合语言记忆库的正确选择。包含一个 docker-compose 配方。

您还可以独立于索引语言固定事实提取器的输出语言，当您想要用一种语言进行记忆存储并用另一种语言进行巩固或记忆召回时，这非常有用。

请参阅 [多语言支持](/developer/multilingual) 文档，了解完整的配置矩阵和后端之间的权衡。

## 更精简、自我修复的图 {#leaner-self-healing-graph}

支持实体扩展和基于链接的记忆的图形层在 0.7.0 中得到了重大清理——将其存储占用空间大约减少了一半，并随着时间的推移保持正确。

**较小的图。** 图的很大一部分是由记忆存储急切地写入但记忆召回从未真正读取过的成对实体链接组成的——实体扩展早已直接遍历底层实体表。 0.7.0 停止具体化这些链接，并根据 `/graph` 和 `/stats` 端点的需求派生它们。在 10k 单元的工作台上，仅此一项就删除了大约一半的图形行，并释放了约 190 MB 的表和索引空间。然后，单独的索引审核删除了九个索引，这些索引要么未使用，要么完全被查询计划者已经首选的复合索引覆盖。 API 响应形状不会改变 — 无需 SDK 再生。

**删除后自我修复。** 当记忆单元被删除时，它所连接的单元会默默地失去链接并永久保持在上限状态，这会慢慢侵蚀图形扩展记忆召回。 0.7.0 检测到这一点并异步地将这些邻居重新填充回配置的上限，而不会对热记忆存储路径产生影响。 定期删除的记忆库——文档重新摄取、GDPR 删除、定期清理——无限期地保持健康的图表。

## 8 种语言的控制平面 {#control-plane-in-8-languages}

控制平面 UI 现已完全国际化，标题中有语言切换器。选自：

- 英语、西班牙语、法语、德语、葡萄牙语
- 日语、韩语、中文

区域设置前缀路由使 URL 保持可预测性，并且如果未来的更改引入了未翻译的面向用户的字符串，则 CI 检查会使构建失败 - 因此随着 UI 的发展，翻译保持同步。

## 更智能的整合 {#smarter-consolidation}

观察 集成可以更好地维护干净、重复数据删除的集，并让您可以更好地控制它的运行时间。

**减少重复观察。** 合并器偶尔会产生近乎重复的同级观察，而不是合并它们。 0.7.0 将其行为调整为在内容重叠时更倾向于更新现有观察而不是创建新观察。每个记忆库`observations_mission`设置现在也可以更清晰地级联到整合器的行为中，因此具有自定义任务的记忆库可以按照您期望的方式整合。

​​**有针对性的重新整合。** `consolidate`端点接受新的`observation_scopes`参数，因此您可以仅重新整合与特定标签组合匹配的记忆，而不是重建整个记忆库。当标签策略更改使观察切片无效时很有用。

**选择退出自动整合。** 新的每记忆库`enable_auto_consolidation` 标志禁用通常在存储记忆之后运行的自动整合。喜欢按计划或按需整合的部署现在可以完全选择退出。

## 新的嵌入选项 {#new-embedding-options}

两种新的嵌入方式：

- **零熵** 是一个新的嵌入提供者 — 设置 `HINDSIGHT_API_EMBEDDINGS_PROVIDER=zeroentropy` 并选择一个模型。
- **Codex OAuth 嵌入** 让现有的 OpenAI 嵌入提供程序通过您的 Codex OAuth 令牌而不是单独的 API 密钥进行身份验证。如果您已经在运行 Codex 并且想要重复使用相同的凭据进行嵌入，这会很方便。

## 用于 Citus 的 ParadeDB pg_search {#paradedb-pg_search-for-citus}

Hindsight 现在支持 [ParadeDB pg_search](https://www.paradedb.com/) 作为 BM25 后端。如果您在 Citus 分布式 Postgres 集群上运行，则可以选择此选项 — pg_search 是跨 Citus 分片工作的唯一真正的 BM25 扩展，因此水平扩展的部署不再需要回退到更简单的本机 tsvector 后端。

通过以下方式设置：

```bash
HINDSIGHT_API_TEXT_SEARCH_EXTENSION=pg_search
```

准备运行的 docker-compose 配方在 `docker/docker-compose/pg_search/` 下发布。您还可以通过 `HINDSIGHT_API_PG_SEARCH_TOKENIZER`（`default`、`whitespace`、`raw` 等）调整语料库的标记化。

## 其他显著变化 {#other-notable-changes}

- **清晰心智模型端点** 重置心智模型的内容，以便下一次刷新从头开始重新合成 - 对于在多次增量刷新中发生漂移的增量模式模型的定期压缩非常有用。在控制平面和 SDK 中公开。
- **阿里巴巴Qwen3重排序器支持
本地交叉编码器路径中的**。
- **正确的智能体整合** — 集成目录中的新条目。
- **OpenCode 前往 LLM 提供商** 用于`opencode-go` 运行时。
- **Ollama 云提供商** 具有正确的云端点身份验证。
- **每操作LLM并发上限** 防止并行工作负载使提供者过载。
- **重排序器分数归一化** 自动检测预标准化分数并相应地切换策略，修复一类微妙的排名回归。
- **Anthropic兼容性** — `temperature` 不再发送（最新型号拒绝发送）。
- **Webhook 交付** 已进行重复数据删除，因此记忆存储批次不会触发重复通知。
- **超大记忆存储项目** 在调用之前被分割，因此非常大的有效负载不再使整个批次失败。
- **禁用的 灰色 工具** 在智能体的系统提示中隐藏，而不仅仅是在调用时门控 - 因此智能体永远不会看到它无法使用的工具。
- **用户自定义标签实体** 不再受到模糊解析的影响，因此用户定义的身份保持稳定。
- **心智模型历史** 设有上限以防止 JSONB 溢出，并且完全刷新可以正确重新调整待定增量基线。
- **控制平面会话** 现在验证签名的 cookie，而不仅仅是检查其存在 - 一个有意义的身份验证强化。
- **Windows嵌入式UI启动**正确解决了`npx`，修复了长期存在的启动失败。
- **API 访问日志记录** 可以通过环境变量启用，无需更改代码。
- **Gzip 中间件** 保持压缩图响应可解析。
- **标签组和触发器
更新标签时，** 被正确保留。
