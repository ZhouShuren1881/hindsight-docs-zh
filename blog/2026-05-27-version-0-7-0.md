Hindsight 0.7.0 是一个重要版本，让 Hindsight 更快、更精简，也更适合在多种环境中部署。多语言部署现在拥有一流的语言调优能力和多语言 CJK 后端；图层的存储量缩减到原来的一半左右，并能在删除后自动修复；控制台现支持八种语言；观测整合在维护整洁观测集方面有了显著提升；记忆库也可以运行在支持真正 BM25 搜索的水平扩展 Postgres 集群上。

<!-- truncate -->

- [**更好的多语言搜索**](#better-multilingual-search)：原生后端支持按语言调优 BM25，并新增适用于混合语言记忆库的多语言 PGroonga 后端。
- [**更精简且可自我修复的图**](#leaner-self-healing-graph)：存储量约减半，并可在删除后自动修复图。
- [**支持 8 种语言的控制台**](#control-plane-in-8-languages)：支持英语、西班牙语、法语、德语、葡萄牙语、日语、韩语和中文。
- [**更智能的整合**](#smarter-consolidation)：减少重复观测，并可按标签范围有针对性地重新整合。
- [**新增嵌入选项**](#new-embedding-options)：支持 ZeroEntropy，以及使用 Codex OAuth 认证的 OpenAI 嵌入模型。
- [**适用于 Citus 的 ParadeDB pg_search**](#paradedb-pg_search-for-citus)：在水平扩展的 Postgres 集群上提供真正的 BM25 搜索。

## 更好的多语言搜索 {#better-multilingual-search}

Hindsight 已能检测输入内容的语言，并在 Retain（存入）和 Recall（召回）过程中保留该语言，但 BM25 搜索实际上一直仅适用于英语。无论记忆库实际使用哪种语言，原生 `tsvector` 索引都会使用英语词干提取。这会降低非英语内容的关键词检索效果；对于需要二元组式分词才能正常工作的 CJK 语言，影响尤其明显。

0.7.0 从两个方面解决了这个问题：

- **原生 BM25 后端**现在使用可配置的语言词典，因此西班牙语、法语或德语记忆库开箱即用时就能采用正确的词干提取规则。
- 新增可选的 **PGroonga 后端**，通过单个多语言索引同时处理英语、中文、日语、韩语等语言，是混合语言记忆库的合适选择。版本中还附带了 `docker-compose` 配置示例。

现在还可以单独指定事实提取器的输出语言，不受索引语言影响。如果希望用一种语言存入内容，再用另一种语言进行整合或召回，这项功能会很有用。

有关各后端完整的配置选项和取舍，请参阅[多语言支持](/developer/multilingual)文档。

## 更精简且可自我修复的图 {#leaner-self-healing-graph}

支撑实体扩展和基于连接的召回的图层在 0.7.0 中经过了大幅精简：存储占用量约减半，同时能够长期保持正确。

**图更精简。** 图中很大一部分是成对的实体连接；Retain 会主动写入这些连接，但 Recall 实际上从未读取它们，因为实体扩展早已直接遍历底层实体表。0.7.0 不再将这些连接实体化，而是在 `/graph` 和 `/stats` 端点需要时按需生成。在包含 10k 个单元的基准测试中，仅这一项改动就移除了约一半的图记录，并释放了约 190 MB 的表和索引空间。随后进行的另一项索引审查又删除了九个索引：它们要么未被使用，要么已被查询规划器更青睐的复合索引完全覆盖。API 响应结构没有变化，因此无需重新生成 SDK。

**删除后自动修复。** 过去，删除一个记忆单元时，与它相连的单元会悄然丢失连接，并永久低于配置的上限，导致图扩展召回能力逐渐减弱。0.7.0 会检测这种情况，并在后台异步补充这些相邻单元，使它们恢复到配置的上限，不影响 Retain 的关键路径。对于定期删除数据的记忆库——例如重新摄取文档、执行 GDPR 删除或定期清理——图能够长期保持健康。

## 支持 8 种语言的控制台 {#control-plane-in-8-languages}

控制台 UI 现已全面国际化，并在页眉中提供语言切换器。可选语言包括：

- 英语、西班牙语、法语、德语、葡萄牙语
- 日语、韩语、中文

带区域设置前缀的路由让 URL 保持可预测。CI 检查还会在未来的改动引入未翻译的用户界面字符串时令构建失败，确保 UI 持续演进时各语言的翻译也保持同步。

## 更智能的整合 {#smarter-consolidation}

观测整合在维护整洁、去重后的观测集方面有所改进，也让你能更精细地控制整合的运行时机。

**减少重复观测。** 整合器有时会生成彼此近似重复的同级观测，而不是将其合并。0.7.0 调整了整合器的行为：内容重叠时，它会优先更新已有观测，而不是创建新观测。每个记忆库的 `observations_mission` 设置现在也能更顺畅地影响整合器的行为，因此配置了自定义任务说明的记忆库会按预期进行整合。

**有针对性地重新整合。** `consolidate` 端点新增 `observation_scopes` 参数，因此可以只重新整合匹配特定标签组合的记忆，而不必重建整个记忆库。如果标签策略变更导致一部分观测失效，这项功能会很有用。

**关闭自动整合。** 新增按记忆库配置的 `enable_auto_consolidation` 标志，可禁用通常在 Retain 之后自动运行的整合。偏好按计划或按需整合的部署现在可以明确关闭自动整合。

## 新增嵌入选项 {#new-embedding-options}

新增两种使用嵌入模型的方式：

- **ZeroEntropy** 是新增的嵌入模型服务提供方。设置 `HINDSIGHT_API_EMBEDDINGS_PROVIDER=zeroentropy`，然后选择一个模型即可。
- **Codex OAuth 嵌入**让现有的 OpenAI 嵌入模型服务提供方使用 Codex OAuth 令牌进行身份认证，无需单独的 API 密钥。如果你已经在使用 Codex，并希望为嵌入模型复用相同凭据，这会很方便。

## 适用于 Citus 的 ParadeDB pg_search {#paradedb-pg_search-for-citus}

Hindsight 现在支持 [ParadeDB pg_search](https://www.paradedb.com/) 作为 BM25 后端。如果你运行在 Citus 分布式 Postgres 集群上，可以选择此后端：pg_search 是唯一能够跨 Citus 分片工作的真正 BM25 扩展，因此水平扩展部署不再需要退回到较简单的原生 `tsvector` 后端。

通过以下设置启用：

```bash
HINDSIGHT_API_TEXT_SEARCH_EXTENSION=pg_search
```

可直接运行的 `docker-compose` 配置示例位于 `docker/docker-compose/pg_search/`。你还可以通过 `HINDSIGHT_API_PG_SEARCH_TOKENIZER`（`default`、`whitespace`、`raw` 等）为语料配置分词方式。

## 其他重要变更 {#other-notable-changes}

- **清空心智模型端点**会清空心智模型的内容，使下一次刷新从头开始综合生成。对于经过多次增量刷新后内容已发生漂移、需要定期压缩的增量模式心智模型，这项功能很有用。该端点已在控制台和各 SDK 中开放。
- 本地交叉编码器路径新增对 **Alibaba Qwen3 重排序模型**的支持。
- **Right Agent 集成**：集成目录新增一项集成。
- **OpenCode Go LLM 服务提供方**：适用于 `opencode-go` 运行时。
- **Ollama Cloud 服务提供方**：修正了云端点的身份认证。
- **按操作设置 LLM 并发上限**：防止并行工作负载令服务提供方过载。
- **重排序分数归一化**会自动检测已归一化的分数，并据此切换策略，修复一类不易察觉的排序回归问题。
- **Anthropic 兼容性**：不再发送 `temperature`（最新模型不接受该参数）。
- **Webhook 投递**现在会进行去重，因此 Retain 批次不会触发重复通知。
- **超大 Retain 输入项**会在调用前拆分，因此超大型载荷不再导致整个批次失败。
- **已禁用的 Reflect 工具**会从智能体的系统提示中隐藏，而不只是限制其调用，因此智能体不会看到自己无法使用的工具。
- **用户定义的标签实体**不再进行模糊消解，因此用户定义的身份能保持稳定。
- **心智模型历史记录**现在设有上限，以防止 JSONB 溢出；完整刷新也能正确地重新设定待处理增量的基线。
- **控制台会话**现在会验证已签名的 Cookie，而不再只检查 Cookie 是否存在，从而显著加强身份认证。
- **Windows 嵌入式 UI 启动**现在能正确解析 `npx`，修复了一项长期存在的启动故障。
- **API 访问日志记录**现在无需更改代码，只需通过环境变量即可启用。
- **Gzip 中间件**确保压缩后的图响应仍可解析。
- **更新标签时**，标签组和触发器现在都能正确保留。
