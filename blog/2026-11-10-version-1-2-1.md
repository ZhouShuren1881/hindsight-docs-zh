Hindsight 1.2.1 将 Knowledge Pages 更名为 **Pages（页面）**：现有功能不会中断，旧名称在 2.x 之前仍可使用。此版本还支持服务器运行时切换嵌入模型、为查询和存储文本使用不同的嵌入模型、接入自定义 LLM 类，以及在决策模型无法完成 Recall 时回退到重排序器。大型记忆库的性能也大幅提升：实体搜索、更新状态检查、整合和关键词 Recall 最多加快 50 倍，同时还有一系列可靠性修复。**所有使用 1.2.0 的用户都应升级**，完整列表见[更新日志](/changelog)。

## Knowledge Pages 更名为 Pages {#knowledge-pages-are-now-pages}

这项功能在 API、SDK、CLI、MCP 工具和控制台等所有位置都改称 [Pages（页面）](/developer/pages)。我们将「knowledge」一词留给即将推出的 Knowledge Banks（知识库）。

**现有功能不会中断。** 在 Hindsight 2.x 之前，所有旧名称都将作为弃用别名继续使用，数据库也无需更改。你可以在方便时迁移到新名称：

| 之前 | 现在 |
| --- | --- |
| `/v1/default/banks/{bank_id}/knowledge-base/...` | `/v1/default/banks/{bank_id}/pages/...` |
| `hindsight knowledge-base ...` | `hindsight pages ...` |
| MCP `get_knowledge_page`, `search_knowledge_base`, ... | `get_page`, `search_pages`, ... |
| `HINDSIGHT_API_KNOWLEDGE_PAGE_DEFAULT_TRIGGER` / 记忆库键 `knowledge_page_default_trigger` | `HINDSIGHT_API_PAGE_DEFAULT_TRIGGER` / `page_default_trigger` |
| 心智模型列表 `exclude_knowledge_pages` | `exclude_pages` |

`mcp_enabled_tools` 允许列表中的旧 MCP 工具名称仍会启用新工具，但智能体现在只能看到新名称。如果在 OpenClaw 的 `tools.allow` / `tools.deny` 中列出了 Hindsight 工具，请在那里重命名：插件启动时会针对发现的每个旧名称发出警告。

## 不停机重新生成嵌入向量 {#re-embed-without-downtime}

存储记忆后，服务器无法使用维度不同的嵌入模型启动。现在可以原地切换：在运行命令的环境中设置新的 `HINDSIGHT_API_EMBEDDINGS_*` 变量，然后运行 `hindsight-admin reembed --all-schemas`（或 `--schema <name>`）。重新生成嵌入向量期间，服务器继续处理读写；所有服务器都运行新模型后，使用 `--finish` 解除最后的写入保护。完整过程见[管理 CLI](/developer/admin-cli)。

## 分离查询和文本嵌入模型 {#separate-query-and-passage-embedders}

Recall 查询和存储文本现在可以使用不同的嵌入设置。任意 `HINDSIGHT_API_QUERY_EMBEDDINGS_<X>` 或 `HINDSIGHT_API_PASSAGE_EMBEDDINGS_<X>` 变量仅为对应一侧替代 `HINDSIGHT_API_EMBEDDINGS_<X>`；例如，搜索可以使用快速本地模型，存储文本则使用远程模型。

## 自定义 LLM 服务提供方 {#custom-llm-providers}

对于内置服务提供方均不支持的后端，可通过导入路径将服务提供方设为自己的类：`HINDSIGHT_API_LLM_PROVIDER=mypackage.llm:MyLLM`。全局设置、各操作设置和故障转移链均支持此功能。你的类也可以选择支持批量请求。

## 决策模型 Recall 的重排序器回退 {#reranker-fallback-for-decision-model-recall}

设置 `HINDSIGHT_API_RECALL_DECISION_MODEL_FALLBACK=true` 后，决策模型失败或拒绝处理的 Recall 将由配置的重排序器排序，而不会失败。此功能默认关闭。

## 大型记忆库加速 {#faster-on-large-banks}

大部分性能优化针对包含数十万条记忆的记忆库：此前某些查询扫描的行数远超所需。

| 加速的操作 | 之前 | 之后 |
| --- | --- | --- |
| 使用 `HINDSIGHT_API_TEXT_SEARCH_EXTENSION=vchord` 的关键词 Recall（整合中的长查询） | 5–6 s | 0.09 s |
| 检查共享一个标签的 53 个页面的更新状态（100k 条记忆） | 904 ms | 18 ms |
| 按标签集对观测分组（1M 条观测） | 3.2 s | 107 ms |
| 在标签范围内按一个名称搜索实体（300k 条记忆、20k 个实体） | 585 ms | 58 ms |
| 标签范围内的实体详情 | 68 ms | 4 ms |
| 统计待整合记忆（354k 行） | 256–756 ms | 2 ms |
| 检查是否还有整合工作（1M 行） | ~140 ms | ~12 ms |
| 许多观测共享来源时的 Recall token 预算分配 | 6.4 ms | 0.8 ms |
| 向 3,500 个现有文档执行带范围的 Retain | ~3 s | 每 1,000 个文档读取一次 |

此外：

- **所有连接池连接均关闭 Postgres JIT。** 在大型记忆库中，Postgres 以前每次调用都会编译 Recall 的观测查找；现在作为普通查询运行（在报告者的场景中从 210 ms 降至 50 ms）。
- **同一记忆库中的写入操作不再因图维护锁而相互排队。** 原本等待另一个 Retain 提交 3 秒的写入操作现在无需等待。
- 删除页面文件夹时，不再为其中每个页面重新扫描记忆库。

## 其他新增功能 {#smaller-additions}

- **文档标签**：使用 `PATCH` 和 `add_tags` / `remove_tags` 修改指定标签，无需发送完整标签集。
- **轮换数据库凭据**：`HINDSIGHT_API_DATABASE_CONNECT_HOOK` 指向自定义连接函数，使连接池的新连接获取最新凭据。
- **扩展**可以在存储前审查提取的记忆和整合写入，也可以拒绝刷新后的心智模型页面。
- **统计信息**会统计暂停自动刷新的心智模型，`total_links` 现在统计所有实体链接。
- **控制台**：可按记忆库开关 Recall 剪枝和去重。
- **CLI**：每个版本都附带原生 Windows x64 二进制文件。

## 可靠性 {#reliability}

- 临时故障和等待 LLM 槽位不再暂停心智模型的自动刷新。
- 对相同内容并发执行两次 Retain 时，每条事实只存储一次；批量提取会拒绝重复的自定义 ID。
- 已删除记忆库中正在运行的任务不再重新创建该库；重新创建的记忆库不再显示旧库的统计信息。
- 克隆、迁移导入和重命名不再占用已有别名；两个恢复操作同时尝试写入同一个新记忆库时会被拒绝，而不会合并。
- 关闭时，工作进程立即停止领取任务，并在宽限期内完成正在处理的工作。
- 已知嵌入后端不可用时，Retain 跳过 LLM 处理。
- 时间 Recall 兼容 dateparser 1.5.0。
- 大文档更新以批次保存，因此中断后仍保留已完成的进度。
- 工具调用的回复会根据所调用的函数进行检查，并在必要时纠正一次；Reflect 工具轮次和视觉 Retain 不再连续发送两个用户轮次，部分服务提供方会拒绝这种情况。
- 随 Retain 上传但因操作失败而遗留的图片和文件将由每日清理任务删除，不再永久保留（`HINDSIGHT_API_ATTACHMENT_SWEEP_INTERVAL_SECONDS`，设为 `0` 可关闭）。
- 使用 `hindsight` 服务提供方的决策模型 Recall 在一个请求中发送整个候选池，而不再拆分，从而减少调用次数。
- 关闭 `store_document_text` 的由记忆存储负责管理的记忆库不再保留分块文本。
- 整库导出和导入归档始终位于该记忆库的存储前缀下。
- 标签组从配置中移除后，由其标签派生的 tags 仍保留在记忆上。
- 追加操作对文本的分块方式与下一次追加时重新分块的方式一致。
- 整合收到不符合模式的回复时会重新询问一次，每条观测只保留最近三条先前状态备注；对于偏离主题的事实，心智模型更新可以不更改页面。
- OpenAI Responses 回复只读取最终答案；可选工具参数使用所有服务提供方均接受的模式。
- 即使租户扩展未列出基础数据库模式，启动时也会迁移它。
- 在 `SQL_ASCII` 数据库中，页面搜索摘要不再返回 500；在 Oracle 上，指向 Retain 期间被删除的记忆的链接不再导致批次失败。
- 本地模型在 Windows 上也会将释放的内存归还给操作系统。
- MCP 多记忆库工具每个结果只发送一次，不再重复发送。
- 记忆库统计中的 `total_links` 再次统计所有实体链接，心智模型读取和刷新的大小以 token 报告。

---

**数据库迁移：** 启动时会运行三项迁移。其中一项在 Oracle 上为大型表（`chunks`、`memory_units`）添加索引，因此大型 Oracle 部署需要预留额外时间。
