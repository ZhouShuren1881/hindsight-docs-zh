Hindsight 0.5.2 在控制平面中引入了新的实体共现图，使操作员能够更好地控制心智模型刷新，在异步操作上公开更丰富的元数据，并在记忆存储、集成和嵌入式守护进程中提供了一些可靠性修复。

<!-- truncate -->

- [**实体共现图**](#entity-co-occurrence-graph)：可视化实体如何在记忆库内连接。
- [**心智模型记忆召回控制**](#recall-controls-for-mental-models)：调整提供心智模型刷新的记忆召回步骤。
- [**异步操作可观察性**](#async-operation-observability)：任务负载和文档 ID 现在显示在异步操作上。
- [**改进记忆库统计**](#revamped-bank-statistics)：控制平面记忆库视图中的更清晰的见解。
- [**识别用户-智能体**](#identifying-user-agent)：所有HindsightSDK客户端现在发送可识别的用户智能体。
- [**可靠性修复**](#reliability-fixes)：记忆存储、集成、嵌入式守护进程和记忆库模板。

## 实体共现图 {#entity-co-occurrence-graph}

控制平面现在包括一个共现图视图，显示哪些实体在记忆库的记忆中一起出现。它可以轻松地发现往往同时出现的集群（人员、项目、工具），并从节点导航到连接它们的记忆。这是实体解析和图检索的天然伴侣，为操作员提供了一种直观的方式来检查记忆库知识图的形状，而无需编写查询。

![Hindsight控制平面中的实体共现图](/img/blog/hindsight-0-5-2-entity-graph.webp)

## 心智模型记忆召回控制 {#recall-controls-for-mental-models}

心智模型是从记忆库的基本事实合成的综合知识。到目前为止，提供心智模型刷新的记忆召回步骤使用固定默认值。在 0.5.2 中，心智模型触发器 API 接受记忆召回控制 - 因此您可以调整每次刷新时提取的上下文数量和类型。当您想要更紧密、以主题为中心的心智模型时，或者相反，当您想要在特定刷新时拓宽网络时，这非常有用。

## 异步操作可观察性 {#async-operation-observability}

异步操作（记忆存储、整合、展望）现在公开了底层任务负载和它们接触的文档 ID。以前，您只能看到操作状态，但看不到它实际在做什么。通过此更改，您可以将异步操作关联回其摄取的文档或计划的任务 - 对于仪表板、调试卡住的操作和审核工作人员行为非常有用。

## 改进记忆库统计 {#revamped-bank-statistics}

​​控制平面记忆库统计视图已在一组现代化的共享 UI 原语之上重建。信息密度更高，图表更容易一目了然，并且相同的原语现在可以在其他控制平面视图中重复使用，以获得更一致的外观和感觉。

![改进了Hindsight控制平面中的记忆库统计视图](/img/blog/hindsight-0-5-2-bank-stats.webp)

## 识别用户-智能体 {#identifying-user-agent}

所有官方 Hindsight 客户端 — Python、TypeScript、Rust/Go — 现在在每个 HTTP 请求上发送一个标识性 `User-Agent` 标头。这使得服务器端日志、代理日志和可观察性仪表板更易于阅读：您可以一眼看出哪个SDK版本正在推动流量，在野外发现过时的客户端，并在调试时按客户端过滤流量。

## 可靠性修复 {#reliability-fixes}

一系列修复解决了生产和长期运行的基准测试中发现的边缘情况：

- **整合重试预算。** 重试预算现在已正确应用于LLM 调用站点，因此集成实际上遵循配置的重试限制，而不是默默地过度或不足重试。
- **记忆存储长度不匹配崩溃。**记忆存储不再引发`IndexError`——检测并处理不匹配情况。
- **嵌入式守护进程清理。** 嵌入模式清理路径现在在获取其锁定时使用超时，以防止在争用情况下关闭时出现一类挂起。
- **OpenClaw智能体钩子注册。**OpenClaw插件在每次条目调用时可靠地注册其智能体挂钩，修复了自动记忆召回/自动记忆存储可以在重复插件加载时默默停止触发的回归。
- **记忆库模板配置。** `BankTemplateConfig` 验证现在与 `_CONFIGURABLE_FIELDS` 集保持一致，因此在模板应用程序时会捕获无效或先前忽略的设置。
- **TypeScript SDK 类型导出。** `BankTemplate` 类型从包根重新导出，因此使用者不再需要进入子路径来导入它们。

## 变更日志工具 {#changelog-tooling}

0.5.2 也是第一个版本，对我们的变更日志生成器进行了小改动：仅涉及 `hindsight-integrations/` 的提交现在被排除在主变更日志之外。集成已经转向自己的发布节奏（每个都有自己的标签和每个集成变更日志），因此将它们排除在核心变更日志之外使得核心发行说明集中在API、控制平面、客户端和基准测试上。
