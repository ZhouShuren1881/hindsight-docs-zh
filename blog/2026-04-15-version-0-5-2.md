Hindsight 0.5.2 在控制台中新增实体共现图，让运维人员可以更灵活地控制心智模型刷新，为异步操作公开更丰富的元数据，并针对 Retain（存入）、整合和嵌入式守护进程修复了一些可靠性问题。

<!-- truncate -->

- [**实体共现图**](#entity-co-occurrence-graph)：可视化记忆库中实体之间的关联。
- [**心智模型的召回控制**](#recall-controls-for-mental-models)：调整为心智模型刷新提供上下文的 Recall（召回）步骤。
- [**异步操作的可观测性**](#async-operation-observability)：现在会在异步操作中显示任务载荷和文档 ID。
- [**改版后的记忆库统计**](#revamped-bank-statistics)：让控制台中的记忆库视图呈现更清晰的信息。
- [**标识客户端的 User-Agent**](#identifying-user-agent)：所有 Hindsight SDK 客户端现在都会发送可识别客户端的 User-Agent。
- [**可靠性修复**](#reliability-fixes)：涵盖 Retain、整合、嵌入式守护进程和记忆库模板。

## 实体共现图 {#entity-co-occurrence-graph}

控制台现在提供共现图视图，展示记忆库的记忆中有哪些实体共同出现。借助该视图，可以轻松发现经常共同出现的实体群组（例如人物、项目和工具），还可以从节点进入将它们关联起来的记忆。这项功能与实体消解和图检索相辅相成，让运维人员无需编写查询，就能直观检查记忆库知识图谱的结构。

![Hindsight 控制台中的实体共现图](/img/blog/hindsight-0-5-2-entity-graph.webp)

## 心智模型的召回控制 {#recall-controls-for-mental-models}

心智模型是基于记忆库底层事实整合后综合生成的知识。此前，为心智模型刷新提供依据的召回步骤使用固定默认值。0.5.2 中，心智模型触发器 API 开始接受召回控制参数，因此你可以调整每次刷新所获取的上下文数量和类型。如果你想让心智模型更聚焦于特定主题，可以收窄范围；如果想在某次刷新中扩大检索范围，也可以相应调整。

## 异步操作的可观测性 {#async-operation-observability}

现在，异步操作（Retain（存入）、整合、Reflect（反思））会公开底层任务载荷以及涉及的文档 ID。此前，你只能看到操作状态，却看不到它实际处理的内容。此次更新后，你可以将异步操作与它摄取的文档或安排给它的任务对应起来，这有助于构建仪表板、调试卡住的操作，以及审计工作进程的行为。

## 改版后的记忆库统计 {#revamped-bank-statistics}

控制台中的记忆库统计视图现已基于一套现代化的共享 UI 基础组件重建。该视图展示的信息更丰富，图表也更便于快速查看；同一套基础组件还用于控制台的其他视图，使整体观感更加一致。

![Hindsight 控制台中改版后的记忆库统计视图](/img/blog/hindsight-0-5-2-bank-stats.webp)

## 标识客户端的 User-Agent {#identifying-user-agent}

所有官方 Hindsight 客户端（Python、TypeScript、Rust/Go）现在都会在每个 HTTP 请求中发送可识别客户端的 `User-Agent` 标头。这样一来，服务器日志、代理日志和可观测性仪表板都更易于阅读：你可以一眼看出当前流量使用的是哪个 SDK 版本，发现正在使用的过时客户端，并在调试时按客户端筛选流量。

## 可靠性修复 {#reliability-fixes}

一系列修复解决了生产环境和长时间运行的基准测试中发现的边缘情况：

- **整合重试预算。** 重试预算现在会在 LLM 调用处正确生效，因此整合会遵循配置的重试上限，不再悄然重试过多或过少。
- **Retain 长度不匹配导致的崩溃。** 当生成的嵌入向量数量与提取出的事实数量不一致时，Retain 不再引发 `IndexError`，而是会检测并处理这一不匹配情况。
- **嵌入式守护进程清理。** 嵌入式模式的清理流程现在会在获取锁时使用超时，从而避免在资源竞争时关闭程序可能发生的一类挂起问题。
- **OpenClaw 智能体钩子注册。** OpenClaw 插件现在会在每次入口调用时可靠地注册其智能体钩子，修复了重复加载插件后自动召回/自动存入可能悄然停止触发的回归问题。
- **记忆库模板配置。** `BankTemplateConfig` 的验证现在与 `_CONFIGURABLE_FIELDS` 集合保持一致，因此应用模板时会捕获无效或此前被忽略的设置。
- **TypeScript SDK 类型导出。** `BankTemplate` 类型现在从包根目录重新导出，使用者无需再进入子路径导入这些类型。

## 变更日志工具 {#changelog-tooling}

0.5.2 也是首次在变更日志生成器中引入一项小改动的版本：现在，仅修改 `hindsight-integrations/` 的提交会从主变更日志中排除。集成项目已采用独立的发布节奏（每个集成都有自己的标签和变更日志），将它们排除在核心变更日志之外，可以让核心发行说明专注于 API、控制台、客户端和基准测试。
