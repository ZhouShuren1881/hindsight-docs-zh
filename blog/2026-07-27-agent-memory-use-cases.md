“智能体记忆”听起来很抽象，直到您注意到它是应用于十几个不同问题的相同解决方案。任何时候，智能体应该记住当前会话之后的事情，并且今天从一张白纸开始，这就是一个记忆形状的洞。 [Hindsight](https://vectorize.io/hindsight) 到处都用相同的三个操作填充它：`retain` 写入，`recall` 读取，`reflect` 推理。从一个用例到下一个用例的变化不是原语，而是记忆属于谁以及它出现在哪里。

这里是人们实际构建的智能体记忆用例，每个用例都有一个具体的例子。

<!-- truncate -->

## ​​1。编码了解您的代码库的智能体 {#1-coding-agents-that-know-your-codebase}

这是最常见的一种，因为编码智能体是最明显的健忘症。每个新会话，您的智能体都会重新学习您使用 `uv` 而不是 pip，API 是 asyncpg 上的 FastAPI，您上个月决定删除消息队列。持久记忆会保留这些约定、决策和过去的错误，因此您在存储库中工作的时间越长，智能体就会变得越有用。

Hindsight 已插入大多数流行的代码：Aider、Zed、Cursor、Claude Code、Roo Code 和 ZCode。记忆库通常按存储库划分范围，因此记忆约为 *这个* 代码库。由于存储位于任何一种工具之外，因此您在一个编辑器中构建的上下文也存在于下一个工具中。

## 2。具有每个用户记忆的面向客户的产品 {#2-customer-facing-products-with-per-user-memory}

当你的产品为多个人服务时，记忆就变成了一种数据模型决策，而不是功能切换。每个用户都需要自己独立的记忆，并且这些记忆绝不能在租户之间泄漏。这是一个每个用户的记忆库，预先确定边界很重要。

一位构建者写的正是这样做的：[多用户AI 从第一天起就记住金融产品](/blog/2026/04/13/hindsight-financial-ai-memory-customer-story)，其中每个用户的历史记录都局限于他们自己的记忆库，因此助手可以记住他们的情况，而无需看到其他人的情况。这是任何助手背后的模式，需要在每次使用它时专门记住*你*。

## 3。支持和客户助理 {#3-support-and-account-assistants}

支持是最纯粹形式的记忆。客户不必每次回来时都重新解释他们的设置、计划或上周提出的问题。由“记忆”支持的助手会在回答之前回忆帐户的历史记录，因此对话将从中断处继续，而不是重新开始。

这里的形状是每个客户的记忆，通常与`tags`结合使用，以将计费等主题与一个帐户内的技术问题分开。 `reflect` 也能赚到钱：“这个帐户的总体状态是什么”是一个综合问题，而不是查找问题。

## 4。跨通话记忆的语音智能体 {#4-voice-agents-that-remember-across-calls}

语音提高了记忆的风险，因为呼叫者希望被认识。没有人愿意向昨天迎接他们的智能语音重复他们的名字、订单号和问题。 Hindsight 与 Vapi 和 Pipecat 等语音堆栈集成，因此可以在智能体已经知道谁在呼叫以及上次发生了什么的情况下打开呼叫。

机制与文本相同：记忆召回通话开始时的相关历史记录，记忆存储通话结束时发生的情况。不同之处在于，在声音中，遗忘显然更加粗鲁。

## 5。聊天平台智能体 {#5-chat-platform-agents}

Slack、Discord 或 Telegram 中的智能体面临特定记忆挑战：许多用户、许多渠道、一个机器人。您通常希望机器人记住跨渠道的人，或跨人的渠道上下文，并且您想要选择哪一个。像 OpenClaw 这样的集成可以通过每个用户或每个渠道的范围来处理这个问题，以便机器人的记忆与您的团队的实际工作方式相匹配。

## 6。你自己建造的任何智能体 {#6-any-agent-you-build-yourself}

并非每个智能体都是现成的工具。如果您正在构建一个框架，那么记忆应该是一个临时项目，而不是一个项目。 Hindsight 具有跨框架生态系统的集成：LangGraph、CrewAI、Pydantic AI、Google ADK、OpenAI 智能体 SDK、LlamaIndex 等，以及任何使用它的普通 MCP。

价值在于你不构建记忆系统。您针对记忆库调用`retain`和`recall`（当您需要综合时还调用`reflect`），困难的部分、提取、实体解析、集成和排名检索都会为您处理。

## 7。共享所学知识的多智能体系统 {#7-multi-agent-systems-that-share-what-they-learn}

当你管理一个由智能体、规划者、研究人员、审阅者组成的团队时，有趣的行为来自于他们相互构建。将他们指向一个共享的记忆库，研究人员保留的事实可供记忆召回上的审阅者使用。记忆成为团队的共同理解，而不是每个智能体的私人笔记本。

对立面是隔离：应该*不是*共享上下文的智能体拥有自己的记忆库。哪个智能体共享一个记忆库是整个设计决策，我们写了一个[正确使用的现场指南](/blog/2026/07/16/bank-strategy-agent-memory)。

## 8。对记忆做出反应的自动化 {#8-automations-that-react-to-memory}

记忆不仅仅用于聊天。通过Zapier和n8n，工作流程可以在事件触发时记忆存储某些内容，并在稍后记忆并做出决定。表单提交成为持久的事实；预定的工作反映了一周积累的记忆以产生摘要。 记忆成为自动化中的一流步骤，而不是附加的数据库。

## 共同点 {#the-common-thread}

这些都不是不同的产品。它们是相同的原语，`retain`、`recall`和`reflect`在记忆库上，范围和表面不同。每个存储库的编码智能体范围。每个用户的产品范围。团队共享一个记忆库。自动化对事件进行写入和读取。一旦你将智能体记忆视为“谁拥有这个记忆，它出现在哪里”，用例就不再看起来像一个列表，而是开始看起来像一种你可以指向任何地方的功能。

如果您有一个每次会话都从零开始的智能体，那么您就有一个用例。剩下的就是决定如何确定其范围。
