为记忆库写下“关注计费决策以及谁批准了它们”这样的使命，保存后，提取可能改善，也可能没有。

那么，这句话到底放到了哪里？

如果猜系统提示词，在使用它的三种操作中，有两种猜错了。

<!-- truncate -->

## 要点 {#tldr}

- 存储和整合使命位于**用户**消息。反思使命位于系统提示词，替换智能体角色行，而非追加。
- `POST /banks/{id}/prompts/preview` 返回存储、整合或反思将发送的准确消息，不调用 LLM、不写入。
- 活动块逐字节拼接为真实提示词，测试验证其与实际构建器一致。
- 已关闭设置以非活动块返回，位于它原本应出现的位置。
- 端点有意拒绝示例文本或候选使命。
- 随 v0.10.0 发布，Cloud 与自托管均可使用。

## 为什么使命放到了用户消息 {#why-the-mission-moved}

存储和整合的系统前缀有意不依赖记忆库，同一服务器所有库使用相同前缀，提供商的一份提示缓存即可共享。将各库使命写进前缀，会变成每库独立缓存，高吞吐摄取中成本明显。

因此使命放入用户消息：retain 使用代码围栏包裹的 `FOCUS` 前言，整合使用 `## MISSION` 标题。Reflect 是例外，`reflect_mission` **替换角色行**，而非追加。“关注计费问题”会悄然删除“你是通过检索记忆进行推理、回答问题的反思智能体”这条默认角色说明。

配置页看不出这些。你设置字符串，位置由代码决定。

预览填补的就是这个空白。新增功能的提交直言：只有看到使命进入的提示词，它才有实际意义；此前必须追踪 Python 常量和格式化调用。

## 返回什么 {#what-it-returns}

`POST /v1/default/banks/{bank_id}/prompts/preview` 接收操作名称，按发送顺序返回消息，并将每条拆成块：

```json
{
  "text": "FOCUS — 此记忆库应存储什么……",
  "source": "config",
  "field": "retain_mission",
  "active": true,
  "kind": "text",
  "editable": true
}
```

每块标明来源：`source` 为 `config` 或 `builtin`，`field` 表示对应设置，`editable` 指示它是可修改的记忆库级配置，还是服务端配置；若界面提供修改后者，只会得到 400。

核心保证写在代码注释里：*活动块精确划分提示词*。拼接后就是模型收到的字节。测试并排渲染预览和真实提取提示词，断言完全一致，防止偏离。

两条消息始终返回，即使一条为空。只显示系统提示词，会让已配置的使命看起来不存在，模块说明指出这恰好与事实相反。

## 看得见的缺失项 {#absence-you-can-see}

设计得很好的部分是关闭设置时的处理。

它仍返回：`active: false`、空文本，位于启用时*本该*出现的位置。空文本无法通过匹配定位，渲染器将其锚定到上一个匹配片段，而非漂到响应末尾，否则无法说明位置。

源码中的理由是：

> 尚未写下的使命，正是你来到这里准备编写的内容；它目前没有文字可供定位。

两项细化避免噪声：不存在对应位置时不生成关闭块，例如非 `custom` 模式不显示 `retain_custom_instructions`，因为构建器不会读取；整合使命永不显示为非活动，因为未设置时由内置默认值填充。

## 不接收示例文本 {#it-wont-take-your-sample-text}

这是最容易引起反对的设计：请求体只包含操作，以及可选的存储策略。不能传候选使命，也不能传自定义示例文本。

文档字符串不仅记录设计，也解释理由：

> 操作就是整个请求：影响提示词的内容都来自记忆库，有意不提供覆盖项。预览回答“这个记忆库发送什么”；允许调用方传使命或示例，会把问题移到记忆库无法回答的地方。测试候选值时，先保存，再查看。

因此每块都带 `editable`。工作流是“修改，再查看”，不是模拟修改。控制平面提供该循环：就地编辑块对应设置，保存后重新获取预览。

若要查看*输出*，使用另一个端点。存储测试器执行真实 LLM 提取试运行，不保存内容，与预览不同，它允许少量白名单覆盖项。一个免费展示输入，另一个付一次调用费用展示输出。

## 只有查看才能知道的细节 {#things-you-can-only-learn-by-looking}

提示词组装存在边界问题，以下均是真实行为，配置页却看不出来。

| 设置 | 实际行为 |
|---|---|
| 策略名称拼错 | 记录警告而非错误；策略内未知字段静默忽略 |
| 非 `custom` 模式设置 `retain_custom_instructions` | 不读取，设置无效 |
| `custom` 模式但指令为空 | 静默回退到 `concise` |
| 无 `entity_labels` 却设置 `entities_allow_free_form` | 无效，该句只位于配置标签后才存在的标签区 |
| `llm_output_language` | 替换默认语言规则，避免矛盾，不是追加 |
| `chunks` 提取模式 | 不发送提示词，使命、标签和自定义指令均不生效 |

最能说明此端点必要性的，是它自己的提交：试运行和预览曾直接解析配置，没经过 retain 解析器，导致默认策略记忆库的预览使用真实存储不会采用的设置。展示真相的工具一度也说了同样的谎，现在已加入回归测试。

## 成本与影响范围 {#what-it-costs-and-what-it-touches}

不花费模型调用，也不修改状态。

渲染器不访问 LLM 客户端、队列或锁，不创建不存在的记忆库，不写操作记录，路由也无审计装饰器。测试断言预览后记忆单元数量不变。

权限与读取记忆库配置相同，不是普通读取权限。将设置渲染为提示词只是另一条披露路径，因此扩展拒绝读取配置时，也拒绝预览。由于渲染器使用完全解析的内部配置，还有专门测试确保提供商凭据不会泄露。

## 预览没有展示的内容 {#what-it-doesnt-show}

将预览视为完整事实前，应了解：

- **省略部分运行时区块。** 存储预览显示分块、事件日期和上下文，却不显示真实调用中的元数据、叙述者或附件指令。图片较多的记忆库会缺少相当一段文字。
- **Reflect 按最大能力渲染。** 包含全部工具、无标签指令，没有请求级预算指导。真实调用选项不同，提示词也不同。
- **整合的容量说明不会出现。**
- **没有 CLI 或 MCP。** 只有 HTTP 端点和生成的客户端方法；CLI 豁免说明，多块响应是面向界面的结构，不适合作为 CLI 输出。
- **块归属尽力而为。** 构建器改写片段时，该块可能被跳过，其文字保留在周边内置块中。拼接保证仍成立，标签降级也不影响提示词准确性。

## 常见问题 {#faq}

**预览消耗 token 吗？**
不消耗，不调用模型。控制平面测试器的提取试运行会调用，明确标为付费部分。

**能预览未保存的修改吗？**
不能，先保存再查看。响应标明可编辑块，便于知道可修改什么。

**系统消息看起来为空，为何返回两条消息？**
因为存储和整合使命在用户消息，只显示系统消息会让配置看起来缺失。

**与提取测试器有什么区别？**
同一对话框，不同部分。预览免费展示三种操作的输入；测试器仅针对 retain，对示例文本执行真实提取，不保存。
