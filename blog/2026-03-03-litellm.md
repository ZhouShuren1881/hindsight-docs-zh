`hindsight-litellm`为任何内容添加持久记忆LLM提供者通过LiteLLM — OpenAI, Anthropic、Groq、Azure、基岩、顶点AI，以及 100 多个以上。三行设置，每行LLM呼叫会自动从过去的对话中获取上下文。

## 问题：无状态LLM 调用 {#the-problem-stateless-llm-calls}

您使用LLM构建应用程序。用户周一与其交谈。周二回来。 LLM 不知道他们是谁。

这对于每个提供商都是如此。 OpenAI、Anthropic、Groq、Azure — 每个 API 调用都是一张白纸。 LLM 不记得偏好、过去的对话或您之前讨论过的任何内容。

大多数团队通过将最后 N 条消息填充到上下文窗口中来解决此问题。但这不是记忆——它是一个滑动窗口，会删除所有早于token限制的内容。用户上周的偏好？走了。上个月的项目背景？走了。

如果每个 LLM 呼叫都自动拥有过去对话中的正确上下文会怎么样？

---

## 修复：三条线，任何提供商 {#the-fix-three-lines-any-provider}

`hindsight-litellm` 挂钩到 LiteLLM 以拦截每个 LLM 调用。在调用之前，它从Hindsight检索相关记忆并将其注入到提示中。通话结束后，它会存储对话以供将来检索。

```
Your code ──→ hindsight_litellm.completion()
                    │
                    ├─→ 1. Recall/Reflect from Hindsight (relevant memories)
                    ├─→ 2. Inject memories into prompt
                    ├─→ 3. Forward to LLM (any provider via LiteLLM)
                    ├─→ 4. Store conversation to Hindsight
                    └─→ 5. Return response
```

设置如下：

```python
import hindsight_litellm

hindsight_litellm.configure(
    hindsight_api_url="http://localhost:8888",
)

hindsight_litellm.set_defaults(
    bank_id="my-agent",
)

hindsight_litellm.enable()
```

就是这样。现在每个`completion()`调用都有记忆：

```python
response = hindsight_litellm.completion(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "帮助我完成我的Python项目"}],
    hindsight_query="我对用户的Python项目了解多少？",
)
```

`hindsight_query`告诉Hindsight要在记忆中搜索什么。响应会返回过去对话的上下文 - LLM 了解用户的项目、他们的偏好、他们的技术堆栈。

> **注意：** 您还可以使用 [Hindsight Cloud](https://ui.hindsight.vectorize.io) 并完全跳过自托管设置。

## 任何提供商，相同的记忆 {#any-provider-same-memory}

由于集成通过LiteLLM运行，因此它可以与LiteLLM支持的每个提供商配合使用。自由切换模型——记忆如下：

```python
messages = [{"role": "user", "content": "上次我们讨论了什么？"}]
query = "我与该用户讨论了什么？"

# OpenAI
hindsight_litellm.completion(model="gpt-4o", messages=messages, hindsight_query=query)

# Anthropic
hindsight_litellm.completion(model="claude-sonnet-4-20250514", messages=messages, hindsight_query=query)

# Groq
hindsight_litellm.completion(model="groq/llama-3.1-70b-versatile", messages=messages, hindsight_query=query)

#天蓝色OpenAI
hindsight_litellm.completion(model="azure/gpt-4", messages=messages, hindsight_query=query)

#AWS 基岩
hindsight_litellm.completion(model="bedrock/anthropic.claude-3", messages=messages, hindsight_query=query)

#Google 顶点AI
hindsight_litellm.completion(model="vertex_ai/gemini-pro", messages=messages, hindsight_query=query)
```

相同的记忆库，相同的记忆，任何型号。从OpenAI迁移到Anthropic，你的智能体仍然知道一切。

## 两种记忆模式 {#two-memory-modes}

### 记忆召回：原始记忆 {#recall-raw-memories}

默认模式检索单个记忆事实并将它们作为编号列表注入：

```python
hindsight_litellm.set_defaults(bank_id="my-agent", use_reflect=False)
```

LLM 看到类似以下内容：

```
#相关记忆
1. [WORLD] User is building a FastAPI application
2. [WORLD] User prefers pytest for testing
3. [OBSERVATION] User likes type hints
```

最适合LLM需要单独数据点的精确、事实上下文。

### 反思：综合语境 {#reflect-synthesized-context}

反思模式将记忆合成为一个连贯的段落，而不是原始事实：

```python
hindsight_litellm.set_defaults(
    bank_id="my-agent",
    use_reflect=True,
    reflect_context="我是一名编码助理，帮助完成Python项目。",
)
```

LLM 看到类似以下内容：

```
The user is an experienced Python developer working on a FastAPI application.
They prefer pytest for testing and value type hints. In past conversations,
they asked about async patterns and database migrations.
```

最适合自然的对话环境。 `reflect_context` 参数决定Hindsight 如何推理记忆而不影响它检索的内容。

## 直接记忆 API {#direct-memory-apis}

有时您想在LLM调用之外查询记忆。直接 API 为您提供完全控制：

### 记忆召回 — 查询原始记忆 {#recall--query-raw-memories}

```python
from hindsight_litellm import recall

memories = recall("用户正在从事哪些项目？", budget="mid")
for m in memories:
    print(f"- [{m.fact_type}] {m.text}")
```

### 反思 — 综合上下文 {#reflect--synthesized-context}

```python
from hindsight_litellm import reflect

result = reflect(
    "你对用户的偏好了解多少？",
    context="我是一名客户支持智能体。",
)
print(result.text)
```

### 记忆存储 — 手动存储记忆 {#retain--store-memories-manually}

```python
from hindsight_litellm import retain

retain(
    content="用户提到他们正在从 Flask 切换到 FastAPI",
    context="关于Web框架的讨论",
)
```

这三个都有异步变体：`arecall()`、`areflect()`、`aretain()`。

## 每次调用覆盖 {#per-call-overrides}

默认很方便，但有时您需要每次调用控制：

```python
response = hindsight_litellm.completion(
    model="gpt-4o-mini",
    messages=[...],
    hindsight_query="我对爱丽丝了解多少？",
    hindsight_bank_id="other-agent",          #这次通话的不同记忆库
    hindsight_budget="high",                  #更彻底的检索
    hindsight_reflect_context="目前正在帮助入职",
)
```

任何默认值都可以用 `hindsight_*` 前缀覆盖。

## 原生SDK 包装器 {#native-sdk-wrappers}

如果直接使用OpenAI或Anthropic SDK（不带LiteLLM），则有原生包装器：

### OpenAI {#openai}

```python
from openai import OpenAI
from hindsight_litellm import wrap_openai

client = OpenAI()
wrapped = wrap_openai(
    client,
    bank_id="my-agent",
    hindsight_api_url="http://localhost:8888",
)

response = wrapped.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "你对我了解多少？"}]
)
```

### Anthropic {#anthropic}

```python
from anthropic import Anthropic
from hindsight_litellm import wrap_anthropic

client = Anthropic()
wrapped = wrap_anthropic(
    client,
    bank_id="my-agent",
    hindsight_api_url="http://localhost:8888",
)

response = wrapped.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello!"}]
)
```

相同的记忆，没有LiteLLM依赖性。

## 上下文管理器 {#context-manager}

对于临时记忆整合：

```python
from hindsight_litellm import hindsight_memory
import litellm

with hindsight_memory(
    hindsight_api_url="http://localhost:8888",
    bank_id="user-123",
):
    response = litellm.completion(
        model="gpt-4o",
        messages=[{"role": "user", "content": "Hello!"}],
        hindsight_query="问候语",
    )
#记忆积分在区块后自动禁用
```

## 记忆库 使命 {#bank-missions}

告诉Hindsight记忆库应该构建什么样的知识。这决定了记忆如何整合到心智模型中。将`mission`和`bank_name`传递给`configure()`：

```python
hindsight_litellm.configure(
    hindsight_api_url="http://localhost:8888",
    mission="""此智能体路由客户支持请求。
    记住哪些问题类型属于哪些团队（计费、技术、销售）。
    ​​跟踪客户偏好和过去的解决方案。""",
    bank_name="客户支持路由器",
)
```

## 回顾 {#recap}

- `hindsight-litellm` 在对话中提供任何 LLM 持久记忆
- 通过LiteLLM以及本机OpenAI和Anthropic包装器与100多个提供商合作
- 三行设置：`configure()`、`set_defaults()`、`enable()`
- 两种模式：`recall`用于原始事实，`reflect`用于合成上下文
- 直接 API（`recall`、`reflect`、`retain`）用于手动记忆控制
- 每次调用覆盖、记忆库任务、异步支持和调试模式

集成自动处理记忆检索、提示注入和对话存储。您只需像往常一样调用 `completion()` — LLM 会记住一切。
