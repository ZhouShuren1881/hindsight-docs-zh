## 问题：无状态的 LLM 调用 {#the-problem-stateless-llm-calls}

你用 LLM 构建了一个应用。用户周一和它交谈，周二回来时，LLM 却完全不知道对方是谁。

每家服务提供方都如此。无论 OpenAI、Anthropic、Groq 还是 Azure，每次 API 调用都像一张白纸。LLM 不记得用户的偏好、过去的对话，也不记得之前讨论过的任何内容。

大多数团队会把最近的 N 条消息塞进上下文窗口来应对。但这不是记忆，而是一个滑动窗口：超过 token 限制的旧内容都会被丢弃。用户上周的偏好？没了。上个月的项目背景？也没了。

如果每次 LLM 调用都能自动获得过去对话中恰当的上下文，会怎么样？

---

## 解决方案：三行配置，支持任何服务提供方 {#the-fix-three-lines-any-provider}

`hindsight-litellm` 接入 LiteLLM，拦截每次 LLM 调用。调用前，它会从 Hindsight 检索相关记忆，并将记忆注入提示词；调用后，它会存储这段对话，供之后检索。

```
你的代码 ──→ hindsight_litellm.completion()
                    │
                    ├─→ 1. 从 Hindsight 执行 Recall（召回）/ Reflect（反思），获取相关记忆
                    ├─→ 2. 将记忆注入提示词
                    ├─→ 3. 将请求转发给 LLM（通过 LiteLLM 使用任何服务提供方）
                    ├─→ 4. 将对话存入 Hindsight
                    └─→ 5. 返回响应
```

配置方法如下：

```python
import hindsight_litellm

hindsight_litellm.configure(
    hindsight_api_url="http://localhost:8888",
)

hindsight_litellm.set_defaults(
    bank_id="my-agent",
)

hindsight_litellm.enable()
```

就这么简单。现在，每次调用 `completion()` 都会带上记忆：

```python
response = hindsight_litellm.completion(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Help me with my Python project"}],
    hindsight_query="What do I know about the user's Python project?",
)
```

`hindsight_query` 告诉 Hindsight 要在记忆中搜索什么。响应会带上过去对话中的上下文，因此 LLM 能了解用户的项目、偏好和技术栈。

> **注意：** 你也可以使用 [Hindsight Cloud](https://ui.hindsight.vectorize.io)，完全跳过自托管配置。

## 任意服务提供方，同一份记忆 {#any-provider-same-memory}

由于集成通过 LiteLLM 运行，因此支持 LiteLLM 提供的所有服务提供方。你可以自由切换模型，记忆会随之保留：

```python
messages = [{"role": "user", "content": "What did we discuss last time?"}]
query = "What have I discussed with this user?"

# OpenAI
hindsight_litellm.completion(model="gpt-4o", messages=messages, hindsight_query=query)

# Anthropic
hindsight_litellm.completion(model="claude-sonnet-4-20250514", messages=messages, hindsight_query=query)

# Groq
hindsight_litellm.completion(model="groq/llama-3.1-70b-versatile", messages=messages, hindsight_query=query)

# Azure OpenAI
hindsight_litellm.completion(model="azure/gpt-4", messages=messages, hindsight_query=query)

# AWS Bedrock
hindsight_litellm.completion(model="bedrock/anthropic.claude-3", messages=messages, hindsight_query=query)

# Google Vertex AI
hindsight_litellm.completion(model="vertex_ai/gemini-pro", messages=messages, hindsight_query=query)
```

同一个记忆库、同一份记忆，适用于任何模型。从 OpenAI 迁移到 Anthropic 后，你的智能体依然记得一切。

## 两种记忆模式 {#two-memory-modes}

### Recall：原始记忆 {#recall-raw-memories}

默认模式会检索单条记忆事实，并将它们作为编号列表注入：

```python
hindsight_litellm.set_defaults(bank_id="my-agent", use_reflect=False)
```

LLM 看到的内容大致如下：

```
# Relevant Memories
1. [WORLD] User is building a FastAPI application
2. [WORLD] User prefers pytest for testing
3. [OBSERVATION] User likes type hints
```

适合需要单独数据点的 LLM 获取精确、基于事实的上下文。

### Reflect：综合生成的上下文 {#reflect-synthesized-context}

Reflect 模式会将记忆综合生成连贯的段落，而不是提供原始事实：

```python
hindsight_litellm.set_defaults(
    bank_id="my-agent",
    use_reflect=True,
    reflect_context="I am a coding assistant helping with Python projects.",
)
```

LLM 看到的内容大致如下：

```
The user is an experienced Python developer working on a FastAPI application.
They prefer pytest for testing and value type hints. In past conversations,
they asked about async patterns and database migrations.
```

适合提供自然、符合对话语境的上下文。`reflect_context` 参数会影响 Hindsight 如何依据记忆进行推理，但不会改变它检索的内容。

## 直接调用记忆 API {#direct-memory-apis}

有时，你可能想在 LLM 调用之外查询记忆。直接调用 API 可以让你完全掌控这些操作：

### Recall — 查询原始记忆 {#recall--query-raw-memories}

```python
from hindsight_litellm import recall

memories = recall("what projects is the user working on?", budget="mid")
for m in memories:
    print(f"- [{m.fact_type}] {m.text}")
```

### Reflect — 综合生成上下文 {#reflect--synthesized-context}

```python
from hindsight_litellm import reflect

result = reflect(
    "what do you know about the user's preferences?",
    context="I am a customer support agent.",
)
print(result.text)
```

### Retain（存入）— 手动存储记忆 {#retain--store-memories-manually}

```python
from hindsight_litellm import retain

retain(
    content="User mentioned they're switching from Flask to FastAPI",
    context="Discussion about web frameworks",
)
```

这三种操作都有异步版本：`arecall()`、`areflect()` 和 `aretain()`。

## 单次调用覆盖默认值 {#per-call-overrides}

默认值很方便，但有时你需要针对某次调用单独控制：

```python
response = hindsight_litellm.completion(
    model="gpt-4o-mini",
    messages=[...],
    hindsight_query="What do I know about Alice?",
    hindsight_bank_id="other-agent",          # 此次调用使用其他记忆库
    hindsight_budget="high",                  # 进行更全面的检索
    hindsight_reflect_context="Currently helping with onboarding",
)
```

任何默认值都可以通过带有 `hindsight_*` 前缀的参数覆盖。

## 原生 SDK 包装器 {#native-sdk-wrappers}

如果你直接使用 OpenAI 或 Anthropic SDK（不通过 LiteLLM），也可以使用原生包装器：

### OpenAI {#openai}

```python
from openai import OpenAI
from hindsight_litellm import wrap_openai

client = OpenAI()
wrapped = wrap_openai(
    client,
    bank_id="my-agent",
    hindsight_api_url="http://localhost:8888",
)

response = wrapped.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "What do you know about me?"}]
)
```

### Anthropic {#anthropic}

```python
from anthropic import Anthropic
from hindsight_litellm import wrap_anthropic

client = Anthropic()
wrapped = wrap_anthropic(
    client,
    bank_id="my-agent",
    hindsight_api_url="http://localhost:8888",
)

response = wrapped.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello!"}]
)
```

记忆保持一致，且不依赖 LiteLLM。

## 上下文管理器 {#context-manager}

如果只想临时启用记忆集成，可以使用上下文管理器：

```python
from hindsight_litellm import hindsight_memory
import litellm

with hindsight_memory(
    hindsight_api_url="http://localhost:8888",
    bank_id="user-123",
):
    response = litellm.completion(
        model="gpt-4o",
        messages=[{"role": "user", "content": "Hello!"}],
        hindsight_query="greeting context",
    )
# 退出代码块后会自动禁用记忆集成
```

## 记忆库任务说明 {#bank-missions}

告诉 Hindsight，你希望记忆库构建哪类知识。这会影响记忆如何整合为心智模型。将 `mission` 和 `bank_name` 传给 `configure()`：

```python
hindsight_litellm.configure(
    hindsight_api_url="http://localhost:8888",
    mission="""This agent routes customer support requests.
    Remember which issue types go to which teams (billing, technical, sales).
    Track customer preferences and past resolutions.""",
    bank_name="Customer Support Router",
)
```

## 回顾 {#recap}

- `hindsight-litellm` 为任何 LLM 提供跨对话的持久记忆
- 通过 LiteLLM 支持 100 多家服务提供方，还提供 OpenAI 和 Anthropic 原生包装器
- 三行即可完成配置：`configure()`、`set_defaults()`、`enable()`
- 两种模式：`recall` 用于获取原始事实，`reflect` 用于综合生成上下文
- 直接调用 API（`recall`、`reflect`、`retain`）可手动控制记忆
- 支持单次调用覆盖默认值、记忆库任务说明、异步操作和调试模式

该集成会自动处理记忆检索、提示注入和对话存储。你只需像往常一样调用 `completion()`，LLM 就会记住一切。
