大多数智能体记忆都有一种无声的故障模式：它只提供已有内容，却从不说明这些内容是否仍是最新的。检索层根据相似度返回最接近的匹配，却不提示该匹配是否仍反映现实。用于演示时，这样做问题不大；在生产环境中，智能体若根据待更新的快照自信作答，那就不是在记忆，而是在自信地猜测。

Hindsight 面临这项风险有其具体原因，也有相应的处理机制。它快速、概括层面的记忆属于**派生记忆**：观测和心智模型是在后台从原始事实中整合而来的。派生数据可能落后于来源。因此，Hindsight 不会假装整合层始终是最新的，而是衡量它落后的程度，并让 [Reflect（反思）](/developer/reflect) 智能体决定何时根据核验依据进行验证。

## 概览 {#tldr}

<!-- truncate -->

- Hindsight 有三个检索层：**心智模型**（人工维护的概括）、**观测**（整合后的认知判断）和**原始事实**。前两层是派生内容，并以异步方式刷新，因此可能落后于新写入的内容。
- Reflect 智能体读取整合层时，Hindsight 会附加 **`is_stale`** 信号，让智能体知道该层是否已跟上近期记忆。
- 对于**观测**，待更新程度按仍在等待整合的已存入记忆数量分级：`up_to_date`、`slightly_stale` 或 `stale`。
- 对于**心智模型**，如果自上次刷新以来摄取了新的范围内记忆，`is_stale` 就为 `true`。
- Reflect 循环会把这个信号用作路由决策：如果某一层待更新，就转而调用 `recall()`，根据原始事实核验后再作答；内容仍为最新的层则可直接信任。

## 为什么整合后的记忆会滞后 {#why-consolidated-memory-lags}

让 Hindsight 能够快速写入的机制，也正是造成滞后的原因。

调用 `retain()` 后，原始事实会立即写入。随后，后台会运行整合流程，把这些事实归并为去重后的观测。这样可以让存入调用保持快速，但也意味着记忆库中的观测总会有一段时间落后于记忆库实际收到的信息。心智模型离原始信息更远：它们会定期刷新，所以两次刷新之间，新记忆会不断累积，而尚未反映这些内容的概括仍留在那里。

这不是缺陷，而是拥有快速综合层所付出的代价。关键在于系统如何处理这种情况。扁平存储不会做任何处理，仍然提供旧视图；Hindsight 则会衡量两者之间的差距并将其显露出来。

## 待更新状态信号 {#the-staleness-signal}

Reflect 智能体按层级工作，先读取成本最低、综合程度最高的内容：

1. **[心智模型](/developer/api/mental-models)**：人工维护的高层概括。
2. **[观测](/developer/observations)**：有证据依据的整合后认知判断。
3. **[原始事实](/developer/api/recall)**：通过 `recall()` 检索、用作核验依据的内容。

智能体读取任一派生层时，结果都会带有 `is_stale` 标志。两层的计算方式不同，因为“落后”对每一层来说含义略有不同。

### 观测：按整合积压量分级 {#observations-graded-by-consolidation-backlog}

智能体搜索观测时，Hindsight 会根据仍等待整合的已存入记忆数量，报告整合滞后的程度：

| 待处理的未整合记忆 | 信号 |
| --- | --- |
| 0 | `up_to_date` |
| 少于 10 条 | `slightly_stale` |
| 10 条或更多 | `stale` |

只要还有任何待处理内容，`is_stale` 就为真。设置等级，是为了让智能体能区别对待“落后 1 条记忆”和“落后 50 条记忆”。

### 心智模型：距上次刷新后的滞后 {#mental-models-behind-since-last-refresh}

心智模型按各自的节奏刷新，因此其待更新状态取决于上次刷新的时间边界。**自上次刷新以来摄取了新的范围内记忆**时，心智模型就会被标记为 `is_stale`，并附带说明这一确切原因。这个信号告诉智能体：这份概括在上次刷新时是准确的，但此后情况已经发生变化。

## Reflect 如何使用这个信号 {#how-reflect-uses-it}

这个信号不是装饰。它是内置于智能体指令中的路由决策：先读取成本较低的层，**如果该层待更新，就不要停在这里；作答前应到较低层核验。**

具体来说：

- 内容最新且相关的心智模型可以独立回答问题。
- 如果心智模型**待更新**，智能体就会交叉核验：它还会搜索观测；如果观测也待更新，就会调用 `recall()` 检索原始事实。
- 如果待更新的观测是回答的核心，同样要根据底层记忆进行核验。

这样，智能体只会在确有必要时花费检索预算。综合层仍是最新内容时，它会信任这些内容，以较低成本作答；内容落后时，它会付出额外成本去查证，而不是自信地提供尚未纳入新信息的快照。

这就是全部要点：待更新状态是一个**应当核验，而不是丢弃**的信号。待更新的观测不会被丢弃；智能体依赖它之前，会先根据原始事实加以确认。

## 为什么这很重要 {#why-this-matters}

如果没有待更新状态信号，综合生成的记忆层就无法如实说明自己存在滞后。于是可能出现以下问题：

- **依据落后一周的概括作答。** 用户昨天改变了方向，心智模型仍反映上周的情况，却没有任何信号提示这一点。
- **在积压尚未处理时信任整合后的认知判断。** 刚刚存入了 50 条新记忆，但一条也尚未整合，智能体却把观测当作完整内容来作答。
- **无法区分“当前”与“可能仍是当前”。** 无论综合生成的答案内容有多滞后，每个答案都带有同样隐含的置信度。

具备待更新状态感知的检索会把“这是最接近的综合匹配”变成“这是最接近的匹配，同时也会告诉你是否应该再核查”。智能体会判断信息是否仍是最新的，而不只判断相关性。

这补足了 Hindsight 在[整合](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)过程中处理矛盾的方式：新事实推翻旧事实时，观测会被改写以记录这一变化，而不是被覆盖。待更新状态覆盖的是整合赶上之前的这段空档：新记忆已经存在，但综合层尚未将其纳入其中。

## 回顾 {#recap}

| | 扁平记忆存储 | 具备待更新状态感知的记忆 |
| --- | --- | --- |
| 综合/概括层 | 原样提供 | 标记 `is_stale` |
| 是否知道写入内容尚未反映 | 否 | 观测按整合积压量分级 |
| 是否知道概括早于新事实 | 否 | 心智模型标记“自上次刷新以来”待更新 |
| 内容滞后时的行为 | 提供待更新的视图 | Reflect 根据原始事实核验 |
| 信任方式 | 置信度一概相同 | 内容最新时信任，待更新时核验 |
