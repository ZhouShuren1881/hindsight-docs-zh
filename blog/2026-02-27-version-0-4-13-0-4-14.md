## 模型排行榜 {#model-leaderboard}

我们推出了公开的[模型排行榜](https://benchmarks.hindsight.vectorize.io/)，对所有受支持的 LLM 在 `retain` 和 `reflect` 操作中的表现进行排名，并列比较事实提取质量、速度和成本。无论您是想提高准确性，还是降低推理成本，排行榜都能提供实际数据，帮助您为工作负载选出合适的模型。

## Chat SDK 集成 {#chat-sdk-integration}

Hindsight 现在集成了 [AI SDK](https://sdk.vercel.ai/) 的 `useChat` 钩子，让您可以轻松为任意聊天机器人添加跨会话的持久记忆。

```typescript
import { useChat } from "ai/react";
import { createHindsightMiddleware } from "hindsight-sdk/chat";

const { messages, input, handleSubmit } = useChat({
  middleware: createHindsightMiddleware({
    bankId: "user-123",
    serverUrl: "http://localhost:8888",
  }),
});
```

中间件会自动存入每轮对话，并将召回的上下文注入每个请求，无需修改现有的聊天路由或 LLM 调用。

配置选项和完整的快速入门请参阅 [Chat SDK 文档](/sdks/integrations/chat)。

## CrewAI 集成 {#crewai-integration}

CrewAI 智能体现在可以使用 Hindsight 作为持久记忆后端。该集成接入 CrewAI 的记忆接口，并通过 Hindsight 记忆库处理存储与检索。

```python
from crewai import Agent, Crew
from hindsight_integrations.crewai import HindsightMemory

crew = Crew(
    agents=[...],
    tasks=[...],
    memory=True,
    memory_config={
        "provider": "hindsight",
        "config": {
            "bank_id": "my-crew",
            "server_url": "http://localhost:8888",
        },
    },
)
```

这样，CrewAI 智能体就能使用 Hindsight 的完整检索技术栈，包括语义检索、BM25、图遍历和重排序，而不必依赖默认的进程内存储。

详情请参阅 [CrewAI 集成文档](/sdks/integrations/crewai)。

## 可配置的 MCP 工具 {#configurable-mcp-tools}

现在，您可以为每个记忆库配置要公开的 MCP 工具。此前所有工具始终可用；现在，您可以限制工具集，使其恰好符合智能体或用户应能执行的操作。

```bash
export HINDSIGHT_API_MCP_ENABLED_TOOLS="recall,retain"
```

此版本还扩展了 MCP 工具集，新增了一些工具，并为现有工具添加了参数，让 MCP 客户端无需自定义 API 集成，就能更灵活地控制记忆操作。

## 批量观测整合 {#batch-observations-consolidation}

观测整合现在会在一次批处理中处理多个观测，而不是逐个处理。当一次存入操作触发多个实体的观测整合时，这能减少 LLM 调用开销。在我们的测试中，对于整合密集型工作负载，整合速度提升了 **10 倍**。

无需进行任何配置：摄取后自动整合观测时，这项改进会自动生效。

## ZeroEntropy 重排序模型 {#zeroentropy-reranker}

[ZeroEntropy](https://zeroentropy.dev/) 现在可用作重排序服务提供方。它与现有的本地交叉编码器和 TEI 选项并列，可用于对召回结果重新排序。

```bash
export HINDSIGHT_API_RERANKER_PROVIDER=zeroentropy
export HINDSIGHT_API_ZEROENTROPY_API_KEY=your-key
```

## 观测的来源事实 {#observation-source-facts}

召回观测时，响应现在会包含生成该观测所依据的来源事实。这样更容易追溯观测形成的原因，并核实其来源。

```python
results = client.recall(bank_id="my-bank", query="user preferences")

for result in results:
    if result.type == "observation":
        print(result.text)
        for fact in result.source_facts:
            print(" -", fact.text)
```

## 其他更新 {#other-updates}

**0.4.14**
- **默认启用记忆库配置 API**：每个记忆库的配置 API 现在默认启用；设置 `HINDSIGHT_API_ENABLE_BANK_CONFIG_API=false` 可将其禁用。
- **OpenClaw**：新增了用于切换 `autoRecall` 和排除特定 LLM 服务提供方的选项。修复了健康检查，使其能正确传递身份验证令牌。
- **Reflect（反思）和 Retain（存入）自定义配置**：增加了 Reflect、Retain 和观测整合行为的配置选项。
- **源文档元数据**：事实提取结果现在包含源文档元数据。
- **嵌入维度验证**：当嵌入维度超过 pgvector 的 HNSW 限制时，现在会给出明确错误，而不是等到运行时才失败。
- **多租户数据库模式隔离**：修复了存储和记忆库配置 API 中的隔离问题。
- **Recall 性能**：减少了检索过程中的内存用量。

**0.4.13**
- **默认 OpenAI 模型**：将默认 OpenAI LLM 切换为 `gpt-4o-mini`，降低了新部署的成本。
- **MCP 兼容性**：使本地 MCP 实现与服务器规范保持一致，并移除了已弃用的 `stateless` 参数。
- **Docker 命名卷**：修复了使用 Docker 命名卷时启动失败的问题。
- **重排序稳定性**：上游重排序服务提供方返回错误时不再导致崩溃。
- **时间顺序**：通过缩小每条事实的时间偏移，提高了事实时间顺序的准确性。
- **文档追踪**：修复了事实提取未返回任何事实时文档未被追踪的问题。
