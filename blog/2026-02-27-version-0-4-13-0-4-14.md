## 模特排行榜 {#model-leaderboard}

我们推出了一个公共[模特排行榜](https://benchmarks.hindsight.vectorize.io/)，对`retain`和`reflect`操作上的每个支持的LLM进行排名，并排衡量事实提取质量、速度和成本。无论您是要优化准确性还是试图降低推理成本，排行榜都会为您提供真实数据，以便您为您的工作负载选择正确的模型。

## 聊天SDK集成 {#chat-sdk-integration}

Hindsight 现在与 [AISDK](https://sdk.vercel.ai/) `useChat` 挂钩集成，可以轻松地为任何聊天机器人提供跨会话的持久记忆。

```typescript
import { useChat } from "ai/react";
import { createHindsightMiddleware } from "hindsight-sdk/chat";

const { messages, input, handleSubmit } = useChat({
  middleware: createHindsightMiddleware({
    bankId: "user-123",
    serverUrl: "http://localhost:8888",
  }),
});
```

中间件透明地保留对话轮次并将调用的上下文注入每个请求中 - 无需更改现有的聊天路由或 LLM 调用。

请参阅 [聊天SDK文档](/sdks/integrations/chat) 了解配置选项和完整的快速入门。

## CrewAI 集成 {#crewai-integration}

CrewAI智能体现在可以使用Hindsight作为持久记忆后端。该集成插入CrewAI的记忆界面，并通过Hindsight记忆库路由存储和检索。

```python
from crewai import Agent, Crew
from hindsight_integrations.crewai import HindsightMemory

crew = Crew(
    agents=[...],
    tasks=[...],
    memory=True,
    memory_config={
        "provider": "hindsight",
        "config": {
            "bank_id": "my-crew",
            "server_url": "http://localhost:8888",
        },
    },
)
```

这使CrewAI智能体可以访问完整的Hindsight检索堆栈（语义搜索、BM25、图形遍历和重排序），而不是默认的进程记忆储。

详情请参阅[CrewAI集成文档](/sdks/integrations/crewai)。

## 可配置MCP工具 {#configurable-mcp-tools}

您现在可以配置为每个记忆库公开哪些MCP工具。以前，所有工具始终可用；现在现在，您可以限制工具集以完全匹配智能体或用户应该能够执行的操作。

```bash
export HINDSIGHT_API_MCP_ENABLED_TOOLS="recall,retain"
```

此版本还通过附加工具和现有工具的新参数扩展了MCP工具集，使MCP客户能够更好地控制记忆操作，而无需自定义API集成。


## 批量观察整合 {#batch-observations-consolidation}

观察整合现在可以在单个批处理过程中处理多个观察，而不是单独处理。当记忆存储操作触发跨多个实体的整合时，这减少了LLM调用开销。在我们的测试中，对于集成繁重的工作负载，这导致了**速度提升10倍**。

无需配置——摄取后合并观察时，改进会自动应用。

## 零熵重排序器 {#zeroentropy-reranker}

[零熵](https://zeroentropy.dev/)现已作为重排序器提供商提供。它加入了现有选项（本地交叉编码器，TEI）以对召回结果进行重排序。

```bash
export HINDSIGHT_API_RERANKER_PROVIDER=zeroentropy
export HINDSIGHT_API_ZEROENTROPY_API_KEY=your-key
```

## 观察来源事实 {#observation-source-facts}

当回顾观察时，响应现在包括观察所源自的源事实。这使得追踪观察形成的原因并验证其出处变得更加容易。

```python
results = client.recall(bank_id="my-bank", query="用户偏好")

for result in results:
    if result.type == "observation":
        print(result.text)
        for fact in result.source_facts:
            print(" -", fact.text)
```

## 其他更新 {#other-updates}

**0.4.14**
- **记忆库配置API默认启用**：每个记忆库配置API现在默认打开；设置 `HINDSIGHT_API_ENABLE_BANK_CONFIG_API=false` 将其禁用。
- **OpenClaw**：添加了用于切换 `autoRecall` 并排除特定 LLM 提供商的选项。修复了健康检查以正确传递身份验证令牌。
- **反思和记忆存储定制**：增加了回忆、记忆存储和整合行为的配置选项。
- **源文档元数据**：事实提取结果现在包括源文档元数据。
- **嵌入维度验证**：当嵌入尺寸超过 pgvector HNSW 限制时，会引发明显的错误，而不是在运行时失败。
- **多租户模式隔离**：修复了存储和记忆库配置API中的隔离问题。
- **记忆再现表现**：减少检索期间的内存使用量。

**0.4.13**
- **默认OpenAI型号**：切换为`gpt-4o-mini`作为默认OpenAILLM，降低新部署的成本。
- **MCP兼容性**：将本地MCP实现与服务器规范保持一致，并删除了已弃用的`stateless`参数。
- **Docker 命名卷**：修复了使用命名Docker卷时的启动失败。
- **重排序机稳定性**：防止上游重排序器提供程序返回错误时发生崩溃。
- **时间排序**：通过减少每个事实的时间偏移来提高事实时间排序的准确性。
- **文档追踪**：修复了当事实提取返回零事实时不跟踪文档的问题。
