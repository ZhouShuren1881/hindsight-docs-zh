Hindsight 0.8.0 是一个重要版本，重点是**大规模运行记忆，以及洞察其内部运作**。现在可以通过内置的导出/导入功能在实例之间迁移记忆库；Retain（存入）、Recall（召回）和 Reflect（反思）背后的每次 LLM 调用都会默认记录追踪；内置去重功能能够捕捉过去导致重复观测的 LLM 偏差，大幅提升整合的可靠性；服务提供方提示缓存则降低了 Hindsight 代为发起的 LLM 调用的成本和延迟。

<!-- truncate -->

- [**跨实例迁移记忆库**](#cross-instance-bank-migration)：导出整个记忆库，或只导出其中的文档，再导入另一个 Hindsight 实例；在目标实例本地重新生成嵌入，无需重新运行 LLM。
- [**操作与可观测性**](#operations--observability)：默认记录完整的 LLM 请求追踪，支持恢复长时间运行的操作，并在控制台中提供更清晰的操作视图。
- [**更智能的整合**](#smarter-consolidation)：默认启用内置去重，修复导致重复观测的 LLM 偏差。
- [**服务提供方提示缓存**](#provider-prompt-caching)：在 Retain、整合和 Reflect 中缓存提示前缀，默认启用，以降低令牌成本和延迟。

## 跨实例迁移记忆库 {#cross-instance-bank-migration}

过去，将记忆库从一个 Hindsight 部署迁移到另一个部署（例如从预发布环境迁移到生产环境、从自托管环境迁移到 Cloud，或在不同区域之间迁移），意味着要重新摄取源内容，并再次支付每次提取的费用。0.8.0 提供了原生迁移功能。

- **导出/导入整个记忆库。 `hindsight-admin export-bank` 命令会将完整记忆库打包成归档文件，其中包括记忆单元、心智模型、实体、链接、配置和心智模型历史记录；`import-bank` 则会将其恢复到另一个实例。目标实例会使用自己的嵌入模型在本地重新生成嵌入**，因此无需重新运行 LLM 提取，迁移既快速又经济。
- **传输文档。** 专用的文档传输 API 端点可以在不同记忆库之间迁移源文档，无需重新运行 LLM。这样，你就可以根据原始文档重建或分叉记忆库。

由于目标实例会在导入时重新生成嵌入，即使两个实例使用不同的嵌入后端，也可以相互迁移记忆库。

## 操作与可观测性 {#operations--observability}

0.8.0 在可视化和运维方面做了大量改进，让你能看清 Hindsight 在幕后做什么，也更容易对其进行运维管理：从每个请求背后的单次 LLM 调用，到维护记忆库的长时间运行作业，都能查看。

### LLM 请求追踪 {#llm-request-tracing}

Hindsight 会代你发起大量 LLM 调用：Retain 期间提取事实，Recall 期间分析查询并重排结果，Reflect 期间综合生成答案，以及在后台执行整合。0.8.0 会按记忆库记录每一次调用，**默认启用**，包括失败的调用。

![Hindsight 的 LLM 请求追踪详情，显示服务提供方、模型、令牌用量、跨度，以及 Retain 调用背后的确切提示](/img/blog/version-0-8-0-llm-request-tracing.webp)

每条追踪记录都会包含服务提供方和模型、令牌用量（输入、输出、缓存、总计）、延迟，以及该请求背后的确切提示和工具调用。追踪数据由 OpenTelemetry GenAI recorder 记录，并保留一天，以免无限累积。新增的 `llm-requests` 端点可提供追踪记录和聚合统计信息；控制台也内置了上图所示的查看器。Python 和 TypeScript 客户端现在还会公开 Reflect 的 `tool_calls` 和 `llm_calls` 追踪信息，让你准确了解答案是如何生成的。Recall 追踪也会保留倒数排名融合中各来源的排名，因此你可以判断每条结果是由哪种检索策略找到的。

如果 Retain 的结果看起来有误，或 Reflect 的回答出乎意料，你可以打开追踪记录，查看背后的实际提示、模型和工具调用。

### 可恢复、可检查的操作 {#resumable-inspectable-operations}

整合和批量 Retain 等长时间运行的工作现在会在执行过程中写入**持久化进度快照**。你可以轮询操作以查看进度；如果工作进程在执行期间重启，它会从中断处继续，而不是从头开始。因此，部署或暂时性崩溃不会再让已完成的工作白费。

![Hindsight 控制台的后台操作视图，列出整合、Retain 和文件转换操作及其实时状态：等待处理、处理中（带有 24/36 的进度条）和已完成；还显示类型/状态筛选器和取消操作](/img/blog/version-0-8-0-operations.webp)

控制台在 后台操作视图中呈现这些信息。你可以按类型或状态筛选，查看进行中操作的进度，并取消等待处理的工作。

### 更清晰的控制台 {#clearer-control-plane}

操作视图和图谱图例现已完全本地化。禁用某项功能时，审计日志和 LLM 请求视图会显示清楚的“未启用”提示，而不是报错。

## 更智能的整合 {#smarter-consolidation}

整合是一个由 LLM 驱动的后台过程，会将原始事实转化为一组清晰的观测和心智模型：模型读取新事实，然后决定更新现有观测还是新建观测。实际使用中，模型有时会**偏离预期**，新写入的观测与已有观测几乎相同，却没有合并到其中；久而久之，重复内容便会不断累积。

0.8.0 不再把这个问题交给模型自行处理，而是强化了周边基础设施。**内置去重现在默认启用**：在创建和更新流程中，系统都会检查新观测是否与现有观测的相似度达到阈值（默认为 0.97）；如果达到，就会自动检测并合并，而不是任其累积。过去可能漏过的偏差，现在能以确定性的方式捕捉；这让持续写入负载下的记忆库更加可靠。

实际效果显著：在我们的持续基准测试中，此版本将重复观测的占比从约 **30%** 降至约 **1%**。你可以在[持续性能仪表板](https://vectorize-io.github.io/hindsight-continuous-performance-monitor/obs.html)上实时查看这项指标。

去重流程也变得**更快、更轻量**。用于查找合并目标观测的检索不再运行交叉编码器重排器；整合会直接交错处理检索结果。这既完全省去了重排步骤，也更可靠地找出几乎相同的观测（重排器过去往往会把它排到后面），所以整合所做的工作更少，同时产生的重复项也更少。

## 服务提供方提示缓存 {#provider-prompt-caching}

Hindsight 现在会对 Retain、整合和 Reflect 背后的 LLM 调用使用**服务提供方提示前缀缓存**。这些提示中跨记忆库共用的前缀会缓存在服务提供方，从而降低重复调用的令牌成本和延迟。该功能默认启用，无需配置。

## 其他重要变更 {#other-notable-changes}

- **更快的时间检索。** 时间入口点扫描现在会将每种事实类型的候选范围限制在排名靠前的匹配项，从而修复了在含有大量同日期记忆的记忆库中出现的异常缓慢问题。
- **有界的记忆历史。** 心智模型和观测的历史记录已从单个 JSONB 列移至专用表，消除了历史记录无限增长、进而可能影响大型记忆库稳定性的限制。
- **更灵活地使用 LLM。** `HINDSIGHT_API_LLM_STRICT_SCHEMA` 现在适用于所有支持 JSON Schema 的服务提供方，`HINDSIGHT_API_LLM_EXTRA_BODY` 现在适用于所有 API 服务提供方；默认 MiniMax 模型已升级至 M3。
- **ONNX 本地嵌入。** 新增基于 ONNX 的本地嵌入服务提供方，与现有的本地和 TEI 选项并列。
- **可调节的检索。** 你可以为各项策略（`semantic`、`bm25`、`graph`、`temporal`）单独设置检索加权，并配置 `HINDSIGHT_API_SEMANTIC_MIN_SIMILARITY` 下限，以便根据自己的语料调整 Recall。
- **修复外部 Postgres 支持。** VectorChord 的目录现在会添加到 `search_path`，让 vchord 能在由外部管理的 PostgreSQL 上正常工作；向 pgvector 写入前也会验证嵌入维度，以便及早发现不匹配。
- **Oracle 23ai 后端。** Recall 和心智模型历史记录现在支持 Oracle 后端；文档锁定和插入或更新操作也会根据数据库方言进行处理。
- **更稳健的 BM25。** PGroonga 会对 BM25 查询文本进行转义，避免特殊字符导致关键词检索失败。
- **更可靠的模型初始化。** 如果服务提供方阻塞，模型初始化现在会快速失败，而不是无限期挂起；对于会静默忽略 `tool_choice="required"` 的服务器，该设置会被降级处理。
- **更精简的 Reflect。** 较新的心智模型可以跳过强制检索，从而避免额外的 LLM 调用。
- **Retain 完整性。** Retain 会在提取前重新检查数据是否仍为最新状态，并串行处理对同一文档的并发写入；它还会阻止记忆库路由键污染事实归因，并提供更丰富的单项结果元数据。
- **配置正确性。** 对于从未执行过 Retain 的记忆库，配置 `PATCH` 现在也会持久保存更改。
