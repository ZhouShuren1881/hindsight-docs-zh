Hindsight 0.8.0 是专注于 **大规模运行记忆并观察其内部** 的主要版本。 记忆库现在可以通过内置的导出/导入在实例之间移动，记忆存储、记忆召回和回忆背后的每个 LLM 调用都可以开箱即用地进行追踪，由于内置的重复数据删除功能捕获了过去留下重复观察的 LLM 漂移，因此集成更加可靠，并且提供程序提示缓存降低了 LLM 调用的成本和延迟Hindsight 代您制作。

<!-- truncate -->

- [**跨实例记忆库迁移**](#cross-instance-bank-migration)：导出整个记忆库（或仅其文档）并将其导入另一个Hindsight实例，在本地重新嵌入，无需重新运行LLM。
- [**操作与可观察性**](#operations--observability)：默认情况下完整的LLM请求跟踪、可恢复的长时间运行操作以及控制平面中更清晰的操作视图。
- [**更智能的整合**](#smarter-consolidation)：内置重复数据删除，可修复重复观察背后的LLM漂移，默认情况下处于启用状态。
- [**提供者提示缓存**](#provider-prompt-caching)：跨记忆存储、整合和映射的提示前缀缓存（默认开启）以降低令牌成本和延迟。

## 跨实例记忆库迁移 {#cross-instance-bank-migration}

将记忆库从一个Hindsight部署移动到另一个部署（暂存到生产、自托管到云或在区域之间）过去意味着重新摄取源内容并再次为每次提取付费。 0.8.0 添加了一流的迁移。

- **整个记忆库导出/导入。** `hindsight-admin export-bank` 命令将完整的记忆库（记忆单元、心智模型、实体、链接、配置和心智模型历史）打包到存档中，`import-bank` 将其恢复到另一个实例中。目标**重新嵌入本地**针对其自己的嵌入模型，因此无需重新运行LLM提取，并且迁移快速且廉价。
- **文件传输。** 专用文档传输API端点可在记忆库之间移动记忆库的源文档，而无需重新运行LLM，因此您可以从其原始内容重建或分叉记忆库。

由于目标在导入时重新嵌入，因此即使实例运行不同的嵌入后端，您也可以在实例之间迁移。

## 操作与可观察性 {#operations--observability}

0.8.0 投入了大量工作，使 Hindsight 在幕后所做的事情可见且易于操作 - 从每个请求背后的单个 LLM 调用到维护记忆库的长期运行作业。

### LLM 请求追踪 {#llm-request-tracing}

Hindsight 代表您进行大量LLM调用——记忆存储期间的事实提取、记忆召回期间的查询分析和重排序、反思期间的综合以及后台的整合。 0.8.0 记录了每一个记忆库，**默认开启**——包括失败。

![HindsightLLM请求跟踪详细信息，显示提供者、模型、令牌使用情况、跨度以及记忆存储调用背后的确切提示](/img/blog/version-0-8-0-llm-request-tracing.webp)

每个跟踪都会捕获提供者和模型、令牌使用情况（输入、输出、缓存、总计）、延迟以及请求背后的确切提示和工具调用。跟踪是通过 OpenTelemetry GenAI 记录器记录的，具有一天的保留窗口，因此跟踪不会无限制地累积。新的 `llm-requests` 端点公开跟踪和聚合统计数据，控制平面将查看器发送到上面，而 Python 和 TypeScript 客户端现在会显示来自 镜子 的 `tool_calls` 和 `llm_calls` 跟踪，以便您可以准确地看到答案是如何生成的。 记忆痕迹还保留了倒数排名融合源排名，因此您可以辨别每个结果出现的检索策略。

如果记忆存储看起来错误或者答案令你惊讶，你可以打开跟踪并阅读其背后的实际提示、模型和工具调用。

### 可恢复、可检查的操作 {#resumable-inspectable-operations}

长期运行的工作——整合和批量记忆存储——现在在运行时写入**持久进度快照**。您可以轮询操作以观察其进展情况，如果工作人员在运行中重新启动，它将从停止的位置恢复而不是重新开始，因此部署或短暂崩溃不再丢弃已完成的工作。

![Hindsight 控制平面后台操作视图列出整合、记忆存储和文件转换操作，具有实时状态 - 待处理、使用 24/36 进度条处理和已完成 - 加上类型/状态过滤器和取消操作](/img/blog/version-0-8-0-operations.webp)

控制平面在 **后台操作** 视图中显示所有这些，您可以在其中按类型或状态进行过滤、查看正在进行的进度并取消待处理的工作。

### 更清晰的控制平面 {#clearer-control-plane}

操作和图形图例现已完全本地化，并且当功能被禁用而不是出错时，审核日志和LLM请求视图会显示清晰的“未启用”提示。

## 更智能的整合 {#smarter-consolidation}

整合——将原始事实转化为一套干净的观察和心智模型的后台过程——是LLM驱动的：模型读取新事实并决定是更新现有观察还是编写新事实。在实践中，该模型偶尔会**漂移**，编写一个几乎相同的观察结果，而不是合并到已有的观察结果中，随着时间的推移，这些重复项会堆积起来。

0.8.0 不再将其留给模型并强化其周围的基础设施。 **内置重复数据删除现已默认开启**：在创建和更新路径上，都会自动检测并合并现有观察相似度阈值（默认 0.97）内的新观察，而不是留下累积。过去容易出现的偏差现在可以确定地捕获，而不是希望消失——对于稳定写入负载下的任何记忆库来说，这是一次有意义的可靠性升级。

在实践中效果很大：在我们的连续基准测试中，在此版本中，重复观察的份额从大约**30%**下降到大约**1%**。您可以在我们的 [持续绩效仪表板](https://vectorize-io.github.io/hindsight-continuous-performance-monitor/obs.html) 上实时关注该指标。

去重路径也是**更快更轻**。找到要合并的观察的查找不再运行跨编码器重排序器——整合直接交错检索结果。这完全放弃了重排序过程，*和*在呈现几乎相同的双胞胎时更加可靠（重排序器倾向于将其掩埋），因此整合可以减少工作量并同时产生更少的重复项。

## 提供者提示缓存 {#provider-prompt-caching}

Hindsight 现在使用 **提供商提示前缀缓存** 来调用记忆存储、整合和联想背后的 LLM。这些提示的共享、与记忆库无关的前缀缓存在提供商处，从而降低了重复调用的令牌成本和延迟。它默认启用，无需配置。

## 新集成 {#new-integrations}

- **Claude智能体SDK** — 一种新的集成，可提供基于 Anthropic 的 Claude 智能体 SDK 持久 Hindsight 记忆的智能体。
- **超级特工** — 一种安全中间件集成，用于通过 Hindsight 路由 Superagent 交互。

## 其他显著变化 {#other-notable-changes}

- **更快的时间记忆。** 时间入口点扫描现在仅限于每个事实类型的顶部匹配，修复了具有许多相同日期记忆的记忆库上的病理性减慢。
- **有限的记忆历史。** 心智模型和观察历史记录从单个 JSONB 列移至专用表中，消除了可能破坏大型记忆库稳定性的无限增长上限。
- **更多LLM灵活性。** `HINDSIGHT_API_LLM_STRICT_SCHEMA` 在所有支持 JSON 模式的提供商中得到尊重，`HINDSIGHT_API_LLM_EXTRA_BODY` 应用于所有 API 提供商，并且默认的 MiniMax 模型升级到 M3。
- ​​**ONNX 本地嵌入。** 一个新的基于 ONNX 的本地嵌入提供程序加入了现有的本地和 TEI 选项。
- **可调谐检索。** 按策略检索增强（`semantic`、`bm25`、`graph`、`temporal`）和可配置的 `HINDSIGHT_API_SEMANTIC_MIN_SIMILARITY` 底板可让您根据语料库调整记忆召回。
- **外部Postgres修复。** VectorChord 目录添加到`search_path`，因此 vchord 在外部管理的 PostgreSQL 上工作，并且在 pgvector 写入之前验证嵌入维度以尽早捕获不匹配。
- **Oracle 23ai 后端。** 记忆召回和心智模型历史现在可以在 Oracle 后端运行，并且文档锁定/更新插入具有方言感知能力。
- **稳健BM25。** PGroonga BM25 查询文本已转义，因此特殊字符不再破坏关键字搜索。
- **更可靠的模型初始化。
当提供者阻塞时，** 模型初始化会快速失败，而不是永远挂起，并且`tool_choice="required"` 对于默默丢弃它的服务器会降级。
- **瘦了。** 新鲜的心智模型可以短路强制检索，避免额外的LLM调用。
- **记忆存储完整性。** 记忆存储运行提取前的新鲜度重新检查，并将并发写入者序列化到同一文档，阻止记忆库路由键污染事实归因，并显示更丰富的每项结果元数据。
- **配置正确性。**记忆库配置`PATCH`现在保留从未保留的记忆库。
