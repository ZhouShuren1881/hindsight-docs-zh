Hindsight 0.5.1 是一个打磨完善的版本，重点改进 CLI，并修复 Retain、Recall 和嵌入式守护进程中的可靠性问题。此外，本版本还新增了供自托管部署使用的 Cloudflare OAuth 代理、SiliconFlow 重排序服务提供方、创建记忆库时应用的默认模板，以及用于管理守护进程生命周期的新软件包 `@vectorize-io/hindsight-all`。

<!-- truncate -->

- [**CLI 覆盖范围**](#cli-coverage)：现在可以通过 `hindsight` 使用每个 OpenAPI 端点及其请求正文参数。
- [**Cloudflare OAuth 代理**](#cloudflare-oauth-proxy)：为自托管 Hindsight 提供可直接部署的 OAuth 入口。
- [**默认记忆库模板**](#default-bank-template)：通过一个环境变量，将模板清单应用于每个新建的记忆库。
- [**SiliconFlow 重排序服务**](#siliconflow-reranker)：新增一种重排序服务提供方。
- [**守护进程生命周期软件包**](#daemon-lifecycle-package)：新增 `@vectorize-io/hindsight-all`，用于以编程方式启动和停止守护进程。
- [**可靠性修复**](#reliability-fixes)：修复 Recall、Retain、观测整合工作进程和嵌入式守护进程中的问题。

## CLI 覆盖范围 {#cli-coverage}

`hindsight` CLI 现已扩展为支持 OpenAPI 规范中的所有端点及其全部请求正文参数。对于 CLI 尚未实现的操作，无需再改用 `curl`。Webhook、审计、操作和记忆历史子命令现已全部编入文档。

错误信息也更便于调试：API 错误现在会显示 HTTP 响应正文；`memory list` 命令也会正确标注事实类型，不再把每一行都显示为 `[UNKNOWN]`。

## Cloudflare OAuth 代理 {#cloudflare-oauth-proxy}

自托管 Hindsight 部署通常希望在 API 前面接入 OAuth，但又不想运行完整的身份提供方。新增的 Cloudflare OAuth 代理是一个 Cloudflare Worker，部署在 Hindsight 前端，负责处理 OAuth 握手，并将通过身份验证的请求转发到下游。它附带测试、CI 和安全加固，旨在为已使用 Cloudflare 作为边缘网络的团队提供可直接部署的方案。

## 默认记忆库模板 {#default-bank-template}

新增的环境变量 `HINDSIGHT_API_DEFAULT_BANK_TEMPLATE` 会将模板清单应用于每个新建的记忆库。这样，部署时无需修改应用代码或添加配置后钩子，就能统一记忆库配置，包括提取任务说明、观测、心智模型和强制指令。

此功能可与 0.5.0 引入的 Bank Template Hub 搭配使用：先导出一个经过验证的记忆库模板，之后每个新建的记忆库都会采用相同的基线配置。

## SiliconFlow 重排序服务 {#siliconflow-reranker}

SiliconFlow 现已成为受支持的重排序服务提供方，可与现有选项并用，为自托管部署和注重成本的部署再提供一种托管式重排序服务。与其他提供方一样，通过 `HINDSIGHT_API_RERANKER_PROVIDER` 配置即可。

## 守护进程生命周期软件包 {#daemon-lifecycle-package}

`@vectorize-io/hindsight-all` 是一个新的 npm 软件包，用于管理一体化守护进程的生命周期，包括启动、停止和健康检查。借助它，基于 Node.js 的应用可以在本地启动和关闭 Hindsight，而无需调用 shell 命令。它适用于本地开发、嵌入式部署，以及需要在每次运行时启动全新 Hindsight 实例的测试框架。

## 可靠性修复 {#reliability-fixes}

本版本修复了一系列在生产环境中发现的边缘情况：

- **Recall 的 RRF 排名。** 当重排序服务配置为直通模式时，RRF 排序现在会从头到尾保持不变，不再被静默替换。
- **异步查询嵌入。** Recall 现在通过异步批量嵌入路径处理查询，避免在事件循环中执行阻塞调用。
- **Retain 文本分块的幂等插入。** 插入文本分块时遇到完整性错误不再重试，从而消除了并发 Retain 时可能出现的一类重复插入循环。
- **事务内创建 ANN 种子。** Retain 的 ANN 种子临时表现在会在对应事务内创建，修复了并发负载下偶尔出现的“关系不存在”错误。
- **观测整合槽位计数。** 工作进程现在会在配置的 `max_slots` 范围内预留观测整合槽位，不再偶尔超出上限。
- **嵌入式守护进程生命周期。** 守护进程的启动和停止现在会串行执行，因此启动新实例不会再于请求处理中终止一个运行正常的实例。
- **macOS 本地嵌入模型和重排序服务。** 回归曾导致部分 Apple Silicon 环境中的 GPU 初始化失败；现在已恢复 macOS 上本地嵌入模型和重排序服务的 `FORCE_CPU` 默认值。
- **显示重排序服务错误。** 重排序服务初始化现在会显示实际的导入错误，而不再只报告通用失败；此外，也绕过了 `jina-mlx` 路径中 Transformers 5.x 的竞态问题。
- **推理模型和 Azure OpenAI。** 对于推理模型和 Azure OpenAI，LLM 调用现在会发送 `max_completion_tokens`（而不是 `max_tokens`），修复了近期 OpenAI 推理系列模型的请求失败问题。
- **Reflect 内部子召回的计费。** Reflect 发起的内部 Recall 调用现在会标记为内部调用，因此不会对调用方重复计费。

## 文档 {#documentation}

- 心智模型的标签筛选说明现已明确指出：标签用于筛选刷新时作为来源的记忆。
- 文档现已明确说明审计日志默认关闭。
- Retain 的 `update_mode` 参数现已完整记录。
- CLI 参考文档现已补充 Webhook、审计、操作和记忆历史子命令的说明。
