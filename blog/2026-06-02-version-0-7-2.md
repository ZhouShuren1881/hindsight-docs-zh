Hindsight 0.7.2 是一个可靠性版本：新增 Flowise 集成，修复了一系列存入完整性问题，避免记忆在未报告问题的情况下丢失；增强了并发场景下的整合能力，也让升级到 0.7.x 系列更加顺畅。所有使用 0.7.x 的用户都应升级，尤其是大规模运行整合任务，或正将较旧的 PostgreSQL 部署升级到 0.7.x 的用户。

<!-- truncate -->

- [**新增 Flowise 集成**](#new-flowise-integration)：为 Flowise 流程提供可直接使用的 Recall、Reflect 和 Retain 节点。
- [**强化存入完整性**](#retain-integrity-hardening)：修复多项问题，避免处理大型文档、提取失败和链接竞争时丢失记忆。
- [**增强整合能力**](#tougher-consolidation)：采用原子操作并感知数据范围，确保并发负载下的整合结果正确。
- [**让升级与运维更顺畅**](#smoother-upgrades--ops)：解决 PostgreSQL 升级受阻的问题，完善备份与恢复，并限制机器学习线程池的大小。
- [**Fireworks AI 批量推理**](#fireworks-ai-batch-inference)：新增一种推理服务提供方。

## 新增 Flowise 集成 {#new-flowise-integration}

Hindsight 现已接入 [Flowise](https://flowise.ai/)，提供可直接使用的 **Recall（召回）**、**Reflect（反思）** 和 **Retain（存入）** 工具节点。这样，无需编写胶水代码，就能为低代码 Flowise 智能体添加持久记忆。

请参阅 [Flowise 集成文档](/sdks/integrations/flowise)开始使用。

## 强化存入完整性 {#retain-integrity-hardening}

0.7.2 修复了一系列问题，堵住了存入操作仍可能丢失数据的几种情况：

- **提取失败时不再静默丢弃。** 如果某个项目的事实提取失败，之前的存入操作可能会直接丢弃该项目而不报告问题。0.7.2 会保留这条记忆并报告故障，而不是将其丢弃。
- **正确拆分超大文档。** 如果单篇文档太大，无法通过一次调用处理而必须拆分，分块索引可能会在不同子批次之间冲突，完整的文档正文也可能无法保留。这两个问题现已修复，因此大型文档可以按原有顺序完整存入。
- **消除链接竞争。** 存入记忆时插入记忆连接可能发生竞争，导致连接指向尚未提交的记忆单元。这个竞争窗口现已关闭。
- **稳健处理特殊 Unicode 字符。** Retain 和 Recall 现在可以处理特殊 token 字面量和孤立的代理字符，不会因此报错。

如果你要摄取大型文档或高吞吐量数据流，请升级到 0.7.2，确保内容不会遗漏。

## 增强整合能力 {#tougher-consolidation}

在 0.7.1 提升整合可靠性的基础上，本次发布让每个记忆库的整合以原子方式执行，并感知数据范围，从而避免并发触发相互干扰或重复处理。重试退避时间也有所缩短，使工作进程能更快地从暂时性故障中恢复，减少空等。持续承受写入负载的记忆库，无需人工干预也能维持干净且经过去重的观测集。

## 让升级与运维更顺畅 {#smoother-upgrades--ops}

三项改动让 Hindsight 的运行和升级更加省心：

- **解除 PostgreSQL 升级受阻的问题。** 将较旧的部署升级到 0.7.x 系列时，迁移过程可能会卡住。0.7.2 修复了迁移路径，使现有 PostgreSQL 数据库可以顺利升级。
- **完善备份与恢复。** 备份和恢复现在会包含此前遗漏的多个表，因此恢复出的记忆库能够忠实还原原始记忆库。
- **限制机器学习线程池大小。** 本机机器学习线程池现在会限制在可用 CPU 核心数以内，防止线程过量占用资源而影响繁忙主机的稳定性。

## Fireworks AI 批量推理 {#fireworks-ai-batch-inference}

Hindsight 新增 **Fireworks AI** 作为批量推理服务提供方，为提取、整合和 Reflect 背后的 LLM 调用提供另一个托管选项。

## 其他值得关注的改动 {#other-notable-changes}

- **修复控制台的 i18n 重定向循环**：固定 Next.js 版本后，国际化路由不再陷入重定向循环。
- **强化控制台身份认证**：登录重定向现在会验证返回目标（从而关闭开放重定向漏洞），并正确遵循 `basePath`。
- **加快图维护**：图维护所用的向量检索种子数据生成速度显著提升；新增了性能测试套件以持续验证性能。
- **改进 vchord 上的向量检索**：使用余弦距离操作符类，并应用特定于后端的调优，使 ANN 结果准确且经过良好调优。
- **保留经过校准的重排序分数**：对于本身就返回 `[0,1]` 范围内分数的服务提供方，保留其原始分数，不再重新归一化。
- **工作进程遵循最大重试次数**：任务重试判定现在会遵守配置的最大重试次数。
- **改进守护进程的网络配置与启动**：遵循显式配置的主机和端口，并在回收端口前等待健康检查通过。
- **改进 Windows 体验**：嵌入式守护进程不再额外打开终端标签页，嵌入式 Postgres 的停止和重启也更加可靠。
- **修复 CLI 问题**：`hindsight memory retain` 能正确处理 `--timestamp`，并使用正确的事实类型值。
- **隔离 Claude Code 服务提供方**：Claude Code 服务提供方的子进程与用户插件隔离，避免相互干扰。
