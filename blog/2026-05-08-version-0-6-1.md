Hindsight 0.6.1 是 0.6.0 的后续版本，具有两个新的 LLM 提供程序集成（**z.ai** 和带有后备链的 **LiteLLM路由器**）、用于高性能记忆召回的 **AlloyDB ScaNN** 向量索引、用于结构化实体提取的 **地图型实体标签**、 **可选只读后端** 用于将记忆召回流量与写入分离，**访问密钥登录** 用于控制平面。还修复了一些可靠性问题 - 最值得注意的是事实提取中的重试风暴预防以及与 PyTorch MPS 的 macOS 守护进程模式兼容性。

<!-- truncate -->

- [**新LLM提供商**](#new-llm-providers)：z.ai（智谱）和带有自动后备链的LiteLLM路由器。
- [**AlloyDB ScaNN 向量索引**](#alloydb-scann-vector-index)：用于 AlloyDB 部署的高性能向量索引。
- [**地图类型实体标签**](#map-type-entity-labels)：结构化实体组而不是平面字符串标签。
- [**只读记忆召回后端**](#read-only-recall-backend)：将记忆召回路由到副本，同时写入保留在主副本上。
- [**控制平面访问-密钥登录**](#control-plane-access-key-login)：无需完整 SSO 的管理 UI 的轻量级身份验证。
- [**记忆库下拉菜单记忆统计**](#bank-dropdown-memory-stats)：记忆库选择器现在显示每个记忆库的记忆计数一目了然。
- [**可靠性修复**](#reliability-fixes)：事实提取重试、macOS守护进程、记忆存储压力等等。

## 新LLM提供商 {#new-llm-providers}

两个 LLM 方面的改进在 0.6.1 中发布：

- **z.ai (智谱)**现已成为一流提供商。设置 `HINDSIGHT_API_LLM_PROVIDER=zai` 并选择一个模型 - 默认使用免费套餐友好的 `glm-4.5-flash`，因此您可以在没有付费计划的情况下尝试它。感谢[@Burgunthy](https://github.com/Burgunthy)的贡献。
- **LiteLLM路由器** 是一个新的提供程序，它将多个 LLM 端点包装在具有自动回退链的单个配置后面。如果您的主要模型速率限制或失败，路由器会透明地切换到下一个候选模型，因此记忆存储/转发保持可用，而无需将重试逻辑连接到您自己的应用程序中。

## AlloyDB ScaNN 向量索引 {#alloydb-scann-vector-index}

Google 的 AlloyDB ScaNN 扩展带来了基于树的 ANN 索引，具有强大的大规模记忆召回/吞吐量权衡。 Hindsight 现在在安装时检测 ScaNN，并在可用时将其用作向量索引 - 在 AlloyDB 上运行的大型部署可以更快地获得更快的记忆召回，而无需更改模式或查询。感谢[@can1357](https://github.com/can1357)登陆此。

## 地图类型实体标签 {#map-type-entity-labels}

实体提取现在还可以生成**结构化群体
除了平面字符串标签之外，**。例如，可以将 `address` 实体提取为 `{street, city, country, postal_code}` 字段的结构化映射，而不是单个串联字符串。这使得下游过滤和加入更加清晰——尤其是对于具有明确子字段的人员、地点和组织的事实。

在记忆库的实体标签配置中将实体标签`type`设置为`map`以选择加入。

## 只读记忆召回后端 {#read-only-recall-backend}

记忆召回现在可以配置为使用单独的只读数据库后端，而记忆存储和未来继续通过主数据库写入。对于运行带有只读副本的PostgreSQL的部署，这可以让记忆召回流量水平扩展，而不会与写入工作负载竞争，并保持读取路径对主要故障转移的弹性。

通过`HINDSIGHT_API_READ_DATABASE_URL`进行配置。未设置时，记忆召回会像以前一样使用主记忆。

## 控制平面访问-密钥登录 {#control-plane-access-key-login}

​​控制平面现在支持可选的**访问密钥登录**流。当您只想将管理 UI 置于共享密钥后面时，这是设置完整 SSO 的轻量级替代方案 - 对于临时环境、内部工具或单团队部署非常有用。中间件在每个受保护的路由上强制执行访问密钥，并且通过更清晰的错误和正确的重定向处理来强化登录用户体验。

## 记忆库下拉菜单记忆统计 {#bank-dropdown-memory-stats}

控制平面的记忆库选择器现在直接在下拉列表中显示每个记忆库的记忆计数，因此您可以选择正确的记忆库，而无需先导航到每个记忆库。当您跨用户、智能体或环境处理许多记忆库时，这些计数非常有用，这些计数可以让您立即了解哪些记忆库是活动的，哪些是空的。

## 可靠性修复 {#reliability-fixes}

多项修复提高了正确性和稳健性：

- **事实提取重试风暴**：删除了事实提取中的乘法重试层。以前，单个瞬态 LLM 错误可能会级联为多次重试；现在重试仅限于单层。
- **macOS 守护进程 + PyTorch MPS**：守护进程模式将 `os.fork()` 替换为 `subprocess.Popen`，修复了在 Apple Silicon 上使用 PyTorch MPS 运行时长期存在的崩溃问题。
- **记忆存储 记忆压力**：现在使用后会清除内容引用，帮助长时间运行的工作人员避免大批量记忆存储上的 OOM。
- **batch_retain 错误传播**：失败的子操作现在会将其 `error_message` 传播到父操作，因此失败会显示有意义的原因，而不是一般错误。
- **反思文档元数据**：现在从原始记忆存储参数中读取文档元数据，因此输出包含正确的文档上下文。
- **TypeScript客户端版本**：`CLIENT_VERSION` 现在是通过 tsup `define` 派生的，因此发布的包始终报告正确的版本。
- **Docker `--user` 覆盖**：`/home/hindsight`现在是`chmod 755`，因此容器可以在`--user UID:GID`下干净地运行。
- **Worker 与旧数据库的兼容性**：工作线程在调用可选的`schemas_with_pending_work()`函数之前探测`pg_proc`，因此旧的PostgreSQL部署不会使工作线程崩溃。
- **元包固定**：`hindsight-api`、`hindsight-all` 和 `hindsight-all-slim` 现在硬固定到匹配的 `hindsight-api-slim` 版本，防止 `pip install -U` 之后过时的精简安装。

## 其他显著变化 {#other-notable-changes}

- **CLI `--strategy` 标志**：`memory retain-files`接受新的`--strategy`标志，用于选择文件在保留之前的分割方式。
- **Worker 扇出范围**：进度统计扇出范围现在仅限于具有待处理工作的模式，从而消除了对空闲租户的浪费轮询。
