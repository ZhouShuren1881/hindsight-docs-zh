Hindsight 0.6.1 是 0.6.0 的后续版本，新增了两种 LLM 服务提供方集成（**z.ai** 和支持回退链的 **LiteLLM 路由器**）、用于高性能召回的 **AlloyDB ScaNN** 向量索引、用于结构化实体提取的 **映射类型实体标签**、可选的 **只读后端**（用于将召回流量与写入流量分开），以及 **访问密钥登录**（供控制台使用）。本次还修复了若干可靠性问题，其中最值得一提的是防止事实提取发生重试风暴，以及让 macOS 守护进程模式兼容 PyTorch MPS。

<!-- truncate -->

- [**新增 LLM 服务提供方**](#new-llm-providers)：z.ai（智谱）和支持自动回退链的 LiteLLM 路由器。
- [**AlloyDB ScaNN 向量索引**](#alloydb-scann-vector-index)：面向 AlloyDB 部署的高性能向量索引。
- [**映射类型实体标签**](#map-type-entity-labels)：使用结构化实体组，而非扁平的字符串标签。
- [**只读召回后端**](#read-only-recall-backend)：将召回请求路由到只读副本，同时继续在主库上写入。
- [**控制台访问密钥登录**](#control-plane-access-key-login)：无需完整 SSO，即可为管理界面启用轻量身份验证。
- [**记忆库下拉菜单中的记忆统计**](#bank-dropdown-memory-stats)：现在可直接在记忆库选择器中查看各库的记忆数量。
- [**可靠性修复**](#reliability-fixes)：事实提取重试、macOS 守护进程模式、存入时的内存压力等。

## 新增 LLM 服务提供方 {#new-llm-providers}

0.6.1 带来了两项 LLM 相关改进：

- **z.ai（智谱）** 现已作为正式服务提供方集成。设置 `HINDSIGHT_API_LLM_PROVIDER=zai` 并选择模型即可使用；默认模型为适合免费套餐的 `glm-4.5-flash`，因此无需付费套餐即可试用。感谢 [@Burgunthy](https://github.com/Burgunthy) 的贡献。
- **LiteLLM 路由器** 是一种新的服务提供方，可在单一配置中封装多个 LLM 端点，并自动设置回退链。如果主模型触发速率限制或发生故障，路由器会自动切换到下一个候选模型，因此 Retain（存入）和 Reflect（反思）仍可使用，无需你在自己的应用中编写重试逻辑。

## AlloyDB ScaNN 向量索引 {#alloydb-scann-vector-index}

Google 的 AlloyDB ScaNN 扩展提供了基于树的 ANN 索引，在大规模部署中能在召回效果与吞吐量之间取得良好权衡。Hindsight 现在会在安装时检测 ScaNN，并在可用时将其用作向量索引。这样，在 AlloyDB 上运行的大型部署无需更改模式或查询，就能加快召回速度。感谢 [@can1357](https://github.com/can1357) 完成这项工作。

## 映射类型实体标签 {#map-type-entity-labels}

除了扁平的字符串标签，实体提取现在还可以生成**结构化分组**。例如，`address` 实体可以提取为由 `{street, city, country, postal_code}` 字段组成的结构化映射，而不再是一个拼接后的字符串。这让后续的筛选和联接更加简单，尤其适用于具有明确子字段的人物、地点和组织相关事实。

如需启用此功能，请在记忆库的实体标签配置中将 `type` 设为 `map`。

## 只读召回后端 {#read-only-recall-backend}

现在可以将 Recall（召回）配置为使用单独的只读数据库后端，同时让 Retain（存入）和 Reflect（反思）继续通过主库写入。对于使用 PostgreSQL 只读副本的部署，这可以让召回流量横向扩展，避免与写入负载争用资源，并提高读取路径应对主库故障切换的能力。

通过 `HINDSIGHT_API_READ_DATABASE_URL` 配置此功能。未设置时，召回仍像以前一样使用主库。

## 控制台访问密钥登录 {#control-plane-access-key-login}

控制台现在支持可选的**访问密钥登录**流程。如果你只想用共享密钥保护管理界面，这是一种轻量的方案，无需配置完整的 SSO；适用于预发布环境、内部工具或单团队部署。中间件会在每个受保护的路由上校验访问密钥；登录流程也经过改进，错误信息更清晰，重定向处理更完善。

## 记忆库下拉菜单中的记忆统计 {#bank-dropdown-memory-stats}

控制台的记忆库选择器现在会直接在下拉菜单中显示各记忆库的记忆数量，因此你无需逐一进入记忆库，就能选出合适的库。如果你需要管理多个用户、智能体或环境中的许多记忆库，这些数量能让你立即了解哪些库正在使用、哪些库为空。

## 可靠性修复 {#reliability-fixes}

本次修复提升了系统的正确性和稳健性：

- **事实提取重试风暴**：移除了事实提取中层层叠加的重试逻辑。以前，一次短暂的 LLM 错误就可能引发大量连锁重试；现在重试只在单一层执行，并受到限制。
- **macOS 守护进程模式与 PyTorch MPS**：守护进程模式改用 `subprocess.Popen` 替代 `os.fork()`，修复了在 Apple Silicon 上使用 PyTorch MPS 时长期存在的崩溃问题。
- **存入时的内存压力**：现在会在使用后清除内容引用，帮助长时间运行的工作进程处理大型存入批次时避免 OOM。
- **`batch_retain` 错误传播**：失败的子操作现在会将其 `error_message` 传递给父操作，因此错误会显示具体原因，而非笼统信息。
- **Reflect 文档元数据**：Reflect 现在会从原始存入参数中读取文档元数据，确保输出包含正确的文档上下文。
- **TypeScript 客户端版本**：现在通过 tsup `define` 派生 `CLIENT_VERSION`，确保发布的程序包始终报告正确的版本。
- **Docker `--user` 覆盖**：现在会对 `/home/hindsight` 设置 `chmod 755`，使容器能够在指定 `--user UID:GID` 时正常运行。
- **工作进程兼容旧版数据库**：工作进程现在会先查询 `pg_proc`，再调用可选的 `schemas_with_pending_work()` 函数，避免旧版 PostgreSQL 部署因此崩溃。
- **元程序包版本固定**：现在将 `hindsight-api`、`hindsight-all` 和 `hindsight-all-slim` 硬性固定为与 `hindsight-api-slim` 相匹配的版本，避免执行 `pip install -U` 后安装了过时的 slim 版本。

## 其他值得关注的变更 {#other-notable-changes}

- **CLI `--strategy` 标志**：`memory retain-files` 新增了 `--strategy` 标志，用于选择存入前如何拆分文件。
- **工作进程扇出范围**：进度统计的扇出现在仅针对有待处理任务的模式执行，从而避免在空闲租户上进行无效轮询。
