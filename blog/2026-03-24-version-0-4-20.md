Hindsight 0.4.20 新增了 Claude Code 和 LangGraph 集成、NemoClaw 安装 CLI、集成包独立版本管理，以及 Reflect 改进（包括事实类型筛选、排除心智模型和墙钟超时），还包含一批可靠性修复。

<!-- truncate -->

- [**Claude Code 集成**](#claude-code-integration)：通过基于钩子的插件，为 Claude Code 提供持久的长期记忆。
- [**LangGraph 集成**](#langgraph-integration)：通过工具、节点或 BaseStore API，在 LangGraph 智能体中使用 Hindsight 记忆。
- [**NemoClaw 集成**](#nemoclaw-integration)：在 NemoClaw 沙箱中通过一条命令完成 Hindsight 设置。
- [**集成包独立版本管理**](#independent-integration-versioning)：集成现在拥有各自的版本号和发布周期。
- [**Reflect 改进**](#reflect-improvements)：事实类型筛选、排除心智模型和墙钟超时。

## Claude Code 集成 {#claude-code-integration}

`hindsight-memory` 是一款新插件，可为 [Claude Code](https://docs.anthropic.com/en/docs/claude-code) 提供持久的长期记忆。它适用于交互式会话，也适用于 Claude Code Channels（Telegram、Discord、Slack）。

从 marketplace 安装：

```bash
# 添加 Hindsight marketplace 并安装插件
claude plugin marketplace add vectorize-io/hindsight
claude plugin install hindsight-memory

# 配置用于记忆提取的 LLM 服务提供方
# 选项 A：OpenAI（自动检测）
export OPENAI_API_KEY="sk-your-key"

# 选项 B：Anthropic（自动检测）
export ANTHROPIC_API_KEY="your-key"

# 选项 C：无需 API 密钥（使用 Claude Code 自带的模型）
export HINDSIGHT_LLM_PROVIDER=claude-code

# 启动 Claude Code——插件会自动激活
claude
```

该插件使用 Claude Code 的四个钩子自动管理记忆：

- **SessionStart** — 检查 Hindsight 是否可访问，并可选择启动本地守护进程。
- **UserPromptSubmit** — 自动召回相关记忆，并将其作为上下文注入。
- **Stop** — 自动将对话记录存入长期记忆。
- **SessionEnd** — 清理并可选择关闭守护进程。

支持三种连接模式：

1. **外部 API** — 将 `hindsightApiUrl` 和 `hindsightApiToken` 指向远程 Hindsight 服务器。
2. **本地守护进程** — 将 `hindsightApiUrl` 留空，插件便会通过 `uvx hindsight-embed@latest` 自动启动本地实例。只需提供 LLM API 密钥。
3. **现有本地服务器** — 将 `apiPort` 设为你已运行的服务器所使用的端口。

动态记忆库 ID 可按智能体、项目、会话、通道或用户隔离记忆；具体由 `dynamicBankId` 和 `dynamicBankGranularity` 设置控制。该插件完全使用 Python 编写，且没有任何外部依赖。

完整配置参考请见 [Claude Code 集成文档](/sdks/integrations/claude-code)。如需了解如何将它与 Claude Code Channels 配合使用，请参阅 [Claude Code + Telegram + Hindsight](/blog/2026/03/23/claude-code-telegram) 博客文章。

## LangGraph 集成 {#langgraph-integration}

`hindsight-langgraph` 为 [LangGraph](https://github.com/langchain-ai/langgraph) 智能体提供三种接入 Hindsight 记忆的方式。

```bash
pip install hindsight-langgraph
```

**工具** — 可与 LangChain 和 LangGraph 配合使用：

```python
from hindsight_client import Hindsight
from hindsight_langgraph import create_hindsight_tools
from langchain_openai import ChatOpenAI

client = Hindsight(base_url="http://localhost:8888")
tools = create_hindsight_tools(client=client, bank_id="user-123")

model = ChatOpenAI(model="gpt-4o").bind_tools(tools)
```

**记忆节点** — 为 LangGraph 图提供专用的召回和存入节点：

```python
from hindsight_client import Hindsight
from hindsight_langgraph import create_recall_node, create_retain_node

client = Hindsight(base_url="http://localhost:8888")

recall = create_recall_node(client=client, bank_id="user-123")
retain = create_retain_node(client=client, bank_id="user-123")

builder.add_node("recall", recall)
builder.add_node("retain", retain)
```

**BaseStore** — 由 Hindsight 提供支持、原生适用于 LangGraph 的检查点记忆：

```python
from hindsight_client import Hindsight
from hindsight_langgraph import HindsightStore

client = Hindsight(base_url="http://localhost:8888")
store = HindsightStore(client=client)

graph = builder.compile(checkpointer=checkpointer, store=store)

await store.aput(("user", "123", "prefs"), "theme", {"value": "dark mode"})
results = await store.asearch(("user", "123", "prefs"), query="theme preference")
```

系统内置多租户路由：将 `bank_id_from_config="user_id"` 传给任意节点或工具工厂后，运行时会从 LangGraph 的 `configurable` 字典中动态解析记忆库 ID。

完整 API 参考请见 [LangGraph 集成文档](/sdks/integrations/langgraph)。

## NemoClaw 集成 {#nemoclaw-integration}

`hindsight-nemoclaw` 是一项新集成，可自动完成在 [NemoClaw](https://nemoclaw.ai) 沙箱中添加 Hindsight 记忆的五步流程：

```bash
npx @vectorize-io/hindsight-nemoclaw setup \
  --sandbox my-assistant \
  --api-url https://api.hindsight.vectorize.io \
  --api-token <your-api-key> \
  --bank-prefix my-sandbox
```

CLI 会处理插件安装、配置、网络策略更新（让沙箱能够访问 Hindsight API）以及网关重启。应用更改前，可使用 `--dry-run` 预览。

完整设置指南请见 [NemoClaw 集成文档](/sdks/integrations/nemoclaw)。

## 集成包独立版本管理 {#independent-integration-versioning}

LiteLLM、Pydantic AI、CrewAI、AI SDK、Chat、OpenClaw、LangGraph 和 NemoClaw 等集成包现在各自拥有版本号和发布周期，与 Hindsight 核心服务器分开管理。

过去，每次发布核心版本时，所有集成都要一起更新版本并发布，即使它们没有任何变化。这使人难以判断某个集成的新版本究竟包含实际改动，还是仅仅更新了版本号。

从 0.4.20 开始，每个集成都独立管理版本并独立发布。这对你意味着：

- **版本号对应实际改动**：当你在 PyPI/npm 上看到 `hindsight-langgraph` 或 `hindsight-litellm` 发布了新版本时，该版本包含相应软件包的实际更新。
- **更快发布集成修复**：某项集成的缺陷修复或功能准备就绪后即可发布，无需等待下一次核心版本发布。
- **每个集成都有自己的变更日志**：现在每个集成都有独立的变更日志页面，路径为 `/changelog/integrations/<name>`，你可以据此追踪所用软件包的改动。

## Reflect 改进 {#reflect-improvements}

新增三项功能，让 Reflect 更易控制、行为更可预测。

**事实类型筛选** — `fact_types` 用于限制反思智能体检索哪些事实类型。传入 `["world", "experience", "observation"]` 的一个子集，即可限制搜索范围并节省 LLM tokens：

```json
{
  "query": "What does the user prefer?",
  "fact_types": ["experience", "observation"]
}
```

**排除心智模型** — `exclude_mental_models` 会完全跳过心智模型搜索，`exclude_mental_model_ids` 则按 ID 排除指定模型。这些筛选项也适用于心智模型触发器，因此可将其保存在自动刷新的模型配置中。Reflect 智能体会在工具层强制执行筛选：如果 LLM 尝试调用已禁用的工具，就会收到错误，而不会静默地返回来自已排除来源的结果。

**墙钟超时** — Reflect 操作现在会执行可配置的超时限制（默认值：300 秒）。此前，LLM 服务提供方响应缓慢或迭代次数过多，可能导致一次 Reflect 调用挂起长达 40 分钟。超时触发时，API 会返回 HTTP 504。

```bash
HINDSIGHT_API_REFLECT_WALL_TIMEOUT=300  # 秒
```

## 其他更新 {#other-updates}

**改进**
- 新增脚本入口点后，现在可以直接通过 `uvx hindsight-api` 运行 `hindsight-api` 软件包。
- 默认 MiniMax 模型已从 M2.5 升级到 M2.7。
- OperationValidator 扩展在验证操作时现在会收到更丰富的上下文。
- OpenAI 兼容客户端的初始化现在支持传入查询参数，以便兼容更多服务提供方。

**错误修复**
- 修复了实体解析中的内存泄漏：在事实提取和刷新之间发生异常时，`_pending_stats` 和 `_pending_cooccurrences` 字典可能会无限增长。
- 修复了 PostgreSQL `pg_trgm` 扩展不可用时的启动崩溃和静默存入失败。现在迁移可以妥善处理缺少 `pg_trgm` 的情况；实体解析会回退到全表扫描，并发出警告。
- 通过在观测搜索结果中禁用来源事实，修复了 Reflect 的上下文溢出问题。
- 现在会从所有服务提供方的 LLM 输出中剥除 Markdown 代码围栏，而不再仅限于本地模型。
- 空的 Recall 查询现在会返回清晰的 400 错误，而不再因 SQL 参数间隙而失败。
- 文件存入请求现在会包含身份验证标头，使经过身份验证的部署也能正常上传文件。
- 修复了 `MCP_AUTH_TOKEN` 与 `TENANT_API_KEY` 不同时 MCP 工具调用失败的问题。
- 修复了 Linux/Docker 环境中的 `claude-agent-sdk` 安装问题。
- 如果没有显式提供 `hindsight_query`，LiteLLM 集成现在会回退使用最后一条用户消息。
- 修复了非原子地创建异步操作可能导致操作记录不一致的问题。
- 修复了批量存入的子操作因未处理的异常而失败时，父操作遗留的问题。
- 通过确保正确设置实体 ID，修复了非 ASCII 实体名称导致的故障。
- 修复了 LLM 标记为 "assistant" 的事实被存储为错误事实类型，而非 "experience" 的问题。
