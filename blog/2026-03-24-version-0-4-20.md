Hindsight 0.4.20 添加了 Claude Code和 LangGraph 集成、NemoClaw 设置 CLI、集成包的独立版本控制以及包括事实类型过滤器、心智模型排除和挂钟超时在内的多项改进，以及一批可靠性修复。

<!-- truncate -->

- [**Claude Code集成**](#claude-code-integration)：通过基于钩子的插件为Claude Code提供持久的长期记忆。
- [**LangGraph 整合**](#langgraph-integration)：通过工具、节点或 BaseStore API 在LangGraph智能体中​​使用Hindsight记忆。
- ​​[**NemoClaw 整合**](#nemoclaw-integration)：在NemoClaw沙箱内设置Hindsight单命令。
- [**独立集成版本控制**](#independent-integration-versioning)：集成现在有自己的版本号和发布生命周期。
- [**反思 改进**](#reflect-improvements)：事实类型过滤器、心智模型排除和挂钟超时。

## Claude Code集成 {#claude-code-integration}

`hindsight-memory` 是一个新插件，可以为 [Claude Code](https://docs.anthropic.com/en/docs/claude-code) 提供持久的长期记忆。它在交互式会话中以及通过 Claude Code通道（Telegram、Discord、Slack）运行。

从市场安装：

```bash
#添加Hindsight市场并安装插件
claude plugin marketplace add vectorize-io/hindsight
claude plugin install hindsight-memory

#配置您的 LLM 提供程序以进行记忆提取
#选项 A：OpenAI（自动检测）
export OPENAI_API_KEY="sk-your-key"

#选项 B：Anthropic（自动检测）
export ANTHROPIC_API_KEY="your-key"

#选项C：不需要API密钥（使用Claude Code自己的模型）
export HINDSIGHT_LLM_PROVIDER=claude-code

#开始Claude Code——插件自动激活
claude
```

该插件使用四个Claude Code挂钩来自动管理记忆：

- **会话开始** — 验证 Hindsight 是否可达，并可选择启动本地守护进程。
- **用户提示提交** — 自动回忆相关记忆并将其作为上下文注入。
- **停止** — 自动保留对话记录以长期记忆。
- **课程结束** — 清理和可选的守护进程关闭。

支持三种连接模式：

1. **外部API** — 将 `hindsightApiUrl` 和 `hindsightApiToken` 指向远程 Hindsight 服务器。
2. **本地守护进程** — 将 `hindsightApiUrl` 留空，插件将通过 `uvx hindsight-embed@latest` 自动启动本地实例。只需提供 LLM API 密钥即可。
3. **现有本地服务器** — 设置 `apiPort` 以匹配您已经运行的服务器。

动态记忆库 ID 可让您隔离每个智能体、项目、会话、通道或用户的记忆 — 由 `dynamicBankId` 和 `dynamicBankGranularity` 设置控制。该插件作为纯 Python 提供，外部依赖性为零。

请参阅 [Claude Code集成文档](/sdks/integrations/claude-code) 以获取完整的配置参考，并参阅 [Claude Code + 电报 + Hindsight](/blog/2026/03/23/claude-code-telegram) 博客文章以了解将其与 Claude Code通道一起使用的演练。

## LangGraph 整合 {#langgraph-integration}

`hindsight-langgraph`通过三种集成模式将Hindsight记忆添加到[LangGraph](https://github.com/langchain-ai/langgraph)智能体中​​。

```bash
pip install hindsight-langgraph
```

**工具** — 适用于 LangChain 和 LangGraph：

```python
from hindsight_client import Hindsight
from hindsight_langgraph import create_hindsight_tools
from langchain_openai import ChatOpenAI

client = Hindsight(base_url="http://localhost:8888")
tools = create_hindsight_tools(client=client, bank_id="user-123")

model = ChatOpenAI(model="gpt-4o").bind_tools(tools)
```

**记忆节点** — LangGraph 图的专用记忆召回和记忆存储节点：

```python
from hindsight_client import Hindsight
from hindsight_langgraph import create_recall_node, create_retain_node

client = Hindsight(base_url="http://localhost:8888")

recall = create_recall_node(client=client, bank_id="user-123")
retain = create_retain_node(client=client, bank_id="user-123")

builder.add_node("recall", recall)
builder.add_node("retain", retain)
```

**基地存储** — LangGraph-由Hindsight支持的原生检查点记忆：

```python
from hindsight_client import Hindsight
from hindsight_langgraph import HindsightStore

client = Hindsight(base_url="http://localhost:8888")
store = HindsightStore(client=client)

graph = builder.compile(checkpointer=checkpointer, store=store)

await store.aput(("user", "123", "prefs"), "theme", {"value": "深色模式"})
results = await store.asearch(("user", "123", "prefs"), query="主题偏好")
```

内置多租户路由——将`bank_id_from_config="user_id"`传递到任何节点或工具工厂，并且记忆库ID在运行时从LangGraph`configurable`字典动态解析。

请参阅 [LangGraph集成文档](/sdks/integrations/langgraph) 以获取完整的 API 参考。

## NemoClaw 整合 {#nemoclaw-integration}

`hindsight-nemoclaw` 是一个新的集成，可自动执行将 Hindsight 记忆添加到 [NemoClaw](https://nemoclaw.ai) 沙箱的五步过程：

```bash
npx @vectorize-io/hindsight-nemoclaw setup \
  --sandbox my-assistant \
  --api-url https://api.hindsight.vectorize.io \
  --api-token <your-api-key> \
  --bank-prefix my-sandbox
```

CLI 处理插件安装、配置、网络策略更新（以便沙箱可以到达 Hindsight API）和网关重启。在应用之前使用 `--dry-run` 预览更改。

请参阅[NemoClaw集成文档](/sdks/integrations/nemoclaw) 获取完整的设置指南。

## 独立集成版本控制 {#independent-integration-versioning}

集成包 - LiteLLM、Pydantic AI、CrewAI、AI SDK、Chat、OpenClaw、LangGraph 和 NemoClaw - 现在拥有自己的版本号和发布生命周期，与核心分离Hindsight服务器。

以前，即使没有任何变化，每个集成都会与每个核心版本一起发布并发布。这使得很难判断新版本的集成是否包含实际更改或只是无操作碰撞。

从0.4.20开始，每个集成都是独立版本和发布的。这对您意味着什么：

- **版本号 期待真正的变化**：当您在 PyPI/npm 上看到新版本的 `hindsight-langgraph` 或 `hindsight-litellm` 时，它包含对该软件包的实际更新。
- **更快的集成修复**：一个集成中的错误修复或功能一旦准备就绪就会立即发布，而无需等待下一个核心版本。
- **每个集成变更日志**：每个集成现在在 `/changelog/integrations/<name>` 都有自己的更改日志页面，以便您可以跟踪您使用的包中的更改。

## 反思 改进 {#reflect-improvements}

增加了三个，让回忆变得更加可控和可预测。

**事实类型过滤器** — `fact_types` 限制反思智能体检索的事实类型。传递`["world", "experience", "observation"]`的子集来限制搜索范围并保存LLM令牌：

```json
{
  "query": "用户喜欢什么？",
  "fact_types": ["experience", "observation"]
}
```

**心智模型排除** — `exclude_mental_models` 完全跳过心智模型搜索，`exclude_mental_model_ids` 通过 ID 排除特定模型。这些过滤器也适用于心智模型触发器，因此您可以将它们保留在自动刷新模型上。反思智能体在工具级别强制执行过滤器 - 如果 LLM 尝试调用禁用的工具，它会收到错误，而不是默默地从排除的源返回结果。

**挂钟超时** — 操作现在强制执行可配置的超时（默认值：300 秒）。以前，缓慢的 LLM 提供程序或高迭代计数可能会导致 调用挂起长达 40 分钟。当超时触发时，API 返回 HTTP 504。
由于新的脚本入口点，

```bash
HINDSIGHT_API_REFLECT_WALL_TIMEOUT=300  # seconds
```

## 其他更新 {#other-updates}

**改进**
- `hindsight-api`包现在可以直接通过`uvx hindsight-api`运行。
- 默认MiniMax型号已从M2.5升级为M2.7。
- OperationValidator 扩展现在在验证操作时接收更丰富的上下文。
- OpenAI兼容的客户端初始化现在支持传递查询参数以实现更广泛的提供程序兼容性。

**错误修复**
- 修复了实体解析中的记忆泄漏，当事实提取和刷新之间发生异常时，`_pending_stats`和`_pending_cooccurrences`字典可能无限增长。
- 修复了当PostgreSQL`pg_trgm`扩展不可用时启动崩溃和静默记忆存储失败。迁移现在可以优雅地处理丢失的`pg_trgm`，并且实体解析回退到全表扫描并发出警告。
- 通过禁用“观察”搜索结果中的源事实来修复“反思”中的上下文溢出。
- Markdown 代码围栏现在已从所有提供商的 LLM 输出中剥离，而不仅仅是本地模型。
- 空记忆召回查询现在返回明确的 400 错误，而不是因 SQL 参数间隙而失败。
- 文件记忆存储请求现在包含身份验证标头，因此上传可以在经过身份验证的部署中工作。
- 修复了当`MCP_AUTH_TOKEN`和`TENANT_API_KEY`不同时MCP工具调用失败的问题。
- 修复了Linux/Docker环境中的`claude-agent-sdk`安装。
当未提供明确的 `claude-agent-sdk` 时，
- LiteLLM现在，当没有明确的情况时，集成会回退到最后的用户消息`hindsight_query`提供。
- 修复了可能产生不一致的操作记录的非原子异步操作创建。
- 修复了当批处理记忆存储子项因未处理的异常而失败时孤立的父操作。
- 通过确保正确设置实体 ID 修复了非 ASCII 实体名称的故障。
- 修复了LLM标记为“助理”的事实以错误的事实类型而不是“经验”存储。
