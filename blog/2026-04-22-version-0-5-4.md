Hindsight 0.5.4 大幅提升了心智模型增量刷新的速度，并提高了准确性；它还通过守护进程崩溃恢复增强了嵌入式模式，并纳入社区贡献的一系列 Reflect 和 Retain 可靠性修复。

<!-- truncate -->

- [**更智能的增量刷新**](#smarter-delta-refreshes)：增量模式现在只召回新记忆，让更新更快、更聚焦。
- [**嵌入式守护进程恢复**](#embedded-daemon-recovery)：存活检查会自动重启崩溃的守护进程。
- [**Reflect 可靠性**](#reflect-reliability)：修复强制指令泄漏、任务说明中的身份设定，并支持启动时软失败。
- [**存入与工作进程修复**](#retain--worker-fixes)：防止记忆重复、保留文档时间戳，并扫描工作进程所用的数据库模式。

## 更智能的增量刷新 {#smarter-delta-refreshes}

此前，心智模型增量刷新会对记忆库中的所有记忆执行完整检索，和完整重建完全相同，然后再让第二个 LLM 将检索结果与现有文档进行差异比较。这个过程速度慢、成本高；当 LLM 被数百条观测淹没时，还会造成内容重复。

在 0.5.4 中，增量模式会将智能体检索循环的范围限定为自 `last_refreshed_at` 以来创建或更新的记忆。现有文档已经涵盖此前的知识；Reflect 智能体只检索真正新增的内容。增量提示词也经过重写，指导模型将新事实整合进现有结构：合并主题重叠的内容、保留具体示例，并避免会导致内容膨胀的整节替换。

刷新时，Reflect 智能体还会获得心智模型名称和主题的上下文，帮助它聚焦主题，并舍弃检索可能返回的无关观测。

因此，增量刷新成本更低（检索查询更少、LLM 上下文更短），速度更快（内容没有变化时完全跳过增量 LLM 调用），生成的文档也更清晰。

## 嵌入式守护进程恢复 {#embedded-daemon-recovery}

嵌入式模式守护进程（`hindsight-all`、`hindsight-embed`）现在加入了存活检查，可以检测后台进程是否已崩溃或失去响应。检测到问题后，守护进程会使用相同配置自动重启。空闲超时也默认关闭，因此嵌入式实例在请求间隔期间会保持运行，无需手动发送 keepalive 信号。

## Reflect 可靠性 {#reflect-reliability}

以下三项修复提升了 Reflect 的质量和运行稳健性：

- **防止强制指令泄漏。** 对于没有记忆的空记忆库，强制指令内容可能泄漏到 Reflect 的答案文本中。此问题已修复：强制指令现在会留在其应处的位置，也就是系统提示词中。
- **任务说明中的身份设定。** 现在，记忆库的 `reflect_mission` 设置会在提示词构建器中正确塑造智能体身份，因此具有自定义性格设定的智能体会实际采用这些设定。
- **启动时软失败。** 如果启动时无法连接 LLM 服务提供方，服务器现在会记录警告并继续运行，而不会崩溃。这样可以避免服务提供方短暂中断时引发级联重启。

## 存入与工作进程修复 {#retain--worker-fixes}

- **防止记忆重复。** 修复了并发执行文档 upsert 时可能发生的分块索引错乱问题；该问题可能导致生成重复的记忆单元。
- **保留文档时间戳。** 现在，文档 upsert 会保留 `created_at` 时间戳，而不是将其重置。
- **提示词中的非拉丁文本。** LLM 提示词现在使用 `ensure_ascii=False`，确保中文、日文、韩文及其他非拉丁文本都能正确发送。
- **工作进程扫描数据库模式。** 工作进程现在会在领取任务前确认数据库模式处于活动状态，避免处理已退役租户的任务。
- **透传 DeferOperation。** 扩展现在可以通过 `MemoryEngine.execute_task` 抛出 `DeferOperation`，以便正确处理重新入队。
- **可配置的嵌入批次大小。** OpenAI 兼容的嵌入模型服务提供方现在支持配置批次大小，以提高大批量摄取时的吞吐量。
- **合并 Alembic 迁移头。** v0.5.3 中分歧的迁移头现已合并，使升级能够顺利完成。
