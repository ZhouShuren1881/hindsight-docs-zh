Hindsight 0.5.5 为 PDF/DOCX 等提供了全新的 **LlamaParse 文件解析器**，在控制平面中重新设计了 **心智模型页面**，新的 **Pipecat 语音智能体集成**，用于嵌入式运行时的完整 **Windows 支持**，以及一系列 LLM 提供程序兼容性修复（DeepSeek、Bedrock Converse、Ollama、LiteLLM 流媒体）。它还包括一本值得您在升级前花 30 秒阅读的 **小的突破性改变**。

<!-- truncate -->

- [**重大改变**](#breaking-change-bank-profile-no-longer-auto-creates-banks)：`GET /banks/{bank_id}/profile`不再自动创建记忆库。
- [**LlamaParse 文件解析器**](#llamaparse-file-parser)：高保真 PDF/DOCX → 通过 LlamaIndex 云进行降价。
- [**心智模型 — 列表视图**](#mental-models-list-view)：具有服务器端标签过滤功能的新默认分割窗格视图。
- [**Pipecat集成**](#pipecat-voice-agent-integration)：语音智能体的持久记忆。
- [**Windows 支持嵌入模式**](#windows-support-for-embedded-mode)。
- [**LLM 兼容性修复**](#llm-compatibility-fixes)：DeepSeek、Bedrock Converse、Ollama、LiteLLM 流媒体。

## 重大更改：记忆库配置文件不再自动创建记忆库 {#breaking-change-bank-profile-no-longer-auto-creates-banks}

`GET /v1/default/banks/{bank_id}/profile` 之前创建了记忆库（如果它不存在）并返回默认配置文件。这种副作用很容易意外地产生空的记忆库（例如，由于`bank_id`中的拼写错误）和复杂的租赁/生命周期推理。从 0.5.5 开始，当记忆库不存在时，端点返回**404**——与所有其他读取端点相同。

**记忆存储仍然适用于不存在的记忆库。** 此更改确实 **not** 影响写入路径：针对不存在的记忆库调用 `retain`（或任何记忆写入端点）仍会隐式创建它，与以前完全相同。您不需要先调用`POST /v1/default/banks`，也不需要通过配置文件调用来“预热”记忆库。如果你想要一个记忆库存在，就往它里面写。

**您可能需要改变什么。** 只有将 `GET /profile` 视为幂等“创建或获取”调用的调用者才需要更新。将引导程序配置文件调用替换为显式 `POST /v1/default/banks` （如果您特别想要一个没有记忆的记忆库）或只是您的第一个 `retain` 调用（推荐 - 相同的最终状态，减少一次往返）。

## LlamaParse 文件解析器 {#llamaparse-file-parser}

Hindsight 已经支持文件上传 - 您记忆存储的每个文件都会转换为 markdown、分块并存储为记忆。到目前为止，您有两个解析器选择：捆绑的 **降价** 解析器（适用于简单文件，在进程中运行）和 **鸢尾花**（Vectorize 的托管解析器，更适合复杂布局）。 0.5.5增加了第三个选项：**LlamaParse**，LlamaIndex云文档解析API。

LlamaParse 可以处理 Markitdown 偶然发现的杂乱的现实 PDF——多列纸张、扫描收据、嵌入表格的幻灯片、带有表单字段的合同。这是一项付费服务​​（您携带自己的LlamaIndex云API密钥），但它是此类文档的最高保真度选项。

**启用它。** 通过配置设置解析器（env var `HINDSIGHT_API_FILE_PARSER` 加上你的 LlamaParse API 键）：

```bash
HINDSIGHT_API_FILE_PARSER=llama_parse
HINDSIGHT_API_FILE_PARSER_LLAMA_PARSE_API_KEY=llx-...
```

然后像以前一样上传文件 - 解析器是在引擎级别选择的，因此不需要客户端更改。对于非常大或缓慢的文档，轮询间隔和超时是可调的。

## 心智模型 — 列表视图 {#mental-models-list-view}

控制平面中的心智模型页面有一个新的默认**列表**视图：左侧是心智模型的侧边栏（每个条目显示名称、来源查询和上次刷新时间），右侧是渲染的 Markdown 内容 - 文件浏览器样式。

该页面还会获得一个 **服务器端标签过滤器**，可根据心智模型上存在的实际标签自动完成，此外，当您选择多个标签时，还可获得 `any` / `all` 匹配切换。自动完成功能由现有 `GET /v1/default/banks/{bank_id}/tags` 端点上的新 `?source=mental_models` 参数提供支持，因此同一原语可以根据调用者意图列出记忆标签或心智模型标签。

之前的“表格”视图已被删除； “仪表板”视图卡仍作为辅助切换。

## Pipecat语音智能体集成 {#pipecat-voice-agent-integration}

新的[Pipecat](https://www.pipecat.ai/)集成将Hindsight记忆引入语音-AI管道：存储每个回合、记忆召回相关上下文，并将其注入到LLM提示中。在 PyPI 上以 `hindsight-pipecat` 形式提供。感谢[@benfrank241](https://github.com/benfrank241)的贡献。

## Windows 支持嵌入模式 {#windows-support-for-embedded-mode}

`hindsight-embed`（以及嵌入式`hindsight-all`）现在可以在Windows上干净地运行。守护进程管理器处理 Windows 进程组、原子元数据写入，并且 CI 将 Rust CLI 与 Python 轮一起安装以进行同级二进制验证。如果您一直在等待在 Windows 开发盒上评估 Hindsight，请尝试一下。

## LLM 兼容性修复 {#llm-compatibility-fixes}

一些修复使得 Hindsight 能够更好地与更广泛的 LLM 提供商合作：

- **DeepSeek**现已成为一流提供商；处理工具调用的怪癖。
- **亚马逊 Bedrock 匡威** 之前由于不支持数值约束而拒绝了我们的因果关系 Pydantic 模型；这已经被简化了。
- **Ollama / Hermes / 极小极大**有时会换行JSON降价代码围栏中的响应，即使`json_object`响应格式。事实提取解析器现在在解析之前删除这些内容，因此记忆存储停止默默地在这些提供者上生成 0 个事实。
- **LiteLLM 流媒体** 对话已正确存储（流式块聚合错误正在破坏流式响应的记忆存储）。
- ~~JSON 发送到 LLM 的模式已被简化，以删除 `$ref`/`$defs`/`anyOf`/`const`/`oneOf` 构造Ollama 的语法引擎（以及其他严格的结构化输出引擎）不完全支持。~~ *此更改在 0.5.6 中恢复 - 内联模式导致一些 LLM 回显模式结构并未生成有效响应，从而导致生成 0 个事实。*

## 其他值得注意的变化 {#other-notable-changes}

- **Cohere 嵌入输出尺寸** 现在可配置。
- **强制使用 IPv4 进行 Gemini 嵌入** 在受限网络环境中。
- **语句超时** 用于 PostgreSQL 连接，可根据部署进行配置。
- **运行状态** API 和 UI 现在公开 `processing` 和 `cancelled` 状态；响应包括重试次数和下次重试时间。
- **减少检索扇出** 在整合记忆召回期间，以检查大型记忆库上的内存使用量和延迟。
- **`exclude_parents`滤镜**开启`list_operations`在扫描叶子时抑制父级汇总。
- **文档块API + 重新处理 UI** 用于细粒度检查和重新摄取上传的文件。
- **Asyncpg 风格 PostgreSQL URL** 被外部数据库连接字符串接受。
- **首次 UI 启动** 不再要求您手动确认控制平面安装。
- **MCP `delete_memory` 已删除** 关闭授权绕过。
