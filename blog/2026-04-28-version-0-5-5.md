**0.5.5 存在一项回归，可能导致 Retain 过程中提取出 0 个事实。** JSON 模式简化改动已在 [0.5.6](https://github.com/vectorize-io/hindsight/releases/tag/v0.5.6) 中回退。请升级到 0.5.6。

Hindsight 0.5.5 带来了全新的 **LlamaParse 文件解析器**，可解析 PDF、DOCX 等文件；控制平面中的 **心智模型页面**经过重新设计；新增 **Pipecat 语音智能体集成**；嵌入式运行时现已全面支持 **Windows**；还修复了一系列 LLM 服务提供方兼容性问题（DeepSeek、Bedrock Converse、Ollama、LiteLLM 流式处理）。此外还有一项值得在升级前花 30 秒了解的**小型破坏性变更**。

<!-- truncate -->

- [**破坏性变更**](#breaking-change-bank-profile-no-longer-auto-creates-banks)：`GET /banks/{bank_id}/profile` 不再自动创建记忆库。
- [**LlamaParse 文件解析器**](#llamaparse-file-parser)：通过 LlamaIndex Cloud 将 PDF/DOCX 高保真地转换为 Markdown。
- [**心智模型列表视图**](#mental-models-list-view)：新增默认的分栏视图，并支持服务端标签筛选。
- [**Pipecat 语音智能体集成**](#pipecat-voice-agent-integration)：为语音智能体提供持久记忆。
- [**嵌入模式支持 Windows**](#windows-support-for-embedded-mode)。
- [**LLM 兼容性修复**](#llm-compatibility-fixes)：涉及 DeepSeek、Bedrock Converse、Ollama 和 LiteLLM 流式处理。

## 破坏性变更：记忆库配置文件不再自动创建记忆库 {#breaking-change-bank-profile-no-longer-auto-creates-banks}

此前，如果记忆库不存在，`GET /v1/default/banks/{bank_id}/profile` 会创建它并返回默认配置文件。这种副作用很容易意外创建空记忆库（例如，`bank_id` 拼写错误时），也让租户隔离和生命周期管理更难推理。从 0.5.5 开始，如果记忆库不存在，该端点会返回 **404**，与其他所有读取端点的行为一致。

**不存在的记忆库仍可用于 Retain。** 此变更**不影响写入路径**：对不存在的记忆库调用 `retain`（或任何记忆写入端点），仍会像以前一样隐式创建该记忆库。你不必先调用 `POST /v1/default/banks`，也不必通过读取配置文件来“预热”记忆库。要创建记忆库，只需向其中写入内容即可。

**你可能需要做的调整。** 只有将 `GET /profile` 当作幂等的“创建或获取”调用来使用的调用方需要调整。可以将初始化时读取配置文件的调用替换为显式调用 `POST /v1/default/banks`（如果你确实需要一个尚无记忆的记忆库），也可以直接首次调用 `retain`（推荐：最终状态相同，还能少一次往返）。

## LlamaParse 文件解析器 {#llamaparse-file-parser}

Hindsight 早已支持上传文件：每个通过 Retain 存入的文件都会转换为 Markdown、拆分成文本分块，并作为记忆存储。此前有两种解析器可选：内置的 **markitdown** 解析器（适合简单文件，在进程内运行）和 **Iris**（Vectorize 托管的解析器，更适合复杂版式）。0.5.5 新增第三种选择：**LlamaParse**，即 LlamaIndex Cloud 文档解析 API。

LlamaParse 能处理 markitdown 难以解析的复杂真实场景 PDF，例如多栏论文、扫描版收据、嵌有表格的幻灯片，以及带表单字段的合同。这是一项付费服务（你需要提供自己的 LlamaIndex Cloud API 密钥），但对于这类文档，它能提供最高保真度的解析结果。

**启用方法。** 通过配置指定解析器（环境变量 `HINDSIGHT_API_FILE_PARSER`），并设置 LlamaParse API 密钥：

```bash
HINDSIGHT_API_FILE_PARSER=llama_parse
HINDSIGHT_API_FILE_PARSER_LLAMA_PARSE_API_KEY=llx-...
```

之后照常上传文件即可。解析器在引擎级别选择，因此客户端无需改动。对于非常大或解析缓慢的文档，可以调整轮询间隔和超时时间。

## 心智模型列表视图 {#mental-models-list-view}

控制平面中的心智模型页面现在默认使用**列表**视图：左侧边栏列出心智模型（每项显示名称、来源查询和上次刷新时间），右侧显示渲染后的 Markdown 内容，布局类似文件浏览器。

页面还新增了**服务端标签筛选器**。它会根据心智模型上实际存在的标签提供自动补全；选择多个标签时，还可以通过 `any` / `all` 切换匹配方式。自动补全依赖现有 `GET /v1/default/banks/{bank_id}/tags` 端点新增的 `?source=mental_models` 参数。因此，调用方可以根据意图使用同一机制列出记忆标签或心智模型标签。

此前的“表格”视图已移除；卡片式“仪表板”视图仍可通过次级切换选用。

## Pipecat 语音智能体集成 {#pipecat-voice-agent-integration}

新增的 [Pipecat](https://www.pipecat.ai/) 集成将 Hindsight 记忆接入语音 AI 流程：存储每轮对话内容、召回相关上下文，并将上下文注入 LLM 提示词。该集成已在 PyPI 上以 `hindsight-pipecat` 发布。感谢 [@benfrank241](https://github.com/benfrank241) 的贡献。

## 嵌入模式支持 Windows {#windows-support-for-embedded-mode}

现在，`hindsight-embed`（以及嵌入式版本的 `hindsight-all`）可以在 Windows 上正常运行。守护进程管理器现已处理 Windows 进程组和原子元数据写入；CI 也会将 Rust CLI 与 Python wheel 一同安装，以验证同级二进制文件。如果你一直在等 Hindsight 支持 Windows 开发环境，现在可以试用了。

## LLM 兼容性修复 {#llm-compatibility-fixes}

这次的多项修复让 Hindsight 能更好地兼容各种 LLM 服务提供方：

- **DeepSeek** 现已作为一等服务提供方得到支持，并处理了工具调用方面的特殊情况。
- **Amazon Bedrock Converse** 此前会因不支持数值约束而拒绝我们的因果关系 Pydantic 模型；相关约束现已简化。
- 即使使用 `json_object` 响应格式，**Ollama / Hermes / MiniMax** 有时仍会把 JSON 响应包在 Markdown 代码围栏中。事实提取解析器现在会在解析前移除这些围栏，因此这些服务提供方上的 Retain 不再悄悄地提取出 0 个事实。
- **LiteLLM 流式处理**现在可以正确存储对话（此前流式分块聚合错误会导致流式响应上的 Retain 失败）。
- ~~发送给 LLM 的 JSON 模式已简化，移除了 Ollama 语法引擎及其他严格结构化输出引擎无法完全支持的 `$ref` / `$defs` / `anyOf` / `const` / `oneOf` 结构。~~ *此项变更已在 0.5.6 中回退：内联模式会导致一些 LLM 回显模式结构，而不是生成有效响应，最终造成提取出 0 个事实。*

## 其他值得注意的变更 {#other-notable-changes}

- **Cohere 嵌入输出维度**现在可以配置。
- 在受限网络环境中，**Gemini 嵌入**现在可以强制使用 IPv4。
- **PostgreSQL 连接语句超时**现可按部署配置。
- **操作状态** API 和 UI 现在会公开 `processing` 和 `cancelled` 状态；响应还会包含重试次数和下次重试时间。
- **减少整合召回时的检索扇出**，以控制大型记忆库上的内存用量和延迟。
- `list_operations` 新增 **`exclude_parents` 筛选器**，扫描叶级操作时可排除父级汇总项。
- 新增 **文档分块 API 和重新处理界面**，便于细致检查已上传文件并重新摄取这些文件。
- 外部数据库连接字符串现在接受 **Asyncpg 风格的 PostgreSQL URL**。
- **首次启动 UI** 时不再要求你手动确认安装控制平面。
- **已移除 MCP `delete_memory`**，以修复授权绕过问题。
