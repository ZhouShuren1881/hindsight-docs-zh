CrewAI 智能体会在一次团队执行结束后失去所有记忆。`hindsight-crewai` 接入 CrewAI 的 `ExternalMemory`，让知识可以在多次运行之间持续保存——只需三行配置，智能体便会自动存储任务输出并召回相关上下文。

---

## 问题：无状态的团队 {#the-problem-stateless-crews}

CrewAI 有一套记忆系统，包括短期记忆、长期记忆和实体记忆。在一次 `kickoff()` 调用期间，它运行良好。

随后，进程退出。

下一次运行时，团队又从零开始。学到的每一条事实、做出的每一个决定、发现的每一个实体，全都消失了。

如果你要构建会反复运行的团队，这就很重要：

- 随着时间推移不断深化知识的研究团队
- 能记住客户历史的支持团队
- 跨多个冲刺跟踪决策的规划团队

CrewAI 内置的记忆后端（RAG 存储、SQLite）面向单次运行中的持久化而设计。要让记忆在多次运行和多个会话之间持续积累，就需要其他方案。

这正是 `hindsight-crewai` 包的用途。它使用 Hindsight 的记忆引擎实现 CrewAI 的 `Storage` 接口，因此你的团队可以跨运行、跨天、跨周记住所有内容。

---

## 架构 {#architecture}

它们的协作方式如下：

```
CrewAI Crew
  └─ ExternalMemory
       └─ HindsightStorage（实现 Storage 接口）
            ├─ save()   → Hindsight Retain（存入；提取事实、实体和关系）
            ├─ search() → Hindsight Recall（召回；语义、图谱和时间检索）
            └─ reset()  → Hindsight delete_bank + recreate
```

CrewAI 会在每项任务完成后调用 `save()`，并在每项任务开始前调用 `search()`。生命周期由 CrewAI 驱动：它负责调用，Hindsight 负责存储。

在底层，Hindsight 不只是存储文本。它还会提取结构化事实、识别实体、构建知识图谱，并通过交叉编码器重排序执行多策略检索（语义检索、BM25、图遍历和时间排序）。

你的团队因此获得了真正的记忆系统，而不是一堆向量数据。

## 第 1 步：启动 Hindsight {#step-1----start-hindsight}

安装并启动记忆服务器：

```bash
pip install hindsight-all
```

```bash
export HINDSIGHT_API_LLM_API_KEY=YOUR_OPENAI_KEY
hindsight-api
```

服务会在本机 `http://localhost:8888` 上运行，并内置 Postgres、嵌入向量和重排序功能。无需外部基础设施。

> **注意：** 你也可以使用 [Hindsight Cloud](https://ui.hindsight.vectorize.io)，完全跳过自托管设置。

## 第 2 步：安装集成 {#step-2----install-the-integration}

```bash
pip install hindsight-crewai
```

这会将 `hindsight-client` 和 `crewai` 一并作为依赖安装。

## 第 3 步：接入存储 {#step-3----wire-it-up}

```python
from hindsight_crewai import configure, HindsightStorage
from crewai.memory.external.external_memory import ExternalMemory
from crewai import Agent, Crew, Task

# 配置 Hindsight 实例地址
configure(hindsight_api_url="http://localhost:8888")

# 创建智能体
researcher = Agent(
    role="Researcher",
    goal="Find accurate, detailed information on the given topic.",
    backstory="You are a thorough researcher who digs deep into topics.",
    llm="openai/gpt-4o-mini",
)

writer = Agent(
    role="Writer",
    goal="Write clear, well-structured content based on research.",
    backstory="You are a technical writer who values clarity and precision.",
    llm="openai/gpt-4o-mini",
)

# 创建任务
research_task = Task(
    description="Research the benefits of Rust for CLI tools.",
    expected_output="A detailed summary of Rust's strengths for CLI development.",
    agent=researcher,
)

write_task = Task(
    description="Write a short article based on the research.",
    expected_output="A polished 3-paragraph article.",
    agent=writer,
)

# 创建带持久记忆的团队
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    external_memory=ExternalMemory(
        storage=HindsightStorage(
            bank_id="research-crew",
            mission="Track research findings, technical comparisons, and writing preferences.",
        )
    ),
)

crew.kickoff()
```

就这样。调用 `kickoff()` 后，每项任务的输出都会存入 Hindsight。下次运行这个团队时，Hindsight 会在每项任务开始前召回相关的既往工作。

---

## 第 4 步：再次运行 {#step-4----run-it-again}

第二次运行时，换一个主题：

```python
research_task = Task(
    description="Research how Go compares to Rust for CLI tools.",
    expected_output="A comparison of Go vs Rust for CLI development.",
    agent=researcher,
)
```

此时，研究员拥有第一次运行时积累的上下文。它知道自己已经发现了哪些关于 Rust 的信息。写作者也记得上一篇文章的风格和结构。

第三次运行：

```python
research_task = Task(
    description="Which language should I pick for a new CLI tool?",
    expected_output="A recommendation based on all prior research.",
    agent=researcher,
)
```

此时，团队会借助此前两次研究会话中的信息。知识会持续积累。

## 第 5 步：加入 Reflect，进行更深入的综合分析 {#step-5----add-reflect-for-deeper-synthesis}

CrewAI 的 `Storage` 接口提供 `save` 和 `search`。Hindsight 还支持 `reflect`：它会综合推理所有相关记忆，而不是直接返回原始事实。

由于 `reflect` 不属于 `Storage` 接口，它通过 CrewAI 工具提供：

```python
from hindsight_crewai import HindsightReflectTool

reflect_tool = HindsightReflectTool(
    bank_id="research-crew",
    budget="mid",
    reflect_context="You are helping a development team evaluate programming languages.",
)

researcher = Agent(
    role="Researcher",
    goal="Provide deep, synthesized analysis on technical topics.",
    backstory="You are a senior researcher. Use the hindsight_reflect tool to review what you already know before starting new research.",
    tools=[reflect_tool],
    llm="openai/gpt-4o-mini",
)
```

智能体调用 `hindsight_reflect` 后，会得到一份经过综合推理的答复，其中会利用完整知识图谱的信息，而不只是前 k 个向量匹配结果。

## 为每个智能体配置独立记忆库 {#per-agent-memory-banks}

默认情况下，所有智能体共用一个记忆库。如果你希望每个智能体都有独立记忆，可以这样配置：

```python
storage = HindsightStorage(
    bank_id="research-crew",
    per_agent_banks=True,
)
```

研究员会写入 `research-crew-researcher`，写作者会写入 `research-crew-writer`。每个智能体都会建立自己的知识库。

如果要完全控制记忆库名称，可以使用自定义解析器：

```python
storage = HindsightStorage(
    bank_id="research-crew",
    bank_resolver=lambda base, agent: f"{base}-{agent.lower()}" if agent else base,
)
```

## 易错点和边界情况 {#pitfalls-and-edge-cases}

**1. 记忆库 ID 冲突。** 如果多个互不相关的团队共用一个 `bank_id`，它们的记忆就会混在一起。请为每个团队或项目使用唯一的记忆库 ID。

**2. 任务输出过长。** CrewAI 会把完整任务输出传给 `save()`。如果任务输出很长，Hindsight 会负责分块处理，但存入延迟会增加。请在任务定义中为 `expected_output` 设置合理的长度。

**3. 调整召回预算。** 默认的 `budget="mid"` 在速度和全面性之间取得平衡。对延迟敏感的团队可以使用 `"low"`；需要深入分析时可以使用 `"high"`。预算会影响执行的检索策略数量，以及重排序的程度。

**4. 异步事件循环冲突。** CrewAI 在异步事件循环中运行。该集成通过专用线程池透明地处理冲突。如果你也在自定义工具中执行异步工作，请避免在同一事件循环中直接调用 `hindsight-client`。请改用 `HindsightStorage` 和 `HindsightReflectTool` 抽象。

## 小结 {#recap}

- `hindsight-crewai` 为 CrewAI 智能体提供可持续积累的持久记忆
- 它实现了 CrewAI 的 `Storage` 接口，因此只需三行即可完成集成
- 记忆会在任务完成后自动存入，并在任务开始前自动召回
- `HindsightReflectTool` 支持按需综合生成，帮助进行更深入的推理
- 每个智能体可以使用独立记忆库，也可以按需共享知识

该集成处理了复杂部分：异步兼容性、线程安全、事实提取和多策略检索。你只需指定一个记忆库，就能让团队持续积累知识。

## 后续步骤 {#next-steps}

- **本地试用：** 执行 `pip install hindsight-all hindsight-crewai`，然后运行上面的示例
- **使用 Hindsight Cloud：** 注册一个[免费账户](https://ui.hindsight.vectorize.io)，跳过自托管
- **为记忆限定范围添加标签：** 在 Retain 时使用 `tags`，在搜索时使用 `recall_tags`，按项目、环境或主题划分记忆
- **在 Web UI 中检查记忆：** 在本地运行 `hindsight-control-plane`，或使用云端仪表板浏览事实、实体和心智模型
- **结合使用独立记忆库：** 为专门用途的智能体配置自己的记忆，同时通过一个公共记忆库共享跨智能体知识
