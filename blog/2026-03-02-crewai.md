## 问题：无国籍船员 {#the-problem-stateless-crews}

CrewAI有一个记忆系统。短期、长期、实体记忆。它在单个`kickoff()`内运行良好。

然后进程退出。

下一次运行，机组人员从零开始。学到的每一个事实、做出的每一个决定、发现的每一个实体——都消失了。

当您组建重复运行的团队时，这一点很重要：

- 随着时间的推移加深知识的研究团队
- 记住客户历史的支持团队
- 跨冲刺跟踪决策的规划团队

CrewAI 的内置记忆后端（RAG 存储、SQLite）专为单次运行持久性而设计。对于实际复合的跨运行、跨会话记忆，您需要其他东西。

这就是`hindsight-crewai`包的作用。它使用 Hindsight 的记忆引擎实现 CrewAI 的 `Storage` 界面，因此您的工作人员可以记住一切 - 跨越运行、跨越几天、跨越几周。

---

## 建筑 {#architecture}

以下是它的组合方式：

```
CrewAI Crew
  └─ ExternalMemory
       └─ HindsightStorage (implements Storage interface)
            ├─ save()   → Hindsight retain (extract facts, entities, relationships)
            ├─ search() → Hindsight recall (semantic + graph + temporal retrieval)
            └─ reset()  → Hindsight delete_bank + recreate
```

CrewAI 在每个任务完成后调用 `save()`，在每个任务开始前调用 `search()`。您不管理生命周期 - CrewAI 驱动它，Hindsight 存储它。

在引擎盖下，Hindsight不仅仅存储文本。它提取结构化事实，识别实体，构建知识图，并通过跨编码器重排序运行多策略检索（语义搜索、BM25、图遍历、时间排序）。

你的船员得到一个真正的记忆系统，而不是矢量转储。

## 第 3 步——接线 {#step-3----wire-it-up}

```python
from hindsight_crewai import configure, HindsightStorage
from crewai.memory.external.external_memory import ExternalMemory
from crewai import Agent, Crew, Task

#指向您的Hindsight实例
configure(hindsight_api_url="http://localhost:8888")

#创造智能体
researcher = Agent(
    role="Researcher",
    goal="查找有关给定主题的准确、详细的信息。",
    backstory="​​你是一位深入研究课题的彻底研究者。",
    llm="openai/gpt-4o-mini",
)

writer = Agent(
    role="Writer",
    goal="根据研究撰写清晰、结构良好的内容。",
    backstory="您是一位重视清晰度和精确度的技术作家。",
    llm="openai/gpt-4o-mini",
)

#创建任务
research_task = Task(
    description="研究 Rust 对于 CLI 工具的好处。",
    expected_output="Rust 在 CLI 开发方面的优势的详细总结。",
    agent=researcher,
)

write_task = Task(
    description="根据研究写一篇短文。",
    expected_output="一篇精美的三段文章。",
    agent=writer,
)

#创建具有持久记忆的团队
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    external_memory=ExternalMemory(
        storage=HindsightStorage(
            bank_id="research-crew",
            mission="跟踪研究结果、技术比较和写作偏好。",
        )
    ),
)

crew.kickoff()
```

就是这样。在`kickoff()`之后，每个任务输出都保留在Hindsight中。下次您运行该团队时，它会在开始每项任务之前回顾相关的先前工作。

## 步骤 4 -- 再次运行 {#step-4----run-it-again}

第二轮，不同的主题：

```python
research_task = Task(
    description="研究 Go 与 Rust 在 CLI 工具方面的比较。",
    expected_output="CLI 开发中 Go 与 Rust 的比较。",
    agent=researcher,
)
```

现在研究人员已经了解了第一次运行的背景信息。它知道它已经发现了有关 Rust 的内容。作者还记得上一篇文章的风格和结构。

第三轮：

```python
research_task = Task(
    description="我应该为新的 CLI 工具选择哪种语言？",
    expected_output="基于所有先前研究的建议。",
    agent=researcher,
)
```

团队现在借鉴了之前的两次研究成果。知识复合。

## 第五步——添加反思以进行更深入的综合 {#step-5----add-reflect-for-deeper-synthesis}

CrewAI的存储接口有`save`和`search`。但Hindsight还支持`reflect`——一种综合操作，可以对所有相关记忆进行推理，而不是返回原始事实。

由于`reflect`未映射到存储接口，因此它被公开为CrewAI工具：

```python
from hindsight_crewai import HindsightReflectTool

reflect_tool = HindsightReflectTool(
    bank_id="research-crew",
    budget="mid",
    reflect_context="您正在帮助开发团队评估编程语言。",
)

researcher = Agent(
    role="Researcher",
    goal="提供有关技术主题的深入综合分析。",
    backstory="你是一名高级研究员。在开始新的研究之前，使用后视反映工具回顾您已经知道的内容。",
    tools=[reflect_tool],
    llm="openai/gpt-4o-mini",
)
```

当智能体调用`hindsight_reflect`时，它会得到一个综合的、推理的响应，该响应利用完整的知识图——而不仅仅是前k个向量匹配。

## 每智能体记忆库 {#per-agent-memory-banks}

默认情况下，所有智能体共享一个记忆库。如果你希望每个智能体都有独立的记忆：

```python
storage = HindsightStorage(
    bank_id="research-crew",
    per_agent_banks=True,
)
```

研究员写信给`research-crew-researcher`，作者写信给`research-crew-writer`。每个智能体都建立自己的知识库。

要完全控制，请使用自定义解析器：

```python
storage = HindsightStorage(
    bank_id="research-crew",
    bank_resolver=lambda base, agent: f"{base}-{agent.lower()}" if agent else base,
)
```

## 陷阱和边缘情况 {#pitfalls-and-edge-cases}

**1。 记忆库ID冲突。** 如果多个不相关的船员共享一个`bank_id`，他们的记忆就会混合在一起。每个团队或项目使用唯一的记忆库 ID。

**2。大量任务输出。** CrewAI 将完整任务输出传递给`save()`。如果您的任务产生很长的输出，Hindsight 会处理分块，但记忆存储延迟会增加。在任务定义中设置合理的 `expected_output` 长度。

**3。 记忆预算调整。** 默认`budget="mid"` 平衡速度和彻底性。对于对延迟敏感的人员，请使用`"low"`。要进行深入分析，请使用`"high"`。预算影响运行多少检索策略以及发生多少重排序。

**4。异步事件循环冲突。** CrewAI 在异步事件循环内运行。集成通过专用线程池透明地处理此问题，但如果您还在自定义工具中执行异步工作，请避免直接从同一事件循环调用`hindsight-client`。请改用 `HindsightStorage` 和 `HindsightReflectTool` 抽象。

## 回顾 {#recap}

- `hindsight-crewai` 赋予 CrewAI 智能体持久、复合的记忆
- 它实现了CrewAI的`Storage`接口，所以集成就是三行
- 记忆在任务完成后自动存储并在任务前调用
- `HindsightReflectTool` 添加按需合成以进行更深入的推理
- 每个智能体记忆库让您根据需要隔离或共享知识

集成处理困难部分：异步兼容性、线程安全、事实提取、多策略检索。您只需将其指向记忆库，然后让您的团队学习即可。
