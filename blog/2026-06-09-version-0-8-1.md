Hindsight 0.8.1 是[0.8.0](/blog/2026/06/08/version-0-8-0)之上的补丁版本：**跳过存储原始文档文本**的新选项，用于数据最小化和隐私敏感部署，以及针对自我管理PostgreSQL的两个操作修复。 **任何使用 VectorChord 运行外部 PostgreSQL 或单模式部署的人都应该升级。**

<!-- truncate -->

- [**可选文档文本存储**](#optional-document-text-storage)：跳过保留保留文档的原始源文本，同时保持提取的记忆完全可搜索。
- [**操作修复**](#operational-fixes)：纠正不支持探针调整的 VectorChord 索引上的向量索引行为，以及在公共模式上可靠安装维护例程。

## 可选文档文本存储 {#optional-document-text-storage}

默认情况下，Hindsight 保留您记忆存储的每个文档的原始源文本，以便您可以读回文档并稍后附加到它们。出于数据最小化、隐私或合规性原因，某些部署宁愿根本不保留原始文本。

0.8.1 添加`HINDSIGHT_API_STORE_DOCUMENT_TEXT` 标志（默认`true`）。将其设置为 `false` 和 Hindsight 停止保留原始源文本 - 提取的记忆、实体和链接仍然存储并且完全可搜索，但原始文档正文不保留。

```bash
export HINDSIGHT_API_STORE_DOCUMENT_TEXT=false
```

禁用存储：

- **阅读仍然有效。** 获取文档会返回其元数据，文本字段为空，而不是出错，因此现有客户端可以继续工作。
- ​​**追加被拒绝。** 追加到文档需要以现有正文为基础，因此追加请求会返回明确的错误，而不是默默地生成部分结果。
- **控制平面告诉你。** 文档视图显示文本存储已关闭的通知，因此空文本永远不会被误认为数据丢失。

设置是服务器级别的。您已经保留的记忆会保留它们存储的任何文本。

## 操作修复 {#operational-fixes}

两个修复使自我管理的PostgreSQL部署更加健壮：

- **VectorChord 探头调谐。** Hindsight 不再强制在不支持它的 VectorChord 索引上使用 `vchordrq.probes` 会话设置，因此矢量搜索可以跨 VectorChord 索引类型正常工作，而不是在没有基于列表的探测的索引类型上失败。
- **公共模式的维护例程。** 0.8.0 中添加的后台维护例程现在已正确安装在默认`public` 架构中运行的部署上，因此定期集成协调和保留强制执行可以在标准单架构设置上按预期运行。

## 其他显著变化 {#other-notable-changes}

- **本地 ML 附加功能的依赖上限。** `tokenizers` 固定到本地 ML 附加功能的兼容范围，因此全新安装可以干净地解决。
- **更清晰的控制平面 URL。** 区域设置前缀不再添加到控制平面 URL。
