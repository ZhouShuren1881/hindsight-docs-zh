Hindsight 0.8.1 是基于 [0.8.0](/blog/2026/06/08/version-0-8-0) 发布的补丁版本：新增跳过原始文档文本存储的选项，适用于数据最小化和隐私敏感型部署；此外还修复了自托管 PostgreSQL 的两个运维问题。**使用 VectorChord 的外部 PostgreSQL 部署，以及单模式部署的用户，都应升级。**

<!-- truncate -->

- [**可选的文档文本存储**](#optional-document-text-storage)：跳过已摄取文档的原始源文本持久化，同时让提取出的记忆仍可被完整检索。
- [**运维修复**](#operational-fixes)：修正不支持探针调优的 VectorChord 索引上的向量索引行为，并确保维护例程能可靠地安装到 `public` 数据库模式中。

## 可选的文档文本存储 {#optional-document-text-storage}

默认情况下，Hindsight 会保存每份已摄取文档的原始文本，以便之后读取文档或向其中追加内容。出于数据最小化、隐私或合规方面的考虑，有些部署可能希望完全不持久化这些原始文本。

0.8.1 新增了 `HINDSIGHT_API_STORE_DOCUMENT_TEXT` 标志（默认值为 `true`）。将它设为 `false` 后，Hindsight 将停止持久化原始源文本；提取出的记忆、实体和链接仍会保存，并且仍可被完整检索，但不会保留原始文档正文。

```bash
export HINDSIGHT_API_STORE_DOCUMENT_TEXT=false
```

禁用文本存储后：

- **仍可读取文档。** 获取文档时会返回其元数据，文本字段为空，而不会报错，因此现有客户端仍可正常工作。
- **不允许追加内容。** 向文档追加内容需要基于已有正文继续构建，因此追加请求会返回明确错误，不会悄悄生成不完整的结果。
- **控制台会明确提示。** 文档视图会显示文本存储已关闭的提示，避免用户把空文本误认为数据丢失。

此设置作用于服务器级别。此前已摄取的记忆仍保留其原先存储的文本。

## 运维修复 {#operational-fixes}

以下两项修复提升了自托管 PostgreSQL 部署的可靠性：

- **VectorChord 探针调优。** 对于不支持探针调优的 VectorChord 索引，Hindsight 不再强制设置会话参数 `vchordrq.probes`。这样，向量检索便能在各种 VectorChord 索引类型上正常工作，不会再因某些索引不支持基于列表的探测而失败。
- **public 数据库模式中的维护例程。** 0.8.0 新增的后台维护例程现在也能正确安装到使用默认 `public` 数据库模式的部署中，因此在标准的单数据库模式配置下，能按预期定期执行整合协调处理和保留期限规则。

## 其他值得关注的变更 {#other-notable-changes}

- **限制本地 ML 附加依赖的版本范围。** `tokenizers` 现被限制在与本地 ML 附加依赖兼容的版本范围内，使全新安装能够顺利解析依赖。
- **简化控制台 URL。** 控制台 URL 不再添加区域设置前缀。
