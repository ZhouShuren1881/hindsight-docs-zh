# Hindsight 文档翻译规范

## 适用范围与依据

本规范用于 Insight 项目文档的翻译，正文、表格、提示框、内嵌图表和组件中的读者可见文本都在翻译范围内。

- 用户要求翻译新文档时，可以参考其他已有文章的翻译结果。
- 用户要求二次翻译时，任何已翻译文件只可用于确认目录、导入方式、组件接口和代码结构。文章内容应从英文原文重新理解并翻译。
- 以同版本本地英文及其资源为依据。外部链接仍保留，但不把网上的新版本、模型价格或当前推荐替换进这份版本文档。

## 中文表达

- 使用简体中文，面向需要理解架构、调用 API 和部署服务的开发者。表达直接、准确，避免宣传性扩写和生硬的逐词对应。
- 可以调整句内语序、拆分英文长句；必须保留段落的信息、条件、因果、例外和对比关系。不得缩写成摘要，也不得合并掉示例或表格行。
- 清楚指出行为主体：用户、拥有记忆库的智能体、LLM、API 服务、后台工作进程、控制台。英文用 bank 拟人化时，可以按语境写“记忆库”或“记忆库中的智能体”，不能替换成用户。
- 保留义务和概率的强度：must / only / never 对应“必须/仅/绝不”；may / can / typically / recommended 对应“可能/可以/通常/建议”。提示级引导不能译成硬性保证。
- 正文使用中文标点，中文与英文单词、数字之间留一个半角空格；中文标点两侧不加空格。代码、公式、URL、路径和机器值不按此规则重排。
- 普通术语采用术语表的中文。首次出现确有识别需要时附英文；后文不反复中英并列。品牌、数据集、模型名和协议缩写保留原拼写。
- 图中短标签可省略上下文已经明确的“检索”“服务”等词，但不能用新的同义术语。例如正文“语义检索”，图中可以写“语义”。
- 中文几乎不会使用全角斜杠 `／`，使用英文 `/` 替代。

## 核心概念必须分开

| 区分 | 翻译要求 |
| --- | --- |
| Retain / Recall / Reflect | 操作名写 Retain（存入）、Recall（召回）、Reflect（反思）；解释行为分别用“存入/摄取”“检索/召回”“基于记忆推理”。`retain()`、`recall()`、`reflect()` 原样保留。Reflect 不能译成简单搜索。 |
| fact / observation / mental model / knowledge page | 分别为“事实/观测/心智模型/知识页”。观测是整合事实得到、带证据并随证据演变的认知判断；心智模型由用户定义问题、系统生成并维护答案；知识页以心智模型为底层，提供文档与目录树。不得统称为“摘要”。 |
| world / experience | “世界事实/经历事实”。按说话者是否为该库的智能体区分，不按第一人称语法区分。用户说“我买了一辆车”仍是关于用户的世界事实。类型值原样保留。 |
| entity label / tag | “实体标签/标签”。实体标签成为实体，可选择同时写入 tags；一般 tags 用于筛选和限定范围。不能把两者当作同一个字段。 |
| mission / directives / disposition | “任务说明/强制指令/性格倾向”。任务说明提供关注重点或身份背景，强制指令是适用范围内的硬规则，性格倾向影响解读与语气。保留各自作用阶段。 |
| document / chunk / memory unit | “文档/文本分块/记忆单元”。一项输入可以产生多个记忆单元；原始文档与提取后的事实不同。 |
| occurred / mentioned / created / updated | “发生/被提及/创建/更新”。事件时间、提及时间、摄取时间与最后更新时间不能互换。相对时间必须保留其 timestamp 或 query_timestamp 参照。 |
| fresh / stale | “最新/待更新”，表示是否落后于范围内的新记忆，不等于已证明错误或到期删除。需要时写“内容待更新”。 |

## API、配置和示例的语义

- 参数名作标题时保留英文，中文解释放在正文。请求、响应、枚举、工具名和命令中的机器标识符不翻译。
- 保留“省略”“显式 `null`”“空数组 `[]`”“嵌套空数组 `[[]]`”“空对象 `{}`”“`false`”“`0`”“`-1`”的区别。它们的行为依接口而异，不能统译成“未设置”。
- Recall 的 `budget` 表示检索深度/候选规模；Reflect 和心智模型刷新中的 `budget` 表示智能体推理探索的预算。不得跨接口复制解释或默认值。
- Recall 的 `max_tokens` 限定返回事实文本，补充的 chunks 有独立预算；Reflect 的 `max_tokens` 限定最终答案。保留 Recall 首条事实可能完整超预算返回、`max_tokens=0` 可只取分块等例外。
- `temporal_window` 引导 Recall 的时间检索分支和排序，不是整个结果集的时间过滤器。记忆列表的时间窗口才是筛选条件。不要把“提高窗口内结果排名”译成“只返回窗口内结果”。
- tags 匹配须保留 AND / OR、严格匹配是否含无标签数据、`exact` 的集合相等要求。不同接口的默认值不同：Recall、文档列表、心智模型刷新、强制指令适用性分别按所在页面翻译。
- `observation_scopes` 控制整合分组；`consolidation_strategies` 匹配分组后的范围，并非单条事实上的标签。保留首个匹配策略整体生效、未设置项回退到库级默认值等规则。
- “全局”要明确层级：无标签范围是记忆库内的共享范围，不是跨所有租户共享。配置优先级为全局 → 租户 → 记忆库，后者覆盖前者；不是每个字段都允许覆盖。
- 区分同步 API、异步任务、摄取批次和模型供应商的 Batch API。调用成功、排队成功和后台处理完成不等价；观测整合及心智模型刷新有独立生命周期。
- full 刷新是完整重建；delta 刷新是针对既有文档结构应用增量编辑。保留无既有内容、问题变化时回退的条件，以及编辑失败保留旧内容、时间窗口不推进的要求。
- `structured_output` 是在可读答案之外增加的结构化表示，不能译成替代答案。失败、未匹配出数据、HTTP 错误各有不同信号。
- 删除、失效、清空、恢复、重新处理、导出、导入和克隆分别描述。尤其不能把可逆的记忆失效写成物理删除，或把重处理写成保留人工修订。
- 所有默认值、范围、状态码、端口、版本、日期、百分比、金额、单位和公式原样核对。characters 与 tokens、维度与输入长度、秒与毫秒不能互换；不换算币种或更新示例日期。
- 命令和示例原则上完整保留。可翻译纯说明性注释，但必须保留 region/section 标记、命令、转义、缩进、语言标识及与测试对应的文本。改变字符串会影响实体匹配、标签、签名、输出对照或多语言演示时，原样保留。
- 多语言章节中作为被摄取内容、实体名和输出语言演示的中日英文本保留原语言；只翻译其讲解。不能把所有示例改成中文后破坏演示目的。

## Markdown、MDX 和导航结构

- 保留 frontmatter 的键及结构。`title`、`description`、`sidebar_label` 等读者可见值可翻译；`id`、`slug`、`sidebar_position`、布尔开关等不变。
- 保留标题层级、列表结构、表格列数、提示框类型（`note`、`tip`、`info`、`warning`、`caution`）和闭合标记；可翻译提示框标题。
- 保留 import、组件名、变量名、`@site` 路径、`!!raw-loader!`、`CodeSnippet` 的 `section` / `language`、Tabs 的 `value`。Python、Node.js、Go、CLI 等标签保留。
- 链接显示文字可以翻译；链接目标、文件名和查询串不得因中文标题而随意改写。保留显式 `{#anchor}`。
- 中文标题会改变自动锚点。正文翻译应优先保留原文英文锚点作为显式 ID（重复标题也需保持各自原 ID）。不能只对中文标题机械生成锚点。
- 不根据译文内容改变目录或页面分工。
- 按照 CommonMark 规则，当闭合标记前面是标点时，后面必须是空白、标点或行尾。`**文本：**文本` 这样的格式是经典错误。

## 内嵌图表与组件

1. 按资源映射继续读取英文的 `figures/*.json`、直接导入的组件、组件内部的数据和子组件，不能只翻译 MDX 正文。静态图片检查画面中的标题、图例和单位。
2. JSON 图表可翻译读者可见的 `title`、文字形式的 `label`、`label.title`、`label.text`、`caption`、`content[].text` 以及动画场景中动态显示的文字。字段名保持不变；具体值仍要判断是否为技术标识符。
3. `id`、元素引用、`children`、场景/节拍关联、选择器、布局、坐标、颜色、样式、速度和数值全部保留。技术文本如 `caused_by`、`append_block`、`last_memory_seen_at`、函数或工具名即使放在 text 中也不翻译。
4. 动画每个场景都要处理：初始节点、过渡标签、结尾状态、动态覆盖文本、旧版本和证据记录均须一致。示例中的人名变体（Alice Chen / Alice C.）、实体身份、时间、因果和否定关系不能被本地化抹平。
5. 组件可翻译文字节点、可见字符串、tooltip、说明性 alt、`aria-label` 和国际化字典的值；字典键、插值占位符（如 `{memories}`）、图标键和数据索引保持不变。不能对所有字符串全局替换。
6. 基准图中保留数据集、比较对象、数值、单位、坐标尺度和方向。“检索准确率”“每项任务的纠正次数”“每项任务成本”是不同指标；对数轴、三次运行均值、没有公开对比数据等限制必须译出。不能把成本下降解释成完成率提高。
7. 排行榜截图属于原文时点的画面，不据此写成当前排名或当前价格。后续若要制作中文图片，应保留数据与出处，并按具体任务处理资源；不能仅翻译 alt 就声称画面已汉化。
8. 图表资源和组件可能被其他文章共享。应识别共享关系，保持同一资源的译法一致，避免不同页面相互覆盖译法。

## 原文不一致的处理

发现行为描述、默认值或名称互相冲突时，疑点记录应包含英文路径、所在章节、冲突双方和影响；已有疑点见来源清单中的“原文疑点”。不以旧译文、个人经验或网上新版本来消除矛盾。

术语表只规范同一概念的译法，不授权事实修正。若旧页面把 observations 与 mental models 混用，不要悄悄替换英文术语；保留忠实翻译并提出原文疑点。真正的正文修正应作为可审查的独立决定。

## 交付检查

- **源文完整性**：每页对应同版本英文；标题、正文、表格、提示、示例和内嵌资源无遗漏。
- **术语与语义**：按术语表逐项核对；重点检查类型、预算、范围、时间、默认值、否定和例外。
- **结构与接口**：导入、代码片段、机器值、公式和资源关联不被翻译损坏；JSON 可解析。
- **链接完整性**：页内和跨页链接指向正确的锚点，资源路径有效。
- **页面呈现**：检查长中文标签、tooltip、所有动画状态和可访问文本。
- **工具文档质量**：Markdown 结构、来源映射和变更范围准确。
