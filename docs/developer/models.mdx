# 模型 {#models}

Hindsight 使用四类模型。只有 LLM 需要配置：嵌入模型和重排序模型默认在本地运行，决策模型则可按需启用。

| 模型 | 作用 | 默认值 |
|---|---|---|
| [**LLM**](#llm) | 在 Retain 时提取事实、整合观测、撰写 Reflect 答案和知识页 | `openai` 提供方，`gpt-4o-mini` |
| [**嵌入模型**](#embedding-model) | 将文本转换为向量，供语义检索使用 | `BAAI/bge-small-en-v1.5`，本地运行 |
| [**重排序模型**](#cross-encoder-reranker) | 根据相关性对 Recall 候选结果排序 | `hindsight-ai/hs-rerank-1`，本地运行 |
| [**决策模型**](#decision-model) | 快速回答类型化判断问题，让 Recall、整合、Reflect 和知识页中的判断无需调用 LLM | 关闭。参见[决策模型](./decision-models) |

本地模型在首次运行时从 Hugging Face 下载。[配置](./configuration#llm-provider)列出了所有设置；本页介绍各提供方所需的配置。

## LLM {#llm}

用于事实提取、实体消歧、观测整合和答案综合生成。选择提供方后，其卡片会显示默认模型，因此不一定要设置模型。

### 提供方能力 {#provider-capabilities}

部分提供方支持降低成本或延迟的功能。配置的提供方支持时，Hindsight 会自动使用；上方提供方卡片显示了各项支持情况：

- **Batch API**：通过提供方的异步批量端点提交批量 Retain 提取，成本通常降低约 50%。不可用时调用会同步运行。
- **提示缓存**：复用 Retain 和整合每次调用发送的大型固定系统前缀，按提供方的缓存输入费率计费。Gemini 和 Vertex AI 使用 `CachedContent` API。默认启用，可通过 `HINDSIGHT_API_LLM_PROMPT_CACHE_ENABLED=false` 关闭。所有记忆库的缓存前缀相同，因此共享一个缓存；缓存创建失败时会回退到不使用缓存的调用。

:::note
卡片没有“提示缓存”并不意味着提供方没有缓存功能。OpenAI 会在其服务端自动缓存稳定的提示前缀，无需配置。该标记仅表示 Hindsight 的显式缓存接口，目前由 Gemini 和 Vertex AI 实现。
:::

### 模型要求 {#model-requirements}

- **遵循 JSON 模式（JSON Schema）。** 每次调用，包括 Reflect 的工具调用，都是针对响应模式 的回复（结构化输出）；系统不使用原生工具调用，因此模型无需支持工具。
- **至少支持 65,000 个输出 token。** Retain 需要较长的结构化输出。对于输出上限较小的模型，请调低 `HINDSIGHT_API_RETAIN_MAX_COMPLETION_TOKENS`（例如设为 `32000` 或 `16000`）。该值必须高于 `HINDSIGHT_API_RETAIN_CHUNK_SIZE`（默认为 `3000`）；服务启动时会检查。
- **思考模型的推理与可见答案共享输出预算。** 对于 Gemini 2.5+/3.x、GPT-5 和 o 系列、Grok reasoning 及 Claude extended thinking，提供方的输出上限涵盖推理和可见答案，因此较小的上限可能被推理耗尽，导致答案截断。为此，Reflect 的综合生成调用默认不设上限；`HINDSIGHT_API_REFLECT_MAX_COMPLETION_TOKENS` 可设置硬上限，应在页面长度之外为推理留出空间。Gemini 调用达到上限时会记录 `truncated at max_output_tokens` 警告，而不是返回不完整的答案。

LLM 是 Retain 的主要瓶颈。加速方法参见[性能](./performance)。

### 低成本记忆模型与故障切换 {#cheap-memory-model-with-failover}

Hindsight 只会使用自己的凭据调用 LLM 来处理记忆：在 Retain 时提取事实、整合观测、刷新心智模型，以及回答 Reflect 请求。你的智能体仍会调用它原本使用的模型，Hindsight 不会看到或更改该模型。因此，记忆模型可以选择成本较低、吞吐量较高的模型，优先满足处理量需求，而不必与智能体的推理模型相同。

常见的生产配置是将低成本模型设为首选，并在其后配置能力更强、价格更高的模型，仅在低成本模型失败时使用。相关配置方法见[多 LLM 策略](./configuration#multi-llm-strategies-failover--round-robin)和[按操作配置 LLM](./configuration#per-operation-llm-configuration)：

```bash
# 成员 0（主模型）：低成本主力模型，处理几乎所有调用
export HINDSIGHT_API_LLM_PROVIDER=groq
export HINDSIGHT_API_LLM_API_KEY=<groq-key>
export HINDSIGHT_API_LLM_MODEL=<cheap-model>

# 成员 1：中档回退模型
export HINDSIGHT_API_LLM_1_PROVIDER=openai
export HINDSIGHT_API_LLM_1_API_KEY=<openai-key>
export HINDSIGHT_API_LLM_1_MODEL=<mid-model>

# 成员 2：最后使用的高端模型，使用独立的重试预算
export HINDSIGHT_API_LLM_2_PROVIDER=anthropic
export HINDSIGHT_API_LLM_2_API_KEY=<anthropic-key>
export HINDSIGHT_API_LLM_2_MODEL=<top-model>
export HINDSIGHT_API_LLM_2_MAX_RETRIES=3

export HINDSIGHT_API_LLM_MAX_RETRIES=0   # 立即切换到回退模型，不重试当前成员
export HINDSIGHT_API_LLM_STRATEGY='{"mode": "failover"}'
# 也可以分摊负载：'{"mode": "round-robin", "weights": [4, 1, 1]}'
```

若要让某项操作使用更强的模型，只需覆盖该操作的主模型。其回退链仍会使用上方的全局成员：

```bash
# 整合从中档模型开始；Retain 和 Reflect 仍使用低成本模型
export HINDSIGHT_API_CONSOLIDATION_LLM_PROVIDER=openai
export HINDSIGHT_API_CONSOLIDATION_LLM_API_KEY=<openai-key>
export HINDSIGHT_API_CONSOLIDATION_LLM_MODEL=<mid-model>
```

若要为某项操作配置完全独立的模型链，可为其设置独立的索引成员和策略（例如 `HINDSIGHT_API_RETAIN_LLM_1_PROVIDER`、`HINDSIGHT_API_RETAIN_LLM_STRATEGY` 等）。

需要注意：

- **成员编号从 1 开始且不能跳号。** Hindsight 遇到第一个缺少 `HINDSIGHT_API_LLM_<n>_PROVIDER` 的编号时就会停止读取。例如，设置了 `_1_` 和 `_3_` 时，会忽略成员 3。
- **如果某项操作没有配置自己的成员或策略，就会使用全局配置。** 心智模型刷新会先使用 Reflect 的模型链，然后使用全局模型链。
- **批量 Retain 不会执行故障切换。** 设置 `HINDSIGHT_API_RETAIN_BATCH_ENABLED=true` 时，整个批次会使用第一个提供方支持 Batch API 的成员。请在该位置配置可靠的提供方。
- **启动时会向每个已配置的模型发送测试调用。** 如果模型不可用，系统只会记录警告，服务器仍会启动。设置 `HINDSIGHT_API_SKIP_LLM_VERIFICATION=true` 可跳过这些检查，例如回退模型按调用收费或响应缓慢时。

### OpenAI 和兼容端点 {#openai-and-compatible-endpoints}

OpenAI 的 Chat Completions API，以及使用相同协议的 API，例如 Together AI、vLLM 和网关。

<ProviderSetup>

```bash
export HINDSIGHT_API_LLM_PROVIDER=openai
export HINDSIGHT_API_LLM_API_KEY=sk-xxxxxxxxxxxx
export HINDSIGHT_API_LLM_MODEL=gpt-5.6-luna   # default: gpt-4o-mini
```

`openai` 提供方调用 Chat Completions API（`/v1/chat/completions`），因此支持**任何兼容 OpenAI 的 API**（Together AI、vLLM、网关等）：将 `HINDSIGHT_API_LLM_BASE_URL` 设为提供 `/chat/completions` 的 URL。对大多数提供方来说，这是以 `/v1` 结尾的 URL，而**不是**账户或资源根地址。Azure OpenAI 不在资源根地址提供 API，因此仅使用 `https://<resource>.openai.azure.com` 会返回 `404 Resource not found`；可用的 URL 格式参见[设置 Azure OpenAI](#azure-openai-setup)。

</ProviderSetup>

### 设置 GitHub Copilot {#github-copilot-setup}

通过官方 GitHub Copilot SDK 使用 GitHub Copilot 订阅执行 Hindsight 的提取、整合和反思调用。

<ProviderSetup>

**前提条件：**
- 已开通 GitHub Copilot
- 运行 Hindsight 的操作系统用户已登录 Copilot CLI

**配置 Hindsight：**

```bash
export HINDSIGHT_API_LLM_PROVIDER=github-copilot
export HINDSIGHT_API_LLM_MODEL=gpt-5.6-terra
# No HINDSIGHT_API_LLM_API_KEY is needed.
```

该提供方会为 Hindsight 的所有 LLM 通道启动一个共享的 Copilot 运行时。运行时使用不带钩子的临时 `COPILOT_HOME`，其中只保存已登录的账户选择；凭据由运行时从系统密钥链或现有的 `gh` CLI 登录中解析。每次调用都会使用相互隔离的临时会话，并禁用仓库说明、技能、Copilot 记忆、内置工具和跨会话存储。这样可防止记忆集成递归地存入自身的提取调用。

用于自动化时，Copilot SDK 还接受 `COPILOT_GITHUB_TOKEN`、`GH_TOKEN` 或 `GITHUB_TOKEN`。设置其中任一项后，主机无需运行过 Copilot CLI，因此容器和 CI 镜像无需包含 `~/.copilot` 也能运行。GitHub Actions 和服务器到服务器的部署必须具备相应的 Copilot 组织策略和令牌权限。

**重要说明：**
- 用量计入已验证身份的账户或组织的 Copilot 配额及 AI Credits。
- `HINDSIGHT_API_LLM_BASE_URL` 可选，用于指向现有的无头 Copilot 运行时，例如 `http://127.0.0.1:4321`；对于此提供方，它不是 LLM 提供方端点。
- GitHub 托管的 Copilot 会话不会通过 SDK 提供 temperature 或最大输出 token 控制，因此不会应用 Hindsight 的这些设置。
- 嵌入和重排继续使用 Hindsight 单独配置的提供方；其本地默认配置无需 API 密钥。

</ProviderSetup>

### 设置 ChatGPT（使用 ChatGPT 登录） {#chatgpt-setup-sign-in-with-chatgpt}

`chatgpt` 提供方通过 OpenAI 为开源应用提供的[使用 ChatGPT 登录流程](https://developers.openai.com/siwc/token-sharing-open-source)，使用你的 ChatGPT 套餐执行 Hindsight 的 LLM 调用。
首次登录时，Hindsight 会为自身注册 OAuth 客户端；每次调用都会携带 OAuth 访问令牌，发送到公开的
`https://api.openai.com/v1/responses` 端点。此方式不使用 API 密钥。

<ProviderSetup>

它与 `openai-codex` 的区别是：后者复用 Codex CLI 的登录状态，并调用 ChatGPT 的私有
`chatgpt.com/backend-api/codex` 端点。`chatgpt` 使用受支持的访问路径并自行管理凭据，不会与 Codex CLI 共享或轮换令牌。

**前提条件：**
- 允许在第三方应用中使用套餐用量的 ChatGPT 套餐
- 登录操作所在的计算机上有浏览器

**在有浏览器的计算机上设置（例如笔记本电脑）：**

1. **登录：**
   ```bash
   hindsight-admin chatgpt login
   ```
   此命令会打开浏览器，并等待 `http://127.0.0.1:1455/auth/callback` 上的回调
   （`--port` 可更改端口；`--no-browser` 会打印 URL，而不打开浏览器）。请批准请求，包括使用 ChatGPT 套餐用量。
   命令会验证 ID 令牌和已授权的 scope，然后将凭据写入 `~/.hindsight/chatgpt/credentials.json`（权限模式 `0600`），
   并与此主机的 `host_id` 放在一起。
   如果你拒绝了套餐用量授权，请运行 `login --enable-plan-usage` 再次确认。

2. **配置 Hindsight：**
   ```bash
   export HINDSIGHT_API_LLM_PROVIDER=chatgpt
   # export HINDSIGHT_API_LLM_MODEL=gpt-6-luna       # 默认值
   # export HINDSIGHT_API_LLM_REASONING_EFFORT=medium  # 作为 reasoning.effort 发送
   ```

3. **检查已保存的会话**（会显示账户、客户端 ID、scope 和到期时间，不会显示令牌值）：
   ```bash
   hindsight-admin chatgpt status
   ```

**自托管服务器或虚拟机（没有浏览器）：** `127.0.0.1` 回调会到达运行浏览器的计算机，因此请在笔记本电脑上登录，再将凭据文件传到服务器。

1. 在笔记本电脑上按上述步骤运行 `login`。
2. 使用 SSH 复制文件，并在服务器上以运行 Hindsight 的用户身份执行 `login --from-file` 安装凭据（如果服务器设置了 `HINDSIGHT_API_LLM_CHATGPT_HOME`，请在 `login` 前添加 `--home <dir>`）。
   `--from-file` 会保留服务器自己的 `host_id`（首次使用时会创建），而不是使用笔记本电脑的 ID：
   ```bash
   scp ~/.hindsight/chatgpt/credentials.json server:/tmp/chatgpt.json
   ssh server 'hindsight-admin chatgpt login --from-file /tmp/chatgpt.json && rm /tmp/chatgpt.json'
   ```
3. 在笔记本电脑上停止使用该凭据副本，但不要撤销它：
   ```bash
   hindsight-admin chatgpt logout --local-only
   ```
   刷新令牌会轮换，因此复制完成后，只有服务器可以使用并刷新此会话。普通的 `logout` 会撤销会话，也会终止服务器上的会话。
   `--local-only` 会清除笔记本电脑上的令牌，但保留客户端注册，以便之后再次 `login`。
   如果服务器上已注册的是另一个账户，`--from-file` 会拒绝替换，除非传入 `--force`。

之后由服务器负责刷新令牌。若你之后也想在笔记本电脑上使用 Hindsight，请在该电脑上重新登录。

**重要说明：**
- 访问令牌有效期为一小时，并会自动刷新（到期前五分钟刷新；收到 HTTP 401 时也会刷新一次）。刷新令牌会轮换；刷新时会取得文件锁并重新读取文件，因此多个 Hindsight 进程可以共用一个凭据目录。
- 刷新令牌失效后，调用会失败，并提示需要运行的 `login` 命令。
- 在 ChatGPT Plus 上，五小时用量限额由所有使用你套餐的应用共享，包括 Codex。达到限额后，Hindsight 会延后 Retain 和整合工作，并在 30 分钟后重试，而不是直接失败。可在 [ChatGPT 设置 → 用量](https://chatgpt.com/settings/usage)查看用量及各应用限额。
- 此访问路径仍处于预览阶段：Hindsight 会发送 `store: false` 和 `stream: true`，省略该端点不接受的字段（包括 `temperature`、`max_output_tokens`、`user` 等），并将系统提示作为 developer 消息发送。
- `logout` 会撤销会话并清除本地令牌，但保留客户端注册和主机 ID，以便下次 `login`。`logout --local-only` 只清除令牌，不会撤销会话。
- `HINDSIGHT_API_LLM_CHATGPT_HOME` 可更改凭据目录。每个 ChatGPT 账户应使用独立目录。该目录必须可写，因为每次刷新都会将轮换后的令牌写回；在容器中，请在此处挂载可写卷。如果写入失败，进程会在内存中保留新令牌，但其他进程和重启后的进程无法读取它们。

</ProviderSetup>

#### 为长期运行的服务隔离 Codex 身份验证 {#isolating-codex-auth-for-long-running-services}

默认情况下，Hindsight 从 `~/.codex/auth.json` 读取 Codex 凭据；`@openai/codex` CLI、编辑器插件和其他智能体运行时也使用此文件。这对本地开发很方便，但当 Hindsight 与另一个 Codex 进程一起作为**长期运行的服务**（systemd 单元、容器、后台守护进程）运行时，可能会出现一个不易察觉的问题：

- Codex 刷新令牌只能使用一次，刷新后就会轮换。
- 如果另一个进程刷新了共享令牌，Hindsight 的长期运行进程仍持有过期的刷新令牌。
- Recall 和 `/health` 仍可用（数据库和 API 正常），但 `/reflect` 会失败，并显示类似以下错误：
  ```text
  Codex refresh_token is permanently invalid (error.code=refresh_token_reused).
  Run 'codex auth login' to re-authenticate.
  ```

为避免此问题，请通过 `CODEX_HOME` 环境变量为 Hindsight 服务指定**专用的 Codex 身份验证目录**。Hindsight 与 `@openai/codex` CLI 一样遵循 `CODEX_HOME`：设置该变量后会读取 `$CODEX_HOME/auth.json`，而不是 `~/.codex/auth.json`。

```bash
# Dedicated credentials directory for the Hindsight service
export CODEX_HOME=/var/lib/hindsight/codex

# One-time login into that isolated home (opens a browser / device-code flow)
codex auth login   # writes $CODEX_HOME/auth.json

export HINDSIGHT_API_LLM_PROVIDER=openai-codex
hindsight-api
```

对于 systemd 单元，请在服务定义中设置此变量，避免它与交互式 Codex 会话共享凭据：

```ini
[Service]
Environment=CODEX_HOME=/var/lib/hindsight/codex
```

在专用目录中重新登录并仅重启 Hindsight 服务后，`/reflect` 就会使用自己的令牌，不会被其他 Codex 进程轮换失效。

`openai-codex` 嵌入提供方也遵循 `CODEX_HOME`。

#### 在同一进程中使用两个 Codex 配置 {#two-codex-profiles-in-one-process}

`CODEX_HOME` 是进程级设置，因此 Hindsight 进程创建的每个 Codex 提供方都会解析到同一个 `auth.json`。若要运行多个分别授权的 ChatGPT 账户（例如首选账户达到用量上限时进行故障转移），请通过 `HINDSIGHT_API_LLM_CODEX_HOME`（主配置）和 `HINDSIGHT_API_LLM_<n>_CODEX_HOME`（索引式[多 LLM 链](./configuration#multi-llm-strategies-failover--round-robin)成员）为每个账户指定独立凭据目录。未设置时，每个配置会依次回退到 `CODEX_HOME`，再回退到 `~/.codex`。

```bash
# Two profiles, logged in separately
CODEX_HOME=/var/lib/hindsight/codex-a codex auth login
CODEX_HOME=/var/lib/hindsight/codex-b codex auth login

export HINDSIGHT_API_LLM_PROVIDER=openai-codex
export HINDSIGHT_API_LLM_CODEX_HOME=/var/lib/hindsight/codex-a
export HINDSIGHT_API_LLM_1_PROVIDER=openai-codex
export HINDSIGHT_API_LLM_1_CODEX_HOME=/var/lib/hindsight/codex-b
export HINDSIGHT_API_LLM_STRATEGY='{"mode": "failover"}'
```

令牌刷新按身份验证文件路径协调，因此两个配置会分别刷新，互不覆盖。故障转移遵循通用的多 LLM 行为：前一个成员用尽自身重试并报错后，才会尝试下一个成员。系统没有单独的配额分类器或冷却机制，因此达到速率限制的主配置会在每个请求开始时再次重试（并失败），然后才由回退配置处理请求。

</ProviderSetup>

### 设置 Meta Model API {#meta-model-api-setup}

[Meta Model API](https://ai.developer.meta.com) 通过 OpenAI 兼容端点提供 Muse Spark 模型。

<ProviderSetup>

请先在 Model API 控制面板获取密钥，然后：

```bash
export HINDSIGHT_API_LLM_PROVIDER=meta
export HINDSIGHT_API_LLM_API_KEY=your-meta-model-api-key
export HINDSIGHT_API_LLM_MODEL=muse-spark-1.3
```

默认基础 URL 为 `https://api.meta.ai/v1`。可用模型包括 `muse-spark-1.3`（推荐）、`muse-spark-1.2`、`muse-spark-1.1`，以及 1.3 和 1.2 的折扣版 `-contributor` 变体；这些变体允许使用你的提示词和补全内容进行训练。所有模型的上下文窗口均为 1,048,576 个 token。

#### 必须设置的参数 {#required-knobs}

Muse Spark **总是在回复前进行推理**。以下所有设置都由这一特性决定，因此应将它们视为必需项，而非可选的调优参数：

| 变量 | 设置值 | 原因 |
|----------|-----------|-----|
| `HINDSIGHT_API_REFLECT_LLM_TIMEOUT` | `300` | Reflect 的默认值为 30s。Muse Spark 的最终答案合成耗时更久；重试后调用仍会失败，而非降低要求继续运行，Reflect 将不会返回任何内容。 |
| `HINDSIGHT_API_LLM_TIMEOUT` | `300` | 全局超时（默认 120s）也涵盖存入和整合，这两项操作在此模型上的耗时比非推理模型更长。 |
| `HINDSIGHT_API_LLM_REASONING_EFFORT` | 不设置，或设为 `minimal`/`low`/`medium`/`high`/`xhigh` | `none` 会被拒绝并返回 `HTTP 400`。保持未设置可让模型自行决定推理深度。 |
| `HINDSIGHT_API_RETAIN_MAX_COMPLETION_TOKENS` | 保留 `64000` 默认值 | 推理 token 会计入**输出**预算。若将此值调得过低，回复可能完全没有内容。 |

#### 其他说明 {#good-to-know}

- **自动缓存提示词。** 无需设置密钥、开关或分界点；Meta 会自行复用匹配的提示词前缀。因此，下方能力表不会列出显式提示缓存支持，但仍可享受缓存带来的好处。
- **不提供 Batch API 或嵌入端点。** 嵌入仍由你配置的 `HINDSIGHT_API_EMBEDDINGS_PROVIDER` 提供。
- **不接受递归 JSON Schema**（返回 `HTTP 400`）。Hindsight 的代码路径不会发送此类 Schema，只有在你添加自引用响应模型时才需要注意。
- **调用耗时可能更长。** 即使提示词很简单，模型用于推理的 token 也可能多于最终返回的 token。

</ProviderSetup>

### 设置 Cursor（Cursor 订阅） {#cursor-setup-cursor-subscription}

通过无头打印模式下运行的 `cursor-agent` CLI，使用 **Cursor 订阅**提供 Hindsight 的提取、整合和反思调用。无需 API 密钥，也无需建立第二种按 token 计费的关系。

<ProviderSetup>

其方向与 [Cursor 集成](/sdks/integrations/cursor)正好相反：后者让 Cursor 作为 Hindsight 的*客户端*。此处则是由 Hindsight 调用 Cursor 作为模型后端。

**前提条件：**
- 有效的 Cursor 订阅（免费计划也可使用，但只能选择 `auto`，详见下文）
- 已在运行 Hindsight 的同一操作系统用户下安装并登录 `cursor-agent`

**设置步骤：**

1. **安装 CLI：**
   ```bash
   curl https://cursor.com/install -fsS | bash
   ```

2. **登录：**
   ```bash
   cursor-agent login
   ```

3. **验证：**
   ```bash
   cursor-agent --version
   cursor-agent --list-models
   ```

4. **配置 Hindsight：**
   ```bash
   export HINDSIGHT_API_LLM_PROVIDER=cursor
   export HINDSIGHT_API_LLM_MODEL=auto
   # 智能体 CLI 每轮需要 15–30s，远超 Reflect 默认的 30s 超时。
   export HINDSIGHT_API_LLM_TIMEOUT=300
   export HINDSIGHT_API_REFLECT_LLM_TIMEOUT=180
   # 无需 API 密钥。也可改用密钥进行身份验证：
   # export HINDSIGHT_API_LLM_API_KEY=...   # 或 CURSOR_API_KEY
   ```

**重要说明：**

- **调高超时。** 每次调用都会启动一个 `cursor-agent` 轮次，使用 `auto` 时需要 15–30s，比 Chat Completions 请求慢，也超过 `HINDSIGHT_API_REFLECT_LLM_TIMEOUT` 默认的 30s。若保留默认值，Reflect 的第一次迭代会先因超时而重试，之后才恢复。
- **结构化输出通过提示词模拟。** CLI 没有 `response_format`、JSON Schema 或 temperature 标志，只有用于描述封装格式的 `--output-format text|json|stream-json`。Hindsight 会把 Schema 放入提示词，再解析模型返回的 JSON；解析失败时会重试。这种方式不如原生 Schema 可靠，因此建议 Reflect（最依赖该功能的操作）使用明确命名的强模型，而不是 `auto`。
- **免费计划只能使用 `auto`。** 指定 `--model` 会返回 `Named models unavailable Free plans can only use Auto`。付费计划可使用 `cursor-agent --list-models` 列出的任意 ID。
- **会关闭智能体自身的工具。** `cursor-agent` 是智能体而非补全端点：它带有 Shell、Read、Write、Delete、网页抓取等工具；`--mode ask` **不能**关闭工具，无头运行时仍会读取工作目录中的文件。因此，Hindsight 会在空临时工作区中运行 CLI，为其指定独立的 `CURSOR_CONFIG_DIR`（使其无法读取你的 `~/.cursor` 配置、钩子或会话历史），并在其中写入 `cli-config.json`，按名称禁用所有工具。这相当于 `claude-code` 提供方传给 SDK 的 `tools=[]`；由于存入提示词基于你保存在 Hindsight 中的文本构建，因此这一点很重要。
- 用量计入你的 Cursor 订阅。
- 不支持推理强度设置：CLI 没有对应标志；若设置了 `HINDSIGHT_API_LLM_REASONING_EFFORT`，Hindsight 会在启动时警告一次。
- 嵌入和重排仍使用 Hindsight 单独配置的提供方。

</ProviderSetup>

### 设置 SuperGrok 订阅（设备码 OAuth） {#supergrok-subscription-setup-device-code-oauth}

通过 **SuperGrok 订阅**（设备码 OAuth）提供 LLM 调用，无需 API 密钥。如需通过 API 密钥访问 `api.x.ai`，请使用 `provider: openai`，并设置 `HINDSIGHT_API_LLM_BASE_URL=https://api.x.ai/v1`。**此处的提供方用于订阅登录**，与 `openai-codex`（ChatGPT 订阅）及 `claude-code`（Claude 订阅）同类。两种路径访问同一个公开端点，区别仅在凭据：一种是在浏览器中授权一次的固定费率个人订阅，另一种是按 token 计量的密钥。

<ProviderSetup>

身份验证使用 xAI 自己的 OIDC 发行方 `https://auth.x.ai` 和 RFC 8628 设备码流程；公开 OAuth 客户端 ID 发布在 xAI 的 Apache-2.0 许可 Grok CLI 源代码中。Hindsight 使用自己的凭据文件，绝不会读写 Grok CLI 的 `~/.grok/auth.json`。

:::note 订阅权限

xAI 可能会根据 SuperGrok 订阅层级限制 `api.x.ai` 的访问：OAuth 授权本身可能有效，但请求仍会被拒绝并返回 HTTP 403。Hindsight 会将其报告为单独的权限错误并说明原因，而不是凭据错误；同时不会重试，也不会丢弃令牌。遇到此问题时，请确认账户层级，或改用 API 密钥提供方。

用量计入你的 SuperGrok 订阅限额。账户支出上限阻止调用时，Hindsight 会报告单独的配额错误，并保留凭据。

:::

**前提条件：**
- 有效的 SuperGrok 订阅
- 登录所用的计算机上有浏览器（设备码流程需要交互式批准；运行中的服务不会执行该流程）

**设置步骤：**

1. **在要保存凭据的主机上登录一次：**
   ```bash
   python -m hindsight_api.engine.providers.xai_oauth_auth login
   ```
   命令会显示验证 URL 和用户代码，等待你批准，然后以仅所有者可访问的权限写入 `~/.hindsight/xai_oauth.json`。

2. **配置 Hindsight：**
   ```bash
   export HINDSIGHT_API_LLM_PROVIDER=xai-oauth
   # export HINDSIGHT_API_LLM_MODEL=grok-4.5   # 默认值为 grok-4.5
   # 无需 API 密钥
   ```

3. **启动 Hindsight：**
   ```bash
   hindsight-api
   ```

**重要说明：**
- 访问令牌会自动刷新：通常在过期前 60 秒刷新（或按配置的请求超时时间提前刷新，以较长者为准）；收到 HTTP 401 后也会刷新一次。多个已配置的通道可以安全地共用一个凭据文件：刷新时会取得咨询锁，并在锁内重新读取文件，因此同级通道不会各自重复刷新。
- 运行中的服务**绝不会**启动设备码流程。若只有重新登录才能恢复服务，调用会失败并显示需要运行的确切命令。
- 通过 `provider: openai` 访问 `api.x.ai` 时不会这样处理；此提供方会发送该成员配置的 `reasoning_effort`，因此此设置在这里生效。唯一不会转发的值是 `none`：xAI 会直接拒绝它（HTTP 400），所以此通道按 API 要求省略该字段。
- 目前只实现了非流式调用。流式响应不会提供 `prompt_tokens_details`，因此缓存 token 的统计值会偏低。

**可选的环境变量覆盖项：**

| 变量 | 用途 | 默认值 |
|---|---|---|
| `HINDSIGHT_API_XAI_OAUTH_BASE_URL` | 指向其他上游；优先级高于 `HINDSIGHT_API_LLM_BASE_URL`。 | `https://api.x.ai/v1` |
| `HINDSIGHT_API_XAI_OAUTH_TOKEN_PATH` | 更改凭据存储位置，读取和写入都会使用此路径。 | `~/.hindsight/xai_oauth.json` |
| `HINDSIGHT_API_XAI_OAUTH_CLIENT_ID` | 覆盖登录和刷新时使用的 OAuth 客户端 ID。 | xAI 发布的公开客户端 ID |
| `HINDSIGHT_API_XAI_OAUTH_SCOPE` | 覆盖登录时请求的 scope 字符串。 | `openid profile email offline_access grok-cli:access api:access` |
| `HINDSIGHT_API_XAI_OAUTH_REFRESH_SKEW_SECONDS` | 提前这么多秒刷新。很少访问提供方的部署可适当调大。 | `60` |
| `HINDSIGHT_API_XAI_OAUTH_REFRESH_TIMEOUT_SECONDS` | 发现、登录和刷新请求的超时时间。 | `20` |

#### 部署说明 {#deployment-note}

凭据保存在主机本地文件中，只有交互式登录才能创建该文件。因此，容器化引擎需要挂载在已完成登录的主机上创建的凭据存储（也可在容器内交互式登录一次），并将 `HINDSIGHT_API_XAI_OAUTH_TOKEN_PATH` 指向该文件。挂载必须**可写**：与 Grok CLI 自己的文件不同，Hindsight 需要在此存储中写入每次轮换后的令牌，因此只读挂载会在当前令牌过期后导致调用失败。

xAI 每次刷新都会颁发一个**新的刷新令牌**，并使被替换的令牌失效。因此，各个副本必须共用同一个凭据文件，而不能各自从一次登录结果的副本启动：只要另一个副本刷新令牌，副本文件就会失效，必须重新登录。支持的部署方式是使用一个共享的可写卷；如果无法提供该卷，请只在一个副本上使用此提供方，并让其他副本使用 API 密钥通道。

</ProviderSetup>

### 设置 Azure OpenAI {#azure-openai-setup}

Azure OpenAI 通过 **`openai`** 提供方访问；没有 `azure` 提供方，若设置该值，启动时会报错：`Invalid LLM provider: azure`。

<ProviderSetup>

容易出错的地方是基础 URL。Azure 不会在资源根路径提供 OpenAI API，因此 Azure 门户中显示的端点不能单独使用：

| `HINDSIGHT_API_LLM_BASE_URL` | 结果 |
|---|---|
| `https://<resource>.openai.azure.com` | `404 Resource not found` |
| `https://<resource>.openai.azure.com/openai/deployments/<deployment>` | `404 Resource not found`（缺少 `api-version`） |
| `https://<resource>.openai.azure.com/openai/v1` | 可用 |
| `https://<resource>.openai.azure.com/openai/deployments/<deployment>?api-version=<version>` | 可用 |

**建议使用 v1 端点：**

```bash
export HINDSIGHT_API_LLM_PROVIDER=openai
export HINDSIGHT_API_LLM_API_KEY=<azure-openai-resource-key>
export HINDSIGHT_API_LLM_MODEL=<deployment-name>
export HINDSIGHT_API_LLM_BASE_URL=https://<resource>.openai.azure.com/openai/v1
```

**或者使用指定部署的格式**。保留 `api-version` 查询字符串；Hindsight 会从基础 URL 中解析该值并传给 SDK：

```bash
export HINDSIGHT_API_LLM_BASE_URL=https://<resource>.openai.azure.com/openai/deployments/<deployment>?api-version=2025-01-01-preview
```

**重要说明：**
- `HINDSIGHT_API_LLM_MODEL` 应填写你的**部署名称**，而非模型名称。例如，将 `gpt-4o` 部署为 `my-gpt4o` 后，配置值应为 `my-gpt4o`。
- 密钥应使用 Azure OpenAI **资源**密钥（`az cognitiveservices account keys list -n <resource> -g <group>`）。API Management 订阅密钥属于另一种凭据：如果前面有 APIM，基础 URL 必须指向 APIM 路由，并且 APIM 必须转发 `api-key` 标头。请先直接请求 Azure 端点，以确认是哪一层出错。
- 网关和代理必须保留相同的路径格式（`/openai/v1` 或 `/openai/deployments/...?api-version=`）。
- Azure OpenAI 的 GPT 部署接受 `prompt_cache_key`（可改进 GPT-5.6 及更高版本的缓存路由），但同一个 `*.openai.azure.com` 端点也可能提供不接受此参数的非 OpenAI Foundry 模型（DeepSeek、Llama、Mistral）；这类模型会返回 `unrecognized_request_argument`。单看主机名无法区分，因此对于 Azure 主机，[`HINDSIGHT_API_LLM_CACHE_AFFINITY`](./configuration#llm-provider) 会将 `auto` 解析为 `none`。如果部署提供的是 OpenAI 模型，请显式设置为 `openai_prompt_cache_key`。

</ProviderSetup>

### Hindsight Inference {#embeddings-hindsight}

[Hindsight Inference](https://inference.hindsight.vectorize.io) 提供专为智能体记忆构建的嵌入模型 `hs-embed-1`，每百万输入 token 收费 $0.005：支持八种语言，向量为 384 维。

### 本地 {#embeddings-local}

在 API 进程中运行 SentenceTransformers：无需密钥，模型下载后无需网络。这是默认方式。推荐使用专为智能体记忆构建的开放嵌入模型 [`hindsight-ai/hs-embed-1`](https://huggingface.co/hindsight-ai/hs-embed-1)。

<ProviderSetup>

```bash
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=local
export HINDSIGHT_API_EMBEDDINGS_LOCAL_MODEL=hindsight-ai/hs-embed-1
```

`hs-embed-1` 有 112M 个参数（MIT），返回 384 维向量，支持八种语言，可读取最多 8,192 个 token 的输入，无需查询或文档前缀。首次启动时从 Hugging Face 下载。不同模型的向量不能混用，因此切换后须重新嵌入已存入的记忆。

其他 Sentence Transformers 模型也以相同方式使用：

| 模型 | 维度 | 用途 |
|---|---|---|
| `hindsight-ai/hs-embed-1` | 384 | 推荐。专为智能体记忆构建，支持 8 种语言 |
| `BAAI/bge-small-en-v1.5` | 384 | 默认。速度快，支持英语 |
| `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | 384 | 支持 50 多种语言 |

需要 `trust_remote_code` 的模型还需要设置 `HINDSIGHT_API_EMBEDDINGS_LOCAL_TRUST_REMOTE_CODE=true`，仅应为信任的模型启用。如需在独立机器或 GPU 上提供模型，参见 [Text Embeddings Inference](#embeddings-tei)。

</ProviderSetup>

```bash
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=bedrock/amazon.titan-embed-text-v2:0
```

:::tip AWS Bedrock 应用推理配置文件

如果组织的服务控制策略在[应用推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)存在后拒绝对裸模型 ID 执行 `bedrock:InvokeModel`，请保持 `..._MODEL` 不变，并单独添加配置文件 ARN：

```bash
export HINDSIGHT_API_EMBEDDINGS_PROVIDER=litellm-sdk
# Stays a recognizable model id: this is what picks the request format
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL=bedrock/amazon.titan-embed-text-v2:0
# The profile actually invoked
export HINDSIGHT_API_EMBEDDINGS_LITELLM_SDK_MODEL_ID=arn:aws:bedrock:eu-west-1:123456789012:application-inference-profile/abc123
```

两者分开设置，是因为 Bedrock 的嵌入请求和响应格式因模型系列（Titan、Cohere、TwelveLabs、Nova）而异，系统根据模型 ID 判断系列。配置文件 ARN 不透明且限定于账户，因此不能用于判断。

聊天模型不需要这样做：设置 `HINDSIGHT_API_LLM_MODEL=bedrock/converse/<arn>`，因为 Converse API 对所有模型采用同一种格式。

:::

</ProviderSetup>

## 交叉编码器（重排器） {#cross-encoder-reranker}

根据与查询的相关性对 Recall 候选结果排序。默认模型 [`hindsight-ai/hs-rerank-1`](https://huggingface.co/hindsight-ai/hs-rerank-1)（多语言，114M 参数）在 API 进程中运行，无需配置。通过 `HINDSIGHT_API_RERANKER_PROVIDER` 选择提供方；所有选项参见[配置 › 重排序模型](./configuration#reranker)。如果为 Recall 配置了[决策模型](#decision-model)，则改由决策模型排序。

<ModelProviderSearch only="reranker" />

### Hindsight Inference {#reranker-hindsight}

[Hindsight Inference](https://inference.hindsight.vectorize.io) 提供专为智能体记忆构建的交叉编码器 `hs-rerank-1`：支持八种语言，查询和文档最多为 8,192 个 token。

<ProviderSetup>

先使用 [`hindsight-admin cloud login`](./admin-cli#cloud) 登录一次，然后：

```bash
export HINDSIGHT_API_RERANKER_PROVIDER=hindsight
```

在无法登录的服务器上，可改为设置密钥 `HINDSIGHT_API_RERANKER_HINDSIGHT_API_KEY`。该密钥优先于已保存的登录信息。

模型权重开放：[`hindsight-ai/hs-rerank-1`](https://huggingface.co/hindsight-ai/hs-rerank-1)（114M，MIT）也可在自己的机器上运行，参见[本地](#reranker-local)。

</ProviderSetup>

### 本地 {#reranker-local}

在 API 进程中运行 SentenceTransformers CrossEncoder：无需密钥，模型下载后无需网络。默认模型为 [`hindsight-ai/hs-rerank-1`](https://huggingface.co/hindsight-ai/hs-rerank-1)，这是专为智能体记忆构建的开放重排序模型。

<ProviderSetup>

`hs-rerank-1` 有 114M 个参数（MIT），支持八种语言，可读取最多 8,192 个 token 的输入。其权重大部分是词汇表，因此每次推理运行的是 15M 参数的 Transformer，在 CPU 上速度很快。

```bash
export HINDSIGHT_API_RERANKER_PROVIDER=local
export HINDSIGHT_API_RERANKER_LOCAL_MODEL=hindsight-ai/hs-rerank-1
```

首次启动时从 Hugging Face 下载。其他交叉编码器也以相同方式使用：

| 模型 | 用途 |
|---|---|
| `hindsight-ai/hs-rerank-1` | 默认。专为智能体记忆构建，支持 8 种语言，输入上限 8,192 token |
| `cross-encoder/ms-marco-MiniLM-L-6-v2` | 速度快，英语（hs-rerank-1 之前的默认模型） |
| `cross-encoder/ms-marco-MiniLM-L-12-v2` | 更准确，英语 |
| `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` | 多语言 |

如需在独立机器或 GPU 上提供模型，可通过 [Text Embeddings Inference](https://github.com/huggingface/text-embeddings-inference) 运行（CPU 镜像使用模型导出的 int8 ONNX），并将 `tei` 提供方指向它：

```bash
docker run -p 8080:80 ghcr.io/huggingface/text-embeddings-inference:cpu-1.9.3 \
  --model-id hindsight-ai/hs-rerank-1 --auto-truncate

export HINDSIGHT_API_RERANKER_PROVIDER=tei
export HINDSIGHT_API_RERANKER_TEI_URL=http://localhost:8080
```

使用 GPU 时，请使用 GPU 镜像：L4 和其他 Ada GPU 使用 `89-1.9.3`，A100 和 H100 使用 `1.9.3`，并带上 `--gpus all`。

</ProviderSetup>

### Cohere 和兼容端点 {#reranker-cohere}

Cohere 的重排 API 或使用相同协议的任意端点：Azure AI Foundry、Jina、Voyage、自行托管的 BGE。


### TypeSafe（已弃用） {#reranker-typesafe}

已弃用：请改为使用 `typesafe` 提供方配置[决策模型](#decision-model)。Recall 使用决策模型替代重排序模型，整合、Reflect 和知识页也会使用。

<ProviderSetup>

TypeSafe 并非 `/rerank` 端点：它回答有关状态的类型化问题。Hindsight 将候选结果作为一道选择题的选项，返回的概率即为排名。候选池符合 250 个选项的限制及 token 预算时，一次调用即可排序；更大的候选池会分组，各组的头部候选进入最终轮次。`HINDSIGHT_API_RERANKER_TYPESAFE_PRUNE_CANDIDATES=true` 会增加第二个问题，在相关内容结束的位置截断列表（参见[配置](./configuration#typesafe)）。其分数表示排名位置，而非相关性，因此 Recall 不返回 `scores.reranker`，并以 HTTP 400 拒绝 `min_scores.reranker`。

</ProviderSetup>

## 决策模型 {#decision-model}

在远不到一秒的时间内回答简短的类型化问题（是或否、从选项中选择、可能性有多大），使 Hindsight 对无需撰写内容的判断跳过 LLM 调用。此功能可选：未配置时（默认 `HINDSIGHT_API_DECISION_MODEL_PROVIDER=none`），所有操作仍仅使用 LLM。各操作的使用方式参见[决策模型](./decision-models)，全部选项（包括按操作覆盖）参见[配置](./configuration#decision-model)。

<ModelProviderSearch only="decision" />

Reflect 和知识页刷新目前仅支持 `hindsight` 和 `typesafe`。使用其他提供方时，它们仍仅使用 LLM 并记录警告，而 Recall 和整合仍会使用该提供方。如需将其他提供方与用于 Reflect 的 `hindsight` 或 `typesafe` 搭配，请覆盖 Reflect 的提供方（参见 [OpenAI Decisions](#decision-openai)）。

如果端点提供的模型并非该提供方的默认模型，还需设置 `HINDSIGHT_API_DECISION_MODEL_MODEL` 和 `HINDSIGHT_API_DECISION_MODEL_TOKENIZER`，并将 `HINDSIGHT_API_DECISION_MODEL_MAX_REQUEST_TOKENS` 设为该模型的上下文窗口减去一定余量。

### Hindsight Inference {#decision-hindsight}

[Hindsight Inference](https://inference.hindsight.vectorize.io) Decisions API 上的 `hs-decide-1-flash`。用于整合、Reflect 和知识页，启用后也用于 Recall。
