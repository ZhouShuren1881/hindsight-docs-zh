# Reflect：借助性格倾向进行智能体推理 {#reflect-agentic-reasoning-with-disposition}

调用 `reflect()` 时，Hindsight 会运行一个**智能体循环**：它自主收集证据，并从记忆库的性格倾向出发进行推理，从而生成符合上下文的回答。

<Figure doc={reflectLoop} />

---

## 工作原理 {#how-it-works}

与简单检索不同，reflect 是一个**智能体系统**，它会：

1. **自主收集证据**——智能体判断需要哪些信息，并调用相应工具。
2. **采用分层检索**——先检查心智模型，再检查观测，最后检查原始事实。
3. **应用性格倾向**——根据记忆库的性格倾向塑造推理方式。
4. **执行适用的强制指令**——包括全局规则，以及与 reflect 标签范围匹配的规则。
5. **引用来源**——返回本次使用了哪些记忆和观测。

### 智能体循环 {#the-agentic-loop}

reflect 智能体会在循环中运行，并可使用以下工具：

| 工具 | 用途 | 优先级 |
|------|------|----------|
| `search_mental_models` | 由用户维护的摘要；在 token 预算范围内返回最匹配项的全文，其余项返回片段 | 最高（首先检查） |
| `read_mental_models` | 读取以片段形式返回的页面全文 | 片段看起来相关时 |
| `search_observations` | 检索整合后的知识 | 高 |
| `recall` | 检索原始事实（核验依据） | 后备方案 |
| `expand` | 获取某条记忆的更多上下文 | 按需 |
| `done` | 使用最终答案结束 | 准备就绪时 |

智能体会：
- **必须先收集证据**再回答（防护机制会阻止空回答）。
- **最多运行 10 轮**来查找相关信息。
- **验证引用**——只有实际检索到的 ID 才能被引用。

### 分层检索策略 {#hierarchical-retrieval-strategy}

智能体采用经过设计的分层检索顺序：

1. [**心智模型**](/developer/api/mental-models)——用户为常见查询预先整理好的摘要。
2. [**观测**](/developer/observations)——整合后的知识，并会关注其更新状态。
3. **原始事实**——当观测待更新时，用于核验的依据。

**心智模型**是保存下来的 reflect 回答，由你为常见问题创建。由于它们代表经过明确维护的知识，因此会优先检查。有关如何创建和管理心智模型，请参阅[心智模型 API](/developer/api/mental-models)。

如果某条观测被标记为**待更新**，智能体会自动根据当前事实核验它。

## 为什么使用 Reflect？ {#why-reflect}

大多数 AI 系统都能检索事实，却无法以一致的方式对事实进行**推理**。

### 问题所在 {#the-problem}

没有 reflect：
- **缺少一致的特征**：同一个问题每次都会得到不同回答。
- **无法综合知识**：系统从不关联彼此相关的事实。
- **缺少推理上下文**：回答不会体现累积下来的知识。
- **回答千篇一律**：所有 AI 听起来都一样。

### 价值所在 {#the-value}

使用 reflect：
- **特征一致**：性格倾向为“注重细节、谨慎”的记忆库会强调风险并周密规划。
- **知识持续演进**：随着证据累积，观测会得到强化和调整。
- **结合上下文推理**：例如：“根据我对你们团队远程办公成效的了解……”
- **行为各有特点**：客服机器人语气圆融，代码审查助手表达直接。

### 何时使用 Reflect {#when-to-use-reflect}

| 在以下情况下使用 `recall()`…… | 在以下情况下使用 `reflect()`…… |
|------------------------|-------------------------|
| 需要原始事实 | 需要经过推理的解读 |
| 正在自行构建推理流程 | 希望回答符合记忆库的性格倾向 |
| 需要最大程度的控制 | 希望记忆库自行“思考” |
| 只需简单查找事实 | 需要形成建议 |

**示例：**
- `recall("Alice")` → 返回与 Alice 有关的所有事实和相关心智模型。
- `reflect("Should we hire Alice?")` → 智能体收集关于 Alice 的证据，推理她是否合适，并返回带引用的回答。

## 性格倾向特征 {#disposition-traits}

创建记忆库时，你可以通过三个特征配置其性格倾向。这些特征会影响记忆库在 `reflect()` 期间如何解读信息和进行推理：

| 特征 | 范围 | 低（1） | 高（5） |
|-------|-------|----------|----------|
| **怀疑倾向** | 1-5 | 容易信任，照单全收 | 持怀疑态度，会质疑和审视主张 |
| **字面倾向** | 1-5 | 灵活解读，能够体会言外之意 | 按字面解读，依照表面含义理解 |
| **共情能力** | 1-5 | 保持距离，侧重事实 | 富有共情，会考虑情绪背景 |

### 任务说明：用自然语言描述身份 {#mission-natural-language-identity}

除了数值特征，你还可以用自然语言提供一段**任务说明**，描述记忆库的身份及其推理背景：

<CodeSnippet code={memoryBanksPy} section="bank-with-disposition" language="python" />

reflect 的任务说明会为智能体的推理和回答提供框架：
- 提供身份背景：智能体是谁、关心什么。
- 说明实际应用性格倾向的方式。
- 让不同对话中的推理保持一致。

:::info 按操作设置的任务说明
reflect 任务说明只影响 `reflect()`。若要引导 `retain()` 提取哪些内容，请使用 [`retain_mission`](/developer/api/memory-banks#retain-configuration)。若要控制哪些内容会综合生成到观测中，请使用 [`observations_mission`](/developer/api/memory-banks#observations-configuration)。
:::

## 性格倾向如何塑造推理 {#disposition-shapes-reasoning}

给两个记忆库提供关于远程办公的相同事实，但让它们采用不同的性格倾向：

**记忆库 A**（怀疑倾向低、共情能力高）：
> “远程办公带来灵活性，也有助于平衡工作与生活。团队似乎更开心、效率也更高，因为成员可以选择适合自己的工作环境。”

**记忆库 B**（怀疑倾向高、共情能力低）：
> “关于远程办公的说法需要核实。实际生产力指标是什么？这些基于个别经历的好处，未必能转化为可衡量的结果。”

**事实相同 → 结论不同**，因为性格倾向会影响解读方式。

## 按使用场景选择性格倾向预设 {#disposition-presets-by-use-case}

不同使用场景适合不同的性格倾向配置：

| 使用场景 | 建议的特征 | 原因 |
|----------|-------------------|-----|
| **客户支持** | skepticism: 2, literalism: 2, empathy: 5 | 容易信任、灵活、善解人意 |
| **代码审查** | skepticism: 4, literalism: 5, empathy: 2 | 会质疑假设、严谨、直接 |
| **法律分析** | skepticism: 5, literalism: 5, empathy: 2 | 高度审慎、按字面精确解读 |
| **治疗师/教练** | skepticism: 2, literalism: 2, empathy: 5 | 提供支持，能体会言外之意 |
| **研究助理** | skepticism: 4, literalism: 3, empathy: 3 | 会质疑主张，解读较为平衡 |

## 强制指令：必须遵守的规则 {#directives-hard-rules}

性格倾向特征会**影响**推理风格，而**强制指令**则是智能体在当前 reflect 范围内适用时**必须**遵守的硬性规则。没有标签的强制指令是全局规则；带标签的强制指令要求 reflect 标签匹配。有关完整的匹配规则和默认行为表，请参阅[记忆库：强制指令](/developer/api/memory-banks#directives)。

### 何时使用强制指令 {#when-to-use-directives}

当某些限制绝不能违反时，请使用强制指令：

- **合规规则**：“绝不推荐特定股票或金融产品。”
- **隐私限制**：“绝不向第三方分享个人数据。”
- **风格要求**：“始终使用正式英语作答。”
- **领域防护规则**：“提出事实性主张时，始终引用来源。”

### 强制指令的范围与标签 {#directive-scope-and-tags}

强制指令的 `tags` 会限定它何时适用，方式与记忆的标签相同。没有标签的强制指令始终适用；带标签的强制指令仅在 reflect 请求带有匹配标签时适用。因此，不带标签的 `reflect` 只会应用没有标签的强制指令。你可以在请求中设置 `apply_all_directives: true`，以强制应用**所有**当前有效的强制指令。详情请参阅[记忆库：强制指令的范围与标签](/developer/api/memory-banks#directive-scope-and-tags)。

### 强制指令与性格倾向 {#directives-vs-disposition}

| 方面 | 性格倾向 | 强制指令 |
|--------|-------------|------------|
| **性质** | 柔性影响 | 硬性规则 |
| **作用** | 塑造解读方式和语气 | 必须严格遵守 |
| **违反后果** | 可以接受（它只是倾向） | 不可接受 |
| **示例** | 怀疑倾向高 → 会质疑主张 | “绝不作出医疗诊断” |

:::tip
用性格倾向设定个性和特征，用强制指令设置合规要求和防护规则。
:::

有关如何创建和管理强制指令，请参阅[记忆库：强制指令](/developer/api/memory-banks#directives)。

## Reflect 会返回什么 {#what-you-get-from-reflect}

调用 `reflect()` 时会返回：

**返回内容：**
- **回答文本**——受到性格倾向影响的智能体回答。
- **`based_on`**——回答所依据的证据，包括记忆、心智模型和强制指令。
- **`trace`**——工具调用、LLM 调用及访问过的观测（需设置 `include.tool_calls=True`）。
- **`structured_output`**——如果提供了 `response_schema`，则返回解析后的回答。
- **`usage`**——token 用量指标。

**示例：**
```json
{
  "text": "Based on Alice's ML expertise and her work at Google, she'd be an excellent fit for the research team lead position...",
  "based_on": {
    "memories": [
      {"id": "mem-123", "text": "Alice has 5 years of ML experience", "type": "world"},
      {"id": "mem-456", "text": "Alice worked at Google on search ranking", "type": "experience"}
    ],
    "mental_models": [],
    "directives": [
      {"id": "dir-001", "name": "Formal Language", "rules": ["Always respond in formal English"]}
    ]
  },
  "usage": {"input_tokens": 1500, "output_tokens": 500, "total_tokens": 2000}
}
```

智能体会自动收集证据、验证引用，并生成有依据的回答。

## 结构化输出 {#structured-output}

默认情况下，Reflect 返回自然语言文本。传入 `response_schema`（一个带有 `properties` 映射的 JSON Schema **对象**），还可以获得同一回答的机器可读版本：

```json
{
  "query": "How does Alice fit the research lead role?",
  "response_schema": {
    "type": "object",
    "properties": {
      "recommendation": { "type": "string" },
      "strengths": { "type": "array", "items": { "type": "string" } },
      "confidence": { "type": "number" }
    },
    "required": ["recommendation"]
  }
}
```

随后，响应会同时包含自然语言和结构化视图：

```json
{
  "text": "Based on Alice's ML expertise and her work at Google, she'd be an excellent fit...",
  "structured_output": {
    "recommendation": "Strong fit for research lead",
    "strengths": ["5 years of ML experience", "Search ranking at Google"],
    "confidence": 0.9
  }
}
```

**工作方式**。智能体先推理出自然语言回答，再通过第二轮处理将其提取为符合 schema 的 JSON。因此，`structured_output` 始终忠实映射 `text`：你既能获得易读回答，也能获得可供程序处理的类型化对象；两者都会返回，不会互相替代。

**提取失败时**。Reflect 仍会以 `200` 状态码返回自然语言回答，但不返回 `structured_output`，并在 `structured_output_error` 字段中说明原因（例如提供方错误、超时或输出无法解析）。如果缺少 `structured_output`，同时也没有该错误字段，表示回答中没有与 schema 匹配的内容；此时可以只重试未匹配的情况，而不必重试普通情况。

**Schema 规则**。Schema 必须是至少包含一个属性的对象。每个属性的 `type` 必须是 `string`、`number`、`integer`、`boolean`、`array` 或 `object` 之一，`required` 则列出必需的属性名。无效 schema 会在调用执行前被拒绝，因此格式错误会立即失败，而不会悄悄返回空结果。

### 心智模型的结构化输出 {#structured-output-for-mental-models}

固定的心智模型可以在其触发器配置中携带自己的 `response_schema`。每次刷新都会在 Markdown 内容旁保存一个 `structured_output`，该输出从**最终保存的文档**中提取。对于 delta 模式（局部编辑）的刷新，这一点很重要：结构化视图反映的是合并后的完整文档，而不是本次刷新中发生变化的事实。

### 构建 Schema（无需编写代码） {#building-a-schema-no-code}

在控制台中，reflect 视图和心智模型对话框都包含一个 **Build schema** 编辑器，提供 **Visual** 模式（添加字段：名称、类型、是否必需、说明）和 **Code** 模式（原始 JSON）。页面本身只会显示是否已设置 schema；所有编辑都在构建器中进行，因此除非你愿意，否则无需手写 JSON。

## 性格倾向为何重要 {#why-disposition-matters}

没有性格倾向，所有 AI 助手听起来都一样。有了性格倾向：

- **客服机器人**可以做到圆融且富有共情。
- **代码审查助手**可以表达直接、审查细致。
- **创意助手**可以乐于接受非常规想法。
- **风险分析师**可以保持恰当的谨慎。

性格倾向让不同对话中的**特征保持一致**，而观测则会**随证据演进**。
