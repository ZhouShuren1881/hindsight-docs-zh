## 启动 API 服务器 {#start-the-api-server}

<Tabs>
<TabItem value="pip" label="pip（仅 API）">

```bash
pip install hindsight-api
export OPENAI_API_KEY=sk-xxx
export HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY

hindsight-api
```

API 可通过 [http://localhost:8888](http://localhost:8888/docs) 访问

</TabItem>
<TabItem value="docker" label="Docker（完整体验）">

```bash

export OPENAI_API_KEY=sk-xxx

docker run -it --pull always --name hindsight --restart unless-stopped --shm-size=1g -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v $HOME/.hindsight-docker:/home/hindsight/.pg0 \
  ghcr.io/vectorize-io/hindsight:latest
```

- **API**：http://localhost:8888
- **控制平面**（Web UI）：http://localhost:9999

:::tip 在生产环境中为 `HINDSIGHT_API_WORKER_ID` 设置稳定值
工作进程使用容器主机名作为身份标识。Docker 默认会将其设为容器 ID。该值每次重启都会变化，因此容器关闭时正在处理的任务会停留在旧 ID 下，新容器也就无法识别这些任务属于自己。

将 `HINDSIGHT_API_WORKER_ID` 设为稳定值（例如 `-e HINDSIGHT_API_WORKER_ID=hindsight-prod`），让工作进程在重启后保持相同的身份标识。即使部署中只有一个容器，也建议这样设置。诊断和恢复命令请参阅[管理 CLI - 恢复卡住的操作](/developer/admin-cli#recovering-stuck-or-zombie-operations)。
:::

</TabItem>
</Tabs>

:::tip LLM 服务提供方
Hindsight 需要支持结构化输出的大语言模型（LLM）。建议使用 **Groq** 和 `gpt-oss-20b`，以快速且经济地进行推理。
详情请参阅 [LLM 服务提供方](/developer/models#llm)。
:::

## 执行过程 {#whats-happening}

| 操作 | 作用 |
|-----------|--------------|
| **Retain（存入）** | 处理内容、提取事实、识别实体，并在知识图谱中建立关联 |
| **Recall（召回）** | 并行运行语义检索、关键词检索、图检索和时间检索四种策略，查找相关记忆 |
| **Reflect（反思）** | 利用检索到的记忆，生成考虑性格倾向的回答 |
