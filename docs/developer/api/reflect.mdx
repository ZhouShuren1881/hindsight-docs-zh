# Reflect {#reflect}

通过智能体推理循环生成有证据依据、并体现性格倾向的回答。

调用 **reflect** 时，Hindsight 会运行智能体循环，自动使用多个检索工具搜索记忆库，依据记忆库的性格倾向调整推理风格，并根据检索到的内容生成最终答案。与只返回原始事实的 Recall 不同，Reflect 会返回由 LLM 综合生成的回答。

## 参数 {#parameters}

### query {#query}

要进行反思的问题或提示。这是唯一必填字段。如果有会影响回答的情境信息，请直接写入 query，而不要将其作为单独字段提供。

### budget {#budget}

控制智能体在回答前用于探索记忆库的推理预算（探索程度）。可接受的值为 `low`（默认值）、`mid` 和 `high`。设为 `low` 时，智能体会浅层搜索，以速度为先；设为 `mid` 时，会在问题需要时检查多个来源；设为 `high` 时，会深入探索各个知识层级，并可能用多个不同的查询措辞寻找间接关联。对于需要综合多个来源信息的复杂问题，请使用 `high`。

### max_tokens {#max_tokens}

限制最终生成回答的长度。默认值为 `4096`。它不会影响智能体循环期间的检索量，只限制最终答案的长度。

### response_schema {#response_schema}

可选的 JSON Schema **对象**，其中必须包含非空的 `properties` 映射（支持嵌套对象和数组）。提供该参数后，响应会在 Markdown `text` **之外额外包含** `structured_output` 字段：智能体先推理得出答案，再通过第二轮处理将答案提取为符合此 schema 的 JSON。因此，`structured_output` 是对 `text` 的忠实结构化表示：你既会得到可读答案，也会得到便于程序处理的类型化对象，两者并存，不会互相替代。无效 schema（不是对象，或没有 properties）会在调用开始前被拒绝。

### tags {#tags}

定义 reflect 智能体全程使用的可见范围，用于筛选智能体可以检索的原始事实、观测和心智模型。同一组 `tags` 和 `tags_match` 值也用于选择要注入 reflect 提示词的带标签强制指令。

`tags` 默认值为 `null`，`tags_match` 默认值为 `any`，`tag_groups` 默认值为 `null`。对于非空标签，原始事实、观测和心智模型采用与 [Recall 的 tags](./recall#tags)相同的匹配模式。强制指令还有一条规则：无标签强制指令属于全局指令；只要提供了标签范围，即使使用严格匹配或精确匹配，它们仍可能被选中。

| Reflect 配置 | 原始事实和观测 | 心智模型 | 生效的强制指令 |
|----------------|-----------------|----------|------------------|
| 省略 `tags`、`tags_match` 和 `tag_groups` | 所有带标签和无标签的数据 | 所有带标签和无标签的模型 | 仅无标签/全局强制指令 |
| `tags: []`，`tags_match` 使用默认值 `"any"` | 所有带标签和无标签的数据 | 所有带标签和无标签的模型 | 仅无标签/全局强制指令 |
| 不提供 tags，`tags_match: "exact"` | 仅无标签/全局数据 | 仅无标签/全局模型 | 仅无标签/全局强制指令 |
| `tags` 非空，使用 `any` 或 `all` | 匹配的带标签数据，以及无标签/全局数据 | 匹配的模型，以及无标签/全局模型 | 匹配的带标签强制指令，以及无标签/全局强制指令 |
| `tags` 非空，使用 `any_strict` 或 `all_strict` | 仅匹配的带标签数据 | 仅匹配的带标签模型 | 匹配的带标签强制指令，以及无标签/全局强制指令 |
| `tags` 非空，使用 `exact` | 标签集合与请求完全一致的数据 | 标签集合与请求完全一致的模型 | 标签集合完全匹配的带标签强制指令，以及无标签/全局强制指令 |
| `tag_groups` 非空，顶层 `tags_match` 使用默认值 | 符合复合表达式的数据 | 符合复合表达式的模型 | 匹配的带标签强制指令，以及无标签/全局强制指令 |

`tag_groups` 的叶节点可以设置 `resolve: "fuzzy"`，如 [Recall](./recall#fuzzy-leaves) 中所示。Reflect 会在智能体循环开始前解析一次，因此它运行的每个工具都会依据同一组标签进行筛选。

第一行刻意采用不对称规则：未指定范围的 reflect 可以搜索所有记忆，但不会加载带标签的强制指令。若要创建适用于每次 reflect 调用的强制指令，请将其 `tags` 留空。若要创建限定范围的强制指令，请为其指定标签，并在调用 `reflect` 时传入匹配的范围。

:::note `isolation_mode`
`isolation_mode` 是内部 `list_directives` 选项，不是 reflect 请求的公开参数。Reflect 始终启用此选项。当请求未提供 `tags` 或 `tag_groups` 时，它会将强制指令加载范围限制为无标签的指令。目前没有可针对单次请求关闭它的开关。
:::

:::note MCP 中省略 tags 的行为
MCP `reflect` 工具仅在提供 `tags` 时才会传递 `tags_match`。若要通过 MCP 请求空的精确范围，请同时传入 `tags: []` 和 `tags_match: "exact"`。
:::

#### 常见范围示例 {#common-scope-examples}

未指定范围的 reflect 会搜索所有记忆，但只应用全局强制指令：

```json
{
  "query": "Summarize the current project status"
}
```

项目范围会同时包含全局数据和强制指令，以及匹配的 `project:a` 数据和强制指令：

```json
{
  "query": "Summarize the current project status",
  "tags": ["project:a"]
}
```

严格项目范围会排除无标签的记忆、观测和心智模型，但仍会应用全局强制指令：

```json
{
  "query": "Summarize the current project status",
  "tags": ["project:a"],
  "tags_match": "all_strict"
}
```

### tag_groups {#tag_groups}

提供支持递归 `and`、`or` 和 `not` 表达式的复合标签筛选。它影响与扁平 `tags` 相同的 reflect 数据来源和强制指令选择。公开 REST 请求中，`tag_groups` 与 `tags` 互斥。每个叶节点都可以指定自己的匹配模式，默认值为 `any_strict`；顶层各组之间按 AND 关系组合。通常应让顶层 `tags_match` 保持默认值 `any`。使用 `tag_groups` 时，若将其设为 `exact`，还会先把事实、观测和心智模型限制在全局扁平范围内，再应用复合表达式。

目前，MCP `reflect` 工具支持扁平的 `tags` 和 `tags_match`，但不支持 `tag_groups`。

### include {#include}

控制是否在主要响应旁返回可选的补充数据。

#### include.facts {#includefacts}

启用后，响应会包含 `based_on` 对象，列出智能体实际用于构建答案的记忆、心智模型和强制指令。这里只会列出智能体循环期间检索到的来源；系统会验证引用，防止出现臆造的来源。此字段有助于提高透明度并进行核验。

#### include.tool_calls {#includetool_calls}

启用后，响应会包含 `trace` 对象，记录智能体循环中每次工具调用和 LLM 调用的完整执行日志，包括输入、输出和耗时。将 `output` 设为 `false` 可仅包含工具输入，从而缩小负载。此字段有助于调试智能体为何得出某个结论。

### reflect_search_observations_max_tokens {#reflect_search_observations_max_tokens}

当模型没有自行指定预算时，此参数用于设置智能体 `search_observations` 工具的 token 预算。在大型记忆库中，观测证据往往是 reflect 上下文中占比最大的单一部分；降低此值会舍弃排名较低的观测，以换取更小、成本更低且速度更快的 LLM 上下文。默认值为 `5000`。

### reflect_search_observations_include_entities {#reflect_search_observations_include_entities}

用于控制 `search_observations` 是否为每条观测附加已消解的实体名称。如果表层文本使用了别名（例如用“Bob”指代规范名称“Robert Smith”），这些名称会很有帮助；但它们在序列化后的工具负载中可能占一半以上。设为 `false` 可在保留相同观测和排序结果的同时，大幅缩小上下文。默认值为 `true`。

可以通过记忆库的 `reflect_default_options` 配置键为这两个选项设置默认值（参见[配置](../configuration.mdx)）；请求中显式提供的值始终优先。心智模型刷新使用单独的配置，**不会**读取 `reflect_default_options`。请改为设置触发器中的同名字段，或记忆库的 `knowledge_page_default_trigger`（参见[心智模型](./mental-models.mdx)）。

## 响应 {#response}

### text {#text}

以格式良好的 Markdown 字符串返回综合生成的答案。这是 reflect 的主要输出。即使提供了 `response_schema`，仍会返回此字段；`structured_output` 从 `text` 派生，不会取代它。

### structured_output {#structured_output}

按照请求中提供的 `response_schema` 解析后的 LLM 响应。仅在设置了 `response_schema` 时出现；否则为 `null`。

### structured_output_error {#structured_output_error}

无法生成结构化视图的原因。仅当提供了 `response_schema` 且提取过程失败时才会出现，例如提供商错误、超时或输出无法解析。Reflect 本身仍会成功：响应为 `200`，并包含 Markdown `text`。此字段表示机器可读的部分因发生故障而缺失，并非答案中没有符合 schema 的内容。若缺少 `structured_output` **且没有**此字段，则属于后一种正常情况（端点会省略值为 null 的字段）。出现此字段时应将其视为可重试错误；若结构化输出停止工作，也应以此字段作为告警信号。

### based_on {#based_on}

智能体构建答案时使用的来源。仅在启用了 `include.facts` 时出现，包含三个字段：

- `memories` — 检索并引用的记忆事实列表（world、experience、observation）。每项包含 `id`、`text`、`type`、`context`、`occurred_start` 和 `occurred_end`。
- `mental_models` — 使用过的心智模型列表。每项包含 `id`、`text` 和 `context`。
- `directives` — 推理过程中执行的强制指令列表。每项包含 `id`、`name` 和 `content`。

### usage {#usage}

智能体循环中所有 LLM 调用的 token 用量：`input_tokens`、`output_tokens` 和 `total_tokens`。可用于跟踪成本。

### trace {#trace}

智能体循环的完整执行日志。仅在启用了 `include.tool_calls` 时出现，包含：

- `tool_calls` — 每次工具调用的信息，包括 `tool` 名称（`lookup`、`recall`、`learn`、`expand`）、`input`、`output`（若 `output: true`）、`duration_ms` 和 `iteration` 轮次。
- `llm_calls` — 每次 LLM 调用的信息，包括 `scope`（例如 `"agent_1"`、`"final"`）和 `duration_ms`。

## Reflect 失败的情况 {#when-reflect-fails}

Reflect 会根据收集到的证据作答；如果某次运行无法收集证据，就不会作答，而是返回 **500** 错误，不会在毫无依据的情况下给出看似肯定的回答：

- **检索工具抛出异常。** 数据库、嵌入模型或重排序模型不可用。批量调用中只要有一个工具失败，整次运行就会失败：基于一个未返回结果的工具撰写答案，与基于一个确实不含相关主题内容的记忆库撰写答案，无法区分；调用方可能会把前一种答案当作真实答案存储。
- **模型没有生成答案。** `done` 调用返回空内容，或最终综合生成步骤没有返回任何内容。
- **模型或传输层无法驱动工具调用。** Reflect 完全依赖结构化工具调用，并要求每一轮都进行一次工具调用（`tool_choice` 为 `required`，或在强制搜索时指定具名工具）。如果没有决策模型，且模型掌握了足够的证据，它会通过 `answer_ready` 表示这一点，随后系统会再次要求它生成答案，因此答案只会写入一次。若传输层静默丢弃工具定义，系统会明确报错，让你可以切换到支持工具调用的模型；只接受 `tool_choice: "auto"` 的端点在这些轮次中也会失败（LM Studio 和 Ollama 会忽略 `required`，因此系统会向它们发送 `auto`）。
- **提供商持续出错。** 非上下文溢出导致的 LLM 错误会在循环中重试一次，之后便放弃。

**检索成功但没有返回任何结果不算失败**：这表示记忆库确实不包含相关主题的内容，reflect 会在答案中说明这一点。

另有两种情况特意不视为失败。如果运行时*上下文窗口*溢出，系统会依据已有证据综合生成答案：这是提示词对模型而言过大造成的预算问题，并非依赖项故障。如果模型*错误地*调用了工具，例如缺少参数或调用了不存在的工具，系统会将错误返回给模型以便修正，而不会抛出异常。
