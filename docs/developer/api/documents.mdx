## 什么是文档？ {#what-are-documents}

文档是存入内容的容器，可帮助你：

- **跟踪来源** — 确认一条记忆来自哪份 PDF、对话或文件
- **更新内容** — 重新存入文档以更新其中的事实
- **批量删除** — 一次移除某份文档中的所有记忆
- **整理记忆** — 按来源归组相关事实

## 文本分块 {#chunks}

存入内容时，Hindsight 会先将其拆分为文本分块，再提取事实。这些分块会与提取出的记忆一同存储，从而保留原文片段。

**文本分块的作用：**
- **保留上下文** — 分块包含生成事实的原始文本；需要准确措辞时，这些文本很有用
- **提供更丰富的召回结果** — 在召回时包含分块，可为匹配到的事实提供周边上下文

:::tip 在召回结果中包含文本分块
在 Recall（召回）调用中使用 `include_chunks=True`，即可在事实结果旁一并获取原始文本分块。详情请见[召回](./recall)。
:::

## 更新文档 {#update-document}

更新现有文档中可变的字段，无需重新处理内容。目前支持更新 `tags`。

`tags` 数组会**替换**文档原有的标签，而不是与其合并。请发送你希望文档最终包含的完整标签集合：凡是省略的标签都会被移除，空数组会清除所有标签。要移除单个标签，请先读取文档当前的标签，删去要移除的那个，再发送其余标签。完全省略此字段不算更新，且请求会被 `422` 拒绝。

:::info 观测会重新整合
标签发生变化时，由该文档中的记忆生成的任何整合观测都会失效，并进入队列，以新标签重新整合。来自其他文档、且与这些观测共享来源的记忆也会重置。

这是保证正确性所必需的行为，并非附带影响：整合会根据记忆的标签集合划分范围，因此基于旧标签构建的观测不再有效。如果删除该观测，却不把与之共同整合的其他记忆也重新排入队列，这些记忆就会失去对应的整合结果。重新排队的规模取决于与此文档共同来源的记忆数量；在来源高度交叠的记忆库中，这个数量可能是该文档自身记忆数的许多倍。

系统会将标签视为**集合**，与文档当前的标签集合比较。如果更新后集合未变（包括仅调整数组顺序的情况），就不会重新打标签，也不会排队重新整合。因此，可重复执行的标签规范化扫描只会在实际发生变化的那次运行中产生重新整合成本。
:::

## 列出文档 {#list-documents}

列出记忆库中的文档，并可按 ID、标签和时间筛选。

`start_date=` 和 `end_date=` 会根据 `time_field=` 指定的时间戳，将结果限制在左闭右开的区间 `[start, end)` 内。`time_field=` 可以是 `created_at`（文档首次到达的时间）或 `updated_at`（文档最后一次写入的时间，也是默认排序依据）。该字段同时决定排序顺序，结果按时间从新到旧排列。

由于筛选和排序使用同一列，`total` 只统计时间范围内的文档，而不是整个记忆库中的文档。省略这三个参数即可使用默认列表。

### 筛选选项 {#filtering-options}

| 参数 | 说明 |
|---|---|
| `q` | 在文档 ID 或文档文本中执行不区分大小写的子字符串匹配。`report` 可匹配 `report-2024`、`annual-report`，以及文本中包含 `report` 的任何文档。此搜索未建立索引，适用于浏览和检查记忆库，不适合大批量或对延迟敏感的查询（这类查询请使用 Recall）。 |
| `tags` | 按文档标签筛选。可接受多个值。 |
| `tags_match` | 指定标签的匹配方式（默认值：`any_strict`）。见下文。 |
| `limit` / `offset` | 分页。默认 `limit` 为 100。 |

设置 `q` 时，每个返回行都带有 `matched_fields`：值为 `["id"]`、`["original_text"]` 或两者兼有，便于调用方判断文档因何匹配。

`q` 搜索最多统计 1,000 个匹配项。超过此数量后，`total` 是下限，`total_is_estimate` 为 `true`，分页也会在上限处停止。可缩小搜索范围，或添加标签或时间筛选条件，以找到其余结果。某些存储后端对 `q` 的匹配是近似的；`matched_fields` 始终会说明实际匹配的字段。

**`tags_match` 的模式：**

| 模式 | 行为 |
|---|---|
| `any_strict` *(默认)* | 文档必须至少包含一个指定标签。排除未添加标签的文档。 |
| `any` | 与 `any_strict` 相同，但也包括未添加标签的文档。 |
| `all_strict` | 文档必须包含所有指定标签。排除未添加标签的文档。 |
| `all` | 与 `all_strict` 相同，但也包括未添加标签的文档。 |

## 文档历史 {#document-history}

系统会记录每次文档变更及其影响：每次 Retain、追加和重新处理（添加及移除的事实）、每次事实编辑、标记失效、恢复和删除、逐条清除观测、每次标签变更，以及每次整合运行（创建、更新和移除的观测会归入其来源事实所属的每份文档）。

观测会重新构建，而不是保留版本。因此，变更删除某条观测后，这份历史是仍记录其 ID 的唯一位置。每个事件只保存 ID 和计数，不保存文本；每个 ID 列表最多包含 100 项。控制台会在文档的 **History（历史）** 标签页中显示这些记录。

这份历史是根据记忆库的[操作](./operations)（其中包含这些事件）重建的，因此有两个限制：

- 历史范围不会早于操作记录的保留期限（`HINDSIGHT_API_OPERATION_RETENTION_DAYS`；默认不设期限）。
- 未通过操作运行的变更不会出现在历史中：同步 Retain（`async: false`），以及自动整合关闭时进行的事实编辑、删除或标签变更。事实编辑、删除或标签变更会记录在其排队触发的整合操作中，与该操作执行的重建一同列出。清除记忆库中的所有观测不会列出。
