# 知识页 {#knowledge-pages}

按文件夹树组织、会随着记忆库不断学习而自行改写的 Markdown 文档。

知识页以[心智模型](./mental-models)为底层，但配置方式是文档：它只根据记忆库的[观测](../observations)构建，绝不读取其他页面，并会在每次整合后增量刷新。有关 API 背后的概念，请参阅[知识页](../knowledge-pages)。


| 字段 | 说明 |
|---|---|
| `kind` | `folder`（文件夹）或 `page`（页面） |
| `mental_model_id` | 底层心智模型（仅页面有此字段） |
| `description` | 页面的来源查询，也就是用于重新生成页面的问题 |
| `timestamp` | 页面的最后刷新时间；文件夹的最后更新时间 |
| `is_stale` | 仅页面有此字段：自页面上次读取记忆以来，其自身范围内有记忆被写入时为 `true`（见下文） |
| `last_refresh_failed_at` | 仅页面有此字段：页面上次刷新失败的时间；成功时为 `null`。此字段有值时，页面不会因触发条件而自动重建；显式发起的刷新仍会执行，刷新成功后该字段会清空 |
| `managed` | 节点标记为系统管理而非人工编写时为 `true` |

### `is_stale` 的判定方式 {#how-is_stale-is-decided}

系统会根据每个页面自身的范围（其标签和 `fact_types`），使用与[待更新状态检查](./mental-models#staleness-gating)相同的规则，判断计划刷新是否需要执行。被标记的页面意味着刷新确实会改写它；未被标记的页面则会原样保留。若某页面自身范围内没有活动，记忆库其他位置的活动不会将它标记为待更新。

整个目录树通过一次查询返回，因此无论记忆库中有 3 个还是 300 个页面，判定标记的成本都相同；[`GET /mental-models/{id}`](./mental-models) 返回的该页面底层模型的状态也完全一致。

有一类变化无法被检测到：**删除**。检查会查询页面上次读取记忆之后有哪些内容被*写入*；删除范围内的记忆不会留下新的写入记录。因此，即使页面引用的事实已被删除，它仍会报告自己是最新的。

### 参数 {#parameters}

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 页面名称。在所属文件夹中必须唯一，且不区分大小写；名称重复时返回 `409`。（仅 PostgreSQL 会执行此检查。） |
| `source_query` | string | 是 | 页面要回答的问题；每次刷新时都会重新提问。 |
| `parent_id` | string | 否 | 要在其中创建页面的文件夹。传入 `null`（或省略此参数）会在根目录创建页面。 |
| `tags` | list | 否 | 用于限定页面构建所依据记忆范围的标签，参见[标签用于筛选范围](#tags-are-a-filter)。`type:<x>` 标签还会设置页面的呈现类型，同时也会参与范围筛选。 |
| `max_tokens` | int | 否 | 内容预算。默认值为 `4096`（普通心智模型的默认值为 `2048`）。 |
| `trigger` | object | 否 | 刷新配置，见下文。 |

### 标签用于筛选范围 {#tags-are-a-filter}

`tags` 不是页面的标签说明，而是页面构建所依据的范围。默认情况下，带标签的页面使用 **`all_strict`** 匹配记忆：一条记忆必须包含页面的**每一个**标签；完全排除不带标签的记忆。

例如，按以下方式创建页面：

```json
{
  "name": "Homelab Infrastructure",
  "source_query": "NAS, ThinkPad, docker containers, jellyfin",
  "tags": ["type:runbook", "homelab", "infrastructure"]
}
```

该页面只会根据同时带有 `type:runbook`、`homelab` **和** `infrastructure` 标签的记忆构建。如果存入记忆时没有添加这些完全一致的标签（创建页面时才为主题临时发明标签，通常就会出现这种情况），页面将匹配不到任何内容，生成结果会是 *“我没有这方面的信息。”* 对同一查询直接执行[召回](./recall)仍会返回所有内容，因为召回请求没有使用同一筛选条件。

`type:<x>` 标签尤其容易引起混淆：文档说明它会设置页面的呈现类型，但它和其他标签一样也会缩小检索范围。

有三种正确设置方式：

| 目标 | 操作 |
|---|---|
| 让页面根据整个记忆库构建 | 省略 `tags`（或传入 `[]`） |
| 用标签限定页面范围，同时仍纳入无标签记忆 | 保留 `tags`，并添加 `"trigger": {"tags_match": "all"}` |
| 只纳入带齐所有标签的记忆（严格隔离，例如按用户分别创建页面） | 保留 `tags`，使用默认的 `all_strict` |

若页面已生成但内容为空，可通过 `PATCH` 传入 `{"tags": []}`，或使用范围更宽的 `tags_match`，然后刷新页面。标签保存在底层心智模型中，并未固化到页面内容里。

有关 `any`、`all`、`any_strict`、`all_strict` 和 `exact` 的完整语义，请参阅[标签匹配模式](./recall#tags)。

### 默认触发配置 {#default-trigger}

省略 `trigger` 时，页面会采用面向文档的配置：

```json
{
  "mode": "delta",
  "fact_types": ["observation"],
  "exclude_mental_models": true,
  "refresh_after_consolidation": true
}
```

这样创建的页面会成为持续更新的文档，只根据整合后的观测构建；每当整合过程在其范围内产生新知识时，页面就会增量刷新，而且绝不会受其他页面影响。

| 设置 | 原因 |
|---|---|
| `fact_types: ["observation"]` | 页面读取的是整合后的认知判断，而不是其下层原始对话中的零散内容。观测已经去重并有证据支持，因此页面呈现为经过整理的文档，而非对话记录。此限制由结构保证：范围内只有 `observation` 时，刷新智能体根本不会获得原始记忆召回工具。 |
| `exclude_mental_models: true` | 页面绝不会对同级页面进行反思。若不排除，页面可能互相引用并陷入反馈循环，让一个错误说法在整个知识库中传播。 |
| `mode: "delta"` | 每次刷新都会将新内容编辑到现有文档中，而不是重新生成整篇，因此人工调整过的结构和措辞能够保留。参见[刷新模式](./mental-models#refresh-mode)。 |
| `refresh_after_consolidation: true` | 每当整合在页面范围内产生新知识，页面就会自行改写；是否刷新仍受与其他心智模型相同的[待更新状态检查](./mental-models#staleness-gating)控制，因此记忆库中无关位置的活动不会触发重建。 |

### 页面生命周期 {#page-lifecycle}

1. **创建** — 页面以占位内容保存，同时提交后台刷新任务；调用会立即返回 `operation_id`。
2. **首次生成** — 由于没有可供编辑的旧文档，系统会完整生成页面。
3. **整合** — 新记忆被存入并整合为观测。
4. **待更新状态检查** — 对触发配置要求执行检查的页面，根据其自身范围进行检查（标签和 `fact_types` 均会生效）。
5. **增量刷新** — 对待更新页面进行改写，只将新的观测编辑到现有文档中。

页面是根据观测*构建*的，但仍可检查观测背后的证据：刷新智能体可以将一条记忆展开到其原始文本分块或文档（除非记忆库禁用了 `store_document_text`）；此外，若启用了默认关闭的 `HINDSIGHT_API_REFLECT_SOURCE_FACTS_MAX_TOKENS`，观测搜索还会返回每条观测的依据事实。

:::info
传入的 `trigger` 会作为**补丁**处理：只应用请求中实际提供的字段，其余字段保留上述默认值。传入 `{"trigger": {"tags_match": "all"}}` 会放宽标签筛选，但 `mode`、`fact_types`、`exclude_mental_models` 和 `refresh_after_consolidation` 都保持原样。只有两个刷新触发方式是例外：它们互斥，设置 `refresh_cron` 会清除 `refresh_after_consolidation`，反之亦然。
:::

此处接受[心智模型的所有触发设置](./mental-models#trigger-settings)，包括用于按计划重建而非由整合触发重建的 `refresh_cron`，以及用于组合标签范围的 `tag_groups`。

```json

    {
      "id": "kp-2e85...",
```

```json
      "snippet": "The API is deployed via ...",
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `q` | string | — | 必填。搜索查询（最短长度为 1）。 |
| `limit` | int | `10` | 最大结果数，范围为 1–50。 |
| `tags` | string[] | — | 仅搜索带有这些标签的页面，并按照 `tags_match` 匹配。参见[按标签筛选](#filter-by-tags)。 |
| `tags_match` | string | `any` | 可选值：`any`、`all`、`any_strict`、`all_strict` 或 `exact`。 |
| `tag_groups` | string | — | JSON 编码的组合筛选条件，结构与召回 API 的 `tag_groups` 相同。 |

此操作搜索整个页面。要搜索单条记忆，请使用[召回](./recall)。

### 按标签筛选 {#filter-by-tags}

目录树和搜索使用与[召回](./recall)相同的标签筛选方式：通过 `tags` 搭配 `tags_match`，或提供组合形式的 `tag_groups` 表达式（由于两者都是 `GET` 请求，表达式须以 JSON 编码后放入查询字符串）。筛选会匹配每个页面自身的标签。搜索只在符合条件的页面中排名；目录树则只保留符合条件的页面及其上级文件夹。如果文件夹下没有符合条件的页面，该文件夹也会被隐藏，因为文件夹名称本身可能泄露与其页面同样多的信息。

与召回相同，`any` 和 `all` 也会返回**无标签**页面。若只应返回带标签的页面（例如只向用户展示该用户自己的页面），请使用 `any_strict`、`all_strict` 或 `exact`。

## 存储 {#storage}

| 表 | 内容 |
|---|---|
| `knowledge_pages` | 目录树：文件夹和页面、名称、上级节点及排序。页面行引用其底层心智模型；文件夹行不引用模型。 |
| `mental_models` | 页面内容：文档正文、来源查询、标签、token 预算、触发配置和刷新历史。 |

知识页这一层只负责目录树结构；所有页面内容都保存在底层心智模型中，因此心智模型的每项[功能](./mental-models)也都原样适用于知识页。

## 端点摘要 {#endpoint-summary}

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/knowledge-base/tree` | 带待更新状态的嵌套文件夹/页面目录树 |
| `POST` | `/knowledge-base/folders` | 创建文件夹 |
| `POST` | `/knowledge-base/pages` | 创建页面（异步执行首次生成） |
| `GET` | `/knowledge-base/pages/{page_id}` | 以 Markdown 形式读取页面 |
| `GET` | `/knowledge-base/search` | 对页面进行混合搜索 |
| `PATCH` | `/knowledge-base/nodes/{node_id}` | 重命名、移动或重新配置节点 |
| `DELETE` | `/knowledge-base/nodes/{node_id}` | 删除节点及其子树 |
| `GET` | `/knowledge-base/export` | 将整个知识库导出为 Markdown 文件 |
